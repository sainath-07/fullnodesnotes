Topic 1: Never Store Plain Text Passwords

Code Example
const hash = await bcrypt.hash(password, 12);
Explanation

Always hash passwords before storing them in the database. Never save plain text passwords.

Interview Question
Why use bcrypt?
Expected Answer
It hashes passwords with a salt, making them difficult to crack.

Topic 2: Use Environment Variables

Code Example
SECRET_KEY=mySecret
DB_URL=mongodb://localhost:27017/app
Explanation

Store secrets in a .env file instead of hardcoding them.

Interview Question
Why use .env?
Expected Answer
To keep secrets out of source code.

Topic 3: Validate User Input

Code Example
validate(req.body);
// or use express-validator/Joi
Explanation

Validate all client input to prevent invalid or malicious data.

Interview Question
Why validate input?
Expected Answer
To improve security and data integrity.

Topic 4: Prevent NoSQL Injection

Code Example
const user = await User.findOne({ email });
Explanation

Never pass raw user objects directly into database queries.

Interview Question
What is NoSQL Injection?
Expected Answer
Manipulating MongoDB queries using crafted input.

Topic 5: Use HTTPS

Code Example
https.createServer(options, app);
Explanation

Encrypt data in transit using TLS/SSL.

Interview Question
Why HTTPS?
Expected Answer
It protects data from interception.

Topic 6: Secure JWT

Code Example
jwt.sign(payload, SECRET_KEY, { expiresIn:'1h' });
Explanation

Use strong secrets, short expiration times and verify every token.

Interview Question
What should never be stored in a JWT?
Expected Answer
Passwords, OTPs or sensitive personal data.

Topic 7: Protect HTTP Headers

Code Example
app.disable('x-powered-by');
Explanation

Hide framework details and set secure HTTP headers.

Interview Question
Why disable x-powered-by?
Expected Answer
To reveal less information about the server.

Topic 8: Rate Limiting

Code Example
app.use(rateLimit({ windowMs:60000, max:100 }));
Explanation

Limit repeated requests to reduce brute-force and abuse.

Interview Question
Why use rate limiting?
Expected Answer
To protect APIs from excessive requests.

Topic 9: Enable CORS Carefully

Code Example
app.use(cors({ origin:'https://example.com' }));
Explanation

Allow only trusted origins instead of '*'.

Interview Question
Why restrict CORS?
Expected Answer
To reduce unauthorized cross-origin access.

Topic 10: Sanitize Data

Code Example
const name = req.body.name.trim();
Explanation

Remove unwanted characters and normalize input before processing.

Interview Question
What is sanitization?
Expected Answer
Cleaning input before using or storing it.

Topic 11: Handle Errors Safely

Code Example
return res.status(500).json({ message:'Internal Server Error' });
Explanation

Don't expose stack traces or sensitive information in production.

Interview Question
Why hide internal errors?
Expected Answer
To avoid leaking implementation details.

Topic 12: Security Checklist

Code Example
// bcrypt
// HTTPS
// JWT
// CORS
// Rate Limit
Explanation

Combine multiple layers of security rather than relying on one mechanism.

Interview Question
What is the best security practice?
Expected Answer
Use defense in depth with multiple protections.

Quick Revision

  • Hash passwords with bcrypt.
  • Store secrets in .env.
  • Validate and sanitize all user input.
  • Use HTTPS in production.
  • Use short-lived JWTs and verify every request.
  • Restrict CORS origins.
  • Apply rate limiting to public APIs.
  • Don't expose internal error details.
  • Disable unnecessary server information such as x-powered-by.
