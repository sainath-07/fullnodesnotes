Fact 1: Schema vs Model

Code Example
const schema = new mongoose.Schema({ name:String });
const User = mongoose.model('User', schema);
Explanation

A Schema defines document structure. A Model performs CRUD operations on the collection.

Interview Question
What is the difference between Schema and Model?
Expected Answer
Schema defines the structure; Model interacts with MongoDB.

Fact 2: find() vs findOne()

Code Example
await User.find();
await User.findOne({ email });
Explanation

find() always returns an array. findOne() returns an object or null.

Interview Question
What does find() return if no documents exist?
Expected Answer
An empty array [].

Fact 3: Mongoose Pluralizes Collection Names

Code Example
mongoose.model('User', schema);
Explanation

The model 'User' maps to the 'users' collection by default.

Interview Question
Which collection is created for User?
Expected Answer
'users'.

Fact 4: lean()

Code Example
const users = await User.find().lean();
Explanation

lean() returns plain JavaScript objects and improves read performance.

Interview Question
Why use lean()?
Expected Answer
Faster reads when Mongoose document features aren't needed.

Fact 5: select()

Code Example
await User.find().select('name email');
Explanation

select() fetches only the required fields.

Interview Question
Why use select()?
Expected Answer
To reduce data transfer and improve performance.

Fact 6: populate()

Code Example
await Order.find().populate('user');
Explanation

populate() replaces referenced ObjectIds with actual documents.

Interview Question
What does populate() do?
Expected Answer
It fetches referenced documents.

Fact 7: timestamps

Code Example
new mongoose.Schema({}, { timestamps:true });
Explanation

Automatically adds createdAt and updatedAt fields.

Interview Question
What does timestamps:true do?
Expected Answer
Adds createdAt and updatedAt automatically.

Fact 8: Validation

Code Example
email:{ type:String, required:true, unique:true }
Explanation

Mongoose validates data before saving documents.

Interview Question
Does unique validate duplicates by itself?
Expected Answer
No. It creates a unique index; duplicate errors come from MongoDB.

Fact 9: Indexes

Code Example
schema.index({ email:1 });
Explanation

Indexes speed up queries but increase write cost.

Interview Question
Why create indexes?
Expected Answer
To improve query performance.

Fact 10: ObjectId

Code Example
new mongoose.Types.ObjectId(id);
Explanation

MongoDB uses ObjectId as the default primary key.

Interview Question
What is _id in MongoDB?
Expected Answer
A unique ObjectId.

Quick Revision

  • Schema defines structure; Model performs CRUD.
  • find() returns an array; findOne() returns an object or null.
  • Use lean() for faster read-only queries.
  • Use select() to fetch only required fields.
  • populate() resolves referenced documents.
  • timestamps:true adds createdAt and updatedAt.
  • unique creates an index, not a validator.
  • Indexes improve read performance.
  • MongoDB uses ObjectId by default.
