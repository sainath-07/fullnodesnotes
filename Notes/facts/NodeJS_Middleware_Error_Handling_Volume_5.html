Topic 1: What is Middleware?

Code Example
app.use((req,res,next)=>{
 console.log(req.method);
 next();
});
Explanation

Middleware is a function that runs between receiving a request and sending a response. It can modify req/res, end the response, or pass control with next().

Interview Question
What is middleware?
Expected Answer
A function that has access to req, res and next().

Topic 2: Types of Middleware

Code Example
app.use(express.json());
app.use('/api',router);
Explanation

Common types are built-in, application-level, router-level, third-party and error-handling middleware.

Interview Question
Name different middleware types.
Expected Answer
Built-in, application, router, third-party and error middleware.

Topic 3: next()

Code Example
app.use((req,res,next)=>{
 console.log('Auth');
 return next();
});
Explanation

next() passes control to the next matching middleware.

Interview Question
What happens if next() is omitted?
Expected Answer
The request hangs unless a response is sent.

Topic 4: Multiple Middleware

Code Example
app.get('/profile',auth,logger,controller);
Explanation

Multiple middleware execute from left to right.

Interview Question
How are multiple middleware executed?
Expected Answer
In the order they are registered.

Topic 5: Error Middleware

Code Example
app.use((err,req,res,next)=>{
 res.status(500).json({message:err.message});
});
Explanation

Express recognizes error middleware by its four parameters.

Interview Question
Why four parameters?
Expected Answer
It tells Express this middleware handles errors.

Topic 6: next(error)

Code Example
try{
 throw new Error('Oops');
}catch(err){
 next(err);
}
Explanation

Passing an error to next() skips normal middleware and jumps to the error handler.

Interview Question
What does next(err) do?
Expected Answer
Transfers control to error middleware.

Topic 7: Custom Errors

Code Example
throw new AppError('User not found',404);
Explanation

Custom error classes help return consistent status codes and messages.

Interview Question
Why create AppError?
Expected Answer
To standardize error responses.

Topic 8: Global Error Handler

Code Example
const errorHandler=(err,req,res,next)=>{
 res.status(err.statusCode||500).json({message:err.message});
};
Explanation

A single place to format all API errors.

Interview Question
Why use one global error handler?
Expected Answer
Cleaner and reusable error handling.

Topic 9: Middleware Order

Code Example
app.use(express.json());
app.use(routes);
app.use(errorHandler);
Explanation

Register parsers first, routes second and the error handler last.

Interview Question
Where should error middleware be registered?
Expected Answer
After all routes and middleware.

Topic 10: Best Practices

Code Example
return res.status(400).json({message:'Invalid input'});
Explanation

Always return after sending a response and use meaningful HTTP status codes.

Interview Question
What is one middleware best practice?
Expected Answer
Return after sending a response.

Quick Revision

  • Middleware executes in order.
  • Call next() or send a response.
  • next(err) jumps to the error handler.
  • Error middleware must have four parameters.
  • Register the global error handler last.
  • Use custom error classes for consistent API responses.
