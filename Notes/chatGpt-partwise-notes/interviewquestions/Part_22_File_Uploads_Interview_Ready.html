Node.js + Express.js Interview Preparation

Part 22 — File Uploads

Interview-ready learning notes, practical code questions, answers, and “Why?” explanations.

Interview focus: Understand how multipart/form-data reaches Express, how Multer parses files, req.file vs req.files, limits, validation, storage, errors, and why production systems often use cloud/object storage.
1. What is a File Upload?

A file upload means sending a file from a client, such as a browser, to a server. Examples are profile pictures, PDFs, product images, and documents.

Layman example: Think of an online application form. You select your resume and click Upload. The browser sends the file to the server, and the server validates and stores it.
Why is this different from normal JSON?

Files are binary data. A common browser format for sending files together with normal form fields is multipart/form-data.

3. What is multipart/form-data?

multipart/form-data is an HTTP request content type designed for forms that can contain files and normal fields.

POST /upload
Content-Type: multipart/form-data; boundary=...

field: "profile"
file: profile.jpg
Important: Do not manually set the multipart boundary in browser JavaScript when using FormData. The browser sets the correct content type and boundary.

When to use: Use it when a request needs to send files. For normal JSON-only requests, use application/json.

4. What is Multer?

Multer is Express middleware commonly used to process multipart/form-data requests. It makes uploaded file information available to your route handlers.

const multer = require("multer");

const upload = multer({
  dest: "uploads/"
});

app.post("/upload", upload.single("avatar"), (req, res) => {
  console.log(req.file);
  res.json({ message: "Uploaded" });
});
Interview line: “Multer is middleware used in Node.js/Express applications to handle multipart/form-data, especially file uploads.”

7. File Size and Type Validation

Never trust only the browser's validation. The server must enforce upload limits and validate what it accepts.

const upload = multer({
  limits: {
    fileSize: 2 * 1024 * 1024 // 2 MB
  },
  fileFilter: (req, file, cb) => {
    const allowed = [
      "image/jpeg",
      "image/png",
      "image/webp"
    ];

    if (allowed.includes(file.mimetype)) {
      cb(null, true);
    } else {
      cb(new Error("Only image files are allowed"));
    }
  }
});
Security point: MIME type checks are useful, but for sensitive systems you should also inspect the actual file content/signature and consider safe image/document processing. Never trust the filename or client-provided MIME type alone.
8. File Names

Do not blindly use the original filename as a server path. A safer design generates a server-side unique name and stores metadata separately.

const crypto = require("crypto");

const safeName =
  crypto.randomUUID() + ".jpg";
Mistake: Using a user-controlled filename directly in a filesystem path can create collisions and may introduce path traversal risks if handled incorrectly.
9. Disk Storage vs Memory Storage
StorageWhere file data goesTypical useMain concern
DiskServer filesystemTemporary/local filesDisk management and cleanup
MemoryRAM as a BufferSmall files sent directly to another serviceLarge files can consume RAM
 
const upload = multer({
  storage: multer.memoryStorage()
});

app.post("/upload", upload.single("file"), (req, res) => {
  console.log(req.file.buffer);
  res.send("Received");
});
Interview point: Memory storage is convenient when a file is immediately processed or sent to object storage, but size limits are essential because the file occupies memory.
10. File Deletion

If files are stored on disk, application code may need to remove them when a record is deleted or when an upload is replaced.

const fs = require("fs/promises");

await fs.unlink(filePath);

In cloud storage, deletion normally uses the storage provider's SDK/API rather than local filesystem APIs.

11. Cloud Storage Concept

Production applications often store uploaded files in object storage instead of keeping permanent files on the application server.

Examples include services such as Amazon S3, Google Cloud Storage, and Azure Blob Storage. The important interview idea is the separation between file storage and application/database data.

12. Interview Code Questions
Question 1 — What does this code make available?
app.post("/upload", upload.single("avatar"), (req, res) => {
  console.log(req.file);
  console.log(req.files);
  res.send("OK");
});
Answer: With upload.single("avatar"), the uploaded file is placed in req.file. req.files is not the expected property for this single-file middleware.
Why? The Multer middleware method determines the shape of the request data. single() represents one file, while array() and fields() expose multiple files through req.files.
Question 2 — Find the mistake
app.post("/upload", express.json(), upload.single("file"), handler);
Answer: express.json() does not parse multipart file data. The route needs Multer (or another multipart parser) to process the file portion.
Why? JSON parsing and multipart parsing are different formats. A request with multipart/form-data must be handled by multipart-aware middleware.
Question 3 — Why is this dangerous?
const path = "/uploads/" + req.file.originalname;
Answer: The original filename is controlled by the client and should not be trusted as a filesystem path. Generate a safe server-side filename and keep the original name only as metadata if needed.
Why? User-controlled path components can cause path traversal, overwrites, or naming conflicts if the application constructs paths unsafely.
Question 4 — What is the memory risk?
const upload = multer({
  storage: multer.memoryStorage()
});
Answer: Uploaded files are held in memory as Buffers. Without strict size and count limits, large uploads can consume a large amount of RAM and hurt application stability.
Why? RAM is limited and is shared with the Node.js process. Disk/object storage is more suitable for persistent or large files.
Question 5 — What happens with this limit?
const upload = multer({
  limits: { fileSize: 1024 * 1024 }
});
Answer: Multer limits an uploaded file to approximately 1 MiB. A file larger than the configured limit causes an upload error that the application should handle.
Why? Upload limits reduce memory, disk, bandwidth, and denial-of-service risks.
Question 6 — Output-based question
app.post(
  "/photos",
  upload.array("photos", 3),
  (req, res) => {
    console.log(req.files.length);
    res.send("done");
  }
);

Suppose the client sends 2 files using the field name photos. What is printed?

Answer: 2.
Why? array("photos", 3) collects up to three files with that field name into req.files. Two uploaded files therefore produce an array of length 2.
Question 7 — Design question
const upload = multer({
  limits: { fileSize: 5 * 1024 * 1024 }
});

Give two additional protections you would add for an image-upload API.

Answer: Add a strict allowed-file policy and validate the actual file content/signature where appropriate. Also generate safe unique filenames and limit the number of uploaded files.
Why? Size limits alone do not prove that a file is safe or that it is really the expected type. Multiple layers reduce upload abuse and accidental processing of dangerous files.
Question 8 — Error handling
app.post("/upload", upload.single("file"), (req, res) => {
  res.json({ ok: true });
});

How should upload errors be handled in a production Express application?

Answer: Handle Multer errors and pass unexpected errors to the centralized Express error handler. Return a safe HTTP status and a clear client-facing message without exposing internal details.
Why? File-size, file-count, storage, and parsing failures are expected operational errors. Centralized handling keeps API responses consistent and prevents sensitive server details from leaking.
13. Complete Interview-Style Example
const express = require("express");
const multer = require("multer");
const crypto = require("crypto");

const app = express();

const upload = multer({
  storage: multer.memoryStorage(),
  limits: {
    fileSize: 2 * 1024 * 1024,
    files: 1
  },
  fileFilter: (req, file, cb) => {
    const allowed = new Set([
      "image/jpeg",
      "image/png",
      "image/webp"
    ]);

    if (!allowed.has(file.mimetype)) {
      return cb(new Error("Unsupported file type"));
    }

    cb(null, true);
  }
});

app.post("/profile", upload.single("avatar"), async (req, res, next) => {
  try {
    if (!req.file) {
      return res.status(400).json({
        message: "Avatar is required"
      });
    }

    const objectKey =
      `${crypto.randomUUID()}-${req.file.originalname}`;

    // Example: send req.file.buffer to object storage.
    // Store objectKey/URL in the database.

    res.status(201).json({
      message: "Upload accepted",
      key: objectKey
    });
  } catch (error) {
    next(error);
  }
});

app.use((err, req, res, next) => {
  console.error(err);

  res.status(400).json({
    message: err.message || "Upload failed"
  });
});

app.listen(3000);
Interview explanation: “The browser sends multipart/form-data. Multer parses the upload, applies size/type limits, and exposes the file through req.file. The server can then process the Buffer or store the file in object storage and save only its key or URL in the database.”
14. Common Developer Mistakes
  • Using express.json() and expecting it to parse uploaded files.
  • Trusting originalname as a safe filesystem path.
  • Allowing unlimited file sizes or unlimited file counts.
  • Checking only the file extension.
  • Checking only client-side validation.
  • Using memory storage for large uploads without limits.
  • Keeping uploaded files forever after database records are deleted.
  • Returning raw internal storage or filesystem errors to clients.
  • Storing large binary files directly inside a normal database without considering the architecture.
  • Using local disk storage when the application needs multiple servers or horizontally scaled instances.

16. Quick Recap
  • Files are commonly uploaded with multipart/form-data.
  • Multer is middleware for parsing multipart uploads in Express.
  • upload.single() → req.file.
  • upload.array() / upload.fields() → req.files.
  • Always apply size/count limits.
  • Do not trust filenames or client-provided file metadata.
  • Memory storage is useful for small/temporary processing but consumes RAM.
  • Disk storage is useful for local/temporary files.
  • Cloud object storage is common for production, scalable applications.
  • Handle upload errors centrally and return safe API responses.
