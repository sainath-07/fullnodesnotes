Part 1 — Node.js Fundamentals ⭐⭐⭐

Concepts first, then tricky code-based interview questions.

1. What is Node.js?

What: Node.js is a JavaScript runtime that lets JavaScript run outside the browser. It uses the V8 JavaScript engine and adds APIs for networking, files, processes and other server-side work.

Why: Browsers provide browser APIs such as the DOM. Node provides APIs designed for server and system tasks.

Layman: JavaScript is the language, V8 is the engine, and Node.js is the environment around the engine that gives JavaScript extra tools.

JavaScript → V8 executes JS → Node APIs → OS / Network / Files / Processes
Interview line: Node.js is a JavaScript runtime built on V8 that runs JavaScript outside the browser.
2. Node.js vs Browser JavaScript
BrowserNode.js
DOM and windowNo browser DOM/window by default
Web APIsNode APIs such as fs, process and http
UI focusedServer, tools and system tasks

Q1 — Output

console.log(typeof window);
console.log(typeof process);
undefined
object
Why? Node does not provide the browser window object. Node provides process.
3. V8 Engine & Node.js Architecture

V8 executes JavaScript. Node adds runtime APIs and asynchronous I/O machinery around V8.

Important: Saying “Node.js is single-threaded” is incomplete. JavaScript on the main thread executes one piece at a time, while Node can use OS facilities, libuv's worker pool for some operations, and worker threads.

JS → V8 → Node APIs / libuv → OS or I/O → callback/promise continuation → JS

Q2 — Predict output

const fs = require("fs");
console.log("A");
fs.readFile(__filename, () => console.log("B"));
console.log("C");
A
C
B
Why? readFile starts asynchronous I/O. JavaScript continues to C; the callback runs later.
4. Event-Driven Architecture & Non-Blocking I/O

Event-driven: code reacts when an event or asynchronous operation becomes ready. Non-blocking I/O: asynchronous I/O does not synchronously wait for the result.

Request → start I/O → continue JS → I/O completes → callback/event ready → event loop → callback

Q3 — Blocking or non-blocking?

const fs = require("fs");
console.log("start");
const data = fs.readFileSync(__filename,"utf8");
console.log("end");
Answer: Blocking. Why? readFileSync prevents later JavaScript from running until the read finishes.
5. process & process.argv

process represents the current Node process. process.argv contains command-line arguments.

Q4 — Strings matter

// node app.js 10 20
const a = process.argv[2];
const b = process.argv[3];
console.log(a + b);
1020
Why? argv values are strings. Convert with Number() when numeric addition is required.

Q5 — process type

console.log(typeof process);
console.log(typeof process.pid);
object
number
Why? process is an object and pid is a numeric process identifier.
6. process.env

Environment variables provide configuration outside source code. Their values should be treated as strings.

Q6 — Type

// PORT=5000 node app.js
console.log(typeof process.env.PORT);
console.log(process.env.PORT + 1);
string
50001
Why? PORT is the string "5000", so + performs string concatenation.
7. process.exit()

process.exit(code) terminates the process. 0 conventionally means success; non-zero commonly means failure.

Q7 — Output

console.log("before");
process.exit(0);
console.log("after");
before
Why? The process terminates before the second log can execute.
Mistake: Do not use process.exit as routine application control; graceful shutdown is safer when pending work matters.
8. process.cwd(), __dirname, __filename

process.cwd() is the process working directory. In CommonJS, __dirname is the current module directory and __filename is the current module path.

/app/server.js → __filename = /app/server.js
　　　　　　　　　 __dirname = /app
process.cwd() = directory from which node was started

Q8 — Are these always equal?

console.log(process.cwd() === __dirname);
Answer: No, not necessarily. Why? cwd depends on where the process was started; __dirname depends on the current CommonJS file.

Q9 — Relationship

const path = require("path");
console.log(path.dirname(__filename) === __dirname);
true
Why? __dirname is the directory portion of __filename in CommonJS.
9. global & globalThis

Node's traditional global object is global. globalThis is the standard cross-environment way to access the global object. In Node they refer to the same global object.

Q10 — Output

console.log(global === globalThis);
globalThis.app = "Node";
console.log(global.app);
true
Node
Why? Both names refer to the same global object in Node.
Mistake: Avoid storing application state globally because it creates hidden shared state.
10. console

Node's console provides logging methods such as log, error, warn and table.

Q11 — Return value

const x = console.log("Hello");
console.log(x);
Hello
undefined
Why? console.log prints its argument and returns undefined.
11. Node.js REPL

REPL means Read–Eval–Print–Loop. It lets you test JavaScript and Node APIs interactively.

Read → Evaluate → Print → Loop

Q12 — REPL

> const x = 10
> x * 2
20
> typeof process
'object'
Why? The Node REPL runs inside the Node runtime and has access to the process object.
12. MAANG/FANG/MNC Mixed Questions

Q13 — Timer + blocking loop

console.log("A");
setTimeout(() => console.log("B"), 0);
for(let i=0;i<1e8;i++){}
console.log("C");
A
C
B
Why? Synchronous JavaScript, including the long loop, runs before the timer callback can execute.

Q14 — Async architecture

console.log("1");
require("fs").readFile(__filename,() => console.log("2"));
console.log("3");
1
3
2
Why? File I/O is started asynchronously; the synchronous logs run first.

Q15 — Correct mental model

Is Node.js completely single-threaded?

Answer: No. Why? JavaScript execution on the main thread is single-threaded, but Node uses the operating system, libuv's worker pool for some tasks, and can use worker threads for JavaScript work.
13. Common Developer Mistakes
  • Calling Node.js a programming language.
  • Saying the entire Node runtime is single-threaded.
  • Confusing asynchronous I/O with synchronous file APIs.
  • Confusing cwd with __dirname.
  • Treating process.env and process.argv values as numbers.
  • Using process.exit for normal application flow.
  • Assuming browser APIs such as window and DOM exist in Node.
  • Thinking V8 alone is the complete Node runtime.
14. Quick Recap & Interview Points
  • Node.js: JavaScript runtime outside the browser.
  • V8: JavaScript engine used by Node.
  • Architecture: V8 + Node APIs + asynchronous I/O machinery + OS capabilities.
  • Event-driven: application code reacts to events and completed asynchronous work.
  • Non-blocking I/O: asynchronous I/O lets JS continue instead of synchronously waiting.
  • process: current Node process information/control.
  • argv: command-line arguments, normally strings.
  • env: environment variables, normally strings.
  • cwd: process working directory.
  • __dirname: current CommonJS module directory.
  • __filename: current CommonJS module file path.
  • globalThis: standard global-object access.
  • REPL: Read–Eval–Print–Loop.
Golden interview line: “Node.js is a V8-based JavaScript runtime. Its main JavaScript execution is single-threaded, while asynchronous I/O and other runtime mechanisms allow it to handle many operations without synchronously blocking the JavaScript thread.”
