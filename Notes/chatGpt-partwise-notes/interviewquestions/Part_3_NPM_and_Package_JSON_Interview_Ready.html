Part 3 — npm & package.json ⭐⭐⭐

Understand packages, dependency versions, lock files and npm commands through interview-style code questions.

1. What is npm?

What: npm is the package manager commonly used with Node.js. It helps developers install, update, remove and run packages and project scripts.

Why / purpose: Instead of writing every feature yourself, you can use tested packages and manage their versions.

Layman example: Think of npm as a store plus a manager for the libraries your project needs.

Project → npm command → package registry / local cache → node_modules → application
Interview point: npm is a package manager and also provides commands for project scripts and dependency management.

Q1 — Is npm the same thing as Node.js?

Answer: No. Node.js is a JavaScript runtime; npm is a package manager and command-line tool commonly installed with Node.js.
2. npm init & package.json

npm init creates a package.json file interactively. npm init -y creates it using default answers.

npm init npm init -y

package.json describes project metadata, scripts and dependency ranges.

{ "name": "my-api", "version": "1.0.0", "scripts": { "start": "node server.js" }, "dependencies": { "express": "^5.1.0" }, "devDependencies": { "nodemon": "^3.1.0" } }

Q2 — What happens with npm start?

Answer: npm looks for the start script in package.json and runs its command.
Why? The scripts section maps convenient names such as start to shell commands.

Q3 — Why commit package-lock.json?

Answer: It helps the team and CI environments reproduce the same resolved dependency tree.
Why? A dependency range such as ^1.2.3 can allow different compatible versions over time. The lock file records the concrete resolution.

Q4 — Does package-lock.json replace package.json?

Answer: No. They have different jobs. package.json declares project requirements; package-lock.json records the resolved dependency tree.
4. Dependencies vs Dev Dependencies

dependencies: Packages required by the application when it runs.

devDependencies: Packages mainly needed during development, testing or building.

npm install express npm install --save-dev nodemon
dependencies → runtime application needs
devDependencies → development / test / build needs

Q5 — Where should Express normally go?

Answer: dependencies.
Why? A deployed Node application normally needs Express at runtime.

Q6 — Where should a test framework usually go?

Answer: Usually devDependencies because tests are development/CI tooling rather than the production runtime itself.
5. npm install ⭐⭐⭐

npm install with no package name installs project dependencies from package.json. When a lock file is present, npm uses it as part of dependency resolution.

npm install package-name installs a package and normally records it in dependencies.

npm install npm install express npm install --save-dev nodemon

Q7 — What changes after npm install express?

Answer: npm installs Express into the project and normally updates package.json, package-lock.json and node_modules.
Why? The project now declares the package and npm records its resolved dependency information.
6. npm install vs npm ci ⭐⭐⭐
npm installnpm ci
Used for normal dependency installation and dependency changesDesigned for clean, reproducible installs
Can update package-lock.json when resolution changesRequires package.json and lock file to be in sync
Can modify dependency metadataRemoves existing node_modules and performs a clean install
Common during developmentCommon in CI/CD pipelines
CI/CD → package.json + package-lock.json → npm ci → clean node_modules → exact locked tree

Q8 — Why is npm ci preferred in CI?

Answer: It is intended for clean, reproducible installs from the lock file.
Why? CI should avoid carrying old local dependencies and should install the dependency tree represented by the lock file. It also fails when the lock file and package.json are not in sync.

Q9 — What happens if package.json and package-lock.json are out of sync with npm ci?

Answer: npm ci fails instead of silently changing the lock file.
Why? Reproducibility is the goal; the lock file must satisfy the package.json dependency requirements.
7. npm uninstall, update and node_modules
npm uninstall express npm update npm update express

node_modules is where npm installs project packages and their dependencies.

Q10 — Is node_modules usually committed to Git?

Answer: Usually no.
Why? It can be very large and is reproducible from package.json and the lock file. Teams normally add node_modules/ to .gitignore.

Q11 — What is npm update different from npm install?

Answer: npm update updates installed dependencies within the version ranges allowed by the project configuration and lock/resolution rules. npm install is the general command for installing dependencies and can also add packages.
8. npm Scripts
{ "scripts": { "start": "node server.js", "dev": "nodemon server.js", "test": "jest" } }

Run scripts with commands such as npm start, npm run dev and npm test.

Q12 — Why does npm start work without npm run start?

Answer: npm provides special shortcuts for scripts such as start, test, stop and restart.
Why? npm start is a built-in npm lifecycle shortcut for the start script.

Q13 — How do you run a custom script named build?

npm run build
Why? Custom scripts are normally executed through npm run <script-name>.
9. Semantic Versioning — ^, ~ and Exact Versions ⭐⭐⭐

Semantic versioning normally follows MAJOR.MINOR.PATCH.

2.4.7 │ │ │ │ │ └─ patch │ └─── minor └───── major
VersionGeneral meaning
2.4.7Exact version
~2.4.7Allows patch-level updates within the minor line
^2.4.7Allows compatible updates below the next major for a normal major version

Q14 — Which versions can ^2.4.7 generally allow?

Answer: Versions >=2.4.7 and <3.0.0, subject to npm semver rules.
Why? The caret allows compatible minor and patch changes while keeping the major version at 2.

Q15 — Which versions can ~2.4.7 generally allow?

Answer: Versions >=2.4.7 and <2.5.0 in the normal three-part semver case.
Why? Tilde is generally limited to patch updates within the specified minor version.
Important: Semver range behavior has special rules for 0.x versions. Do not apply the simple caret rule blindly to every version.
10. Global Packages vs Local Packages

Local: Installed inside a project and normally used by that project.

Global: Installed for broader command-line use on the machine.

npm install typescript npm install -g typescript

Q16 — Which is usually better for a project's build tool?

Answer: A local dependency is usually better.
Why? The project can pin/control the tool version and teammates/CI can use the project's dependency instead of relying on a machine-wide version.
11. npx

npx is used to execute package binaries, often from the local project's dependencies. It can also fetch a package when appropriate.

npx create-vite@latest npx eslint .

Q17 — Why use npx instead of installing every CLI globally?

Answer: It can run a project-local CLI and avoids depending on a global installation.
Why? Local CLI versions are easier to keep consistent across developers and CI environments.
12. Dependency Tree

A package can depend on other packages. Those dependencies can have their own dependencies. This creates a dependency tree.

my-app
├── express
│ ├── dependency-A
│ └── dependency-B
└── axios
└── dependency-C

Q18 — Why can installing one package add many packages?

Answer: Because packages can have their own dependencies, creating transitive dependencies.
Why? npm resolves the complete dependency graph needed to satisfy the project.
13. MAANG/FANG/MNC Output-Based Questions

Q19 — package.json range + lock file

// package.json "express": "^5.1.0" // package-lock.json resolved express version: 5.1.2 npm ci
Answer: npm ci installs the locked resolved version represented by the lock file, provided the lock file is valid and in sync with package.json.
Why? The lock file is used to make CI installation reproducible.

Q20 — What happens after deleting node_modules?

rm -rf node_modules npm ci
Answer: npm ci creates a clean installation from the lock file.
Why? npm ci is designed to remove an existing node_modules and perform a clean dependency installation.

Q21 — Dependency version trap

// package.json "demo": "^1.2.3" // Developer A installs today. // Developer B installs later.
Answer: They can resolve different compatible versions if the lock file is not used or is regenerated under different conditions.
Why? The caret range permits compatible updates below the next major version. A committed lock file helps keep the resolved tree consistent.

Q22 — Dev dependency trap

"dependencies": { "jest": "^30.0.0" }
Answer: Jest is usually better placed in devDependencies when it is only used for testing.
Why? Production runtime dependencies and development/test tools have different purposes.

Q23 — Lock file question

A teammate changes package.json manually but does not update package-lock.json. What should you expect from npm ci?

Answer: It may fail if the lock file does not satisfy package.json.
Why? npm ci expects the dependency declarations and lock file to be in sync rather than modifying the lock file for you.
14. Common Developer Mistakes
  • Committing node_modules instead of the lock file.
  • Deleting package-lock.json just to fix every dependency problem.
  • Using npm install in CI when a reproducible clean install is expected.
  • Thinking npm ci updates package.json or package-lock.json.
  • Putting build/test tools in runtime dependencies without a reason.
  • Installing project CLIs globally and then getting different versions on different machines.
  • Thinking ^ and ~ mean the same thing.
  • Forgetting that transitive dependencies create a larger dependency tree.
  • Assuming package.json and package-lock.json have the same purpose.

16. Quick Recap & Interview Ready
  • npm: Package manager and command-line tool used with Node.js.
  • npm init: Creates package.json.
  • package.json: Project metadata, scripts and declared dependency ranges.
  • package-lock.json: Records the resolved dependency tree for reproducible installs.
  • dependencies: Runtime packages.
  • devDependencies: Development, testing and build packages.
  • npm install: General dependency installation/update command.
  • npm ci: Clean, reproducible installation using the lock file; expects package.json and lock file to be in sync.
  • npm start: Runs the start script.
  • npm run: Runs custom npm scripts.
  • ^: Generally allows compatible minor/patch updates below the next major for normal major versions.
  • ~: Generally allows patch updates within the specified minor version.
  • Exact version: Pins one version in the dependency declaration.
  • npx: Executes package binaries, commonly from local dependencies.
  • node_modules: Installed dependency tree.
  • Dependency tree: Direct + transitive dependencies.
Most important interview comparison:
package.json = “What versions/ranges does my project request?”
package-lock.json = “What exact dependency tree did npm resolve?”
npm install = flexible development installation and dependency management.
npm ci = clean, reproducible installation for CI/CD.
Golden interview line: “package.json declares the project's dependencies and version ranges, while package-lock.json records the resolved dependency tree. npm ci is designed for clean, reproducible installs and requires the lock file to be synchronized with package.json.”
