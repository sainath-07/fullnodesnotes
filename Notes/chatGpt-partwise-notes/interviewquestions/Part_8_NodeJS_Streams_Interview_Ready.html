Part 8 — Streams ⭐⭐⭐

Learn how Node.js processes large or continuous data without loading everything into memory at once.

1. What are Streams?

What: A stream is an interface for processing data gradually, usually in chunks, instead of waiting for the complete data to be available.

Why: Streams are useful for large files, HTTP requests/responses, compression and other continuous data because they can reduce memory usage and allow processing to begin earlier.

Layman example: Imagine moving water through a pipe. You do not wait for the whole water tank to arrive before using it. Water moves through the pipe piece by piece.

Large source → chunk → chunk → chunk → destination
Process data as it arrives

Q1 — Why can a stream be better than reading a huge file completely?

Answer: A stream can process chunks incrementally, avoiding the need to hold the entire file in memory at once. It can also start processing before the complete file has been read.

Q2 — What is the difference between Duplex and Transform?

Answer: Both can read and write. A Transform stream is specifically designed so that output is derived from input, such as compressing, decompressing or changing data.

Q3 — Is every Transform stream Duplex?

Answer: Conceptually, yes. A Transform stream has readable and writable sides, with the important purpose of transforming data between them.
3. Readable Stream Events and read()

Readable streams can be consumed using APIs such as event-based reading or async iteration. Common events include data, end and error.

const fs = require("fs"); const stream = fs.createReadStream("input.txt"); stream.on("data", chunk => { console.log("Chunk:", chunk.length); }); stream.on("end", () => { console.log("Finished"); }); stream.on("error", err => { console.log("Error:", err.message); });

Q4 — When does "end" happen?

Answer: For a readable stream, end indicates that there is no more data to read.

Q5 — What does a data listener generally do?

Answer: It receives chunks as the readable stream provides data. With a typical flowing-mode stream, adding a data listener causes data to be delivered through that event.
4. Writable Streams — write() and end()
const fs = require("fs"); const out = fs.createWriteStream("output.txt"); out.write("Hello "); out.write("Node.js"); out.end("!");

Q6 — What does end() do?

Answer: It signals that no more data will be written. An optional final chunk can be supplied, as shown above.

Q7 — What does write() return?

Answer: For a writable stream, write() returns a Boolean. true means the caller can generally continue writing; false means the internal buffer has reached its threshold and the caller should wait for drain.
5. Backpressure ⭐⭐⭐⭐⭐
Most important interview topic in this part. Backpressure happens when a data producer can provide data faster than the consumer can process it.
Fast Producer
↓ ↓ ↓ ↓ ↓
Writable buffer fills
↓
write() returns false
↓
Producer waits
↓
"drain" event
↓
Producer continues

Layman example: A water tap is the producer and a small bottle is the consumer. If the tap sends water faster than the bottle can accept it, you must slow or pause the flow.

function writeMany(stream, chunks) { let i = 0; function write() { while (i < chunks.length) { const canContinue = stream.write(chunks[i++]); if (!canContinue) { stream.once("drain", write); return; } } stream.end(); } write(); }

Q8 — Why is checking write() important?

Answer: If write() returns false, the writable stream is telling the producer to slow down. Waiting for drain prevents unlimited buffering and helps control memory usage.

Q9 — What is the danger of ignoring backpressure?

Answer: A fast producer may keep creating or buffering data faster than the consumer can handle it. Memory usage can grow significantly and application performance can suffer.

Q10 — What does drain mean?

Answer: The drain event indicates that the writable stream has reduced its buffered data enough for writing to continue.
6. highWaterMark

highWaterMark is a buffering threshold used by streams. It is important to understand that it is a threshold for buffering behavior, not simply a strict maximum memory limit.

const fs = require("fs"); const out = fs.createWriteStream("out.txt", { highWaterMark: 1024 });

Q11 — Is highWaterMark a hard maximum memory limit?

Answer: No. It is a threshold used to determine buffering/backpressure behavior. Applications can temporarily have more data associated with the stream than that number.

Q12 — How is highWaterMark related to write() returning false?

Answer: As the writable stream's internal buffered data reaches the configured threshold, write() can return false, telling the producer to wait for drain.
7. pipe() and Stream Chaining
const fs = require("fs"); const input = fs.createReadStream("input.txt"); const output = fs.createWriteStream("copy.txt"); input.pipe(output);
Readable stream → pipe() → Writable stream
Input file → chunks → Output file

Q13 — Why is pipe() preferred for many stream-to-stream tasks?

Answer: pipe() connects streams and handles the flow of data between them, including important backpressure behavior.

Q14 — Can streams be chained?

Answer: Yes. For example, readable → transform → transform → writable. This is useful for compression, encryption or other data processing pipelines.
8. Transform and Compression Streams
const fs = require("fs"); const zlib = require("zlib"); fs.createReadStream("input.txt") .pipe(zlib.createGzip()) .pipe(fs.createWriteStream("input.txt.gz"));

Q15 — What does the gzip stream do?

Answer: It is a Transform stream: it accepts input data, compresses it and produces compressed output.

Q16 — Why is this better than loading the whole file first?

Answer: The pipeline can compress chunks as they flow through it, avoiding the need to load the entire file into memory before compression starts.

Q17 — Are Streams and Buffers competitors?

Answer: No. They work together. A stream often delivers binary chunks as Buffers. The stream controls how data flows; the Buffer holds a chunk of bytes.
10. MAANG / FANG / MNC Output & Code Questions ⭐⭐⭐

Q18 — write() backpressure decision

const ok = writable.write(data); if (!ok) { console.log("PAUSE"); }
Answer: If write() returns false, the producer should stop or pause writing and resume after the drain event.

Q19 — data and end order

stream.on("data", () => console.log("data")); stream.on("end", () => console.log("end"));
Answer: Data chunks are delivered before the readable stream's end event. end means no more data is available.

Q20 — What if a writable stream emits error?

output.on("error", err => { console.log("failed"); });
Answer: The error listener receives the stream error. Production code should handle stream errors intentionally, especially when reading/writing files or handling network operations.

Q21 — Does pipe() mean the whole source is loaded first?

Answer: No. The source is processed as chunks. pipe() connects the flow and handles backpressure between the readable and writable sides.

Q22 — What happens if the consumer is slower?

Answer: Backpressure can cause the producer to slow down. For writable streams, write() can return false, and the producer should wait for drain.

Q23 — Which stream is best for changing data?

Answer: A Transform stream. Examples include compression, decompression, encryption or data formatting.

Q24 — Why is backpressure an important interview topic?

Answer: It tests whether you understand real-world stream performance. A producer must not overwhelm a slower consumer. Correct backpressure handling controls buffering, memory usage and throughput.
11. Common Developer Mistakes
  • Loading a huge file into memory when a stream would be better.
  • Ignoring the Boolean returned by write().
  • Continuing to write after write() returns false instead of waiting for drain.
  • Thinking highWaterMark is a hard memory limit.
  • Forgetting to handle stream errors.
  • Calling end() too early.
  • Confusing a Buffer (bytes) with a Stream (data flow).
  • Assuming pipe() means the entire file is stored in memory.
