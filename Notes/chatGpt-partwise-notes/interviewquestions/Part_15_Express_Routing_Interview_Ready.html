Node.js + Express.js Interview Preparation

Part 15 — Express Routing

Interview-ready routing concepts, code questions, output questions, answers, WHY explanations, diagrams, and common mistakes.

1. What is Express Routing?

Routing means deciding which code should run when a client sends a request to a particular HTTP method and URL.

Layman example: Think of a hotel receptionist. A guest says, "I need room 205." The receptionist checks the request and sends the guest to the correct room. Express routing does something similar.
Client→HTTP Method + URL→Route Matching→Handler→Response
Why is routing important?
  • Separates different API operations.
  • Makes APIs easier to understand.
  • Helps organize large applications.
  • Allows middleware to run for selected routes.
2. Route Definitions and HTTP Methods
app.get("/users", getUsers);
app.post("/users", createUser);
app.put("/users/:id", replaceUser);
app.patch("/users/:id", updateUser);
app.delete("/users/:id", deleteUser);
MethodExampleCommon purpose
GET/usersRead resources
POST/usersCreate resource
PUT/users/10Replace resource
PATCH/users/10Partially update resource
DELETE/users/10Delete resource
Interview point: Routing is matched using the HTTP method and URL path, not the URL alone.
3. Route Parameters, Query Parameters, and Request Body
Route parameter
app.get("/users/:id", (req, res) => {
  console.log(req.params.id);
  res.send("OK");
});

// GET /users/42
// req.params.id → "42"
Query parameter
app.get("/users", (req, res) => {
  console.log(req.query.page);
  console.log(req.query.role);
  res.json(req.query);
});

// GET /users?page=2&role=admin
Request body
app.use(express.json());

app.post("/users", (req, res) => {
  console.log(req.body);
  res.json(req.body);
});
Remember: req.params comes from the route path, req.query comes after ?, and req.body contains data sent in the request body when the correct body parser is configured.
4. Route Order and Route Matching
app.get("/users/:id", (req, res) => {
  res.send("dynamic route");
});

app.get("/users/profile", (req, res) => {
  res.send("profile route");
});

Request: GET /users/profile

Important: The dynamic route can match profile as the value of :id. Because Express checks routes in registration order, the first matching route can handle the request.

Better order:

app.get("/users/profile", profileHandler);
app.get("/users/:id", userHandler);
5. express.Router()

express.Router() creates a separate router object. It is useful for splitting a large Express application into smaller route files.

// routes/userRoutes.js
const express = require("express");
const router = express.Router();

router.get("/", getUsers);
router.get("/:id", getUserById);
router.post("/", createUser);

module.exports = router;

// app.js
const userRoutes = require("./routes/userRoutes");

app.use("/users", userRoutes);
app.js→/users→userRouter→handler
Why use it? It keeps route definitions organized and makes large applications easier to maintain.
6. Middleware, Multiple Handlers, and next()
function checkAuth(req, res, next) {
  console.log("Auth check");
  next();
}

function logRoute(req, res, next) {
  console.log("Route handler 1");
  next();
}

app.get("/admin", checkAuth, logRoute, (req, res) => {
  res.send("Admin page");
});
Request→checkAuth→logRoute→Final Handler

next() passes control to the next matching middleware or handler.

Common mistake: If middleware neither sends a response nor calls next(), the request may remain pending.
7. Nested Routers and Route Organization
// app.js
app.use("/users", userRouter);

// userRouter
router.use("/:userId/orders", orderRouter);

// orderRouter
router.get("/", getOrders);
router.get("/:orderId", getOrder);

This can create routes such as:

  • GET /users/10/orders
  • GET /users/10/orders/500
When useful: Nested routers are useful when one resource naturally belongs to another resource, such as users and their orders.

9. Wildcards, Optional Paths, and 404 Routes

Express route-pattern behavior can vary by Express version, so for modern applications prefer explicit route definitions and tested patterns rather than relying on old wildcard syntax.

// Catch-all fallback using middleware
app.use((req, res) => {
  res.status(404).json({
    message: "Route not found"
  });
});
404 rule: Put a catch-all 404 handler after your valid routes. Otherwise it can intercept requests before the intended routes.
10. MAANG / FANG / MNC Code-Based Interview Questions
Q1. What is returned for GET /users/profile?
app.get("/users/:id", (req, res) => {
  res.send("dynamic");
});

app.get("/users/profile", (req, res) => {
  res.send("profile");
});
Answer: dynamic.
Why: Express checks routes in order. :id can match the string profile, so the first route handles it.
Q2. Fix the route-order bug.
app.get("/products/:id", productById);
app.get("/products/search", searchProducts);
app.get("/products/search", searchProducts);
app.get("/products/:id", productById);
Why: The static /products/search route is more specific and should be registered before the dynamic :id route.
Q3. What are the values of req.params.id and req.query.active?
app.get("/users/:id", (req, res) => {
  res.json({
    id: req.params.id,
    active: req.query.active
  });
});

// GET /users/25?active=true
Answer: id is "25" and active is "true". Query values arrive as strings unless your application converts them.
Why: :id is captured from the path, while active=true is read from the query string.
Q4. What happens if this middleware does not call next()?
function auth(req, res, next) {
  console.log("checking");
}

app.get("/dashboard", auth, (req, res) => {
  res.send("dashboard");
});
Answer: The final handler does not run, and the request may stay pending.
Why: The middleware has taken control of the request. It must either finish the response or call next().
Q5. Predict the console output.
app.get("/test",
  (req, res, next) => {
    console.log("A");
    next();
  },
  (req, res, next) => {
    console.log("B");
    next();
  },
  (req, res) => {
    console.log("C");
    res.send("done");
  }
);
Answer:
A
B
C
Why: Express executes matching handlers in registration order. Each next() passes control to the next handler.
Q6. What route handles GET /users/10/orders/99?
app.use("/users", userRouter);

// userRouter
router.use("/:userId/orders", orderRouter);

// orderRouter
router.get("/:orderId", (req, res) => {
  res.json(req.params);
});
Answer: The final order router handler handles it. The parameters are userId = "10" and orderId = "99" when router parameter merging is configured appropriately.
Why: Nested routers compose their path prefixes. In Express, use mergeParams: true on a child router when the child needs access to parent route parameters.
Q7. What is the bug in this 404 handler?
app.use((req, res) => {
  res.status(404).send("Not found");
});

app.get("/users", (req, res) => {
  res.json([]);
});
Answer: The 404 middleware runs before /users, so GET /users is treated as not found.
Why: Express processes middleware and routes in registration order. The fallback must be placed after valid routes.
Q8. Write a route that reads a user ID and a page query parameter.

Example request: GET /users/50?page=3

app.get("/users/:id", (req, res) => {
  const id = req.params.id;
  const page = req.query.page;

  res.json({ id, page });
});
Why: The ID is part of the route path, while page is a query parameter.
Q9. Which route is more specific?
/orders/:id
/orders/recent
Answer: /orders/recent is more specific.
Why: The first route treats recent as a possible dynamic ID. Registering the static route first avoids accidental matching.
Q10. How would you organize routes in a large Express project?
src/
  app.js
  routes/
    user.routes.js
    product.routes.js
    order.routes.js
  controllers/
    user.controller.js
    product.controller.js
  middleware/
    auth.js
    errorHandler.js
Why: Separating routes, controllers, and middleware keeps responsibilities clear and makes the codebase easier to test and maintain.
Q11. What is the difference between req.params, req.query, and req.body?
PropertySourceExample
req.paramsPath/users/10
req.queryQuery string/users?page=2
req.bodyRequest body{"name":"Sam"}
Why: These are three different places from which client-supplied request data can come.
Q12. Why would you use express.Router() instead of putting every route in app.js?
Answer: To modularize routes by feature/resource, reduce the size of app.js, and make route-specific middleware and testing easier.
Why: A modular router gives each feature a clear boundary and improves maintainability as the application grows.
11. Common Developer Mistakes
1. Dynamic route before static route: /users/:id can capture /users/profile.
2. 404 handler too early: Put the fallback after valid routes.
3. Forgetting next(): Middleware can leave a request pending if it neither responds nor calls next().
4. Confusing params and query: /users/10 and /users?id=10 are different request designs.
5. Child router cannot see parent params: Use express.Router({ mergeParams: true }) when required.
6. Putting all routes in one file: Split routes by resource as the application grows.
12. Quick Recap
  • Routing maps an HTTP method and URL to handlers.
  • Route parameters are available through req.params.
  • Query parameters are available through req.query.
  • Request body data is available through req.body after the appropriate parser is configured.
  • Express processes routes and middleware in registration order.
  • express.Router() helps organize routes into modules.
  • next() passes control to the next handler.
  • Specific routes should normally be placed before broad dynamic routes.
  • 404 fallback middleware should come after valid routes.
  • Nested routers help represent parent-child resources.
Golden interview answer: "Express routing maps an incoming HTTP method and URL to one or more handlers. Express checks matching routes and middleware in registration order, while express.Router() lets us organize routes by feature or resource."
13. Interview-Ready Points
Be ready to explain: route order, dynamic vs static routes, req.params vs req.query, next(), router-level middleware, and nested routers.
Senior-level discussion: Explain how route organization affects maintainability, testing, middleware boundaries, and API design.
Output question strategy: First identify the HTTP method, then the exact path, then check routes from top to bottom.
