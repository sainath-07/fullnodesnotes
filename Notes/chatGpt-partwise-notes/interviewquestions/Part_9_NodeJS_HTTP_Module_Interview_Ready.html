Part 9 — HTTP Module ⭐⭐⭐

Understand how a Node.js HTTP server receives a request, processes it and sends a response.

1. What is the Node.js HTTP Module?

What: Node.js provides the built-in http module for creating HTTP servers and working directly with HTTP requests and responses.

Why: It gives you low-level control over the request/response lifecycle. Frameworks such as Express build many convenient features on top of these Node.js HTTP capabilities.

Layman example: Think of a restaurant. The browser is the customer, the HTTP request is the order, the server is the kitchen, and the HTTP response is the completed order.

Q1 — Why would you use the built-in http module instead of Express?

Answer: The http module gives lower-level control and is useful for learning HTTP internals, small servers, custom networking behavior and framework-level understanding. Express provides routing, middleware and many conveniences on top.
2. Creating an HTTP Server
const http = require("http"); const server = http.createServer((req, res) => { res.statusCode = 200; res.setHeader("Content-Type", "text/plain"); res.end("Hello from Node.js"); }); server.listen(3000, () => { console.log("Server running"); });

Q2 — What does createServer() do?

Answer: It creates an HTTP server. Its callback runs when the server receives an HTTP request, receiving the request object and response object.

Q3 — When does the createServer callback execute?

Answer: The callback executes for incoming requests handled by that server.
3. Request Object — req

The request object contains information sent by the client.

PropertyMeaning
req.urlRequest URL/path and query portion as received.
req.methodHTTP method such as GET or POST.
req.headersRequest headers sent by the client.
const server = http.createServer((req, res) => { console.log(req.url); console.log(req.method); console.log(req.headers); });

Q4 — What is the difference between req.url and req.method?

Answer: req.url describes the requested URL/path and query portion, while req.method tells what HTTP operation was requested, such as GET, POST, PUT or DELETE.

Q5 — Where would you read an Authorization token?

Answer: Usually from a request header, for example req.headers.authorization. The exact authentication design depends on the API.
4. Response Object — res
const server = http.createServer((req, res) => { res.statusCode = 200; res.setHeader("Content-Type", "application/json"); res.write(JSON.stringify({ message: "OK" })); res.end(); });

Q6 — What is the purpose of res.statusCode?

Answer: It sets the HTTP status code that will be sent in the response, such as 200, 201, 400 or 404.

Q7 — What is the difference between res.write() and res.end()?

Answer: res.write() can send response data in chunks. res.end() finishes the response and can optionally send the final chunk.

Q8 — What happens if you forget res.end()?

Answer: If no other mechanism finishes the response, the client may continue waiting because the response has not been completed.

Q9 — Explain the HTTP request/response lifecycle in Node.js.

Answer: The client sends a request. Node receives it and invokes the server callback with req and res. The server examines the request, performs routing/business logic, sets the response status and headers, sends the body and finishes with res.end(). The client then receives the response.

Q10 — Why should headers normally be set before sending the body?

Answer: HTTP response headers are sent before the response body. Once the response headers have been sent, changing them is generally too late and can cause an error.
6. Manual Routing
const server = http.createServer((req, res) => { if (req.method === "GET" && req.url === "/users") { res.statusCode = 200; res.setHeader("Content-Type", "application/json"); return res.end(JSON.stringify([{ id: 1, name: "Sam" }])); } res.statusCode = 404; res.end("Not Found"); });

Q11 — What does manual routing mean?

Answer: It means checking values such as req.method and req.url yourself and deciding which code should handle the request.

Q12 — Why can manual routing become difficult in a large application?

Answer: Many conditions can become difficult to read, maintain and test. Frameworks such as Express provide routing abstractions that make larger applications easier to organize.
7. Query Strings and URLSearchParams
const { URL } = require("url"); const server = http.createServer((req, res) => { const url = new URL(req.url, "http://localhost:3000"); const name = url.searchParams.get("name"); res.end(`Hello ${name || "Guest"}`); });

Q13 — Why is URLSearchParams useful?

Answer: It provides a convenient API for reading and manipulating query parameters instead of manually splitting strings.

Q14 — For /products?page=2&limit=10, what are page and limit?

Answer: They are query parameters. page has value 2 and limit has value 10.
8. Request Body and JSON

HTTP request bodies arrive as stream chunks. You commonly collect those chunks and then parse JSON when the request says it contains JSON.

let body = ""; req.on("data", chunk => { body += chunk; }); req.on("end", () => { try { const data = JSON.parse(body); console.log(data); } catch { res.statusCode = 400; return res.end("Invalid JSON"); } res.end("OK"); });

Q15 — Why can JSON.parse(body) fail?

Answer: The body may be incomplete, malformed or not actually JSON. JSON parsing should therefore be handled safely, and the server should validate the received data.

Q16 — Why is the request body handled through data/end events?

Answer: The request is a readable stream, so body data may arrive in multiple chunks. end indicates that all request body data has arrived.

Q17 — A POST successfully creates a user. Which status code is a strong choice?

Answer: 201 Created is the conventional choice when a resource has been successfully created.

Q18 — What is the difference between 401 and 403?

Answer: 401 generally means the request lacks valid authentication credentials. 403 means the server understood the request but refuses to authorize the action.
10. HTTP vs HTTPS
HTTP: Client ⇄ Server
Data is sent without TLS encryption

HTTPS: Client ⇄ TLS ⇄ Server
Encrypted connection + server authentication

HTTP is the basic application protocol. HTTPS is HTTP carried over a TLS-secured connection.

Q19 — Why is HTTPS preferred for production APIs?

Answer: HTTPS protects data in transit with TLS, helps prevent interception and tampering, and provides server authentication through certificates.

Q20 — Does HTTPS change the HTTP request methods?

Answer: No. Methods such as GET, POST, PUT and DELETE are still HTTP methods. HTTPS adds TLS security around the HTTP communication.
11. REST vs RESTful APIs

REST is an architectural style with constraints for designing networked systems. A RESTful API is an API that follows REST principles to a reasonable degree.

Resource-oriented design
/users → collection
/users/42 → one user

GET /users/42 → retrieve
PATCH /users/42 → update part
DELETE /users/42 → delete

Q21 — Is every HTTP API automatically RESTful?

Answer: No. Using HTTP does not automatically make an API RESTful. REST involves architectural constraints such as resource-oriented identification and a stateless client-server interaction model.

Q22 — Why is /users/42 generally more REST-friendly than /getUser?id=42?

Answer: /users/42 identifies a resource and lets the HTTP method express the operation. For example, GET retrieves it and DELETE removes it. This is more resource-oriented.
12. MAANG / FANG / MNC Code & Output Questions ⭐⭐⭐

Q23 — What is printed?

const server = http.createServer((req, res) => { console.log(req.method, req.url); res.end("OK"); });
Answer: Nothing is printed merely by calling createServer(). The callback runs when an incoming request reaches the server. Then it prints that request's method and URL.

Q24 — Find the bug

const server = http.createServer((req, res) => { res.setHeader("Content-Type", "application/json"); res.end({ message: "hello" }); });
Answer: The response body should be a supported data type such as a string, Buffer or typed array. Use JSON.stringify({ message: "hello" }) before sending JSON.

Q25 — Find the lifecycle problem

const server = http.createServer((req, res) => { res.statusCode = 404; res.end("Not Found"); res.statusCode = 200; res.end("OK"); });
Answer: The response is already ended after the first res.end(). The second response operation is invalid. A route should choose one response path, usually with return when needed.

Q26 — Why can this API hang?

const server = http.createServer((req, res) => { if (req.url === "/users") { console.log("users"); } });
Answer: The matching branch does not send or end a response. The client can keep waiting. The handler must eventually send a response such as res.end().

Q27 — Output/body question

res.setHeader("Content-Type", "application/json"); res.write(JSON.stringify({ ok: true })); res.end();
Answer: The client receives a JSON response body containing {"ok":true}, assuming no error occurs. The response ends after res.end().

Q28 — Interview scenario: GET /users?page=2

Answer: The method is GET. /users is the path and page=2 is a query parameter. The server can parse it and use it for pagination.
13. Common Developer Mistakes
  • Forgetting res.end() and leaving clients waiting.
  • Trying to modify headers after response data has already been sent.
  • Sending an object directly instead of serializing JSON.
  • Not handling request body chunks correctly.
  • Parsing malformed JSON without error handling.
  • Mixing multiple response paths without returning after one response.
  • Confusing a URL path with query parameters.
  • Using 200 for every situation instead of meaningful status codes.
  • Assuming HTTP and HTTPS provide the same transport security.
  • Calling every HTTP API “RESTful” without considering REST principles.
