Part 4 — File System (fs) ⭐⭐⭐

Learn file operations, callbacks, promises, buffers, descriptors and streams through interview-style code questions.

1. What is the fs Module?

What: The Node.js fs module provides APIs for working with files and directories.

Why / purpose: Server applications often need to read configuration, save data, process uploads, create logs and manage files.

Layman example: Think of fs as a set of tools for opening a filing cabinet, reading papers, adding papers, moving them or deleting them.

Node.js application → fs API → operating system → file system → file/directory
Interview line: The fs module provides synchronous, callback-based asynchronous and promise-based APIs for file-system operations.

Q1 — Is fs only asynchronous?

Answer: No. fs provides synchronous APIs, callback-based asynchronous APIs and promise-based APIs.
2. Reading Files

The common APIs are fs.readFile(), fs.readFileSync() and fs/promises.readFile().

const fs = require("fs"); fs.readFile("data.txt", "utf8", (err, data) => { if (err) { console.error(err); return; } console.log(data); });

Q2 — Why is "utf8" important?

Answer: It asks Node to decode the file bytes as UTF-8 text.
Why? Without an encoding, readFile() returns a Buffer instead of a string.

Q3 — What is the type without encoding?

fs.readFile("data.txt", (err, data) => { console.log(Buffer.isBuffer(data)); });
true
Why? File contents are bytes. Node represents those bytes as a Buffer when no text encoding is requested.
3. Writing Files
const fs = require("fs"); fs.writeFile("data.txt", "Hello Node", "utf8", err => { if (err) console.error(err); });

Important: writeFile() replaces the existing file contents when the file exists.

Q4 — What happens?

// data.txt initially contains: // ABC fs.writeFile("data.txt", "XYZ", err => {}); // Later read data.txt
XYZ
Why? The default behavior of writeFile is to replace the file contents.
4. Appending Files

Use appendFile() when you want to add content to the end instead of replacing existing content.

fs.appendFile("log.txt", "New log\n", err => { if (err) console.error(err); });

Q5 — Which API should you choose?

Existing file contains Hello. You need the final content to be Hello Node.

fs.appendFile("file.txt", " Node", callback);
Why? appendFile adds data to the existing file rather than replacing it.
5. Deleting, Renaming and Directories
fs.unlink("old.txt", callback); // delete file fs.rename("a.txt", "b.txt", callback); // rename/move fs.mkdir("logs", callback); // create directory fs.readdir("logs", callback); // read directory

Q6 — Which method deletes a file?

Answer: fs.unlink().
Why? It removes a file or symbolic link.

Q7 — Create nested directories safely

fs.mkdir("uploads/images/2026", { recursive: true }, err => { if (err) console.error(err); });
Why? recursive:true lets Node create missing parent directories as needed and avoids failure just because parents do not exist.
6. File Statistics — stat()

fs.stat() gives information such as file size, timestamps and whether a path is a file or directory.

fs.stat("data.txt", (err, stats) => { if (err) return console.error(err); console.log(stats.size); console.log(stats.isFile()); console.log(stats.isDirectory()); });

Q8 — Predict the type of stats.size

Answer: A number representing the size in bytes.
Why? File statistics expose the file's byte size through size.
7. Callback-Based APIs & Error-First Callbacks ⭐⭐⭐

Node callback APIs commonly use the error-first pattern: (err, result).

Operation starts → Node performs I/O → callback(err, result) → check err → use result
fs.readFile("data.txt", "utf8", (err, data) => { if (err) { console.error("Failed:", err); return; } console.log(data); });

Q9 — Why check err before data?

Why? The operation may fail. If an error exists, the result may not be valid and the callback should handle the failure first.

Q10 — What is wrong?

fs.readFile("missing.txt", "utf8", (err, data) => { console.log(data.toUpperCase()); });
Answer: The code ignores err.
Why? If the file cannot be read, data may be undefined, causing another error instead of handling the original file-system error.

Q11 — Output

const fs = require("fs"); console.log("A"); const data = fs.readFileSync(__filename, "utf8"); console.log("B");
A B
Why? The synchronous read blocks until it finishes. B cannot execute before the read returns.

Q12 — Which is dangerous inside a busy HTTP request path?

Answer: Repeated synchronous filesystem operations.
Why? They block the JavaScript thread and can delay handling other requests.
9. Promise-Based APIs & fs/promises ⭐⭐⭐

Promise-based APIs work naturally with async/await.

const fs = require("fs/promises"); async function readData() { try { const data = await fs.readFile("data.txt", "utf8"); console.log(data); } catch (err) { console.error(err); } } readData();

Q13 — Why does the original fs module code need a callback, but this code does not?

Answer: fs/promises exposes promise-based methods, so await receives the fulfilled value or the rejected error can be caught with try/catch.

Q14 — What happens if the file does not exist?

Answer: The promise rejects, and the surrounding try/catch can handle the error.
Why? Promise-based fs APIs report failed operations as rejected promises.
10. Buffers with Files

A Buffer represents raw bytes. It is useful when working with binary data such as images, PDFs and compressed files.

const fs = require("fs"); fs.readFile("image.png", (err, data) => { if (err) return console.error(err); console.log(Buffer.isBuffer(data)); console.log(data.length); });

Q15 — Why should you avoid converting every binary file to a string?

Why? Binary data is bytes, not necessarily text. Treating arbitrary binary data as text can corrupt or misinterpret it.
11. File Descriptors

A file descriptor is a small integer used by the operating system to identify an open file or other resource.

fs.open("data.txt", "r", (err, fd) => { if (err) return console.error(err); console.log(fd); fs.close(fd, err => { if (err) console.error(err); }); });

Q16 — What is fd?

Answer: A file descriptor returned by the operating system through Node's file APIs.
Why? It identifies the open file resource so lower-level operations can use it.
Mistake: Forgetting to close manually opened file descriptors can leak OS resources.
12. Streams with Files ⭐⭐⭐

Streams process data in chunks instead of loading the entire file into memory at once.

const fs = require("fs"); const readStream = fs.createReadStream("large.log", { encoding: "utf8" }); readStream.on("data", chunk => { console.log("Chunk size:", chunk.length); }); readStream.on("end", () => { console.log("Done"); });
Large file → chunk 1 → chunk 2 → chunk 3 → ... → end

Q17 — Why are streams useful for large files?

Answer: They avoid requiring the entire file to be loaded into memory at once.
Why? Data is processed incrementally in chunks, which can reduce memory usage.
13. Output-Based MAANG / FANG / MNC Questions

Q18 — Async callback ordering

const fs = require("fs"); console.log("1"); fs.readFile(__filename, () => { console.log("2"); }); console.log("3");
1 3 2
Why? The file read is asynchronous. The current JavaScript continues to 3 before the callback runs.

Q19 — Promise ordering

const fs = require("fs/promises"); console.log("A"); fs.readFile(__filename, "utf8") .then(() => console.log("B")); console.log("C");
A C B
Why? Starting the promise-based I/O does not synchronously wait for the file. The continuation runs after the asynchronous operation completes.

Q20 — Sync vs async

const fs = require("fs"); console.log("A"); fs.readFileSync(__filename); console.log("B");
A B
Why? The synchronous call blocks until the file read completes, then B runs.

Q21 — Missing callback

const fs = require("fs"); fs.writeFile("a.txt", "hello");
Answer: This uses the callback-based fs.writeFile() API without supplying the required callback, so it throws an argument-type error rather than behaving like a Promise API.
Why? The callback-style method and promise-style method are different APIs. Use fs/promises.writeFile() if you want a Promise.

Q22 — Buffer or string?

fs.readFile("data.txt", (err, data) => { console.log(typeof data); console.log(Buffer.isBuffer(data)); });
object true
Why? A Buffer is an object in JavaScript, and Buffer.isBuffer confirms that the returned value is a Buffer.

Q23 — Error-first callback

fs.readFile("missing.txt", "utf8", (err, data) => { if (data) { console.log("data"); } else { console.log("error"); } });
error
Why? Reading a missing file fails, so the result is not available. Production code should check err explicitly rather than using data truthiness as the error test.

Q24 — Which API for a server?

A server receives many requests and needs to read files without blocking the JavaScript thread. Which is generally preferred: readFileSync(), callback readFile(), or promise readFile()?

Answer: The asynchronous callback or Promise version. Why? Both allow the JavaScript thread to continue while the I/O is performed asynchronously. The Promise version is often easier to structure with async/await.
14. Common Developer Mistakes
  • Using readFileSync() repeatedly inside a busy server request path.
  • Forgetting the callback when using callback-based fs methods.
  • Using fs.readFile() as if it returns a Promise without using the promise API.
  • Ignoring the first err argument in callbacks.
  • Assuming readFile() always returns a string without specifying encoding.
  • Loading a huge file completely into memory when a stream would be more suitable.
  • Forgetting to close manually opened file descriptors.
  • Using text encoding carelessly with binary files.
  • Confusing file path errors with JavaScript errors.
15. Visual Flow — Three fs Styles
Synchronous
fs.readFileSync() → wait → result → continue

Callback
fs.readFile() → start I/O → continue → callback(err, data)

Promise
fs/promises.readFile() → start I/O → continue → Promise settles → await/.then()
16. Quick Recap & Interview Ready
  • fs: Node's file-system module.
  • read: readFile(), readFileSync(), fs/promises.readFile().
  • write: writeFile().
  • append: appendFile().
  • delete: unlink().
  • rename/move: rename().
  • directories: mkdir(), readdir().
  • statistics: stat().
  • Callback: usually follows error-first (err, result).
  • Promise: works naturally with async/await.
  • Sync: blocks the JavaScript execution thread until the operation returns.
  • Buffer: represents raw bytes.
  • File descriptor: OS-level identifier for an open file resource.
  • Stream: processes data in chunks and is useful for large files.
Most important interview comparison:
Callback fs = asynchronous + callback result.
Promise fs = asynchronous + Promise result.
Sync fs = blocking + immediate return/error behavior.
Golden interview answer: “For server-side code, asynchronous file operations are generally preferred because synchronous filesystem calls block the JavaScript execution thread. Callback APIs use error-first callbacks, while fs/promises APIs return Promises and work naturally with async/await. For large files, streams can reduce memory usage by processing data in chunks.”
