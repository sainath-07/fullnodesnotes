Node.js + Express.js Interview Preparation

Part 14 — Express.js Fundamentals

Simple explanations, visual flows, output-based code questions, answers, and interview-ready WHY explanations.

1. What is Express.js?

Express.js is a small and flexible web framework built on Node.js. It makes it easier to create HTTP servers, APIs, routes, and middleware.

Layman example: Node.js gives you the engine. Express.js gives you convenient tools to build the web application on that engine.
Browser / Client→Express Route→Handler→Response
Why use Express?
  • Simple routing.
  • Easy request and response handling.
  • Middleware support.
  • Useful for REST APIs and web servers.
2. Express Architecture and Basic Server
const express = require("express");

const app = express();

app.get("/", (req, res) => {
  res.send("Hello Express");
});

app.listen(3000, () => {
  console.log("Server running on port 3000");
});
How it works: express() creates the application object. A route handles a request. app.listen() starts the server and listens for incoming connections.
express()→app→app.get()→app.listen()
3. HTTP Methods in Express
MethodExpressTypical purpose
GETapp.get()Read data
POSTapp.post()Create data
PUTapp.put()Replace/update a resource
PATCHapp.patch()Partially update a resource
DELETEapp.delete()Delete data
Interview point: Do not say PUT and PATCH are exactly the same. PUT is generally used for replacement, while PATCH is intended for partial updates.
4. Request and Response

req contains information about the incoming request. res is used to send a response back to the client.

app.get("/user", (req, res) => {
  console.log(req.method);
  console.log(req.url);
  res.status(200).json({ name: "Sam" });
});
Client request→req→Route handler→res→Client
5. Response Methods
  • res.send() sends a response.
  • res.json() sends JSON data.
  • res.status() sets the HTTP status code and can be chained.
  • res.end() ends the response without sending a formatted body.
res.status(201).json({
  message: "User created"
});
Common mistake: Do not send two responses for one request. For example, calling res.json() and then trying to call res.send() again can cause "headers already sent" errors.
6. Express Routing
app.get("/users", (req, res) => {
  res.json(["Sam", "John"]);
});

app.post("/users", (req, res) => {
  res.status(201).json({ message: "Created" });
});

app.delete("/users/:id", (req, res) => {
  res.json({ deletedId: req.params.id });
});
Route matching: Express checks the incoming HTTP method and URL against registered routes. The matching handler runs.
7. Interview Questions — Output and Code Based
Q1. What is printed when GET / is requested?
const express = require("express");
const app = express();

app.get("/", (req, res) => {
  console.log("Route 1");
  res.send("Hello");
});

app.listen(3000);
Answer: The terminal prints Route 1, and the client receives Hello.
Why: The request method and path match the registered GET route, so its callback executes.
Q2. What happens here?
app.get("/users", (req, res) => {
  res.json({ ok: true });
  res.send("Done");
});
Answer: The first response is sent. The second response attempts to send another response and can produce a "Cannot set headers after they are sent" error.
Why: One HTTP request should normally receive one completed response. res.json() ends the response, so another response is too late.
Q3. Predict the response status and body.
app.post("/products", (req, res) => {
  res.status(201).json({
    message: "Product created"
  });
});
Answer: HTTP status is 201 and the JSON body is {"message":"Product created"}.
Why: res.status(201) sets the status, and json() sends the object as JSON.
Q4. Which route handles GET /users/42?
app.get("/users", handlerA);
app.get("/users/:id", handlerB);
app.get("/users/profile", handlerC);
Answer: handlerB.
Why: :id is a route parameter and matches the value 42. The static /users/profile route does not match.
Q5. What is the value of req.params.id?
app.get("/users/:id", (req, res) => {
  res.send(req.params.id);
});

Request: GET /users/99



Answer: "99".



Why: Express stores values captured by route parameters in req.params.
Q6. What is wrong with this server?
const express = require("express");
const app = express();

app.get("/", (req, res) => {
  res.send("OK");
});

console.log("Server started");
Answer: No HTTP server is listening because app.listen() was never called.
Why: Creating the Express app and defining routes does not by itself start a network server. app.listen() starts listening on a port.
Q7. What does this return?
app.get("/test", (req, res) => {
  const result = res.status(404);
  console.log(result === res);
  res.end();
});
Answer: true.
Why: Express response methods such as res.status() return the response object, which enables method chaining.
Q8. Why can this route hang?
app.get("/data", (req, res) => {
  console.log("received");
});
Answer: The request may remain pending because the handler neither sends a response nor passes control to another middleware.
Why: Express needs the request lifecycle to continue or finish. Use res.send(), res.json(), res.end(), or next() when appropriate.
Q9. Which handler runs first?
app.get("/users/:id", (req, res) => {
  res.send("parameter");
});

app.get("/users/profile", (req, res) => {
  res.send("profile");
});

Request: GET /users/profile



Answer: The first handler can match profile as :id, so it sends parameter.



Why: Express checks routes in registration order. A route parameter can match the string profile. Put more specific static routes before broad parameter routes.
Q10. What is the difference between res.send() and res.json()?
res.send({ name: "Sam" });
res.json({ name: "Sam" });
Answer: Both can send an object as JSON in modern Express usage, but res.json() clearly communicates that the intended response is JSON and explicitly applies JSON response handling.
Why: res.json() is preferred when the API response is JSON because it makes the developer's intention clear.
Q11. What happens if a route is registered with the wrong HTTP method?
app.get("/login", (req, res) => {
  res.send("GET login");
});

Client sends POST /login.



Answer: This GET route does not handle the POST request. If no other matching route or middleware handles it, Express normally returns a 404 response.



Why: Express routing considers both the HTTP method and path.
Q12. Build routes for CRUD operations.
app.get("/users", (req, res) => {
  res.json(users);
});

app.post("/users", (req, res) => {
  res.status(201).json({ message: "created" });
});

app.put("/users/:id", (req, res) => {
  res.json({ message: "replaced" });
});

app.patch("/users/:id", (req, res) => {
  res.json({ message: "updated partially" });
});

app.delete("/users/:id", (req, res) => {
  res.status(204).end();
});
Why: The routes map common CRUD actions to the HTTP methods used by REST APIs.
8. Common Developer Mistakes
1. Forgetting app.listen()
Routes exist, but no server is listening.
2. Sending two responses
Do not call res.send() and res.json() for the same request.
3. Forgetting to finish the request
A handler that only logs data can leave the client waiting.
4. Wrong HTTP method
A POST request does not automatically use a GET route.
5. Route order problems
Specific routes such as /users/profile should normally appear before broad parameter routes such as /users/:id.
9. Interview-Ready Quick Recap
  • Express is a web framework built on Node.js.
  • express() creates an Express application.
  • app.listen() starts the HTTP server.
  • app.get/post/put/patch/delete() define routes.
  • req represents the incoming request.
  • res is used to send the response.
  • res.status() sets the HTTP status.
  • res.json() sends JSON.
  • Express matches the HTTP method and URL.
  • Route registration order matters.
Golden interview answer: "Express.js is a lightweight Node.js web framework that simplifies HTTP server development by providing routing, request/response helpers, and middleware support."
10. Interview Tips
Tip 1: Explain Express as a layer on top of Node's HTTP capabilities, not as a replacement for Node.js.
Tip 2: When asked about a route, always mention both HTTP method and path.
Tip 3: For debugging an API, trace: Client → Method + URL → Matching route → Handler → Response.
Tip 4: Be ready to explain why "Cannot set headers after they are sent" happens.
