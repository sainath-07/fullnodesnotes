Part 12 — Asynchronous Programming ⭐⭐⭐

Learn how Node.js handles work that finishes later without blocking the main JavaScript execution.

1. What is Asynchronous Programming?

What: Asynchronous programming lets JavaScript start an operation and continue with other work instead of waiting for that operation to finish.

Why: Node.js uses this style heavily for files, databases, HTTP requests and other I/O operations.

Layman example: You order food at a restaurant. You do not stand in the kitchen waiting. You place the order, do other things, and receive the food when it is ready.

Start async operation
↓
Continue JavaScript work
↓
Operation completes later
↓
Callback / Promise reaction runs

Q1 — Does asynchronous mean JavaScript runs two pieces of JavaScript at exactly the same time?

Answer: Not necessarily. JavaScript execution is generally single-threaded. Node.js can perform I/O outside the JavaScript call stack and later schedule the result back into JavaScript.

Q2 — Why is asynchronous programming important in Node.js?

Answer: It helps Node.js keep handling other work while slow I/O operations are in progress, which improves responsiveness and throughput.
2. Callbacks
const fs = require("fs"); fs.readFile("data.txt", "utf8", (err, data) => { if (err) { console.error(err); return; } console.log(data); }); console.log("Reading started");

Q3 — What is the callback in this code?

Answer: The function (err, data) => { ... } is the callback. Node.js calls it after the file operation finishes.

Q4 — Why does the callback receive err first?

Answer: Node.js commonly uses the error-first callback pattern: (err, result). If the operation fails, err contains the error; otherwise it is usually null or undefined.
3. Callback Hell
getUser(id, (err, user) => { if (err) return handle(err); getOrders(user.id, (err, orders) => { if (err) return handle(err); getPayment(orders[0].id, (err, payment) => { if (err) return handle(err); console.log(payment); }); }); });

Q5 — What problem does this code show?

Answer: This is callback hell. Deep nesting makes code harder to read, maintain, test and handle errors in.

Q6 — How do Promises help?

Answer: Promises allow asynchronous steps to be represented as values that settle later. Chaining with .then() can flatten nested operations and centralize error handling with .catch().
4. Promises and Their States

A Promise represents the eventual result of an asynchronous operation.

Pending
↓
Fulfilled OR Rejected

Once settled, the Promise cannot switch to another state.

Pending: operation is still running.

Fulfilled: operation completed successfully.

Rejected: operation failed.

Q7 — Can a fulfilled Promise become rejected later?

Answer: No. A Promise settles only once. After fulfillment or rejection, its state does not change.

Q8 — What does this function return?

async function getValue() { return 10; } console.log(getValue());
Answer: It returns a Promise, not the number 10 directly. The Promise fulfills with the value 10.
5. then(), catch(), finally()
Promise.resolve(10) .then(value => value * 2) .then(value => { console.log(value); }) .catch(err => { console.error(err); }) .finally(() => { console.log("finished"); });

Q9 — What does each method do?

Answer: then() handles fulfillment, catch() handles rejection, and finally() runs after the Promise settles whether it fulfills or rejects.

Q10 — Does finally() receive the Promise result?

Answer: Normally, finally() does not receive the fulfillment value or rejection reason as an argument. It is intended for cleanup work such as hiding a loading indicator.
6. Promise Chaining and Error Propagation ⭐⭐⭐
Promise.resolve(5) .then(x => x * 2) .then(x => { throw new Error("Something failed"); }) .then(() => console.log("not called")) .catch(err => console.log(err.message));

Q11 — Which callback runs?

Answer: The final catch() runs and prints Something failed. The thrown error rejects the Promise returned by that then(), so the next fulfillment handler is skipped.

Q12 — Why is returning inside .then() important?

getUser() .then(user => { return getOrders(user.id); }) .then(orders => { console.log(orders); });
Answer: Returning the Promise connects the next step to that asynchronous operation. Without the return, the next then() may receive undefined instead of waiting for getOrders().
7. async / await
async function loadUser() { try { const user = await getUser(); const orders = await getOrders(user.id); return orders; } catch (error) { console.error(error); } }

Q13 — Does await block the entire Node.js process?

Answer: No. await pauses the execution of that async function until the awaited Promise settles. It does not freeze the whole Node.js event loop.

Q14 — What does an async function always return?

Answer: A Promise. A normal returned value becomes a fulfilled Promise, while a thrown error makes the returned Promise reject.
8. Sequential vs Parallel Operations ⭐⭐⭐⭐⭐

Q15 — Is this sequential or parallel?

const a = await getA(); const b = await getB(); const c = await getC();
Answer: Sequential. getB() starts only after getA() finishes, and getC() starts after getB() finishes.

Q16 — How can independent operations run in parallel?

const [a, b, c] = await Promise.all([ getA(), getB(), getC() ]);
Answer: The three operations are started without waiting for one another, and Promise.all() waits for all of them to fulfill.

Interview rule: If operations are independent, consider parallel execution. If operation B needs the result of A, use sequential execution.

9. Promise.all()

What: Waits for all input Promises to fulfill.

Failure behavior: Rejects when the first rejection is observed.

Promise.all([ Promise.resolve("A"), Promise.resolve("B"), Promise.resolve("C") ]).then(result => console.log(result));

Q17 — What is printed?

Answer: ["A", "B", "C"]. The result array follows the order of the input Promises, not the order in which they finish.

Q18 — When should you use Promise.all()?

Answer: Use it when all results are required and the operations can run independently.
10. Promise.allSettled()
const result = await Promise.allSettled([ Promise.resolve("A"), Promise.reject("B"), Promise.resolve("C") ]); console.log(result);

Q19 — Why use allSettled instead of all?

Answer: allSettled() waits for every input Promise and reports each result as either {status:"fulfilled", value:...} or {status:"rejected", reason:...}. It does not reject just because one operation failed.
11. Promise.race()
const result = await Promise.race([ new Promise(r => setTimeout(() => r("slow"), 100)), new Promise(r => setTimeout(() => r("fast"), 20)) ]); console.log(result);

Q20 — What is the result?

Answer: "fast". The first Promise to settle wins the race.

Q21 — Can race() reject?

Answer: Yes. If the first Promise to settle is rejected, the returned Promise rejects with that reason.
12. Promise.any()
const result = await Promise.any([ Promise.reject("server 1"), Promise.resolve("server 2"), Promise.resolve("server 3") ]); console.log(result);

Q22 — What is printed?

Answer: "server 2". Promise.any() fulfills when the first input Promise fulfills. Rejections are ignored until all inputs reject.

Q23 — What happens when every Promise rejects?

Answer: The returned Promise rejects with an AggregateError.
13. Async Loops ⭐⭐⭐

Q24 — What is the problem with this code?

items.forEach(async item => { await save(item); }); console.log("done");
Answer: forEach() does not wait for the async callbacks. Therefore "done" can print before all saves finish. For sequential work, use for...of with await. For independent work, use Promise.all(items.map(...)).

Q25 — Correct sequential version

for (const item of items) { await save(item); } console.log("done");
Answer: Each save completes before the next one starts. This is sequential execution.
14. Async Function Return Values
async function test() { return 100; } test().then(value => console.log(value));

Q26 — Why can we use then() after test()?

Answer: Because every async function returns a Promise. The returned value 100 becomes the Promise's fulfillment value.

Q27 — What happens here?

async function test() { throw new Error("failed"); } test().catch(err => console.log(err.message));
Answer: The async function returns a rejected Promise. The catch() receives the thrown error.
15. Advanced Output Question ⭐⭐⭐⭐⭐

Q28 — Predict the output order

console.log("A"); Promise.resolve() .then(() => console.log("B")); setTimeout(() => console.log("C"), 0); (async function () { console.log("D"); await Promise.resolve(); console.log("E"); })(); console.log("F");
Answer: A → D → F → B → E → C.

Why: A, D and F are synchronous. The Promise reaction from the first then() is queued as a microtask. The await continuation is also scheduled as a microtask. Timer C runs later.

Q29 — Find the hidden performance problem

const results = []; for (const id of ids) { results.push(await fetchUser(id)); }
Answer: If the requests are independent, this performs them sequentially and can be much slower. A better approach may be await Promise.all(ids.map(fetchUser)), provided parallel requests are safe for the system.
16. Common Developer Mistakes
  • Assuming asynchronous code runs immediately after it is written.
  • Forgetting to return a Promise from a .then() callback.
  • Using forEach(async ...) when the caller needs to wait for completion.
  • Using sequential await for independent API calls when parallel execution is appropriate.
  • Using Promise.all() when partial failures should still be reported.
  • Confusing Promise.race() with Promise.any().
  • Forgetting that an async function always returns a Promise.
  • Not using try/catch or .catch() for rejected Promises.
  • Starting unlimited parallel requests with Promise.all() and overwhelming a service.
  • Thinking await blocks the complete Node.js process.

Golden interview answer: “Node.js asynchronous programming lets slow I/O work finish later while JavaScript continues with other work. Callbacks are the older style; Promises provide composable success and error handling; async/await gives Promise-based code a simpler synchronous-looking style. For independent operations, Promise.all can run them concurrently, while sequential await is needed when one operation depends on the previous result.”
Memory trick: then = success → catch = failure → finally = cleanup → all = everyone → allSettled = everyone reports → race = first settled → any = first success.
18. Interview Tips
  • Always distinguish sequential from parallel/concurrent async work.
  • Know why forEach() does not wait for async callbacks.
  • Know the exact differences between all four Promise combinators.
  • In output questions, separate synchronous code, microtasks and later timer/I/O work.
  • Remember that async function always returns a Promise.
  • Be ready to explain error propagation through Promise chains.
  • Know when parallel API calls improve performance and when they can overload a service.
