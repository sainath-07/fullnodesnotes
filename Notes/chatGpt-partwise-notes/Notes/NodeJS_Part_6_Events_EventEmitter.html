Node.js Interview Preparation • Part 6

🟢 Events & EventEmitter

Understand Node.js event-driven programming and master EventEmitter with practical interview questions.

1. What is Event-Driven Programming?
What?

Event-driven programming means that code reacts when an event happens instead of continuously checking for that event.

Layman example

Think about a doorbell. You do not keep asking, “Did someone press the doorbell?” Instead, you wait. When someone presses it, the bell produces an event and your action runs.

Something happens ↓ Event occurs ↓ Event is emitted ↓ Registered listener runs ↓ Application performs an action
Why?

This model is useful for servers because many things can happen at different times: a request arrives, a file finishes reading, a connection closes, or a custom application event occurs.

Interview-ready: “Node.js uses an event-driven programming model where code can register listeners for events and execute those listeners when the corresponding events occur.”
2. What is EventEmitter?

EventEmitter is a Node.js class used to create objects that can emit named events and allow functions to listen for those events.

const EventEmitter = require("node:events");

const emitter = new EventEmitter();

emitter.on("login", () => {
  console.log("User logged in");
});

emitter.emit("login");
EventEmitter object │ ├── on("login", listener) │ └── emit("login") ↓ listener executes
Important: on() registers a listener. emit() triggers the event.
3. emit()
What?

emit() triggers an event and can pass arguments to listeners.

const EventEmitter = require("node:events");
const emitter = new EventEmitter();

emitter.on("message", (name) => {
  console.log("Hello", name);
});

emitter.emit("message", "Sainath");

Output: Hello Sainath

How it works
emit("message", "Sainath") ↓ Find listeners for "message" ↓ Pass "Sainath" as argument ↓ Listener executes
4. on() — Register a Listener

on() registers a function that runs every time the event is emitted.

emitter.on("data", () => {
  console.log("Data received");
});

emitter.emit("data");
emitter.emit("data");

Output:

Data received
Data received
Interview-ready: “on() adds a persistent listener. The listener can execute every time that event is emitted.”
5. once() — Run Only Once

once() registers a listener that automatically stops listening after its first execution.

emitter.once("welcome", () => {
  console.log("Welcome!");
});

emitter.emit("welcome");
emitter.emit("welcome");

Output:

Welcome!
When to use? Use once() for one-time initialization, one-time connection events, or actions that should happen only once.
6. off() / removeListener()

Both can be used to remove a specific listener. The listener function reference must be available.

function handleLogin() {
  console.log("Login");
}

emitter.on("login", handleLogin);

emitter.emit("login");

emitter.off("login", handleLogin);

emitter.emit("login");

The second emit() does not call handleLogin.

Interview-ready: “off() is an alias-style convenience for removeListener(). Both remove a specific registered listener.”
Common mistake: This does not remove the listener because it creates a different function object: 
emitter.on("login", () => console.log("Login"));
emitter.off("login", () => console.log("Login"));
7. removeAllListeners()

removeAllListeners() removes all listeners for an event, or all listeners from the emitter if no event name is supplied.

emitter.removeAllListeners("login");

After this, the emitter has no listeners for login.

Use carefully: Removing all listeners can affect code you did not intend to remove, especially when several parts of an application share an emitter.
8. listenerCount()

listenerCount() tells you how many listeners are currently registered for an event.

function one() {}
function two() {}

emitter.on("data", one);
emitter.on("data", two);

console.log(emitter.listenerCount("data"));
// 2
When useful? It can help with debugging and checking whether listeners are being added repeatedly.
9. Event Arguments

Arguments after the event name in emit() are passed to the listeners in the same order.

emitter.on("order", (id, amount, status) => {
  console.log(id);
  console.log(amount);
  console.log(status);
});

emitter.emit("order", 101, 499, "paid");
emit("order", 101, 499, "paid") ↓ listener(id, amount, status) ↓ id = 101 amount = 499 status = "paid"
10. Multiple Listeners & Execution Order

You can register multiple listeners for the same event. For normal synchronous listeners, Node.js calls them in registration order.

emitter.on("save", () => console.log("First"));
emitter.on("save", () => console.log("Second"));
emitter.on("save", () => console.log("Third"));

emitter.emit("save");

Output:

First
Second
Third
Interview-ready: “EventEmitter normally invokes listeners synchronously in the order in which they were registered.”
Important: If a listener starts asynchronous work, that async work can finish later. This does not mean EventEmitter itself runs listeners in parallel.
11. EventEmitter Error Event ⭐⭐⭐

The "error" event has special behavior. If an EventEmitter emits "error" and there is no error listener, Node.js throws the error and the process can terminate.

const EventEmitter = require("node:events");
const emitter = new EventEmitter();

emitter.on("error", (err) => {
  console.log("Handled:", err.message);
});

emitter.emit("error", new Error("Something failed"));
emit("error", error) ↓ Is "error" listener registered? ↙ ↘ YES NO ↓ ↓ listener handles uncaught error ↓ ↓ continues process may terminate
Very important: “The error event is special. An EventEmitter should have an error listener when errors may be emitted; otherwise an unhandled error event can terminate the Node.js process.”
12. Custom Events

Event names do not have to be built-in names. You can define events that match your application's needs.

const EventEmitter = require("node:events");

class OrderService extends EventEmitter {
  createOrder(id) {
    console.log("Creating order...");
    this.emit("orderCreated", id);
  }
}

const orders = new OrderService();

orders.on("orderCreated", (id) => {
  console.log("Send email for order:", id);
});

orders.createOrder(5001);
createOrder(5001) ↓ OrderService ↓ emit("orderCreated", 5001) ↓ registered listener ↓ send email / log / notify
When to use? Custom events are useful when one part of an application needs to notify other parts without tightly coupling all the actions together.
13. EventEmitter Memory Warning

Node.js has a default listener warning threshold of 10 listeners per event. Adding more than that does not automatically mean there is a memory leak, but Node.js warns because repeatedly adding listeners can be a sign of a bug.

for (let i = 0; i < 11; i++) {
  emitter.on("data", () => {});
}

You may see a MaxListenersExceededWarning.

Do not blindly fix this by increasing the limit. First check whether listeners are accidentally being registered again and again.
Possible cause
function start() {
  emitter.on("data", handleData);
}

start();
start();
start(); // listener added again

If start() is repeatedly called without cleanup, listeners can accumulate.

14. EventEmitter + async Functions

EventEmitter does not automatically wait for an async listener's Promise.

emitter.on("task", async () => {
  await new Promise(resolve => setTimeout(resolve, 100));
  console.log("Async listener finished");
});

console.log("Before emit");

emitter.emit("task");

console.log("After emit");

The listener begins synchronously until it reaches the first await. Its continuation happens later.

emit("task") ↓ async listener starts ↓ reaches await ↓ listener yields ↓ emit() itself does NOT await it ↓ later → async continuation runs
Interview-ready: “EventEmitter does not automatically await async listeners. If the caller needs to wait for asynchronous work, the design should explicitly coordinate that Promise.”
15. Common Developer Mistakes
  • Confusing on() with emit().
  • Expecting on() to trigger the event immediately.
  • Forgetting that once() removes itself after the first event.
  • Trying to remove an anonymous listener using another anonymous function.
  • Removing all listeners when only one listener should be removed.
  • Ignoring the special "error" event.
  • Assuming multiple listeners execute in parallel.
  • Assuming EventEmitter automatically waits for async listeners.
  • Adding listeners repeatedly inside functions and causing listener accumulation.
  • Increasing the max listener limit without finding the real cause of listener growth.
  • Using one global EventEmitter for unrelated application features, making dependencies difficult to understand.
16. Interview Questions — Click to Show Answer + Why ⭐⭐⭐
MAANG / Product Company
Q1. What is the output?
const EventEmitter = require("node:events");
const emitter = new EventEmitter();

emitter.on("test", () => console.log("A"));
emitter.on("test", () => console.log("B"));

emitter.emit("test");

Code Answer:

A
B

Why? Both listeners are registered for test. EventEmitter invokes normal synchronous listeners in registration order.

Output-Based
Q2. How many times is the message printed?
const EventEmitter = require("node:events");
const emitter = new EventEmitter();

emitter.once("login", () => {
  console.log("Logged in");
});

emitter.emit("login");
emitter.emit("login");
emitter.emit("login");

Code Answer: It prints Logged in exactly once.

Why? once() removes its listener after the first invocation.

Core Node.js
Q3. What is the difference between on() and once()?
emitter.on("data", listener);
emitter.once("data", listener);

Code Answer: on() keeps the listener registered for future emissions. once() runs the listener only for the first matching emission.

Why? once() is designed for one-time events such as initialization or first connection.

Output-Based
Q4. What is the output?
const EventEmitter = require("node:events");
const emitter = new EventEmitter();

function handler() {
  console.log("Hello");
}

emitter.on("greet", handler);
emitter.emit("greet");

emitter.off("greet", handler);
emitter.emit("greet");

Code Answer:

Hello

Why? The first emission occurs while the listener is registered. off() removes the exact function reference, so the second emission has no handler listener.

Important Trap
Q5. Why does this not remove the listener?
emitter.on("data", () => console.log("data"));

emitter.off("data", () => console.log("data"));

Code Answer: The original listener remains registered.

Why? Each arrow function expression creates a different function object. off() needs the same function reference that was originally passed to on().

Arguments
Q6. What is printed?
emitter.on("user", (name, age) => {
  console.log(name, age);
});

emitter.emit("user", "Sam", 25);

Code Answer: Sam 25

Why? Values after the event name in emit() are passed to the listener in the same order.

Execution Order
Q7. What is the output?
emitter.on("event", () => {
  console.log("First");
});

emitter.on("event", () => {
  console.log("Second");
});

console.log("Before");
emitter.emit("event");
console.log("After");

Code Answer:

Before
First
Second
After

Why? emit() invokes the registered synchronous listeners during the call. They execute in registration order before emit() returns.

Very Important
Q8. What happens if an EventEmitter emits "error" without an error listener?
const EventEmitter = require("node:events");
const emitter = new EventEmitter();

emitter.emit("error", new Error("Failed"));

Code Answer: Node.js treats the unhandled "error" event as an uncaught error; the process can terminate.

Why? The "error" event has special EventEmitter semantics. Add an appropriate error listener when your emitter can emit errors.

Debugging
Q9. Why can MaxListenersExceededWarning appear?
for (let i = 0; i < 11; i++) {
  emitter.on("data", () => {});
}

Code Answer: More than the default listener threshold has been added for the event.

Why? Node.js warns because repeatedly adding listeners can indicate accidental listener accumulation or a memory leak. It is a warning, not proof that a leak exists.

Async Trap
Q10. Does emit() wait for an async listener?
emitter.on("task", async () => {
  await doSomething();
  console.log("Done");
});

emitter.emit("task");
console.log("After");

Code Answer: emit() does not automatically wait for the Promise returned by the async listener. “After” can print before “Done”.

Why? EventEmitter does not define emit() as an async-await operation. The async listener's continuation resumes later after its awaited operation completes.

Architecture
Q11. Why is EventEmitter useful in Node.js?

Code Answer: It provides a simple publish/subscribe-style mechanism inside an application: one component emits an event and other components listen for it.

Why? This can reduce direct coupling between components. Node.js itself uses event-based APIs in many places.

Listener Count
Q12. What is the output?
function a() {}
function b() {}

emitter.on("data", a);
emitter.on("data", b);

console.log(emitter.listenerCount("data"));

Code Answer: 2

Why? Two listeners have been registered for the data event.

Advanced
Q13. What is the risk in this pattern?
function start() {
  emitter.on("request", handleRequest);
}

app.on("request", start);

Code Answer: If start() is called repeatedly, the same listener can be added repeatedly.

Why? EventEmitter does not automatically deduplicate listeners. Repeated registration can cause duplicate work and listener warnings.

Conceptual Trap
Q14. Are EventEmitter listeners executed in parallel?

Code Answer: No. Normal listeners are invoked synchronously and sequentially by emit().

Why? An async operation started by a listener can continue later, but that is different from EventEmitter invoking the listeners themselves in parallel.

API Knowledge
Q15. What is the difference between removeListener() and removeAllListeners()?

Code Answer: removeListener() removes a specific listener for an event. removeAllListeners() removes all listeners for an event, or all listeners from the emitter if no event is supplied.

Why? Use the narrower operation when possible so you do not accidentally remove listeners owned by other parts of your application.
