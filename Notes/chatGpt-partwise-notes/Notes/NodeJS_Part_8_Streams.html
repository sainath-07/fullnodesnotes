Node.js Interview Preparation • Part 8

🟢 Streams

Learn how Node.js processes large or continuous data in small pieces instead of loading everything into memory at once.

1. What Are Streams?

A stream is a way to process data gradually, piece by piece, instead of waiting for the complete data to be available.

Layman example

Imagine drinking water from a tap. You do not need to collect all the water in a huge tank before drinking it. Water arrives continuously and you consume it as it arrives.

Large data source ↓ small chunk ↓ process chunk ↓ next chunk ↓ process chunk ↓ ...

In Node.js, streams are useful for files, HTTP requests/responses, compression, and other continuous data.

Interview-ready: “A stream is an interface for processing data incrementally. It avoids the need to load the entire data source into memory before processing it.”
2. Why Use Streams?
  • Handle large files without loading the complete file into memory.
  • Process HTTP data as it arrives.
  • Send data while it is still being produced.
  • Build processing pipelines.
  • Support backpressure between fast and slow parts of a system.
Without stream: Large file → load everything → memory → process With stream: Large file → chunk → process → chunk → process → ...
When to use: Streams are especially useful when data is large, continuous, or produced faster than the consumer can handle.

4. Readable Streams

A readable stream provides data to your program.

const fs = require("node:fs");

const stream = fs.createReadStream("large.txt");

stream.on("data", (chunk) => {
  console.log("Received:", chunk.length, "bytes");
});

stream.on("end", () => {
  console.log("Finished reading");
});

stream.on("error", (err) => {
  console.error(err);
});

The data event is emitted when a chunk is available. The end event means no more data is coming.

5. Writable Streams

A writable stream accepts data.

const fs = require("node:fs");

const output = fs.createWriteStream("output.txt");

output.write("Hello\n");
output.write("Node.js\n");
output.end("Done\n");

write() sends data into the stream. end() tells the stream that no more data will be written.

Common mistake: Calling write() after end() is invalid because the writable stream has already been told that writing is complete.
6. read(), write(), end()
read()

Readable streams can expose a read() method in paused/readable mode to request available data.

const fs = require("node:fs");

const stream = fs.createReadStream("large.txt");

stream.on("readable", () => {
  let chunk;
  while ((chunk = stream.read()) !== null) {
    console.log(chunk);
  }
});
write()
const writable = fs.createWriteStream("output.txt");
writable.write("Hello");
end()
writable.end("Final data");
Remember: write() adds data; end() finishes writing. A readable stream's read() retrieves available data in the appropriate stream mode.

Important: Always consider error handling when working with streams. Unhandled stream errors can terminate the process.
8. Backpressure ⭐⭐⭐ — Most Important Interview Topic

Backpressure happens when the producer creates data faster than the consumer can process it.

Layman example

Imagine a person filling bottles from a very fast water pipe while another person closes the bottles slowly. If water keeps arriving at the same speed, bottles pile up. The producer needs to slow down or wait.

FAST PRODUCER │ │ chunks quickly ↓ ┌─────────────────┐ │ Writable buffer │ ← fills up └─────────────────┘ │ │ slow processing ↓ CONSUMER Backpressure = producer is told to slow down / wait

In Node.js, writable.write() returns a Boolean value.

  • true → the writable stream can currently accept more data.
  • false → internal buffering has reached its threshold; the producer should wait.
const ok = writable.write(chunk);

if (!ok) {
  // Stop writing temporarily.
  writable.once("drain", () => {
    // Continue writing here.
  });
}

When the writable stream is ready again, it emits drain.

Best interview answer: “Backpressure is the mechanism that prevents a fast producer from overwhelming a slow consumer. In a writable stream, when write() returns false, the producer should wait for the drain event before continuing.”
9. highWaterMark

highWaterMark is a threshold used by Node.js streams to control internal buffering behavior. It does not mean “the maximum size of the stream”.

const fs = require("node:fs");

const stream = fs.createWriteStream("output.txt", {
  highWaterMark: 16 * 1024
});

When the internal buffered amount reaches the relevant threshold, write() can return false, creating backpressure.

Interview trap: Do not say “highWaterMark is always the maximum memory used by a stream.” It is a buffering threshold and its exact behavior depends on the stream type.
10. pipe()

pipe() connects a readable stream to a writable stream.

const fs = require("node:fs");

const source = fs.createReadStream("input.txt");
const destination = fs.createWriteStream("copy.txt");

source.pipe(destination);
Readable input.txt │ │ pipe() ↓ Writable copy.txt pipe() helps connect the flow and handles backpressure between the streams.
Interview-ready: “pipe() connects a readable stream to a writable stream and manages the flow of data, including backpressure.”
11. Stream Chaining

Streams can be connected one after another to create a pipeline.

File ↓ Readable Stream ↓ Transform Stream ↓ Writable Stream ↓ Output File
readable
  .pipe(transform)
  .pipe(writable);

This is useful for tasks such as reading, compressing, encrypting, transforming, and writing data.

12. Transform Streams

A Transform stream is both readable and writable. It receives data, changes it, and produces output.

const { Transform } = require("node:stream");

const upper = new Transform({
  transform(chunk, encoding, callback) {
    const result = chunk.toString().toUpperCase();
    callback(null, result);
  }
});
input chunk ↓ Transform ↓ changed chunk ↓ output
Examples: compression, decompression, encryption, decryption, formatting, and data conversion.
13. File Streams
const fs = require("node:fs");

const readStream = fs.createReadStream("large.mp4");
const writeStream = fs.createWriteStream("copy.mp4");

readStream.pipe(writeStream);

Instead of loading the entire video into a Buffer, the file is transferred in chunks.

large.mp4 ↓ small chunk ↓ small chunk ↓ small chunk ↓ copy.mp4
14. HTTP Streams

HTTP request and response objects are stream-like interfaces. This allows Node.js to process request/response data incrementally.

const http = require("node:http");

http.createServer((req, res) => {
  req.on("data", chunk => {
    console.log("Received:", chunk.length);
  });

  req.on("end", () => {
    res.end("Request complete");
  });
}).listen(3000);
Interview point: HTTP data can arrive in multiple chunks. Do not assume the complete request body arrives in one data event.
15. Compression Streams

Node.js provides compression streams through modules such as node:zlib.

const fs = require("node:fs");
const zlib = require("node:zlib");

fs.createReadStream("large.txt")
  .pipe(zlib.createGzip())
  .pipe(fs.createWriteStream("large.txt.gz"));
large.txt ↓ Read Stream ↓ Gzip Transform ↓ Write Stream ↓ large.txt.gz
16. Streams vs Buffer ⭐⭐⭐

Simple interview answer: “A Buffer is a container for bytes, while a Stream is a mechanism for processing data over time in chunks.”
17. Common Developer Mistakes
  • Loading a huge file completely into memory when a stream is better.
  • Ignoring the return value of write() when manually writing many chunks.
  • Continuing to write after write() returns false instead of waiting for drain.
  • Thinking highWaterMark is a hard maximum memory limit.
  • Assuming one data event contains the complete HTTP request.
  • Forgetting stream error handling.
  • Calling end() and then trying to write more data.
  • Using streams without understanding whether the stream is readable, writable, duplex, or transform.
  • Confusing Buffer with Stream. A Buffer holds bytes; a Stream manages data flow.
18. Interview Questions — Click to Show Answer + Why ⭐⭐⭐
Q1. What is a stream in Node.js?
Answer: A stream processes data incrementally in chunks instead of requiring the entire data to be loaded first.

Why? This is useful for large files, HTTP data, and continuous data because it can reduce memory usage and support data flow.
Q2. What are the four main types of streams?
Answer: Readable, Writable, Duplex, and Transform.

Why? They represent different directions and behaviors of data flow.
Q3. What is the difference between Readable and Writable streams?
Answer: A Readable stream provides data to the application; a Writable stream accepts data from the application.

Why? They are the two basic directions of data flow.
Q4. What is backpressure? Give a real Node.js example.
Answer: Backpressure occurs when a producer creates data faster than the consumer can process it. In a writable stream, write() can return false; the producer should wait for drain before continuing.

Why? Without backpressure, internal buffers can grow and cause excessive memory usage.
Q5. What does writable.write() returning false mean?
Answer: It means the writable stream has reached its buffering threshold and the producer should slow down or wait.

Why? Waiting lets the consumer catch up instead of continuously adding more data.
Q6. When should you listen for drain?
Answer: When a writable stream's write() returns false and you are manually managing the writes.

Why? The drain event tells you that it is appropriate to resume writing.
Q7. What is the output?
const fs = require("node:fs");

const stream = fs.createReadStream("file.txt");

stream.on("data", chunk => {
  console.log("chunk");
});

stream.on("end", () => {
  console.log("done");
});
Answer: chunk can be printed multiple times, followed by done.

Why? The file can be delivered in multiple chunks. The end event occurs after all chunks have been delivered.
Q8. Does one data event contain the complete HTTP request body?
Answer: No.

Why? Network data can arrive in multiple chunks. You normally collect/process chunks until the end event.
Q9. What does pipe() do?
Answer: pipe() connects a readable stream to a writable stream and manages the data flow between them.

Why? It makes common stream pipelines simple and handles backpressure between the connected streams.
Q10. What is a Transform stream?
Answer: A Transform stream is a Duplex stream that reads input, transforms it, and produces output.

Why? It is useful for compression, encryption, formatting, and other data transformations.
Q11. What is highWaterMark?
Answer: It is a threshold used by Node.js streams for internal buffering and flow control.

Why? It helps streams decide when buffering has become large enough to apply backpressure.
Q12. Why are streams better than reading a huge file into a Buffer?
Answer: Streams process the file in chunks, so the whole file does not need to be held in memory at once.

Why? This can significantly reduce memory pressure for large files.
Q13. What happens if you call write() after end()?
Answer: The writable stream has already been ended, so further writes are invalid and can result in an error.

Why? end() signals that no more data should be written.
Q14. Write code that manually respects backpressure.
Code Answer: 
function writeChunks(writable, chunks) {
  let i = 0;

  function writeMore() {
    while (i < chunks.length) {
      const canContinue = writable.write(chunks[i++]);

      if (!canContinue) {
        writable.once("drain", writeMore);
        return;
      }
    }

    writable.end();
  }

  writeMore();
}
Why? Once write() returns false, the function stops writing and resumes only after drain.
Q15. Explain Buffer vs Stream in one interview answer.
Answer: “A Buffer stores a sequence of bytes, while a Stream provides a way to process or transfer data incrementally over time. Buffers are data containers; streams are data-flow mechanisms.”

Why? This distinction is important when choosing between loading data into memory and processing it progressively.
Q16. Why can streams improve application performance?
Answer: Streams can reduce memory usage and allow processing to begin before all data has arrived.

Why? Data is handled progressively instead of waiting for the complete data set.
