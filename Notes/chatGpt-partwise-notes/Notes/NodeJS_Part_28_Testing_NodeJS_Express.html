🟢 Part 28 — Testing Node.js + Express ⭐⭐⭐

Learn how to test Node.js applications, Express APIs, middleware and business logic with confidence.

1. What is Testing?

What: Testing means writing code that checks whether our application behaves as expected.

Why: Tests catch bugs early and make refactoring safer.

Layman example: Before selling a car, you test the brakes, lights and engine. Software testing does the same thing for application behavior.

Write code
→
Run test
→
Expected result?
→
Pass / Fail
Interview line: Tests verify behavior. Good tests give fast feedback and reduce the risk of breaking existing functionality.
2. Unit Testing

What: Unit testing checks a small unit of code in isolation, such as a function or service method.

Purpose: Find bugs close to where they are introduced.

function add(a, b) { return a + b; } test("adds two numbers", () => { expect(add(2, 3)).toBe(5); });
When to use: Use unit tests heavily for business rules and pure functions because they are usually fast and easy to isolate.
3. Integration Testing

What: Integration testing checks whether multiple parts work correctly together.

Why: Unit tests prove pieces work alone; integration tests find problems in the connection between pieces.

Typical checks include status code, response body, headers and error behavior.

5. Jest

Jest is a popular JavaScript testing framework. It provides test definitions, assertions, mocks, spies and other testing features.

test("user is active", () => { const user = { active: true }; expect(user.active).toBe(true); });
Interview point: Jest is a testing framework, while Supertest focuses on making HTTP/API testing easier.
6. Node.js Built-in Test Runner

Modern Node.js includes a built-in test runner through node:test.

const test = require("node:test"); const assert = require("node:assert/strict"); test("adds values", () => { assert.equal(2 + 3, 5); });
Interview point: Node's built-in runner avoids adding a separate test framework for projects that only need its built-in testing features.
7. Supertest

Supertest is commonly used to test HTTP servers and Express applications.

const request = require("supertest"); const app = require("./app"); test("GET /health returns 200", async () => { const response = await request(app).get("/health"); expect(response.status).toBe(200); expect(response.body).toEqual({ ok: true }); });
Why: Supertest makes API endpoint testing convenient without requiring a real browser.
8. Mocking

Mocking means replacing a real dependency with controlled behavior during a test.

const paymentService = { charge: jest.fn() }; paymentService.charge.mockResolvedValue({ success: true });

Why: Mocking makes tests faster and lets you simulate external-service success and failure.

9. Spies

A spy observes how a function is used. It can verify call count and arguments.

const logger = { info(message) { console.log(message); } }; const spy = jest.spyOn(logger, "info"); logger.info("User created"); expect(spy).toHaveBeenCalledWith("User created"); spy.mockRestore();
Common mistake: A spy is mainly for observation. It does not automatically mean the original implementation has been replaced.
10. Test Fixtures

Test fixtures are prepared data or setup used by tests.

const userFixture = { name: "Sam", email: "sam@example.com", role: "user" };

Why: Fixtures keep test data consistent and reduce repeated setup code.

11. Test Database

A test database is used only by automated tests.

Test starts
→

Clean data
Important: Never let automated tests accidentally delete or modify production data.
12. Authentication Testing
  • Valid credentials should succeed.
  • Invalid credentials should fail.
  • Missing credentials should be rejected.
  • Expired or invalid tokens should be rejected.
  • Protected routes should not be accessible without valid authentication.
const response = await request(app) .get("/api/profile") .set("Authorization", `Bearer ${token}`); expect(response.status).toBe(200);
13. Error Testing

Do not test only successful cases. Test failures too.

  • Invalid input → 400
  • Unauthenticated → 401
  • Forbidden → 403
  • Missing resource → 404
  • Unexpected server error → 500
Interview point: Good tests verify both the happy path and important failure paths.
14. Middleware Testing

Middleware tests verify whether middleware correctly modifies the request/response or calls next().

function requireAdmin(req, res, next) { if (req.user?.role !== "admin") { return res.status(403).json({ message: "Forbidden" }); } next(); }

Test an admin user, a normal user and a request with no authenticated user.

15. Controller Testing

A controller test checks request handling, service calls and response creation.

Mocking the service keeps the controller test focused on controller behavior.

16. Service Testing

Service tests focus on business rules.

async function createDiscount(user, amount) { if (user.isPremium) { return amount * 0.9; } return amount; }

Test important business cases without needing a full HTTP request for every rule.

17. Async Testing

Async tests must wait for the Promise to finish.

test("loads user", async () => { const user = await getUser(); expect(user.name).toBe("Sam"); });
Common mistake: Starting an asynchronous operation without returning or awaiting it can cause the test to finish before the assertion runs.
18. Coverage

Code coverage measures which parts of the code were executed by tests.

  • Statement coverage
  • Branch coverage
  • Function coverage
  • Line coverage
Important: 100% coverage does not automatically mean the application is bug-free. Poor tests can execute code without checking meaningful behavior.
19. Test Isolation ⭐⭐⭐

Test isolation means each test should be independent and should not rely on another test running before it.

Test A
Own data
Test B
Own data
Test C
Own data

Why: Isolated tests are easier to debug and can usually run in a different order or in parallel.

Common mistake: Test A creates a database record and Test B assumes it exists. If Test B runs alone, it fails.
20. Testing Pyramid
Few
End-to-end / API-heavy tests
More
Integration tests
Many
Fast unit tests

The general idea is many fast unit tests, a useful number of integration tests and fewer expensive end-to-end tests.

21. Common Developer Mistakes
  1. Testing only successful requests.
  2. Using production databases in automated tests.
  3. Sharing mutable test data between tests.
  4. Forgetting to await asynchronous operations.
  5. Writing tests that depend on execution order.
  6. Mocking everything and never testing real integration points.
  7. Testing implementation details instead of observable behavior.
  8. Assuming high coverage means high quality.
  9. Leaving mocks or spies active after a test.
  10. Making tests so large that a failure is difficult to diagnose.
22. Quick Recap
  • Unit test: tests a small unit in isolation.
  • Integration test: checks multiple components working together.
  • API test: checks HTTP request/response behavior.
  • Jest: popular JavaScript testing framework.
  • Node test runner: built into modern Node.js.
  • Supertest: useful for HTTP/Express API testing.
  • Mock: replaces a dependency with controlled behavior.
  • Spy: observes function usage.
  • Fixture: reusable test data/setup.
  • Coverage: shows which code paths were exercised.
  • Isolation: tests should not depend on each other.
  • Always test important success and failure paths.
