Node.js Interview Preparation • Part 7

🟢 Buffers

Understand binary data in Node.js and learn the Buffer APIs commonly asked in interviews.

1. What is a Buffer?

A Buffer is a Node.js object used to work with a fixed-size sequence of bytes. A byte contains a number from 0 to 255.

In simple words, a Buffer is a way to hold raw binary data in memory.

Layman example

Think of a Buffer as a box containing tiny numbered storage slots. Each slot stores one byte. Text, images, audio, video, and network packets can all be represented as bytes.

Text / Image / File / Network data ↓ bytes ↓ Buffer ↓ Node.js processes data
Interview-ready: “A Buffer is a Node.js type used to represent a fixed-size sequence of bytes and is mainly used for handling binary data.”
2. Why Does Node.js Have Buffer?

JavaScript mainly works with strings and objects. Node.js also needs to handle data that is not naturally text, such as files, TCP packets, images, and other binary content.

Buffer gives Node.js a practical way to store and manipulate that byte data.

File system ─────┐ Network ──────────┤ HTTP request ─────┤ Streams ──────────┤ ↓ Buffer ↓ process / transform / send
When to use?
  • Reading binary files.
  • Working with streams.
  • Handling network data.
  • Converting text encodings.
  • Working with images, PDFs, audio, and other binary content.
3. Buffer.from()

Buffer.from() creates a Buffer from existing data such as a string, array of bytes, or another Buffer.

const textBuffer = Buffer.from("Hello");

console.log(textBuffer);
console.log(textBuffer.length);

For UTF-8 text, Hello uses 5 bytes, so the length is 5.

String → Buffer
const buffer = Buffer.from("Hello", "utf8");

console.log(buffer);
Important: Buffer.from() is generally the right API when you already have data and want to create a Buffer from it.
4. Buffer.alloc()

Buffer.alloc(size) creates a Buffer of the requested size and initializes its bytes to zero.

const buffer = Buffer.alloc(5);

console.log(buffer);
// <Buffer 00 00 00 00 00>

Here, the Buffer contains 5 zero bytes.

Interview-ready: “Buffer.alloc() creates an initialized Buffer. Its bytes start as zero, which is safer when you need a clean buffer.”
5. Buffer.allocUnsafe()

Buffer.allocUnsafe(size) creates a Buffer without first initializing its memory to zero.

const buffer = Buffer.allocUnsafe(5);

console.log(buffer);

The contents are not guaranteed to be zero. The memory may contain old data until you overwrite it.

Common mistake: Never assume an unsafe Buffer starts empty. If you use allocUnsafe(), make sure the bytes you expose or use are properly overwritten.
When to use? It can be useful for performance-sensitive code when you know you will immediately write the entire Buffer before reading it.
6. Encoding — Why It Matters

Encoding defines how characters are represented as bytes.

EncodingSimple meaningCommon use
utf8Common text encodingNormal text and web data
hexBytes represented using hexadecimal charactersDebugging and byte-level representation
base64Binary data represented as text charactersTransporting binary data in text-based formats
UTF-8
const b = Buffer.from("Hello", "utf8");
console.log(b.toString("utf8"));
Hex
const b = Buffer.from("Hello");
console.log(b.toString("hex"));
// 48656c6c6f
Base64
const b = Buffer.from("Hello");
console.log(b.toString("base64"));
// SGVsbG8=
Interview-ready: “UTF-8 represents text as bytes, hex displays bytes using hexadecimal digits, and Base64 encodes binary data into text characters. Base64 is an encoding, not encryption.”
7. Buffer.length

buffer.length gives the number of bytes in the Buffer.

const a = Buffer.from("Hello");

console.log(a.length);
// 5

Be careful: Buffer length is bytes, not always the number of characters.

const b = Buffer.from("😊");

console.log(b.length);

The emoji takes multiple UTF-8 bytes, so the byte length is larger than the visible character count.

Interview trap: Do not assume Buffer.from(text).length === text.length for every string.
8. Buffer → String and String → Buffer
Buffer → String
const buffer = Buffer.from("Node.js");

const text = buffer.toString("utf8");

console.log(text);
// Node.js
String → Buffer
const buffer = Buffer.from("Node.js", "utf8");
String │ │ Buffer.from() ↓ Buffer / bytes │ │ toString() ↓ String
Key interview point: Buffer is byte-oriented; String is text-oriented. Conversion needs an encoding when the bytes represent text.
9. Buffer Comparison

Buffer.compare(a, b) compares two Buffers and returns a number.

const a = Buffer.from("abc");
const b = Buffer.from("abc");
const c = Buffer.from("abd");

console.log(Buffer.compare(a, b)); // 0
console.log(Buffer.compare(a, c)); // negative number

A result of 0 means the Buffers contain the same bytes.

Important: Two separately created Buffers are different objects, so a === b is not a content comparison.
console.log(a === b);
// false
10. Buffer Concatenation

Buffer.concat() joins multiple Buffers into a new Buffer.

const first = Buffer.from("Hello ");
const second = Buffer.from("Node.js");

const result = Buffer.concat([first, second]);

console.log(result.toString());
// Hello Node.js
Buffer A ──┐ ├── Buffer.concat() ──→ New Buffer Buffer B ──┘

The original Buffers are not changed by concatenation.

11. Buffer and Files

Node.js file APIs can work with Buffers. If you read a file without specifying a text encoding, you can receive binary data as a Buffer.

const fs = require("node:fs");

fs.readFile("photo.jpg", (err, data) => {
  if (err) throw err;

  console.log(Buffer.isBuffer(data));
});

This is useful because an image is not plain text. You normally want its raw bytes.

photo.jpg ↓ fs.readFile() ↓ Buffer ↓ process / save / send
When to use? Use a Buffer when you need the actual binary file data rather than a decoded text string.
12. Buffer and Streams

Streams process data in smaller pieces instead of requiring the entire data set to be loaded at once. Those chunks are commonly Buffers for binary streams.

const fs = require("node:fs");

const stream = fs.createReadStream("large-video.mp4");

stream.on("data", (chunk) => {
  console.log(Buffer.isBuffer(chunk));
});
Large file ↓ Read small chunk ↓ Buffer ↓ Process chunk ↓ Read next chunk ↓ ...

This helps applications work with large data more efficiently.

Interview-ready: “Streams allow data to be processed incrementally. For binary data, stream chunks are commonly represented as Buffers.”
13. Buffer and HTTP

HTTP requests and responses can carry binary data. Node.js can represent incoming or outgoing binary chunks using Buffers.

const http = require("node:http");

http.createServer((req, res) => {
  const chunks = [];

  req.on("data", (chunk) => {
    chunks.push(chunk);
  });

  req.on("end", () => {
    const body = Buffer.concat(chunks);
    console.log("Bytes:", body.length);
    res.end("Received");
  });
}).listen(3000);
HTTP request ↓ data chunks ↓ Buffer chunks ↓ Buffer.concat() ↓ complete request body
Note: If the request body is text such as JSON, you may convert the Buffer to a string and then parse the JSON.
14. Buffer vs String ⭐⭐⭐
BufferString
Represents bytesRepresents text
Useful for binary dataUseful for readable text
Has byte lengthHas string length in UTF-16 code units
Common in streams/files/network dataCommon for text processing
Can convert to string using encodingCan convert to Buffer using Buffer.from()
Best interview answer: “A String represents text, while a Buffer represents raw bytes. Node.js uses Buffers when it needs to handle binary data such as files, network packets, and stream chunks.”
15. Common Developer Mistakes
  • Thinking Buffer is the same as a normal JavaScript string.
  • Assuming buffer.length always equals the visible character count.
  • Using allocUnsafe() and reading bytes before overwriting them.
  • Thinking Base64 is encryption. It is only an encoding.
  • Using text conversion when the data is actually binary.
  • Forgetting the correct encoding when converting Buffer to text.
  • Comparing Buffer contents with === and expecting content equality.
  • Loading huge files entirely into memory when a stream would be more appropriate.
  • Assuming all stream data is automatically a string.
16. Interview Questions — Click to Show Answer + Why ⭐⭐⭐
MAANG / Product Company
Q1. What is a Buffer in Node.js?

Answer: A Buffer is a fixed-size sequence of bytes used to handle binary data.

Why? Node.js needs to work with files, streams, network packets, images, and other data that is not simply text.

Output-Based
Q2. What is the output?
const buffer = Buffer.from("Hello");

console.log(buffer.length);

Code Answer: 5

Why? The UTF-8 representation of the ASCII text “Hello” uses five bytes.

Core API
Q3. What is the difference between Buffer.from() and Buffer.alloc()?

Answer: Buffer.from() creates a Buffer from existing data. Buffer.alloc(size) creates a new initialized Buffer of the requested size.

Why? One is commonly used for converting existing data into bytes; the other is used when you need a fresh byte storage area.

Security / Performance
Q4. Why is Buffer.allocUnsafe() called unsafe?
const b = Buffer.allocUnsafe(10);

Answer: Its memory is not initialized to zero first, so the Buffer can contain old memory contents.

Why? Skipping initialization can be faster, but the caller must overwrite the relevant bytes before using or exposing them.

Encoding
Q5. What is the output?
const buffer = Buffer.from("Hello");

console.log(buffer.toString("hex"));

Code Answer: 48656c6c6f

Why? Each byte of the UTF-8 text is represented by two hexadecimal digits.

Encoding
Q6. What is Base64? Is it encryption?

Answer: Base64 is an encoding that represents binary data using text characters. It is not encryption.

Why? Anyone who knows the encoding can decode Base64. It provides representation, not confidentiality.

Important Trap
Q7. What is the output?
const a = Buffer.from("abc");
const b = Buffer.from("abc");

console.log(a === b);
console.log(Buffer.compare(a, b));

Code Answer:

false
0

Why? a and b are different Buffer objects, so strict equality is false. Buffer.compare() checks their byte content, and 0 means the contents are equal.

Concatenation
Q8. What is the output?
const a = Buffer.from("Node");
const b = Buffer.from("JS");

const c = Buffer.concat([a, b]);

console.log(c.toString());

Code Answer: NodeJS

Why? Buffer.concat() creates a new Buffer containing the bytes from both Buffers in order.

Very Important
Q9. Why is Buffer preferred over String for binary data?

Answer: Buffer directly represents bytes, while String represents text.

Why? Binary files and network data can contain arbitrary byte values that should not be interpreted as text.

Output-Based
Q10. What is the output?
const text = "😊";
const buffer = Buffer.from(text);

console.log(text.length);
console.log(buffer.length);

Code Answer: In normal JavaScript string length semantics, the emoji uses two UTF-16 code units, while its UTF-8 representation uses four bytes:

2
4

Why? JavaScript String length and Buffer byte length use different representations. This is a common interview trap.

Files
Q11. What type of data can fs.readFile() provide when no encoding is supplied?

Answer: A Buffer for the file data.

Why? Without a text encoding, Node.js does not decode the file into a string. It gives you the raw bytes.

Streams
Q12. Why are Buffers important for streams?

Answer: Streams process data incrementally, and binary stream chunks are commonly represented as Buffers.

Why? This allows large files or network data to be processed in pieces rather than loading everything into memory at once.

Interview Trap
Q13. Does buffer.length always equal the number of characters?

Answer: No.

Why? buffer.length counts bytes. Characters can use different numbers of bytes depending on encoding.

API
Q14. How do you convert a Buffer into a UTF-8 string?
const buffer = Buffer.from("Hello");

Code Answer:

const text = buffer.toString("utf8");

Why? toString() decodes the Buffer's bytes using the specified character encoding.

Advanced
Q15. What problem can occur if a huge file is read entirely into a Buffer?

Answer: The application may consume a large amount of memory.

Why? A complete file Buffer keeps the whole file data in memory. A stream can process smaller chunks progressively and is often more suitable for large files.
