Node.js Interview Preparation • Part 15

🟢 Part 15 — Express Routing ⭐⭐⭐

Learn how Express decides which code should handle each HTTP request, how to organize routes, and how route parameters, query parameters, middleware, routers, and 404 handling work.

1. What is Express Routing?

Routing means deciding which function should run for a particular HTTP method and URL path.

Client ↓ GET /users/25?active=true ↓ Express ↓ HTTP method + path matching ↓ Matching route ↓ Middleware ↓ Route handler ↓ Response
Layman example

Think of a large office. The URL is like a department address. The HTTP method tells the receptionist what the visitor wants to do. Routing sends the visitor to the correct department.

Interview-ready: “Express routing maps an HTTP method and URL path to one or more handler functions.”
2. Route Definitions

The basic pattern is:

app.METHOD(PATH, HANDLER);

Examples:

app.get("/users", (req, res) => {
  res.send("All users");
});

app.post("/users", (req, res) => {
  res.send("Create user");
});

app.delete("/users/:id", (req, res) => {
  res.send("Delete user");
});
Remember: Express considers both the HTTP method and the path when matching a normal route.
3. Route Parameters

A route parameter is a dynamic part of the URL path.

app.get("/users/:id", (req, res) => {
  console.log(req.params.id);
  res.send(`User ID: ${req.params.id}`);
});

Request:

GET /users/25

Then:

req.params.id // "25"
/users/:id ↓ /users/25 ↓ req.params.id ↓ "25"

Route parameters are useful when the value identifies a resource.

Interview line: “Route parameters are values embedded in the URL path and are accessed through req.params.”
4. Multiple Route Parameters
app.get("/users/:userId/orders/:orderId", (req, res) => {
  res.json({
    userId: req.params.userId,
    orderId: req.params.orderId
  });
});

For /users/10/orders/500:

req.params.userId  // "10"
req.params.orderId // "500"
Route parameter values arrive as strings. Convert them when your application needs a number.
5. Query Parameters

Query parameters come after ? in the URL. They are commonly used for filtering, searching, sorting, and pagination.

app.get("/products", (req, res) => {
  console.log(req.query);
  res.json(req.query);
});

Request:

GET /products?category=phone&page=2

Example:

req.query.category // "phone"
req.query.page     // "2"
/products?category=phone&page=2 ↓ req.query ↓ { category, page }
Difference: req.params reads path parameters such as /users/25; req.query reads query parameters such as /users?page=2.
6. Request Body

The request body contains data sent by the client, commonly with POST, PUT, or PATCH.

const express = require("express");
const app = express();

app.use(express.json());

app.post("/users", (req, res) => {
  console.log(req.body);

  res.status(201).json({
    message: "User created",
    data: req.body
  });
});
Client ↓ POST /users ↓ JSON body ↓ express.json() ↓ req.body ↓ route handler
Common mistake: Forgetting express.json() when expecting JSON request bodies can leave req.body unavailable for that content type.
7. Route Matching

Express compares the incoming request against registered routes. For normal routes, the HTTP method and path must match the route.

app.get("/users", (req, res) => {
  res.send("Users");
});

app.get("/products", (req, res) => {
  res.send("Products");
});
GET /users ↓ matches /users ↓ Users handler GET /products ↓ matches /products ↓ Products handler
8. Route Order — Very Important

Route order matters because an earlier matching route can handle the request before a later route gets a chance.

app.get("/users/:id", (req, res) => {
  res.send(`Dynamic user: ${req.params.id}`);
});

app.get("/users/admin", (req, res) => {
  res.send("Admin user");
});

A request to /users/admin can be matched by the dynamic route first, depending on the route definitions.

GET /users/admin ↓ /users/:id matches ↓ dynamic handler runs X /admin route is not reached
Best practice: Put specific routes before broader dynamic routes when route patterns can overlap.
9. Route Handlers

A route handler is the function that processes a matching request.

app.get("/profile", (req, res) => {
  res.json({
    name: "Sam"
  });
});

The (req, res) => { ... } function is the route handler.

10. Multiple Route Handlers

Express allows multiple handlers for one route. A handler can finish the request or call next() to continue.

app.get(
  "/users",
  (req, res, next) => {
    console.log("First handler");
    next();
  },
  (req, res) => {
    res.send("Second handler");
  }
);
Request ↓ Handler 1 ↓ next() Handler 2 ↓ Response
Common mistake: Calling next() after already sending a response can cause confusing behavior or errors. A handler should either complete the response or intentionally pass control onward.
11. next()

next() passes control to the next matching middleware or handler.

app.get("/dashboard", (req, res, next) => {
  console.log("Checking request");
  next();
});

app.get("/dashboard", (req, res) => {
  res.send("Dashboard");
});
GET /dashboard ↓ first handler ↓ next() second handler ↓ response

For errors, Express uses next(error) to pass an error to error-handling middleware.

12. Route-Specific Middleware

Middleware can be applied only to selected routes.

function checkAuth(req, res, next) {
  const loggedIn = true;

  if (!loggedIn) {
    return res.status(401).json({
      message: "Login required"
    });
  }

  next();
}

app.get("/profile", checkAuth, (req, res) => {
  res.send("Private profile");
});
GET /profile ↓ checkAuth ┌──┴──┐ fail pass ↓ ↓ 401 next() ↓ handler ↓ response
13. express.Router()

express.Router() creates a small, independent routing object. It helps organize routes into separate files or modules.

const express = require("express");
const router = express.Router();

router.get("/", (req, res) => {
  res.send("All users");
});

router.get("/:id", (req, res) => {
  res.send(`User ${req.params.id}`);
});

module.exports = router;

Then mount it:

const userRouter = require("./routes/users");

app.use("/users", userRouter);
GET /users ↓ app.use("/users", userRouter) ↓ userRouter.get("/") ↓ handler GET /users/25 ↓ userRouter.get("/:id") ↓ handler
Interview-ready: “express.Router() creates a modular routing system so related routes can be grouped and mounted under a common path.”
14. Router-Level Middleware

Router-level middleware is attached to a router instead of the whole application.

const router = express.Router();

router.use((req, res, next) => {
  console.log("Users router middleware");
  next();
});

router.get("/", (req, res) => {
  res.send("Users");
});
/users request ↓ users router ↓ router middleware ↓ next() route ↓ response

This is useful when several related routes need the same middleware.

15. Nested Routers

Routers can be mounted under other routers or path structures to represent related resources.

// users.js
const router = express.Router();

router.use("/:userId/orders", orderRouter);

module.exports = router;

Conceptually:

/users/10/orders ↓ users router ↓ userId = 10 ↓ orders router

For nested parameters, pay attention to how parameters are made available across routers. In common Express setups, mergeParams: true can be used when a child router needs parent router parameters.

const router = express.Router({
  mergeParams: true
});
16. RESTful Routes

A REST-style API commonly represents resources using URLs and HTTP methods.

MethodExampleCommon meaning
GET/usersRead collection
GET/users/10Read one user
POST/usersCreate user
PUT/users/10Replace/update resource
PATCH/users/10Partially update
DELETE/users/10Delete user
Good REST style: Prefer resource-oriented paths such as /users/10 rather than action-heavy paths such as /getUserById, while remembering that real APIs can have valid variations.
17. Dynamic Routes
app.get("/products/:id", (req, res) => {
  res.json({
    productId: req.params.id
  });
});

Any value in the :id position can match the route.

/products/10 → id = "10" /products/25 → id = "25" /products/99 → id = "99"
18. Optional Parameters

Optional route parameter syntax has changed across Express versions. In modern Express routing, do not blindly copy older examples using ? without checking the version's routing syntax.

A simple and usually clearer design is to use separate routes when a segment is optional:

app.get("/users", handler);
app.get("/users/:id", handler);
Interview point: Explain the concept of an optional route segment, but mention that the exact pattern syntax depends on the Express version and its underlying path matching behavior.
19. Wildcard Routes

A wildcard route is used when you want a route pattern to catch paths that were not handled by more specific routes. Exact wildcard syntax can vary with Express's routing matcher/version.

A common conceptual 404 pattern is to place a final fallback after all normal routes:

app.use((req, res) => {
  res.status(404).json({
    message: "Route not found"
  });
});
Request ↓ Route 1? ─ no ↓ Route 2? ─ no ↓ Route 3? ─ no ↓ Final 404 handler ↓ 404 response
20. 404 Routes

A 404 handler is normally placed after the application's valid routes so it acts as a fallback.

app.get("/users", (req, res) => {
  res.json([]);
});

app.use((req, res) => {
  res.status(404).json({
    message: "Endpoint not found"
  });
});
Important: If the 404 handler is registered too early, it can prevent valid routes below it from being reached.
21. Route Organization

As an application grows, putting every route in app.js becomes difficult to maintain. Use routers to group related resources.

project/
├── app.js
├── routes/
│   ├── users.js
│   ├── products.js
│   └── orders.js
├── controllers/
│   ├── userController.js
│   ├── productController.js
│   └── orderController.js
└── middleware/
    └── auth.js

Example:

// app.js
const userRouter = require("./routes/users");
const productRouter = require("./routes/products");

app.use("/users", userRouter);
app.use("/products", productRouter);
Interview tip: Separate routing from business logic as applications grow. Routers define request paths, while controllers/services can contain the application logic.
22. Common Developer Mistakes
  • Putting a dynamic route such as /:id before a more specific route such as /admin.
  • Confusing req.params with req.query.
  • Forgetting express.json() when expecting JSON request bodies.
  • Calling next() after sending a response.
  • Creating a middleware that neither calls next() nor sends a response.
  • Registering a 404 handler before valid routes.
  • Putting all application routes into one very large file.
  • Forgetting to mount an express.Router().
  • Using inconsistent REST resource names.
  • Assuming route parameter values are automatically numbers.
  • Copying old wildcard/optional-parameter syntax without checking the Express version.
23. Interview Questions — Click to Show / Hide Answer + Why ⭐⭐⭐
Q1. What is routing in Express?
Answer: Routing maps an HTTP method and URL path to one or more handler functions.

Why? It tells Express which application code should handle a request.
Q2. What is the difference between req.params and req.query?
GET /users/25?page=2
Answer: req.params.id would contain "25" if the route is /users/:id. req.query.page contains "2".

Why? Params are part of the path; query values are after the ?.
Q3. What does next() do?
Answer: It passes control to the next matching middleware or handler.

Why? Express middleware uses next() to create a processing chain.
Q4. What happens if middleware does not call next() and does not send a response?
app.get("/test", (req, res, next) => {
  console.log("Hello");
});
Answer: The request can remain pending because the middleware neither completed the response nor passed control onward.

Why? Express needs the middleware chain to continue or the response to be completed.
Q5. Predict the result.
app.get("/users/:id", (req, res) => {
  res.send(`Dynamic: ${req.params.id}`);
});

app.get("/users/admin", (req, res) => {
  res.send("Admin");
});

Request: GET /users/admin



Answer: The first route can handle the request, producing Dynamic: admin.

Why? The dynamic route is registered before the specific route and can match the path. Route order matters.
Q6. How would you fix Q5?
Answer: Put the specific route before the dynamic route.

app.get("/users/admin", adminHandler);
app.get("/users/:id", userHandler);
Why? The specific route gets the first chance to match.
Q7. What is express.Router()?
Answer: It creates a modular router object that can hold related routes and middleware.

Why? It keeps large Express applications organized and easier to maintain.
Q8. What is route-level middleware?
Answer: Middleware applied to a particular route or group of routes.

Why? It is useful for checks such as authentication, validation, or logging only where needed.
Q9. Where should a 404 handler normally be placed?
Answer: After all valid routes and route middleware that should get a chance to handle the request.

Why? It acts as the final fallback when no previous route matched.
Q10. What is a RESTful route for getting user 25?
Answer: GET /users/25.

Why? The URL identifies the user resource and GET expresses retrieval.
Q11. What is the difference between /users/:id and /users?id=25?
Answer: In /users/:id, 25 is a route parameter accessed through req.params.id. In /users?id=25, 25 is a query parameter accessed through req.query.id.

Why? They represent different URL structures and are commonly used for different API purposes.
Q12. What happens here?
app.use((req, res) => {
  res.status(404).send("Not found");
});

app.get("/users", (req, res) => {
  res.send("Users");
});

Request: GET /users

Answer: The first middleware can send the 404 response before the /users route is reached.

Why? The fallback was registered before the valid route. Middleware and route order matters.
Q13. What does this print?
app.get("/users/:id", (req, res) => {
  console.log(typeof req.params.id);
  res.send("OK");
});

Request: GET /users/25

Answer: It prints "string".

Why? URL path parameters are provided as strings. Convert them explicitly if numeric behavior is required.
Q14. What is the output?
app.get("/test", (req, res, next) => {
  console.log("A");
  next();
});

app.get("/test", (req, res) => {
  console.log("B");
  res.send("Done");
});
Answer: Console output is A followed by B, and the client receives Done.

Why? The first handler calls next(), allowing the next matching handler to run.
Q15. Find the bug.
app.get("/profile", checkAuth, (req, res) => {
  res.json({ ok: true });
});

function checkAuth(req, res, next) {
  if (!req.headers.authorization) {
    res.status(401).json({ message: "Login required" });
  }
  next();
}
Answer: After sending the 401 response, the middleware still calls next().

Why? It can allow the protected handler to run after the response has already been sent. Fix it with return res.status(401).json(...).
Q16. Why use nested routers?
Answer: They help represent related resources and keep route modules organized.

Why? A large API becomes easier to understand when related routes are grouped by resource.
Q17. What is router-level middleware?
Answer: Middleware registered on an Express Router, usually with router.use() or on specific router routes.

Why? It applies common behavior to a particular route group instead of the whole application.
Q18. How do you organize Express routes in a larger project?
Answer: Create resource-specific router files such as users.js, products.js, and orders.js, then mount them in the main application.

Why? It reduces one huge routing file and improves maintainability.
Q19. Why is this route order risky?
app.get("/:page", pageHandler);
app.get("/login", loginHandler);
Answer: The dynamic route can match /login first.

Why? A single dynamic path segment is broader than the specific /login route.
Q20. Explain the full Express routing lifecycle.
Answer: Client sends request → Express receives it → application/router middleware runs → Express checks route method/path → route-specific middleware runs → handler executes → response is sent. If no route handles it, the request can reach a final 404 handler.

Why? This mental model helps debug route ordering, middleware, parameters, and missing endpoints.

Strong interview summary:
“Express routing maps HTTP methods and paths to handlers. Dynamic values are available through req.params, query-string values through req.query, and request data through req.body after the appropriate parsing middleware. Middleware can run globally, at router level, or for specific routes, and next() passes control to the next function. express.Router() helps split routes into modules. Route order matters, and a final 404 handler is commonly placed after valid routes.”
