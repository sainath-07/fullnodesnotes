Node.js Interview Preparation • Part 14

🟢 Express.js Fundamentals ⭐⭐⭐

Learn how Express creates HTTP servers, handles requests and responses, defines routes, and builds the basic foundation of a Node.js backend.

1. What is Express.js?

Express.js is a lightweight web framework for Node.js. It gives us convenient tools for building HTTP servers, APIs, routes, middleware, and web applications.

Layman example

Node's built-in http module is like having a basic kitchen. Express gives you ready-made counters, tools, and a better workflow so you can build the application faster.

Client ↓ HTTP request Express application ↓ Route matching ↓ Route handler ↓ Response ↓ Client
Interview-ready: “Express is a minimal Node.js web framework that simplifies HTTP server development by providing routing, middleware support, and convenient request/response handling.”
2. Express Architecture — Simple View
Browser / React / Mobile App ↓ HTTP Request ↓ ┌─────────────────┐ │ Express App │ │ │ │ Middleware │ │ ↓ │ │ Route matching │ │ ↓ │ │ Handler │ └────────┬────────┘ ↓ HTTP Response ↓ Client

Express itself is not a separate runtime. It runs on Node.js and uses Node's HTTP capabilities underneath.

Important: Express is a framework/library layer on top of Node.js; Node.js provides the runtime and core networking capabilities.
3. Installing Express

Create a Node.js project first:

npm init -y

Install Express as a project dependency:

npm install express

This adds Express to package.json and installs it into node_modules.

npm install express ↓ package.json updated ↓ package-lock.json updated ↓ node_modules/express installed
Interview tip: Express is normally installed locally in the project, not globally, because each application should control its dependency version.
4. Creating an Express Server
const express = require("express");

const app = express();

app.listen(3000, () => {
  console.log("Server running on port 3000");
});
How it works
  1. require("express") loads Express.
  2. express() creates an Express application object.
  3. app.listen() starts the HTTP server listening on a port.
require("express") ↓ express() ↓ app object ↓ app.listen(3000) ↓ Server starts listening
5. express()

express() creates an Express application.

const express = require("express");

const app = express();

The returned app object is used to configure routes, middleware, and server behavior.

Interview-ready: “Calling express() creates and returns an Express application instance that exposes methods such as get, post, use, and listen.”
6. app.listen()

app.listen() starts the server and makes it listen for incoming connections.

app.listen(3000, () => {
  console.log("Server started");
});

Here, 3000 is the port number.

Client ↓ localhost:3000 ↓ Node.js HTTP server ↓ Express application
Common mistake: Defining routes but forgetting app.listen() means the application is not listening for incoming HTTP connections.
7. Request and Response

Every HTTP interaction has two important sides:

Request
The client tells the server what it wants.
Response
The server sends the result back to the client.
Client │ │ Request │ method + URL + headers + body ↓ Express │ │ Response │ status + headers + body ↓ Client
app.get("/users", (req, res) => {
  console.log(req.method);
  console.log(req.url);

  res.send("Users");
});

req represents the incoming request. res represents the outgoing response.

8. GET — app.get()

Use app.get() to handle HTTP GET requests.

app.get("/users", (req, res) => {
  res.send("Get all users");
});

When a client sends:

GET /users

Express looks for a matching GET route.

GET /users ↓ app.get("/users", ...) ↓ handler executes ↓ res.send(...) ↓ response
9. POST — app.post()

Use app.post() when the client sends data to create or trigger something on the server.

app.post("/users", (req, res) => {
  res.status(201).json({
    message: "User created"
  });
});
POST /users
Interview tip: GET commonly retrieves data. POST commonly creates a new resource or submits data for processing. The exact API semantics depend on the application design.
10. PUT — app.put()

app.put() handles PUT requests. PUT is commonly used to replace or fully update a resource.

app.put("/users/10", (req, res) => {
  res.json({
    message: "User replaced/updated"
  });
});
PUT /users/10
11. PATCH — app.patch()

app.patch() handles partial updates.

app.patch("/users/10", (req, res) => {
  res.json({
    message: "User partially updated"
  });
});
PATCH /users/10

For example, a PATCH request could change only a user's name without sending every user field.

Interview line: “PUT is generally associated with full replacement, while PATCH is intended for partial modification.”
12. DELETE — app.delete()

app.delete() handles DELETE requests.

app.delete("/users/10", (req, res) => {
  res.status(204).end();
});
DELETE /users/10

A 204 No Content response is commonly used when deletion succeeds and there is no response body to return.

13. Express Route Pattern
app.METHOD(PATH, HANDLER);

Examples:

app.get("/users", handler);
app.post("/users", handler);
app.put("/users/:id", handler);
app.patch("/users/:id", handler);
app.delete("/users/:id", handler);
HTTP Method + URL path ↓ Route matching ↓ Handler function ↓ res sends response
14. res.send()

res.send() sends a response to the client and ends the response.

app.get("/", (req, res) => {
  res.send("Hello from Express");
});

It can send strings and other supported values, with Express handling the response appropriately.

Common mistake: Do not send multiple responses for one request.
15. res.json()

res.json() sends a JSON response.

app.get("/user", (req, res) => {
  res.json({
    id: 10,
    name: "Sam"
  });
});

This is commonly used when building REST-style APIs for frontend applications.

Interview tip: res.json() is designed for JSON API responses and sets the appropriate JSON response behavior.
16. res.status()

res.status() sets the HTTP status code. It can be chained with another response method.

app.post("/users", (req, res) => {
  res.status(201).json({
    message: "Created"
  });
});
res.status(201) ↓ sets status code ↓ .json(...) ↓ sends response
Important: res.status() alone does not normally send the response. You generally follow it with send(), json(), end(), or another response-ending method.
17. res.end()

res.end() finishes the HTTP response. It is useful when there is no body to send.

app.delete("/users/10", (req, res) => {
  res.status(204).end();
});

Compared with res.json(), res.end() is lower-level and does not format an object as JSON.

18. Express Routing

Routing means deciding which code should handle a request based on its HTTP method and URL path.

app.get("/products", (req, res) => {
  res.json({ message: "Products" });
});

app.post("/products", (req, res) => {
  res.status(201).json({ message: "Product created" });
});

app.get("/products/:id", (req, res) => {
  res.json({
    id: req.params.id
  });
});
GET /products ↓ GET products handler POST /products ↓ POST products handler GET /products/25 ↓ GET products/:id handler

Express checks routes and invokes a matching handler.

19. Complete Beginner Express Server
const express = require("express");

const app = express();

app.get("/", (req, res) => {
  res.send("Home page");
});

app.get("/users", (req, res) => {
  res.json([
    { id: 1, name: "Sam" },
    { id: 2, name: "Alex" }
  ]);
});

app.post("/users", (req, res) => {
  res.status(201).json({
    message: "User created"
  });
});

app.listen(3000, () => {
  console.log("Server running on port 3000");
});
Node.js starts ↓ Express app created ↓ Routes registered ↓ app.listen(3000) ↓ Server waits for requests ↓ Request arrives ↓ Matching route runs ↓ Response sent
20. Common Developer Mistakes
  • Forgetting to call app.listen().
  • Using the wrong HTTP method for a route.
  • Sending two responses for one request.
  • Forgetting to end a response when using low-level response APIs.
  • Using res.status(404) without actually sending or ending the response.
  • Returning a success status for a failed operation.
  • Confusing req and res.
  • Assuming Express automatically parses every kind of request body without configuration.
  • Putting a route at the wrong URL path.
  • Thinking Express is the Node.js runtime itself.
21. Interview Questions — Click to Show / Hide Answer + Why ⭐⭐⭐
Q1. What is Express.js?
Answer: Express.js is a lightweight web framework for Node.js used to build HTTP servers, APIs, routing, and middleware-based applications.

Why? It simplifies common server-side HTTP tasks compared with using Node's core HTTP APIs directly.
Q2. Is Express.js a runtime like Node.js?
Answer: No. Node.js is the JavaScript runtime. Express is a framework/library that runs on Node.js.

Why? This is a common interview distinction.
Q3. What does express() do?
Answer: It creates an Express application instance.

Why? The returned app object provides methods for defining routes, middleware, and starting the server.
Q4. What does app.listen() do?
Answer: It starts the HTTP server and makes it listen for incoming connections on a specified port.

Why? Without a listening server, clients cannot connect to the application over HTTP.
Q5. What is the difference between req and res?
Answer: req contains information about the incoming client request. res is used to construct and send the server response.

Why? Understanding this distinction is fundamental to Express route handlers.
Q6. What is routing in Express?
Answer: Routing maps an HTTP method and URL path to a handler function.

Why? It determines which application logic should run for each request.
Q7. What is the difference between app.get() and app.post()?
Answer: app.get() handles GET requests, while app.post() handles POST requests.

Why? HTTP methods communicate the intended operation and Express uses the method when matching routes.
Q8. What is the difference between PUT and PATCH?
Answer: PUT is generally used for replacing a resource, while PATCH is intended for partial modification.

Why? API design should communicate whether the client is replacing the representation or changing only selected fields.
Q9. What does res.send() do?
Answer: It sends a response body and completes the response.

Why? It is one of Express's convenient response helpers.
Q10. What does res.json() do?
Answer: It sends a JSON response to the client.

Why? JSON is a common data format for REST-style APIs and frontend-backend communication.
Q11. What does res.status() do?
Answer: It sets the HTTP status code for the response.

Why? Status codes communicate the result category to clients.
Q12. Does res.status(404) send the response?
Answer: No. It sets the status code. You still need to send or end the response, for example res.status(404).json(...).

Why? A response must actually be completed for the client to receive it.
Q13. What does res.end() do?
Answer: It ends the HTTP response.

Why? It is useful when there is no response body, such as a successful 204 response.
Q14. Predict the response.
app.get("/hello", (req, res) => {
  res.status(200).json({
    message: "Hello"
  });
});

What happens for GET /hello?

Answer: The route handler runs and sends HTTP status 200 with a JSON body containing {"message":"Hello"}.

Why? The method and path match the registered route.
Q15. What is wrong here?
app.get("/users", (req, res) => {
  res.status(200);
});
Answer: The status is set but the response is not completed.

Why? Use something such as res.status(200).json(users), res.send(...), or res.end().
Q16. What is wrong here?
app.get("/users", (req, res) => {
  res.json({ message: "One" });
  res.json({ message: "Two" });
});
Answer: The handler attempts to send two responses for one request.

Why? Once the response is sent, the same request cannot normally receive another independent response. This can cause “headers already sent” style errors.
Q17. Which route handles GET /users/25?
app.get("/users", handlerA);
app.post("/users", handlerB);
app.get("/users/:id", handlerC);
Answer: handlerC.

Why? /users/:id matches the additional path segment, with req.params.id equal to "25".
Q18. What is the role of app.get("/path", handler)?
Answer: It registers a handler for GET requests whose path matches the specified route pattern.

Why? Express uses HTTP method + path when selecting route handlers.
Q19. What is the basic request/response lifecycle in Express?
Answer: Client sends request → Express receives it → Express checks middleware/routes → matching handler runs → handler builds response → response is sent to client.

Why? This is the foundation for understanding Express APIs.
Q20. Express vs Node's http module — why use Express?
Answer: Node's http module provides lower-level HTTP capabilities, while Express adds convenient routing, middleware patterns, response helpers, and application structure.

Why? Express reduces repetitive server code and makes larger HTTP applications easier to organize.
