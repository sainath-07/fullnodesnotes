🟢 Part 23 — Database Integration ⭐⭐⭐

Learn how a Node.js application connects to MongoDB or SQL databases, performs async operations, handles errors, validates data and manages transactions.

1. What is Database Integration?

What: Database integration means connecting your Node.js application to a database so the application can store, read, update and delete data.

Why: Application data should normally survive after the Node.js process stops. A database provides persistent storage.

Layman example: A food delivery app needs to remember users, restaurants, products, orders and payments. The database acts like the application's organized storage room.

Interview line: Node.js database operations are usually asynchronous, so the application can continue handling other work while the database operation is in progress.
2. MongoDB

What: MongoDB is a NoSQL document database. It stores data as BSON documents that are similar in shape to JSON objects.

When to use: It is useful when document-shaped data, flexible schemas or fast development are important.

{ "_id": "...", "name": "Laptop", "price": 50000, "category": "electronics" }

Important: MongoDB does support schema validation features, but MongoDB itself is not the same thing as Mongoose schemas.

3. MongoDB Connection

A Node.js application normally creates a database connection during startup and reuses that connection instead of opening a brand-new connection for every request.

const mongoose = require("mongoose"); async function connectDB() { try { await mongoose.connect(process.env.MONGO_URI); console.log("MongoDB connected"); } catch (error) { console.error("Database connection failed", error); process.exit(1); } }

Common mistake: Starting the server as if the database is ready without deciding how startup should behave when the initial connection fails.
4. Mongoose

What: Mongoose is an ODM (Object Data Modeling) library for MongoDB and Node.js.

Purpose: It gives your application models, schemas, validation, middleware, queries and other helpful abstractions.

Easy way to remember: MongoDB is the database. Mongoose is a Node.js library that provides a structured way to work with MongoDB.
5. Schema and Model

Schema: Describes the structure and rules for documents handled by a Mongoose model.

Model: A constructor created from a schema that you use to create and query documents.

const mongoose = require("mongoose"); const userSchema = new mongoose.Schema({ name: { type: String, required: true }, email: { type: String, required: true, unique: true }, age: { type: Number, min: 18 } }); const User = mongoose.model("User", userSchema);

7. Queries

Queries ask the database for specific data. Good queries should return only the data the application needs.

const users = await User .find({ age: { $gte: 18 } }) .select("name email") .sort({ name: 1 }) .limit(10);

Interview point: Filtering, projection, sorting and limiting can reduce unnecessary database work and network transfer.

8. Validation

What: Validation checks whether data follows required rules before it is stored or processed.

const productSchema = new mongoose.Schema({ name: { type: String, required: true, trim: true }, price: { type: Number, required: true, min: 0 } });
Important: Database/model validation is useful, but API input should also be validated at the request boundary. Do not depend on only one validation layer.
9. Mongoose Middleware

Mongoose middleware, also called hooks, can run before or after certain model operations.

userSchema.pre("save", function(next) { this.name = this.name.trim(); next(); });

When to use: Reusable model-level behavior such as preparing data or running controlled hooks.

Common mistake: Putting too much business logic into model middleware can make execution difficult to understand. Keep important business rules explicit when appropriate.
10. Population and References

MongoDB can store a reference to another document. Mongoose's populate() can then replace a referenced ID with related document data.

const orderSchema = new mongoose.Schema({ user: { type: mongoose.Schema.Types.ObjectId, ref: "User" }, total: Number }); const order = await Order .findById(orderId) .populate("user", "name email");

11. SQL — MySQL / PostgreSQL

SQL databases store structured data in tables and provide SQL for querying and modifying that data.

Users +----+----------+-------------------+ | id | name | email | +----+----------+-------------------+ | 1 | Sam | sam@example.com | | 2 | Alex | alex@example.com | +----+----------+-------------------+

Examples: MySQL and PostgreSQL are relational databases. They are commonly used when relationships, constraints and transactions are important.

12. SQL Connection

Node.js SQL libraries generally support connection pools. The application gets a connection from the pool, performs work, and releases it.

const { Pool } = require("pg"); const pool = new Pool({ connectionString: process.env.DATABASE_URL }); const result = await pool.query( "SELECT id, name FROM users WHERE id = $1", [userId] );
Why placeholders? $1 is a parameter placeholder. The value is supplied separately instead of building SQL by string concatenation.
13. Parameterized Queries

Never build SQL using raw user input like this:

const sql = "SELECT * FROM users WHERE email = '" + email + "'";

Use parameters:

const sql = "SELECT * FROM users WHERE email = $1"; const result = await pool.query(sql, [email]);
Why? Parameterized queries help prevent SQL injection by keeping SQL structure separate from user-supplied values.
14. Connection Pooling

15. Transactions

What: A transaction groups multiple database operations into one logical unit of work.

Layman example: Moving ₹500 from Account A to Account B should not leave the money removed from A if the credit to B fails.

Interview line: Transactions provide atomicity for a group of related database operations: either the transaction commits, or its changes are rolled back.
16. SQL Transaction Example
const client = await pool.connect(); try { await client.query("BEGIN"); await client.query( "UPDATE accounts SET balance = balance - $1 WHERE id = $2", [500, fromId] ); await client.query( "UPDATE accounts SET balance = balance + $1 WHERE id = $2", [500, toId] ); await client.query("COMMIT"); } catch (error) { await client.query("ROLLBACK"); throw error; } finally { client.release(); }

Key idea: Always release the pooled connection in finally.

18. Async Database Operations
app.get("/users", async (req, res, next) => { try { const users = await User.find().limit(20); res.json(users); } catch (error) { next(error); } });

Why async? Database operations involve I/O. Waiting synchronously would prevent the JavaScript thread from doing useful application work.

19. Database Errors

Common database problems include connection failure, timeout, duplicate key errors, validation errors, query errors and transaction failures.

app.use((err, req, res, next) => { console.error(err); res.status(500).json({ message: "Database operation failed" }); });
Production rule: Log useful technical details on the server, but do not expose database credentials, connection strings, stack traces or sensitive internal details to clients.

21. Common Developer Mistakes
  1. Opening a new DB connection for every request.
  2. Ignoring database connection failures during application startup.
  3. Not using await or otherwise handling async database operations correctly.
  4. Not catching rejected database promises.
  5. Building SQL using string concatenation with user input.
  6. Forgetting to release a pooled SQL connection.
  7. Returning raw database errors to clients.
  8. Putting passwords or database URLs directly in source code.
  9. Fetching far more rows/fields than the API needs.
  10. Using transactions without understanding which operations need atomic behavior.
  11. Assuming Mongoose validation replaces API validation.
  12. Using populate() everywhere without considering query cost.
22. Quick Recap
  • MongoDB is a document-oriented NoSQL database.
  • Mongoose is an ODM commonly used with MongoDB and Node.js.
  • A Mongoose schema defines structure and rules; a model provides the API for documents.
  • SQL databases such as MySQL and PostgreSQL use tables and SQL queries.
  • Use parameterized SQL queries instead of string concatenation.
  • Connection pools reuse a controlled number of SQL connections.
  • Database operations are usually asynchronous in Node.js.
  • Transactions group related operations into an atomic unit of work.
  • Handle connection, query and validation errors properly.
  • Keep secrets such as database credentials outside source code.
23. Interview-Ready Points ⭐⭐⭐
  • MongoDB vs Mongoose: MongoDB is the database; Mongoose is a Node.js ODM.
  • Schema vs Model: Schema describes structure/rules; model is used to work with documents.
  • Why connection pooling? Reuse connections and control database concurrency.
  • Why parameterized queries? Separate SQL structure from user input and reduce SQL injection risk.
  • Why async DB operations? Database I/O should not block the JavaScript execution thread.
  • Why transactions? Keep related operations consistent as one logical unit.
  • What is populate()? A Mongoose feature that resolves referenced documents.
  • What happens when DB connection fails? The application should have a deliberate startup/retry/failure strategy rather than silently serving broken requests.
