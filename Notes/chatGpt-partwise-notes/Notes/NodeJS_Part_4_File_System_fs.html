Node.js Interview Preparation • Part 4

🟢 File System (fs)

Learn how Node.js reads, writes, updates, deletes, and manages files and folders.

1. What is the File System (fs) module?
What?

The Node.js fs module provides APIs for working with files and directories on the computer's file system.

Why / purpose?
  • Read files.
  • Create and write files.
  • Append content.
  • Delete and rename files.
  • Create and inspect directories.
  • Read file information.
  • Work with streams, buffers, and file descriptors.
How to import?
const fs = require("fs");

With CommonJS you can use require(). In an ES module project:

import fs from "node:fs";
Node.js application ↓ fs module ↓ Operating system file system ↓ Files / folders / metadata
Layman example

Think of fs as a librarian who can open a book, write a note in it, rename it, move it, or tell you information about it.

Interview-ready: “The Node.js fs module provides APIs to interact with files and directories on the operating system.”
2. Reading Files
Asynchronous callback method
const fs = require("node:fs");

fs.readFile("notes.txt", "utf8", (err, data) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log(data);
});

"utf8" tells Node.js to return text rather than a raw Buffer.

Promise-based method
const fs = require("node:fs/promises");

async function readNotes() {
  try {
    const data = await fs.readFile("notes.txt", "utf8");
    console.log(data);
  } catch (err) {
    console.error(err);
  }
}

readNotes();
Synchronous method
const fs = require("node:fs");

const data = fs.readFileSync("notes.txt", "utf8");
console.log(data);
Common mistake: Using readFileSync() inside a high-traffic server request can block the JavaScript thread while the file operation completes.
3. Writing Files

writeFile() creates a file if needed and writes content to it. If the file already contains data, the normal behavior is to replace that content.

const fs = require("node:fs");

fs.writeFile("message.txt", "Hello Node.js", "utf8", (err) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log("File written");
});

Promise version:

const fs = require("node:fs/promises");

await fs.writeFile("message.txt", "Hello Node.js", "utf8");
Remember: writeFile() is different from appendFile(). Write normally replaces the existing file content; append adds content to the end.
4. Appending Files

Use appendFile() when you want to add content without replacing the existing content.

const fs = require("node:fs");

fs.appendFile("app.log", "User logged in\n", "utf8", (err) => {
  if (err) {
    console.error(err);
  }
});

Promise version:

const fs = require("node:fs/promises");

await fs.appendFile("app.log", "Another event\n", "utf8");
When to use?

Appending is useful for simple log files, audit text, or data that should be added to the end of an existing file.

5. Deleting Files

Use unlink() to remove a file.

const fs = require("node:fs");

fs.unlink("old.txt", (err) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log("File deleted");
});

Promise version:

const fs = require("node:fs/promises");

await fs.unlink("old.txt");
Common mistake: Always handle errors. The file may not exist, or the process may not have permission to remove it.
6. Renaming Files

Use rename() to rename or move a file.

const fs = require("node:fs");

fs.rename("old.txt", "new.txt", (err) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log("Renamed");
});

Promise version:

const fs = require("node:fs/promises");

await fs.rename("old.txt", "new.txt");
Interview-ready: “fs.rename can rename a file and can also be used to move a file when the destination path is different.”
7. Creating Directories

Use mkdir() to create a directory.

const fs = require("node:fs");

fs.mkdir("uploads", { recursive: true }, (err) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log("Directory ready");
});

recursive: true allows Node.js to create missing parent directories as needed.

const fs = require("node:fs/promises");

await fs.mkdir("uploads/images", { recursive: true });
When to use? Use recursive directory creation when your application cannot assume that parent folders already exist.
8. Reading Directories

Use readdir() to get entries inside a directory.

const fs = require("node:fs");

fs.readdir("uploads", (err, files) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log(files);
});

It can return names, or with options you can ask for directory entry objects.

const fs = require("node:fs/promises");

const entries = await fs.readdir("uploads", {
  withFileTypes: true
});

for (const entry of entries) {
  console.log(entry.name, entry.isDirectory());
}
9. File Statistics — stat()

stat() gives metadata about a file or directory.

const fs = require("node:fs/promises");

const info = await fs.stat("notes.txt");

console.log(info.size);
console.log(info.isFile());
console.log(info.isDirectory());
console.log(info.mtime);
Useful information
  • size — size in bytes.
  • mtime — last modification time.
  • isFile() — checks whether the path is a file.
  • isDirectory() — checks whether the path is a directory.
Interview tip: stat() reads metadata. It does not mean “read the entire file contents.”
10. Synchronous vs Asynchronous fs Methods
Synchronous
const data = fs.readFileSync("notes.txt", "utf8");
console.log(data);
console.log("Next");

The current JavaScript execution waits until the operation finishes.

Asynchronous callback
fs.readFile("notes.txt", "utf8", (err, data) => {
  if (err) return console.error(err);
  console.log(data);
});

console.log("Next");

The callback is called after the file operation completes. Other JavaScript work can continue while Node.js handles the I/O.

Promise-based
const fs = require("node:fs/promises");

async function main() {
  const data = await fs.readFile("notes.txt", "utf8");
  console.log(data);
}

main();

Promises provide a modern way to write asynchronous filesystem code, especially with async/await.

Synchronous JavaScript ↓ fs.readFileSync() ↓ WAIT ↓ Continue Async callback JavaScript ↓ start file I/O ↓ continue other work ↓ I/O completes ↓ callback runs Promise JavaScript ↓ start file I/O ↓ await / promise pending ↓ I/O completes ↓ promise resolves ↓ continuation runs

Strong interview answer: “Synchronous fs methods block the current JavaScript execution until the operation finishes. Callback-based methods are asynchronous and report completion through a callback. Promise-based methods are also asynchronous but return Promises, which work naturally with async/await.”
12. fs/promises

node:fs/promises exposes promise-based filesystem APIs.

const fs = require("node:fs/promises");

async function createFile() {
  try {
    await fs.writeFile("hello.txt", "Hello");
    const data = await fs.readFile("hello.txt", "utf8");
    console.log(data);
  } catch (error) {
    console.error(error);
  }
}

createFile();
Why use it?
  • Works naturally with async/await.
  • Avoids deeply nested callbacks.
  • Errors can be handled with try/catch around awaited operations.
Memory: fs contains callback and synchronous APIs; fs/promises provides promise-based APIs.
13. Error-First Callbacks

Many Node.js callback APIs follow the error-first callback pattern:

fs.readFile("notes.txt", "utf8", (err, data) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log(data);
});

The first callback parameter is normally the error. If the operation succeeds, it is usually null or undefined, and the result is passed in a later parameter.

(err, data) │ ├── err exists → handle error │ └── no error → use data
Common mistake: Ignoring err and immediately using data. File operations can fail for many reasons.
14. Encoding and Buffers
Without encoding
const fs = require("node:fs");

fs.readFile("photo.jpg", (err, data) => {
  if (err) throw err;

  console.log(Buffer.isBuffer(data)); // true
});

Without a text encoding, file content is commonly returned as a Buffer.

With UTF-8 encoding
fs.readFile("message.txt", "utf8", (err, data) => {
  if (err) throw err;

  console.log(typeof data); // string
});
What is a Buffer?

A Buffer represents raw binary data. It is useful for images, PDFs, videos, compressed data, and other non-text content.

File on disk ↓ raw bytes ↓ Buffer ↓ optional decoding ↓ string / application data
Interview-ready: “A Buffer is used to represent raw binary data in Node.js. When reading text, passing an encoding such as utf8 lets the API return a string.”
15. File Descriptors

A file descriptor is a small operating-system-level identifier for an open file or resource.

const fs = require("node:fs");

fs.open("notes.txt", "r", (err, fd) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log("File descriptor:", fd);

  fs.close(fd, (closeErr) => {
    if (closeErr) console.error(closeErr);
  });
});
Application ↓ fs.open() ↓ Operating system opens file ↓ file descriptor (fd) ↓ read / write operations ↓ fs.close(fd)
Common mistake: Forgetting to close manually opened file descriptors can waste OS resources.
16. Streams with Files

For large files, reading everything into memory at once may be inefficient. A readable stream can process data in chunks.

const fs = require("node:fs");

const stream = fs.createReadStream("large-video.mp4");

stream.on("data", (chunk) => {
  console.log("Received chunk:", chunk.length);
});

stream.on("end", () => {
  console.log("Finished");
});
Large file ████████████████████████ ↓ createReadStream() ↓ chunk → chunk → chunk → chunk ↓ process progressively ↓ end
When to use?

Streams are useful when working with large files or data that should be processed progressively instead of loading the entire content into memory.

Interview tip: For a large file, explain why a stream can reduce peak memory usage: the application processes chunks instead of holding the entire file in memory at once.
17. Writing with a Stream
const fs = require("node:fs");

const output = fs.createWriteStream("output.txt");

output.write("First line\n");
output.write("Second line\n");
output.end("Last line\n");

A writable stream accepts chunks of data over time.

Important: Streams are especially useful when data is large or arrives progressively, such as file uploads, downloads, or media processing.
18. Practical File Operations
const fs = require("node:fs/promises");

async function manageFile() {
  try {
    // Create / write
    await fs.writeFile("data.txt", "Hello");

    // Append
    await fs.appendFile("data.txt", "\nNode.js");

    // Read
    const content = await fs.readFile("data.txt", "utf8");
    console.log(content);

    // Metadata
    const stats = await fs.stat("data.txt");
    console.log(stats.size);

    // Rename
    await fs.rename("data.txt", "final.txt");

    // Delete
    await fs.unlink("final.txt");
  } catch (error) {
    console.error("File operation failed:", error);
  }
}

manageFile();
writeFile ↓ appendFile ↓ readFile ↓ stat ↓ rename ↓ unlink
19. Interview Output / Code Questions ⭐⭐⭐
Question 1
const fs = require("node:fs");

console.log("A");

fs.readFile("data.txt", "utf8", (err, data) => {
  console.log("B");
});

console.log("C");

Question: What is the likely order of A, B, and C if the read operation completes asynchronously?

Answer: A → C → B.

Why? readFile() starts the asynchronous file operation and its callback runs after the operation completes.

Question 2
const fs = require("node:fs");

console.log("A");

const data = fs.readFileSync("data.txt", "utf8");

console.log("B");

Question: Does B print before the file read finishes?

Answer: No.

Why? readFileSync() blocks the current JavaScript execution until the operation completes.

Question 3
const fs = require("node:fs");

fs.readFile("missing.txt", "utf8", (err, data) => {
  console.log(data);
});

Question: What is the developer mistake?

Answer: The callback does not check err.

Why? The file may not exist or may not be readable. In an error-first callback, the error must be checked before using the result.

Question 4
const fs = require("node:fs");

fs.readFile("image.png", (err, data) => {
  console.log(Buffer.isBuffer(data));
});

Question: What is the expected value when the read succeeds?

Answer: true.

Why? No text encoding was supplied, so file data is returned as a Buffer.

Question 5
const fs = require("node:fs/promises");

async function test() {
  const data = await fs.readFile("data.txt", "utf8");
  console.log(data);
}

Question: What does await wait for?

Answer: It waits for the Promise returned by readFile() to settle.

Why? The promise-based fs API returns a Promise, and await pauses the async function's continuation until that Promise settles. It does not block the whole Node.js process in the same way as readFileSync().

Question 6 — Interview favorite

Question: Which is better for a high-traffic Node.js server: readFileSync() or asynchronous readFile()?

Answer: Usually the asynchronous API.

Why? Synchronous filesystem operations block the current JavaScript execution. Asynchronous I/O lets Node.js continue handling other work while the operating system performs the I/O.

20. Common Developer Mistakes
  • Using synchronous file methods in performance-sensitive server request paths.
  • Forgetting to handle callback errors.
  • Forgetting try/catch around awaited Promise-based fs operations.
  • Using a text encoding for binary files when a Buffer is required.
  • Reading huge files completely into memory instead of considering streams.
  • Forgetting to close manually opened file descriptors.
  • Assuming writeFile() appends; it normally replaces file content.
  • Assuming readFile() is suitable for every file size.
  • Using relative paths without understanding the process working directory.
  • Not checking whether a directory exists before an operation when the code requires it.
  • Ignoring permissions and operating-system errors.
