Node.js Interview Preparation • Part 5

🟢 Path Module

Learn how Node.js safely creates, resolves, analyzes, and normalizes file and directory paths.

1. What is the Path Module?
What?

The Node.js path module provides utilities for working with file and directory paths.

Why / purpose?

Different operating systems use different path separators and path rules. The path module helps your Node.js code work with paths correctly without manually joining strings.

const path = require("node:path");
Layman example

Think of a path like a postal address. You need to combine the house number, street, city, and other parts in the correct format. The path module helps Node.js build that address correctly for the current operating system.

Application ↓ path module ↓ Build / resolve / inspect path ↓ File or directory location
Interview-ready: “The Node.js path module provides platform-specific utilities for manipulating file and directory paths.”
2. path.join()
What?

path.join() joins multiple path parts into one path and normalizes the result.

const path = require("node:path");

const result = path.join("users", "sainath", "documents", "file.txt");

console.log(result);

On Windows, the result uses Windows path rules. On Linux/macOS, it uses the platform's path rules.

Why?

It is safer and clearer than manually writing:

"users/" + "sainath/" + "documents/" + "file.txt"
Normalization
path.join("users", "sainath", "..", "file.txt");
// users/file.txt
Remember: join() mainly answers: “How do I combine these path pieces?”
3. path.resolve()
What?

path.resolve() processes path segments from right to left until it can form an absolute path.

const path = require("node:path");

const result = path.resolve("users", "sainath", "file.txt");

console.log(result);

If the supplied parts are relative, Node.js uses the current working directory as the starting point.

console.log(process.cwd());
console.log(path.resolve("data", "users.json"));
Layman example

join() is like putting address pieces together. resolve() is like asking: “What is the full address from where I am currently standing?”

Current working directory + relative path ↓ path.resolve() ↓ absolute path
Interview-ready: “path.resolve() produces an absolute path, normally using the current working directory when no absolute segment is supplied.”

Example
const path = require("node:path");

console.log(path.join("a", "b", "file.txt"));
console.log(path.resolve("a", "b", "file.txt"));

The first is a normalized path made from the supplied pieces. The second is an absolute path based on the current working directory.

Best interview answer: “join() combines path segments and normalizes them. resolve() resolves path segments into an absolute path. If the input is relative, resolve() uses the current working directory as part of that resolution.”
5. path.basename()

basename() returns the last part of a path, usually the file name.

const path = require("node:path");

const file = path.basename("/users/sainath/docs/resume.pdf");

console.log(file);
// resume.pdf
Remove extension
const name = path.basename("/docs/resume.pdf", ".pdf");

console.log(name);
// resume
When to use? Use it when you need the file name from a complete path.
6. path.dirname()

dirname() returns the directory portion of a path.

const path = require("node:path");

console.log(
  path.dirname("/users/sainath/docs/resume.pdf")
);

// /users/sainath/docs
/users/sainath/docs/resume.pdf │ ┌──────────┴──────────┐ ↓ ↓ dirname() basename() ↓ ↓ /users/sainath/docs resume.pdf
7. path.extname()

extname() returns the extension of the final part of a path.

console.log(path.extname("photo.jpg"));
// .jpg

console.log(path.extname("archive.tar.gz"));
// .gz

console.log(path.extname("README"));
// ""
Common mistake: extname("archive.tar.gz") returns only .gz, not .tar.gz.
8. path.parse()

parse() breaks a path into useful parts.

const result = path.parse("/users/sainath/resume.pdf");

console.log(result);

Conceptually, the result contains:

  • root
  • dir
  • base
  • ext
  • name
{
  root: "/",
  dir: "/users/sainath",
  base: "resume.pdf",
  ext: ".pdf",
  name: "resume"
}
Interview tip: Remember: parse() is useful when you need several path components at the same time.
9. path.format()

format() does roughly the reverse of parse(): it builds a path string from path components.

const result = path.format({
  dir: "/users/sainath",
  name: "resume",
  ext: ".pdf"
});

console.log(result);
// /users/sainath/resume.pdf
path.parse(path) ↓ path parts ↓ path.format(parts) ↓ path string
10. path.normalize()

normalize() cleans a path by resolving repeated separators and ./.. segments according to platform rules.

console.log(path.normalize("users//sainath/./docs/../file.txt"));
// users/sainath/file.txt
Why?

It turns a messy path into a normalized path representation.

Note: join() also normalizes the path after joining its arguments, so you often do not need to call normalize() separately.
11. path.isAbsolute()

isAbsolute() checks whether a path is absolute.

console.log(path.isAbsolute("/users/sainath/file.txt"));
// true

console.log(path.isAbsolute("./file.txt"));
// false
What is an absolute path?

It gives the complete location from the root or drive.

What is a relative path?

It describes a location relative to another location, commonly the current working directory.

12. __dirname + path

In CommonJS modules, __dirname points to the directory of the current module file.

const path = require("node:path");

const filePath = path.join(
  __dirname,
  "data",
  "users.json"
);

console.log(filePath);
Current JavaScript file ↓ __dirname ↓ path.join(__dirname, "data", "users.json") ↓ stable file path based on this module's directory
Interview-ready: “In CommonJS, __dirname represents the directory of the current module. Combining it with path.join() is a common way to create paths relative to the module file.”
Common mistake: Do not confuse __dirname with process.cwd(). __dirname is tied to the current CommonJS module; process.cwd() is the process's current working directory.
13. Relative vs Absolute Paths
RelativeAbsolute
./data/users.json/home/app/data/users.json
Depends on a starting locationContains the complete location
ShorterMore explicit
Relative path ./data/users.json ↓ starting location + relative path ↓ actual file location Absolute path /home/app/data/users.json ↓ complete location

For application code, build paths with path.join() or path.resolve() instead of hard-coding platform-specific separators.

14. Windows vs Linux Paths

Windows commonly uses a backslash separator, while Linux/macOS commonly use a forward slash separator.

// Windows example
C:\\Users\\Sainath\\project\\data.txt

// Linux/macOS example
/home/sainath/project/data.txt

Use the path module instead of manually assuming one separator.

const filePath = path.join("project", "data", "users.json");
Interview tip: If your Node.js application can run on different operating systems, avoid manually building paths with "/" or "\\" when path utilities can do the job.
15. Code-Based Interview Questions ⭐⭐⭐
Question 1 — join vs resolve
const path = require("node:path");

console.log(path.join("users", "admin", "file.txt"));
console.log(path.resolve("users", "admin", "file.txt"));

Question: What is the key difference?

Answer: join() combines and normalizes the path segments. resolve() produces an absolute path.

Why? resolve() uses the current working directory when it needs a starting point for relative input.

Question 2 — path lookup
const path = require("node:path");

const file = "/app/src/index.js";

console.log(path.basename(file));
console.log(path.dirname(file));
console.log(path.extname(file));

Answer: index.js, /app/src, .js.

Why? basename() gets the final component, dirname() gets the containing directory, and extname() gets the final extension.

Question 3 — normalize
const path = require("node:path");

console.log(
  path.normalize("app//src/./utils/../index.js")
);

Answer: A normalized equivalent of app/src/index.js on the usual POSIX-style path rules.

Why? The repeated separator is cleaned, . means the current directory, and .. moves one directory up.

Question 4 — parse
const path = require("node:path");

const result = path.parse("/app/server/index.js");

console.log(result.name);
console.log(result.ext);
console.log(result.base);

Answer: index, .js, index.js.

Why? parse() breaks the path into components, including name, extension, and base.

Question 5 — absolute or relative?
const path = require("node:path");

console.log(path.isAbsolute("./data/file.txt"));
console.log(path.isAbsolute("/app/data/file.txt"));

Answer: false, then true on POSIX-style systems.

Why? The first path starts with a relative marker. The second starts from the root.

Question 6 — __dirname vs cwd
console.log(__dirname);
console.log(process.cwd());

Question: Are these always the same?

Answer: No.

Why? __dirname refers to the current CommonJS module's directory, while process.cwd() returns the process's current working directory. The process can change its working directory, while the module's __dirname does not change with that.

Question 7 — path.format
const path = require("node:path");

const result = path.format({
  dir: "/app/files",
  name: "report",
  ext: ".pdf"
});

console.log(result);

Answer: /app/files/report.pdf.

Why? format() builds a path from its components.

Question 8 — Windows-safe code
const path = require("node:path");

const file = path.join("uploads", "images", "profile.png");

console.log(file);

Question: Why is this better than "uploads/images/profile.png" for cross-platform Node.js code?

Answer: path.join() uses the platform's path rules and separators.

Why? The same source code can construct paths correctly on supported operating systems without manually choosing slash characters.

16. Common Developer Mistakes
  • Confusing path.join() with path.resolve().
  • Assuming join() always returns an absolute path.
  • Assuming resolve() simply concatenates strings.
  • Using process.cwd() when the intention is a path relative to the current CommonJS module.
  • Manually concatenating paths with "/" or "\\".
  • Forgetting that extname("archive.tar.gz") returns .gz.
  • Using a relative path without understanding what directory it is relative to.
  • Assuming Windows and Linux use exactly the same path syntax.
  • Using normalize() as a security solution. Path normalization alone does not make untrusted file paths safe.
  • Hard-coding machine-specific absolute paths into portable applications.
