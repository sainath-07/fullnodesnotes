Learn how to prepare, deploy, protect, monitor and scale a Node.js + Express application in production.

1. What Does “Production” Mean?

What: Production is the real environment where users access your application.

Purpose: Production code must handle real traffic, failures, security risks, configuration differences and operational problems.

Layman example: A practice restaurant kitchen can tolerate mistakes. A busy restaurant serving customers needs safety rules, staff processes, backups and reliable equipment. Production software needs the same kind of discipline.

Interview line: Production readiness is more than “the server works”; it includes configuration, security, reliability, observability, graceful failure and deployment practices.
2. Environment Configuration

Environment configuration means keeping settings outside application code when they can change between environments.

PORT=5000 DATABASE_URL=... JWT_SECRET=... NODE_ENV=production

Typical configuration includes database URLs, ports, API keys, secrets, feature flags and external service settings.

Why: The same application code can run in development, testing and production with different configuration values.
Security: Do not commit real secrets into Git. Protect production credentials and provide only the environment variables a process actually needs.

4. NODE_ENV

NODE_ENV is a commonly used environment variable for describing the application environment.

if (process.env.NODE_ENV === "production") { console.log("Production configuration"); }

When to use: Use it when application behavior or configuration should differ by environment.

Common mistake: Do not treat NODE_ENV as a replacement for all configuration. Use specific environment variables for actual settings such as database URLs and secrets.

6. PM2

PM2 is a process manager commonly used with Node.js applications.

npm install pm2 -g pm2 start server.js --name my-api pm2 status pm2 logs pm2 restart my-api pm2 stop my-api

Why: PM2 can keep applications running, restart processes after failures and manage multiple instances.

Interview point: PM2 is a process manager; it is not the same thing as a reverse proxy or load balancer.
7. Graceful Shutdown ⭐⭐⭐

Graceful shutdown means stopping a server in an orderly way instead of immediately killing it.

Shutdown signal
→
Stop accepting new work
→
Finish active work
→
Close DB / resources
→
Exit

Why: It reduces the chance of dropped requests, unfinished operations or unclosed connections.

8. SIGTERM and SIGINT

Node.js processes can receive operating-system signals.

  • SIGTERM: commonly used to request a process to terminate gracefully, especially in deployment/container environments.
  • SIGINT: commonly generated by an interrupt such as pressing Ctrl+C in a terminal.
const server = app.listen(PORT); async function shutdown(signal) { console.log(`${signal} received`); server.close(async () => { await mongoose.connection.close(); process.exit(0); }); } process.on("SIGTERM", () => shutdown("SIGTERM")); process.on("SIGINT", () => shutdown("SIGINT"));
Common mistake: Calling process.exit() immediately can terminate the process before active work and cleanup have finished.

11. Nginx Concept

Nginx is commonly used as a web server and reverse proxy in front of Node.js applications.

Client | v Nginx :443 | +----> Node.js :5000

Why: Nginx can accept public traffic while the Node.js application stays behind it on an internal network or port.

13. Production Logging

Production logs should be structured, searchable and safe.

{ "level": "error", "service": "orders-api", "requestId": "req-42", "route": "/api/orders", "statusCode": 500, "message": "Database unavailable" }
  • Use appropriate log levels.
  • Include request/correlation IDs.
  • Log useful context.
  • Do not log secrets or passwords.
  • Use centralized log collection when needed.

18. Production Security
  • Use HTTPS.
  • Validate and sanitize input.
  • Use secure authentication and authorization.
  • Protect secrets.
  • Use secure cookie attributes where cookies are used.
  • Apply rate limiting where appropriate.
  • Configure CORS deliberately.
  • Use security headers.
  • Limit request sizes.
  • Do not expose stack traces or secrets to clients.
  • Keep dependencies updated.

21. Common Developer Mistakes
  1. Hard-coding production secrets inside source code.
  2. Using development error responses in production.
  3. Calling process.exit() before cleanup is complete.
  4. Ignoring SIGTERM during container or process shutdown.
  5. Running an API without useful health checks.
  6. Logging passwords, tokens or secret keys.
  7. Using a cache without invalidation rules.
  8. Assuming one Node.js process is enough for every traffic level.
  9. Keeping application state only in local process memory when horizontally scaling.
  10. Skipping monitoring because the application “works on my machine.”
  11. Exposing Node.js directly to the public internet when the architecture requires a reverse proxy.
  12. Deploying without a rollback plan.
