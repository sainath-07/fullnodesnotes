🟢 Part 22 — File Uploads ⭐⭐⭐

Learn how files move from a browser to a Node.js + Express server using multipart/form-data and Multer.

1. What is a File Upload?

What: A file upload means sending a file from the client, such as a browser, to a server.

Why: Applications need uploads for profile photos, product images, PDFs, resumes and documents.

Layman example: When you select a profile photo and click “Upload”, the browser sends that photo to the server. The server receives it, validates it, and stores it.

Interview line: File uploads are usually sent as multipart/form-data, and Multer is commonly used with Express to parse multipart requests.
2. multipart/form-data

What: multipart/form-data is an HTTP request format designed to send files and normal form fields together.

How: The request is divided into separate parts. A part can contain text such as username or binary file data such as an image.

<form action="/upload" method="POST" enctype="multipart/form-data"> <input type="text" name="username"> <input type="file" name="avatar"> <button type="submit">Upload</button> </form>
Common mistake: Using application/json for a normal file upload. JSON is not the usual format for sending raw files through a browser form.
3. What is Multer?

What: Multer is Express middleware used to handle multipart/form-data requests.

Purpose: It reads the uploaded file and makes useful information available through objects such as req.file or req.files.

const express = require("express"); const multer = require("multer"); const app = express(); const upload = multer({ dest: "uploads/" }); app.post("/upload", upload.single("avatar"), (req, res) => { console.log(req.file); res.json({ message: "Uploaded successfully" }); });
Important: The field name in upload.single("avatar") must match the form field's name="avatar".
4. req.file vs req.files
MiddlewareResultUse case
upload.single("avatar")req.fileOne file
upload.array("photos", 5)req.filesMany files using one field
upload.fields([...])req.files as an objectDifferent file fields

Why? Multer chooses the output structure based on how the upload middleware is configured.

5. Single File Upload

Use single() when the request should contain one file for a particular field.

const upload = multer({ dest: "uploads/" }); app.post("/profile", upload.single("profileImage"), (req, res) => { console.log(req.file); res.json({ file: req.file.filename }); } );

When to use: Profile picture, resume, one product image, one document.

6. Multiple File Upload
app.post("/gallery", upload.array("photos", 5), (req, res) => { console.log(req.files); res.json({ count: req.files.length }); } );

5 is the maximum number of files accepted by this middleware configuration.

Do not trust the client: Even if the UI says “maximum 5 files”, enforce the limit on the server.
7. File Size Limits

Why: Large uploads can consume disk, memory, CPU and network resources.

const upload = multer({ dest: "uploads/", limits: { fileSize: 2 * 1024 * 1024 // 2 MB } });

Interview point: Upload limits are a resource-protection measure. Always validate on the server.

8. File Type Validation

Do not accept a file only because its filename ends with .jpg. The server should validate what it is willing to accept.

const upload = multer({ storage, fileFilter: (req, file, cb) => { const allowed = ["image/jpeg", "image/png", "image/webp"]; if (allowed.includes(file.mimetype)) { cb(null, true); } else { cb(new Error("Only image files are allowed")); } } });
Security note: MIME type checks are useful, but for high-security upload systems, inspect file content/signatures too and consider malware scanning. Never rely only on the original filename.
9. Storage Configuration

Multer can store uploaded files on disk or temporarily keep them in memory.

Disk storage
const storage = multer.diskStorage({ destination: (req, file, cb) => { cb(null, "uploads/"); }, filename: (req, file, cb) => { cb(null, Date.now() + "-" + file.originalname); } }); const upload = multer({ storage });
Memory storage
const upload = multer({ storage: multer.memoryStorage() }); app.post("/upload", upload.single("file"), (req, res) => { console.log(req.file.buffer); res.send("Received in memory"); });
Disk storageFile is written to disk.Useful for local file processing/storage.
Memory storageFile data is held in req.file.buffer.Useful when passing data directly to another service, but large files can consume RAM.
10. File Information

A Multer file object can contain information such as the original field name, original filename, MIME type, size and storage information. The exact properties depend on the storage engine.

console.log(req.file.fieldname); console.log(req.file.originalname); console.log(req.file.mimetype); console.log(req.file.size); console.log(req.file.filename);
Important: originalname comes from the client. Do not blindly use it as a trusted server filename.
11. File Names

Why generate server-side names? User filenames may contain spaces, duplicate names or unsafe characters. A generated unique name reduces collisions and avoids trusting client input.

const crypto = require("crypto"); const filename = crypto.randomUUID() + ".jpg";

In a real application, preserve a safe extension only after validating the file type. Store the original filename separately if the UI needs to display it.

13. File Deletion

When a database record is deleted, the physical file may also need to be deleted. Otherwise, unused files can accumulate.

const fs = require("fs/promises"); await fs.unlink("uploads/example.jpg");
Common mistake: Delete the database record but forget the physical/cloud file. This can create storage leaks.
14. Upload Errors

Multer can reject uploads because of file size, file count, field configuration or filtering rules. Handle upload errors centrally or close to the route.

const multer = require("multer"); app.post("/upload", upload.single("avatar"), (req, res) => { res.json({ message: "Uploaded" }); }); app.use((err, req, res, next) => { if (err instanceof multer.MulterError) { return res.status(400).json({ message: "File upload failed", code: err.code }); } next(err); });
15. Cloud Storage Concept

For production systems, files are often stored in object storage rather than the application's local disk.

The database normally stores metadata such as an object key or URL, while the actual file is stored separately.

Interview line: Keep large binary files in object storage and keep file metadata/reference information in the database.
16. Complete Interview-Style Upload Example
const express = require("express"); const multer = require("multer"); const app = express(); const upload = multer({ dest: "uploads/", limits: { fileSize: 2 * 1024 * 1024 }, fileFilter: (req, file, cb) => { const allowed = ["image/jpeg", "image/png"]; if (allowed.includes(file.mimetype)) { cb(null, true); } else { cb(new Error("Only JPG and PNG files are allowed")); } } }); app.post("/avatar", upload.single("avatar"), (req, res) => { if (!req.file) { return res.status(400).json({ message: "Avatar is required" }); } res.status(201).json({ message: "Avatar uploaded", filename: req.file.filename, size: req.file.size }); }); app.use((err, req, res, next) => { res.status(400).json({ message: err.message || "Upload failed" }); }); app.listen(3000);
17. Common Developer Mistakes
  1. Forgetting enctype="multipart/form-data" in an HTML form.
  2. Using a field name that does not match upload.single().
  3. Accepting unlimited file sizes.
  4. Trusting the original filename.
  5. Checking only the filename extension.
  6. Using memory storage for very large files without considering RAM.
  7. Storing files locally in a multi-server production environment without a shared strategy.
  8. Forgetting to delete old files.
  9. Returning internal filesystem paths to clients.
  10. Not handling Multer errors.
18. Quick Recap
  • multipart/form-data is used to send files through HTTP forms.
  • Multer parses multipart requests in Express.
  • single() gives one uploaded file through req.file.
  • array() gives multiple files through req.files.
  • Use file-size limits to protect resources.
  • Validate file type and, for stronger security, inspect file content.
  • Disk storage writes files to disk; memory storage keeps file data in RAM.
  • Use safe server-generated filenames.
  • Production systems often use cloud/object storage.
  • Handle upload errors explicitly.
19. Interview-Ready Points ⭐⭐⭐
  • What is Multer? Express middleware for handling multipart/form-data uploads.
  • req.file vs req.files? Depends on the Multer upload method and whether one or multiple files are expected.
  • Why multipart/form-data? It supports files and normal form fields in the same request.
  • Disk vs memory storage? Disk stores files on disk; memory keeps them in RAM.
  • Why file limits? To reduce resource-exhaustion risk.
  • Why validate file type? To accept only intended file types and reduce security risk.
  • Why avoid original filenames? They are client-controlled and may collide or contain unsafe characters.
  • Cloud storage? Store binary files in object storage and keep metadata/reference in the database.
