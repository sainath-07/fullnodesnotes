Before You Answer: Mental Model
  • Call stack: runs JavaScript code currently being executed.
  • Event loop: helps Node.js schedule asynchronous callbacks.
  • nextTick: Node-specific queue with very high priority.
  • Promise microtasks: run after the current synchronous work and according to Node's scheduling rules.
  • Timers: become eligible after their delay; the delay is not a guaranteed execution time.
  • Streams: process data in chunks and can control memory through backpressure.
  • Workers: useful for CPU-heavy JavaScript work.
  • Cluster: uses multiple Node.js processes, giving process isolation.
Quick Recap
  • Do not confuse process.nextTick() with browser-style microtasks.
  • setTimeout(fn, 0) does not mean “run immediately.”
  • setImmediate() and timers can have different ordering depending on context.
  • Backpressure prevents a fast producer from overwhelming a slower consumer.
  • EventEmitter listeners run synchronously when an event is emitted.
  • Promises provide concurrency tools such as all, allSettled, race, and any.
  • Worker threads handle CPU-heavy JavaScript without blocking the main event loop.
  • Cluster creates separate Node.js processes.
  • Middleware order matters because Express processes middleware in registration order.
  • Graceful shutdown means stopping new work, finishing important work, closing resources, and then exiting.
Interview-Ready Speaking Points
Strong answer style: “First I identify synchronous code. Then I identify which queue or phase receives each asynchronous callback. Finally I explain when the event loop gets a chance to execute it.”
  • “Node.js is single-threaded for normal JavaScript execution, but it can use the OS and other threads for asynchronous work.”
  • “Backpressure is a flow-control mechanism that prevents a producer from sending data faster than the consumer can handle.”
  • “EventEmitter is synchronous by default: listeners execute during the emit() call.”
  • “Worker threads are for CPU-intensive JavaScript; ordinary I/O usually does not need a worker.”
  • “Cluster gives multiple processes, while worker threads give multiple threads inside a process.”
  • “Express middleware is order-dependent.”
  • “Graceful shutdown protects in-flight requests and closes resources instead of killing the process immediately.”
Common Developer Mistakes
  1. Assuming a timer delay is an exact execution time.
  2. Using CPU-heavy loops on the main thread and blocking every request.
  3. Calling process.nextTick() recursively and starving the event loop.
  4. Ignoring stream backpressure.
  5. Adding EventEmitter listeners repeatedly without removing them.
  6. Using Promise.all() when partial success is required.
  7. Starting a worker for simple I/O work and adding unnecessary complexity.
  8. Assuming cluster shares all memory between workers.
  9. Registering a broad Express route or middleware before a more specific route.
  10. Returning detailed internal errors to production clients.
  11. Exiting immediately on SIGTERM instead of performing graceful shutdown.
