Node.js Interview Preparation • Part 3

🟢 npm & package.json

Learn how Node.js projects install packages, track dependencies, run scripts, and reproduce the same dependency setup.

1. What is npm?
What?

npm stands for Node Package Manager. It is the standard package manager commonly used with Node.js. It helps developers install, remove, update, and manage JavaScript packages.

Why / purpose?
  • Install third-party packages.
  • Track project dependencies.
  • Run project commands through scripts.
  • Share project dependency information with other developers.
Layman example

Imagine building a house. You could make every tool yourself, or you could buy ready-made tools. npm is like the store and delivery system for reusable software packages.

Your Project ↓ npm ↓ Package Registry ↓ Download package ↓ node_modules ↓ Your application uses the package
Interview-ready: “npm is the package manager used in the Node.js ecosystem to install and manage packages, dependencies, scripts, and project metadata.”
2. npm init
What?

npm init creates a new Node.js project configuration by generating a package.json file.

npm init

npm asks questions such as the project name, version, description, entry point, and license.

For the default answers:

npm init -y
npm init ↓ Ask project questions ↓ Create package.json ↓ Project has npm metadata
When to use?

Use it when starting a new Node.js project that needs npm package management.

Common shortcut: npm init -y creates the file using default values instead of asking each question.
3. package.json
What?

package.json is the main configuration file for an npm project.

{
  "name": "my-app",
  "version": "1.0.0",
  "scripts": {
    "start": "node app.js"
  },
  "dependencies": {
    "express": "^5.1.0"
  },
  "devDependencies": {
    "nodemon": "^3.1.10"
  }
}
What can it contain?
  • Project name and version
  • Description
  • Entry point
  • Scripts
  • Dependencies
  • Development dependencies
  • Module configuration
  • Other package metadata
Think of it as: the project's instruction and metadata file. It describes what the project needs and how common project commands should run.
4. package-lock.json
What?

package-lock.json records the exact dependency tree that npm resolved for the project, including package versions and dependency information.

Why?

It helps different developers or environments install the same resolved dependency versions.

package.json ↓ Allowed dependency ranges ↓ npm resolves packages ↓ package-lock.json ↓ Exact resolved dependency tree
Important: package.json describes the dependencies your project requests. package-lock.json records the resolved dependency tree that npm selected.

Best interview answer: “package.json declares the project's dependencies and configuration. package-lock.json records the exact dependency resolution, including the dependency tree, so installations can be reproduced more consistently.”
6. Dependencies
What?

Dependencies are packages required by the application at runtime.

npm install express

This normally adds Express to the dependencies section of package.json.

"dependencies": {
  "express": "^5.1.0"
}
Layman example

If your application needs a calculator to work, the calculator is part of the application's normal equipment. Runtime dependencies are similar.

Interview-ready: “A dependency is a package required by the application to perform its normal runtime work.”
7. Dev Dependencies
What?

Dev dependencies are packages mainly needed while developing, testing, linting, formatting, or building the application.

npm install --save-dev nodemon

This places the package in devDependencies.

"devDependencies": {
  "nodemon": "^3.1.10"
}
Examples
  • Testing tools
  • Linters
  • Formatters
  • Development servers
  • Build tools
Common mistake: Do not decide only from package popularity. Ask whether the application needs the package during production runtime or only during development/build/test work.
8. npm install
Install a package
npm install express

npm downloads the package and its required dependencies, updates project metadata, and normally updates the lockfile.

Install everything listed in the project
npm install
npm install express ↓ Read package information ↓ Resolve dependency versions ↓ Download packages ↓ node_modules ↓ Update package.json / lockfile
Remember: Running npm install without a package name is commonly used after cloning a project to install its declared dependencies.
9. npm uninstall

npm uninstall removes a package from the project.

npm uninstall express

npm removes the package from node_modules and updates the project's package metadata and lockfile as appropriate.

Interview tip: Know that uninstalling a package is more than deleting its folder manually. npm also updates the dependency records.
10. npm update

npm update updates installed packages within the version ranges allowed by the project configuration and npm's resolution rules.

npm update

You can also target a package:

npm update express
Important: npm update is not the same as blindly moving every package to its newest major version. Version ranges and lockfile state matter.
11. npm ci
What?

npm ci is designed for clean, reproducible dependency installation, especially in CI/CD environments.

npm ci
Important behavior
  • Requires a lockfile such as package-lock.json.
  • Performs a clean installation.
  • Removes an existing node_modules before installing.
  • Uses the lockfile's resolved dependency information.
  • Does not use the command as a way to update your dependency ranges.
package.json + package-lock.json ↓ npm ci ↓ Clean node_modules ↓ Install locked dependency tree ↓ Reproducible build
Interview-ready: “npm install is flexible and can update the lockfile as dependencies are resolved. npm ci is intended for clean, reproducible installs from the lockfile and is commonly used in CI/CD.”
12. npm install vs npm ci ⭐⭐⭐
Pointnpm installnpm ci
Main purposeInstall/update project dependenciesClean, reproducible installation

node_modulesDoes not normally start by deleting itRemoves existing node_modules before installing

Strong interview answer: “Use npm install during normal dependency management and development. Use npm ci when you want a clean installation based on the committed lockfile, especially in CI/CD.”
13. npm start

npm start runs the start script from package.json.

{
  "scripts": {
    "start": "node app.js"
  }
}
npm start

npm finds the start script and executes node app.js.

npm start ↓ package.json ↓ scripts.start ↓ node app.js ↓ Application starts
Common mistake: npm start is not a magical Node.js command. It is npm running the project's start script.
14. npm Scripts

The scripts section defines reusable project commands.

{
  "scripts": {
    "start": "node app.js",
    "dev": "nodemon app.js",
    "test": "jest",
    "build": "webpack"
  }
}

Run a script:

npm run dev
npm run test
npm run build

The special start script can be run with npm start.

Why? Scripts give a team one standard command instead of asking every developer to remember long commands.
15. Semantic Versioning

Semantic Versioning, commonly written as SemVer, uses:

MAJOR . MINOR . PATCH 2 . 5 . 3
  • MAJOR — incompatible/breaking changes.
  • MINOR — backward-compatible features.
  • PATCH — backward-compatible bug fixes.
2.5.3
↑ ↑ ↑
│ │ └── patch
│ └──── minor
└────── major
Interview-ready: “SemVer communicates the kind of change through major, minor, and patch version numbers.”
16. ^ Caret Version

The caret allows npm to select newer compatible versions according to npm's semver rules, generally allowing minor and patch updates for a typical non-zero major version.

"express": "^5.1.0"

Conceptually, this means the project is allowing compatible releases in the 5.x line according to the range.

Important: Do not memorize “caret always means any minor update” without considering special SemVer cases such as 0.x versions.
17. ~ Tilde Version

The tilde is commonly used to allow patch-level updates within a minor version.

"express": "~5.1.0"

Conceptually, this keeps the dependency within the 5.1.x line according to the semver range.

Quick memory: ^ usually allows a wider compatible range; ~ usually allows a narrower patch range for normal non-zero versions.
18. Exact Versions

An exact version does not use a range operator.

"express": "5.1.0"

This declares exactly version 5.1.0 rather than a range in package.json.

"5.1.0" ↓ Exact version "~5.1.0" ↓ Patch range "^5.1.0" ↓ Compatible range according to SemVer rules
Interview tip: Be careful when saying “exact version.” package.json and package-lock.json have different roles. The lockfile still records the resolved dependency tree.
19. Global Packages

A global package is installed for use from the command line rather than as a normal dependency of one project.

npm install -g package-name

Global packages can be useful for command-line tools, but application dependencies should normally be installed locally in the project.

Common mistake: Installing an application's runtime dependency globally. Another developer or a deployment server may not have that global package.
20. npx
What?

npx is a command runner that comes with npm. It can run package-provided command-line tools, often using a locally installed package when available.

npx create-vite my-app

Another common pattern:

npx eslint .
npx command ↓ Find suitable package executable ↓ Run the CLI ↓ Command finishes
Layman example: npm is like getting a tool installed; npx is like saying “use this tool now” without manually typing its full executable path.
Interview-ready: “npx is used to execute package binaries, commonly allowing project-local CLI tools to be run without installing them globally.”
21. node_modules

node_modules is the directory where npm installs the project's packages and their dependencies.

package.json + package-lock.json ↓ npm ↓ node_modules/ ├── express/ ├── axios/ ├── dependency-a/ └── dependency-b/
Should you commit it to Git?

For normal Node.js projects, node_modules is usually excluded from Git using .gitignore. The project can recreate it from the package metadata and lockfile.

Common mistake: Committing node_modules can make repositories huge and unnecessary because dependencies can be installed again.
22. Dependency Tree

A dependency tree shows not only the packages your application directly uses, but also packages those packages depend on.

Your App │ ├── express │ ├── package-A │ └── package-B │ └── package-C │ └── axios └── package-D

Your app's direct dependencies are sometimes called direct dependencies. Packages installed because another package needs them are transitive dependencies.

Why this matters: A package can bring many other packages into your project. This is why lockfiles and dependency management are important.
23. npm install vs npm ci — Interview Deep Dive ⭐⭐⭐
Scenario

Your team commits both package.json and package-lock.json. A CI server starts from a clean environment. Which command is usually better?

Answer: npm ci.

Why? CI should install the dependency tree represented by the lockfile in a clean, predictable way. npm ci is designed for this use case.

# CI pipeline
npm ci
npm test
npm run build
One-line answer: “npm install is generally for normal dependency installation and management; npm ci is for clean, reproducible installs from the lockfile, especially in CI/CD.”
24. Output / Practical Interview Questions
Question 1 — package.json script
{
  "scripts": {
    "start": "node server.js"
  }
}

What does npm start execute?

Answer: node server.js.

Why? npm maps npm start to the project's scripts.start command.

Question 2 — dependency type

You install a package used only for automated tests. Where should it normally go?

npm install --save-dev test-package

Answer: devDependencies.

Why? The package is needed for development/testing rather than the application's normal runtime.

Question 3 — version range
"library": "~2.4.1"

What kind of updates does this range commonly permit for a normal non-zero version?

Answer: Patch updates within the 2.4.x line.

Why? Tilde generally allows patch-level changes within the specified minor version.

Question 4 — node_modules

Why can a team remove node_modules and recreate it?

Answer: Because npm can install the dependency tree from the project's package metadata and lockfile.

Why? node_modules is generated installation output, not normally the source of truth for the project.

Question 5 — CI environment

A CI server has package.json and package-lock.json. Which is generally preferred?

Answer: npm ci.

Why? It is designed for clean, reproducible dependency installation using the lockfile.

25. Common Developer Mistakes
  • Deleting package-lock.json unnecessarily when troubleshooting.
  • Committing node_modules to Git.
  • Installing project dependencies globally.
  • Using npm install in CI when the pipeline specifically needs a clean lockfile-based install.
  • Not committing the lockfile for an application where reproducible installs are important.
  • Thinking package.json always contains the exact version of every transitive dependency.
  • Confusing dependencies with devDependencies.
  • Thinking ^ and ~ mean exactly the same thing.
  • Assuming npm start is built into Node.js rather than an npm script convention.
  • Running a CLI globally when npx or a project-local installation is more appropriate.
  • Forgetting that a dependency can bring many transitive dependencies.
