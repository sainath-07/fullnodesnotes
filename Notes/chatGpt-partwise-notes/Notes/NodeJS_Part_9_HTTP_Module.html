Node.js Interview Preparation • Part 9

🟢 HTTP Module

Learn how Node.js creates HTTP servers, receives requests, sends responses, handles routes, reads request bodies, and builds simple APIs.

1. What is HTTP?

HTTP stands for HyperText Transfer Protocol. It is a set of rules used for communication between clients and servers.

Layman example

Think of a restaurant. You are the customer, the waiter carries your request to the kitchen, and the kitchen sends the result back.

Client / Browser │ │ HTTP Request ↓ Node.js Server │ │ HTTP Response ↓ Client / Browser
Interview-ready: “HTTP is a request-response protocol. A client sends a request to a server, and the server sends a response.”
2. Node.js HTTP Module

Node.js provides a built-in http module for creating HTTP servers and handling HTTP requests and responses.

const http = require("node:http");

const server = http.createServer((req, res) => {
  res.end("Hello from Node.js");
});

server.listen(3000);

No npm package is required because http is a built-in Node.js module.

When to use: Use the built-in HTTP module when you want to understand or build HTTP behavior directly. Frameworks such as Express build higher-level features on top of Node's HTTP capabilities.
3. http.createServer()

http.createServer() creates an HTTP server and accepts a request listener function.

const http = require("node:http");

const server = http.createServer((req, res) => {
  console.log("Request received");
  res.end("OK");
});

server.listen(3000, () => {
  console.log("Server running on port 3000");
});
Browser sends request ↓ createServer listener ↓ (req, res) ↙ ↘ req res request response data methods ↓ res.end() ↓ Response sent

5. Response Object (res)

The res object is used to build and send the server's response.

Method / PropertyPurpose
res.statusCodeSets the HTTP status code.
res.setHeader()Sets a response header.
res.write()Writes response data.
res.end()Finishes the response.
 
res.statusCode = 200;
res.setHeader("Content-Type", "text/plain");
res.write("Hello ");
res.end("World");
Common mistake: Forgetting res.end() can leave the response unfinished.
6. Request / Response Lifecycle ⭐⭐⭐
1. Browser / Client ↓ 2. Creates HTTP request ↓ 3. Network sends request ↓ 4. Node.js HTTP server receives it ↓ 5. createServer callback runs ↓ 6. Node reads req.url / req.method / req.headers ↓ 7. Application chooses route + logic ↓ 8. Server sets status / headers ↓ 9. Server writes response ↓ 10. res.end() ↓ 11. HTTP response reaches client ↓ 12. Client processes response
Top interview answer: “The client sends an HTTP request. Node's HTTP server receives it and invokes the request listener with req and res. The server reads request information, performs application logic, sets the response status and headers, writes data if needed, and finishes with res.end().”
7. res.statusCode and res.setHeader()
const http = require("node:http");

http.createServer((req, res) => {
  res.statusCode = 200;
  res.setHeader("Content-Type", "application/json");

  res.end(JSON.stringify({
    message: "Success"
  }));
}).listen(3000);

The status code tells the client the result category. Headers provide additional information about the response.

Important: Set headers before the response headers are sent. Once the response has started, changing certain headers is too late.
8. res.write() vs res.end()
res.write("Part 1");
res.write("Part 2");
res.end("Final part");
res.write("Part 1") ↓ res.write("Part 2") ↓ res.end("Final part") ↓ Response complete

write() can send data without finishing the response. end() finishes the response and can optionally send final data.

10. Manual Routing

With the built-in HTTP module, you can manually check the method and URL.

const http = require("node:http");

const server = http.createServer((req, res) => {
  if (req.method === "GET" && req.url === "/users") {
    res.statusCode = 200;
    res.end("Users");
    return;
  }

  if (req.method === "GET" && req.url === "/products") {
    res.statusCode = 200;
    res.end("Products");
    return;
  }

  res.statusCode = 404;
  res.end("Not Found");
});

server.listen(3000);
Request ↓ method + URL ↓ /users? ── yes → Users │ no ↓ /products? ── yes → Products │ no ↓ 404 Not Found
Interview point: Manual routing works, but as an application grows it becomes difficult to maintain. Frameworks provide routing abstractions and middleware.
11. Query Strings and URL

For a URL such as /products?category=mobile&page=2, the path is /products and the query string contains category=mobile&page=2.

const { URL } = require("node:url");

const url = new URL(
  req.url,
  "http://localhost:3000"
);

console.log(url.pathname);
console.log(url.searchParams.get("category"));
console.log(url.searchParams.get("page"));
/products?category=mobile&page=2 │ ├── pathname → /products └── searchParams ├── category → mobile └── page → 2
12. Request Body

POST, PUT, and PATCH requests often carry data in the request body. In Node's HTTP module, the request is a stream, so the body may arrive in multiple chunks.

let body = "";

req.on("data", chunk => {
  body += chunk;
});

req.on("end", () => {
  console.log(body);
});
Common mistake: Do not assume the entire request body is available immediately in the first data event.
13. JSON Request Body
let body = "";

req.on("data", chunk => {
  body += chunk;
});

req.on("end", () => {
  try {
    const data = JSON.parse(body);

    res.setHeader("Content-Type", "application/json");
    res.end(JSON.stringify({
      received: data
    }));
  } catch (error) {
    res.statusCode = 400;
    res.end("Invalid JSON");
  }
});

The client commonly sends a header such as Content-Type: application/json. The server reads the body as text and uses JSON.parse() to convert it into a JavaScript value.

15. REST API vs RESTful API

REST is an architectural style for designing networked APIs. A RESTful API is an API that follows REST principles reasonably closely.

Client ↓ HTTP method + resource URL ↓ REST-style API ↓ Resource operation ↓ HTTP response

Example resource endpoints:

GET    /users
GET    /users/10
POST   /users
PATCH  /users/10
DELETE /users/10
Interview wording: “REST is the architectural style; RESTful describes an API that follows REST principles.”
16. HTTP vs HTTPS
HTTPHTTPS
HTTP communication is not encrypted by TLS.HTTP is protected by TLS.
Data can be exposed if intercepted.TLS helps protect data in transit.
Uses the HTTP protocol directly.HTTP runs over a TLS-secured connection.
HTTP: Client ───────── Server HTTPS: Client │ │ encrypted TLS connection ↓ Server

HTTPS helps provide confidentiality and server authentication and protects the integrity of data in transit.

17. Node.js https Module

Node.js also provides a built-in https module for creating HTTPS servers. HTTPS requires TLS configuration such as a certificate and private key.

const https = require("node:https");
const fs = require("node:fs");

const options = {
  key: fs.readFileSync("private-key.pem"),
  cert: fs.readFileSync("certificate.pem")
};

https.createServer(options, (req, res) => {
  res.end("Secure server");
}).listen(443);
Note: In real production systems, HTTPS is often terminated at a reverse proxy/load balancer rather than directly inside the Node.js application.
18. Common Developer Mistakes
  • Forgetting res.end().
  • Calling res.end() and then trying to write more response data.
  • Trying to change response headers after the response has started.
  • Assuming a request body arrives in one chunk.
  • Calling JSON.parse() without handling invalid JSON.
  • Returning the wrong HTTP status code.
  • Ignoring request method and treating every request the same way.
  • Manually parsing query strings when URL/URLSearchParams is safer and clearer.
  • Confusing HTTP with HTTPS.
  • Calling every API “RESTful” without understanding resource-oriented design.
  • Putting a large amount of application routing logic directly inside one createServer() callback.
19. Interview Questions — Click to Show / Hide Answer + Why ⭐⭐⭐
Q1. What is the request/response lifecycle in Node.js HTTP?
Answer: The client sends a request. Node's HTTP server receives it and calls the request listener with req and res. The server reads the request, performs logic, sets response headers/status, writes data if needed, and calls res.end().

Why? This is the core flow of every HTTP server and is one of the most important Node.js interview topics.
Q2. What is the difference between req and res?
Answer: req represents the incoming client request. res represents the server's outgoing response.

Why? Mixing these objects causes incorrect request reading or response handling.
Q3. What is the difference between res.write() and res.end()?
Answer: res.write() sends a piece of response data but does not finish the response. res.end() finishes the response and may send final data.

Why? The client needs the response to be completed before it knows the response has ended.
Q4. What happens if res.end() is never called?
Answer: The HTTP response remains open until it is otherwise terminated or fails.

Why? end() signals that the server has finished sending the response.
Q5. What is req.url?
Answer: req.url contains the request target URL as provided to the Node.js HTTP server, such as /users?page=2.

Why? It can be used to inspect the requested path and query string when implementing low-level routing.
Q6. What is req.method?
Answer: It contains the HTTP method, such as GET, POST, PUT, PATCH, or DELETE.

Why? The same URL can perform different operations depending on the HTTP method.
Q7. Why can a POST body arrive in multiple chunks?
Answer: HTTP request data is delivered as a stream, and network transport does not guarantee that the complete body arrives in one chunk.

Why? Applications must collect/process chunks until the end event when they need the complete body.
Q8. Write a Node.js server that returns JSON for GET /users.
Code Answer: 
const http = require("node:http");

const server = http.createServer((req, res) => {
  if (req.method === "GET" && req.url === "/users") {
    res.statusCode = 200;
    res.setHeader("Content-Type", "application/json");

    res.end(JSON.stringify([
      { id: 1, name: "Sam" },
      { id: 2, name: "John" }
    ]));
    return;
  }

  res.statusCode = 404;
  res.end("Not Found");
});

server.listen(3000);
Why? The method and path are checked first. The JSON content type tells the client what format the response uses, and JSON.stringify() converts the JavaScript value into JSON text.
Q9. What status code should normally be returned when a new resource is created?
Answer: 201 Created is commonly used.

Why? It communicates that the request successfully created a resource.
Q10. What is the difference between 401 and 403?
Answer: 401 generally means the request lacks valid authentication credentials. 403 means the server understood the request but refuses to authorize it.

Why? Authentication and authorization are different concepts.
Q11. What is manual routing?
Answer: Manual routing means checking values such as req.method and req.url yourself and deciding which code should handle the request.

Why? It demonstrates what routing frameworks automate for developers.
Q12. What is the difference between HTTP and HTTPS?
Answer: HTTPS is HTTP protected by TLS. It helps encrypt data in transit and authenticate the server.

Why? Sensitive information should not be sent over an unprotected HTTP connection.
Q13. Output-based question: What will this server return for GET /?
const http = require("node:http");

const server = http.createServer((req, res) => {
  if (req.url === "/" && req.method === "GET") {
    res.statusCode = 200;
    res.end("Home");
    return;
  }

  res.statusCode = 404;
  res.end("Not Found");
});
Answer: It returns status 200 with the body Home.

Why? Both conditions are true for a GET request to /, so the first branch executes and returns.
Q14. Code question: Safely parse a JSON request body.
Code Answer: 
let body = "";

req.on("data", chunk => {
  body += chunk;
});

req.on("end", () => {
  try {
    const data = JSON.parse(body);
    console.log(data);
  } catch (error) {
    res.statusCode = 400;
    res.end("Invalid JSON");
  }
});
Why? The body may arrive in chunks, and JSON.parse() throws when the received text is not valid JSON.
Q15. What is REST vs RESTful API?
Answer: REST is an architectural style. RESTful describes an API that follows REST principles, such as resource-oriented URLs and appropriate HTTP methods.

Why? Interviewers often check whether candidates understand that REST is not simply “using JSON over HTTP.”
Q16. Why should you use URL instead of manually splitting req.url for query parameters?
Answer: The URL and URLSearchParams APIs correctly handle URL structure and query parameters.

Why? Manual string splitting is easier to get wrong, especially with encoded characters and multiple parameters.
