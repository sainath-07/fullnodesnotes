Interview-ready system design questions for intermediate and experienced backend interviews.

How to Approach Any System Design Question
Requirements → Capacity → API → Architecture → Database → Cache → Queue → Scaling → Security → Failure Handling → Trade-offs
Interview tip: Start with requirements. Do not immediately draw technologies. Explain why each component exists.
Client ↓ Load Balancer / API Gateway ↓ Express API instances ├── Auth / Validation ├── Cache ├── Database └── Queue → Workers → External services ↓ Monitoring / Logs / Metrics
Quick Recap — System Design Interview Checklist
  1. Clarify users, traffic, latency, availability, storage and consistency needs.
  2. Define important APIs and request/response shapes.
  3. Keep Express instances stateless so they can scale horizontally.
  4. Use indexes for frequent database queries and pagination for large datasets.
  5. Use Redis carefully for hot data, rate limits, sessions, or distributed coordination.
  6. Use queues for slow, retryable, or asynchronous work.
  7. Use object storage for large files instead of storing file bytes in the application database.
  8. Add timeouts, retries with limits, idempotency, circuit-breaking patterns where appropriate.
  9. Protect APIs with authentication, authorization, validation, rate limiting and secure secrets.
  10. Explain the bottleneck and the trade-off of every scaling decision.
Strong interview structure: “Here are the requirements. Here is the API. Here is the high-level architecture. Now I will explain data storage, scaling, failures, and security. Finally, here are the trade-offs.”
