🟢 Part 27 — Node.js Cluster & Scaling ⭐⭐⭐

Learn how Node.js applications can use multiple CPU cores and how production systems scale across processes and machines.

1. What is Node.js Cluster?

What: The Node.js cluster module allows a Node.js application to create multiple worker processes that can share a server port.

Why: One Node.js process cannot make JavaScript execute on multiple CPU cores at the same time. Cluster can run multiple processes so more CPU cores can be used.

Layman example: Imagine one shop with one cashier. If there are four cashiers, more customers can be served at the same time. The cluster primary process manages several worker processes.

Interview line: Cluster is process-based scaling inside a machine; each worker is a separate Node.js process.
2. Primary Process and Worker Processes

The primary process starts and manages workers. A worker process runs the application code that handles requests.

const cluster = require("node:cluster"); const os = require("node:os"); if (cluster.isPrimary) { const count = os.availableParallelism(); for (let i = 0; i < count; i++) { cluster.fork(); } } else { // Worker process // Start the HTTP server here. }
Note: Current Node.js versions provide os.availableParallelism() as a better way to ask for an appropriate parallelism value than simply assuming the number of CPUs is the right worker count.

5. Process Isolation

Each cluster worker is a separate operating-system process with its own JavaScript heap and event loop.

Own heap
Worker B
Own heap

Own heap

This gives stronger isolation than ordinary code running in the same process. However, it also means memory is not automatically shared between workers.

Interview point: If one worker crashes, other workers can continue serving requests, provided the overall architecture handles the failure correctly.
6. Worker Failure and Restart

Production systems should monitor worker processes. If a worker exits unexpectedly, the primary process can decide whether to create a replacement.

cluster.on("exit", (worker, code, signal) => { console.log(`Worker ${worker.process.pid} exited`); // Restart policy should be controlled carefully. cluster.fork(); });
Common mistake: Blindly restarting a worker that immediately crashes can create a restart loop. Production systems should use sensible health checks, logging and restart limits.

8. Horizontal vs Vertical Scaling

Vertical scaling: Give one machine more CPU, RAM or other resources.

Horizontal scaling: Add more application instances or machines.

10. PM2 Concept

PM2 is a process manager commonly used with Node.js applications. It can keep applications running, restart crashed processes, manage multiple instances and provide operational features such as logs.

Common pattern: Keep shared session/state data in a shared store such as Redis rather than relying only on one Node.js process's memory.

13. Common Developer Mistakes
  1. Thinking cluster turns one Node.js process into multiple JavaScript threads.
  2. Creating too many workers without measuring CPU and memory usage.
  3. Keeping important session state only in worker memory.
  4. Assuming a crashed worker will always be restarted automatically.
  5. Blindly restarting a worker that has a deterministic startup bug.
  6. Using cluster when the actual bottleneck is a slow database query.
  7. Ignoring load-balancer health checks.
  8. Using local in-memory caches as if all distributed instances shared the same memory.
  9. Confusing horizontal scaling with vertical scaling.
  10. Assuming a load balancer alone solves database bottlenecks.

15. Quick Recap
  • Cluster: Node.js module for running multiple worker processes.
  • Primary: Manages worker processes.
  • Worker process: Handles application work.
  • Multiple cores: Multiple processes can be scheduled across CPU cores.
  • Process isolation: Each worker has its own process memory.
  • Worker restart: Can be implemented after unexpected exits, but should use a safe restart policy.
  • Horizontal scaling: Add more instances/machines.
  • Vertical scaling: Make one machine bigger.
  • Load balancer: Distributes traffic across instances.
  • PM2: Process manager with features such as restarts, logs and multi-instance management.
  • Stateless API: Does not depend on one specific server's local memory for user state.
  • Distributed sessions: Usually need shared state or a stateless authentication design.
