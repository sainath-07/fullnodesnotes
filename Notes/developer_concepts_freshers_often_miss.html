1. Optimistic UI / Optimistic Update

Very useful in React apps

Simple meaning: Update the screen immediately, assuming the server request will succeed.

Example: User clicks Like. You immediately show ❤️ Liked instead of waiting for the API response.
User clicks Like
→
UI shows ❤️
→
API runs in background
→
Server confirms
If API fails: UI changes back → 🤍 Like. This is called rollback.

Important: The cache does not confirm the server. The client sends a mutation to the server. The local state/cache is updated optimistically, then reconciled with the server response or refetched.

// Pseudo flow
setLiked(true);             // instant UI update
await api.likePost(id);     // server update
// on failure → setLiked(false)
Interview: “I use optimistic updates when the action is likely to succeed and the UI should feel instant. If the mutation fails, I rollback the local state and show an error.”

2. Pessimistic Update

Meaning: Wait for the server to succeed before changing the UI to the final state.

Click Like
→
API request
→
Server success
→
Show ❤️
Use when: You cannot safely assume success, or incorrect immediate UI would be risky.

Optimistic vs Pessimistic: Optimistic = UI first. Pessimistic = server first.

3. Cache Invalidation

Meaning: Tell the application that cached data may no longer be fresh.

Cached data
→
Mutation happens
→
Mark cache stale
→
Refetch latest data

Example: After creating a new todo, invalidate the todos query so the list can fetch the latest server data.

A useful phrase: “The cache is stale, so I need to reconcile it with the server.”

4. Debounce

Meaning: Wait until the user stops triggering an event for a period of time.

R
Re
Rea
React
→
wait 500ms
→
API call

Common use: Search boxes, autocomplete, validation.

Key idea: Every new event resets the timer.

clearTimeout(oldTimer);
timer = setTimeout(() => {
  searchAPI(value);
}, 500);

5. Throttle

Meaning: Allow an event to run at most once within a fixed time window.

Scroll scroll scroll scroll
→
run at most once / 200ms
→
handler

Common use: Scroll, resize, mouse movement, continuous browser events.

Easy memory: Debounce = “wait until quiet.” Throttle = “limit the speed.”

6. Race Condition

Meaning: Multiple operations run at the same time, and the final result depends on which one finishes first.

Search A
→
slow response
Search B
→
fast response
Problem: B may finish first and show correct data, then A may finish later and overwrite the UI with stale data.

Common fix: Abort old requests, use a cancellation flag, request IDs, or a library that handles stale queries.

Interview: “Debouncing reduces how many requests start; race-condition handling decides which response is allowed to update the UI.”

7. Idempotency

Meaning: Repeating the same operation produces the same intended final result.

Request #1
→
Server result
→
Retry request
→
Same intended result

Why it matters: Networks fail. A client may retry. Without idempotency, a payment or order operation could accidentally happen twice.

Common technique: Send an idempotency key so the server can recognize a repeated request.

8. Pagination

Meaning: Split a large dataset into smaller pages.

10,000 records
→
Page 1: 20
Page 2: 20
Page 3: 20

It reduces the amount of data transferred and rendered at once.

Types: Page-number pagination and cursor-based pagination. Cursor pagination is often useful for feeds where data changes frequently.

9. Infinite Scroll

Meaning: Load the next batch automatically when the user gets near the bottom.

Load 20
→
User scrolls
→
Near bottom
→
Load next 20

Important: Usually combine it with pagination/cursors and a guard such as isLoading to avoid duplicate requests.

10. Lazy Loading

Meaning: Do not load something until it is actually needed.

Initial page
→
Load critical content
→
User needs image/component
→
Load it now

Examples: Images below the fold, heavy React components, routes.

11. Code Splitting

Meaning: Break one large JavaScript bundle into smaller chunks that can be loaded when needed.

Large app bundle
→
Home chunk
Admin chunk
Reports chunk

Benefit: Users do not need to download every part of a large application on the first page load.

12. Memoization

Meaning: Remember a previous computation so you can reuse the result instead of calculating it again.

const result = expensiveFunction(input);
// If input has not changed,
// reuse the previous result.

In React, useMemo caches a calculated value and useCallback caches a function reference.

Memoization is not automatically a performance win. It also has a memory and comparison cost. Use it when it solves a real performance problem.

13. Stale Data

Meaning: Data in the UI/cache is older than the latest server state.

Server = 120 likes
→
Browser cache = 119
→
Cache is stale

Related concepts: stale time, cache invalidation, refetching, revalidation.

14. Retry & Exponential Backoff

Meaning: If a temporary request fails, try again after waiting.

Try 1
→
wait 1s
→
Try 2
→
wait 2s
→
Try 3

Exponential backoff increases the waiting time between retries. Add jitter in distributed systems to avoid many clients retrying at exactly the same time.

Do not blindly retry everything. A permanent 400-style validation error usually should not be retried automatically.

15. Optimistic Locking

Meaning: Detect whether someone else changed a record before you save your changes.

Read version 5
→
Someone changes it → version 6
→
Your update says “version 5”
→
Reject / conflict

Typical mechanism: version number or timestamp in the database. This is different from Optimistic UI: one is about user experience, the other is about concurrent data changes.

16. Eventual Consistency

Meaning: Different parts of a distributed system may temporarily see different values, but they are expected to converge later.

Write succeeds
→
Replica A updated
→
Replica B catches up
→
All converge

This concept becomes important when applications use replicas, caches, queues, or distributed services.

17. Observability

Meaning: The ability to understand what is happening inside a running system from its external signals.

Logs
Metrics
Traces
→
Understand system behavior

Example: A user says checkout is slow. Logs show an error, metrics show high latency, and a trace shows which downstream service is slow.

18. Feature Flags

Meaning: Turn a feature on or off through configuration instead of deploying new code.

Code deployed
→
Flag OFF
→
Enable for 5% users
→
Enable for everyone

Uses: gradual rollout, A/B tests, emergency kill switches, unfinished features.

19. Circuit Breaker

Meaning: Temporarily stop sending requests to a failing service instead of repeatedly hammering it.

Service failing
→
Circuit opens
→
Fast failure / fallback
→
Test recovery

This helps prevent one unhealthy service from causing a chain reaction across a distributed system.

20. Rate Limiting

Meaning: Limit how many requests a client can make within a time period.

Client
→
100 requests/min
→
Allow
Too many
→
429 / blocked

Why: Protect APIs, control costs, prevent abuse, and keep services stable.

Common algorithms: fixed window, sliding window, token bucket, leaky bucket.
