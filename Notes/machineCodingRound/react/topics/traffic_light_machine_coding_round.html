Questions / Topics
WHAT

What is a Traffic Light?

A Traffic Light machine coding problem is a state-driven UI component that displays traffic signal states such as Red, Yellow and Green and changes between them according to a defined sequence and timing rule.

Simple interview definition: “Traffic Light is a finite state machine where the UI represents the current signal state and a timer or user action transitions the component to the next valid state.”

Typical requirements

Red → Green → Yellow → Red Automatic timer Countdown Start / Pause / Reset Configurable duration Accessibility

WHY

What problem does a Traffic Light component solve?

This problem tests whether you can model a UI that has multiple states, strict transitions and time-based behavior. It is less about drawing three circles and more about managing state predictably.

Problems it demonstrates

  • State management: Only one signal state should be active at a time.
  • State transitions: A state can transition only to the next valid state.
  • Timers: The UI must change at the correct time.
  • Cleanup: Timers must be stopped when the component is paused or unmounted.
  • Derived UI: The active light and countdown come from the current state.
  • Extensibility: Start, pause, reset and configurable durations can be added cleanly.
Key interview point: Treat the traffic light as a small state machine, not as three independent boolean variables such as isRed, isYellow and isGreen.
HOW

How to implement a Traffic Light

  1. Define the allowed states: RED, GREEN, YELLOW.
  2. Define the duration for each state.
  3. Keep one state variable for the current light.
  4. Keep a countdown/timer value if the UI needs to display remaining seconds.
  5. On every timer tick, decrement the countdown.
  6. When the countdown reaches zero, transition to the next valid state.
  7. Reset the countdown using the duration of the new state.
  8. Clear the interval when paused, reset or when the component unmounts.
  9. Render the active light based on the current state.

1 MINUTE

How to explain Traffic Light to the interviewer in 1 minute

“I implemented the traffic light as a small finite state machine. I have three valid states: Red, Green and Yellow, and each state has a configured duration. I keep the current state and remaining time in state. A one-second interval decrements the remaining time. When it reaches zero, I transition to the next valid state and reset the countdown using that state's duration. The UI only renders based on the current state, so there is one source of truth. I also clean up the interval on pause, reset and component unmount to avoid multiple timers or memory leaks.”

What the interviewer should hear

  • Finite state machine
  • One current state, not three unrelated booleans
  • Configured state durations
  • Timer lifecycle and cleanup
  • Predictable state transitions
  • UI derived from state
  • Easy extension to pause, reset and countdown
5 MINUTES

How to explain Traffic Light in 5 minutes

1. Clarify the requirement

“I first clarify the sequence and durations. For example, Red → Green → Yellow → Red. I also ask whether the timer should be visible and whether Start, Pause and Reset are required.”

2. Model it as a state machine

“I don't keep separate isRed, isGreen and isYellow flags because those can become inconsistent. Instead, one variable represents the current state.”

3. Define durations

const durations = {
  RED: 5,
  GREEN: 4,
  YELLOW: 2
};

4. Run the timer

“Every second I decrement the remaining time. When it reaches zero, I calculate the next state and reset the remaining time to that state's duration.”

5. Handle lifecycle

“The interval must be cleared when the component is paused or unmounted. If I use React, this belongs inside an effect cleanup so the component never leaves an orphaned timer.”

6. Explain edge cases

  • Pause should freeze both the light and countdown.
  • Resume should continue from the current remaining time.
  • Reset should restore the initial state and duration.
  • Invalid duration values should be normalized or rejected.
  • Changing duration configuration should not create duplicate intervals.
  • Tab/background throttling means browser timers are not real-time clocks for safety-critical systems.
Strong closing line: “The key design decision is to model the problem as a state machine with one source of truth and a well-managed timer lifecycle. That makes the behavior predictable and easy to extend.”
MY IMPLEMENTATION

How I implemented it — explanation to interviewer

Explain your implementation in this order:

1. Constants

“I defined the states and their durations separately so the transition logic doesn't contain hard-coded timing everywhere.”

2. Current state

“I store one current state such as RED. The active CSS class is derived from that value.”

3. Countdown

“I keep remaining seconds separately because it is display state. It is reset whenever the signal changes.”

4. Transition function

“I use a deterministic mapping: RED → GREEN, GREEN → YELLOW, YELLOW → RED.”

5. Timer

“The interval runs only while the component is active. Each tick updates the countdown and triggers a transition at zero.”

6. Cleanup

“I clear the interval during cleanup. This prevents multiple intervals and stale updates after unmount.”

Interview-friendly statement: “I first built the state transition correctly, then added the timer, then added controls and cleanup. This keeps the core logic independently testable.”

      opacity: .3;
    }

    .light.active {
      opacity: 1;
    }

    .red.active {
      background: red;
    }

    .yellow.active {
      background: orange;
    }

    .green.active {
      background: green;
    }
  </style>
</head>
<body>

  <div class="traffic-light">
    <div id="red" class="light red"></div>
    <div id="yellow" class="light yellow"></div>
    <div id="green" class="light green"></div>
  </div>

  <p id="status"></p>

  <button id="start">Start</button>
  <button id="pause">Pause</button>
  <button id="reset">Reset</button>

  <script>
    const durations = {
      RED: 5,
      GREEN: 4,
      YELLOW: 2
    };

    const nextState = {
      RED: "GREEN",
      GREEN: "YELLOW",
      YELLOW: "RED"
    };

    let current = "RED";
    let remaining = durations[current];
    let timerId = null;

    function render() {
      document.querySelectorAll(".light")
        .forEach(light => light.classList.remove("active"));

      document
        .getElementById(current.toLowerCase())
        .classList.add("active");

      document.getElementById("status").textContent =
        `${current} · ${remaining}s`;
    }

    function tick() {
      if (remaining > 1) {
        remaining -= 1;
      } else {
        current = nextState[current];
        remaining = durations[current];
      }

      render();
    }

    function start() {
      if (timerId !== null) return;

      timerId = setInterval(tick, 1000);
    }

    function pause() {
      clearInterval(timerId);
      timerId = null;
    }

    function reset() {
      pause();
      current = "RED";
      remaining = durations[current];
      render();
    }

    document.getElementById("start")
      .addEventListener("click", start);

    document.getElementById("pause")
      .addEventListener("click", pause);

    document.getElementById("reset")
      .addEventListener("click", reset);

    render();
  </script>

</body>
</html>
React implementation
import { useEffect, useState } from "react";

const DURATIONS = {
  RED: 5,
  GREEN: 4,
  YELLOW: 2
};

const NEXT = {
  RED: "GREEN",
  GREEN: "YELLOW",
  YELLOW: "RED"
};

function TrafficLight() {
  const [current, setCurrent] = useState("RED");
  const [remaining, setRemaining] = useState(DURATIONS.RED);
  const [running, setRunning] = useState(true);

  useEffect(() => {
    if (!running) return;

    const timerId = setInterval(() => {
      setRemaining(prev => {
        if (prev > 1) {
          return prev - 1;
        }

        setCurrent(currentState => {
          const next = NEXT[currentState];
          return next;
        });

        return DURATIONS[NEXT[current]];
      });
    }, 1000);

    return () => clearInterval(timerId);
  }, [running]);

  const reset = () => {
    setRunning(false);
    setCurrent("RED");
    setRemaining(DURATIONS.RED);
  };

  return (
    <div>
      <div className="traffic-light">
        {["RED", "YELLOW", "GREEN"].map(light => (
          <div
            key={light}
            className={`light ${light.toLowerCase()}
              ${current === light ? "active" : ""}`}
          />
        ))}
      </div>

      <p>
        {current} · {remaining}s
      </p>

      <button onClick={() => setRunning(true)}>
        Start
      </button>

      <button onClick={() => setRunning(false)}>
        Pause
      </button>

      <button onClick={reset}>
        Reset
      </button>
    </div>
  );
}

export default TrafficLight;
Production note: For an interview implementation, a one-second interval is usually enough. For real timing guarantees, use timestamp-based calculations because browser timers can be delayed when a tab is backgrounded.
COMMON MISTAKES

Common developer mistakes

1. Using three independent booleans

Keeping isRed, isYellow and isGreen can create impossible states where multiple lights are active.

Better: Keep one current state.

2. Creating multiple intervals

Starting a new setInterval every render or every button click can make the light change too quickly.

Better: Ensure only one active timer exists and clean it up.

3. Forgetting cleanup

An interval that continues after unmount can cause memory leaks or stale updates.

Better: Clear the interval in cleanup.

4. Hard-coding transitions everywhere

Scattering if/else timing and transition logic makes the component harder to extend.

Better: Keep durations and next-state mapping in configuration.

5. Resetting the timer incorrectly

After RED expires, accidentally using RED's duration for GREEN produces incorrect timing.

Better: Set remaining time from the new state's duration.

6. Mixing DOM manipulation with state

Manually adding/removing classes in many places can drift away from application state.

Better: Render the UI from the current state.

7. Pause creates another timer on resume

If the old timer isn't cleared, resume can create multiple intervals.

Better: Make Start idempotent and track the active timer.

8. Ignoring browser timer limitations

setInterval is not a real-time clock and can be throttled in background tabs.

Better: Use elapsed timestamps for accuracy-sensitive behavior.

9. No initial render

The component may show no active light until the first timer tick.

Better: Render the initial state immediately.

10. Overengineering too early

Building a complex state library or animation system before the state machine works wastes machine-coding time.

Better: Implement the state transition and timer lifecycle first.

Machine coding round tip: Say this explicitly: “I am treating the traffic light as a finite state machine, and the timer only drives transitions between valid states.”
FOLLOW-UPS

Likely interviewer follow-up questions

How would you change the duration dynamically?

Keep durations in configuration/state and make the transition logic read the latest duration for the active state.

How would you add a countdown?

Keep remaining seconds as derived display state and decrement it on each tick.

How would you implement pause/resume?

Track a running flag and create/clear the interval based on that flag while preserving remaining time.

How would you test the transition logic?

Extract the state transition into a pure function and test RED → GREEN, GREEN → YELLOW and YELLOW → RED independently.

Why not use three booleans?

Because one enum-like current state guarantees only one active state and makes transitions explicit.

What happens when the browser tab is inactive?

Timers can be throttled. For accurate timing, compare timestamps instead of assuming exactly one callback per second.

How would you add pedestrian mode?

Add a higher-level state machine or transition rules for pedestrian requests instead of directly changing light classes.

How would you make it accessible?

Expose the current state and countdown with an appropriate status/live region and ensure controls have accessible names and keyboard support.
