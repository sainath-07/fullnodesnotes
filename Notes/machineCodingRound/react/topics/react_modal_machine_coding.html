React Modal

A common React machine-coding task for displaying focused content above the current page.

Goal: Open a modal, display content, and close it through clearly defined user actions.

Left Side — Questions
1. What is a Modal?

Technical definition: A Modal is a temporary UI layer displayed above the current page to focus the user's attention on a specific task, message, form, confirmation, or piece of information.

Layman example: Imagine you are shopping online and click "Delete account". Instead of immediately deleting it, a small window appears asking, "Are you sure?" That window is a modal.

Core React concepts State → Event Handling → Conditional Rendering → Overlay → Reusable Component

2. What Problem Does a Modal Solve?

A Modal lets the application temporarily focus the user on an important action or piece of information without navigating to another page.

  • Confirmation dialogs.
  • Login and signup forms.
  • Image previews.
  • Product details.
  • Edit forms.
  • Warnings and important messages.
Machine-coding point: The interviewer is checking state management, conditional rendering, event handling, component structure, overlay behavior, and edge cases such as Escape and outside clicks.
3. Requirements
Basic requirements
  1. Show an "Open Modal" button.
  2. Clicking it opens the modal.
  3. Display title and content inside the modal.
  4. Provide a close button.
  5. Clicking the overlay can close the modal.
  6. Pressing Escape can close the modal.
  7. Prevent background interaction while the modal is open.
Good clarification questions
  • Should clicking outside the modal close it?
  • Should Escape close it?
  • Should the background page scroll while the modal is open?
  • Does the modal need to be reusable with custom content?
  • Should the modal support different sizes?
  • Does it need accessibility and focus management?
4. State Design — What State Do I Need?

For a basic Modal, I only need one piece of state: whether the modal is open.

const [isOpen, setIsOpen] = useState(false);

The state has two possible values:

  • false → modal is closed.
  • true → modal is open.
Core logic:
Open button → setIsOpen(true)
Close button → setIsOpen(false)
Overlay click → setIsOpen(false)
Escape → setIsOpen(false)
Interview concept: The modal's visibility is derived from a single source of truth: isOpen.

6. How I Have Implemented It — Interview Explanation
Step 1 — Manage visibility

I use useState(false) to track whether the modal is open or closed.

Step 2 — Open the modal

The Open button calls setIsOpen(true).

Step 3 — Conditionally render

I render the Modal component only when isOpen is true.

Step 4 — Close actions

The close button, overlay click, and Escape key can all call the same close function.

Step 5 — Keep Modal reusable

Instead of hardcoding one use case, I can pass title, children, and an onClose callback as props.

One-line implementation summary: "I control modal visibility with one boolean state, render the modal conditionally, centralize the close behavior, and keep the Modal component reusable through props."
7. Full React Code — Reusable Modal
import { useEffect, useState } from "react";

function Modal({ isOpen, onClose, title, children }) {
  useEffect(() => {
    if (!isOpen) return;

    const handleKeyDown = (event) => {
      if (event.key === "Escape") {
        onClose();
      }
    };

    document.addEventListener("keydown", handleKeyDown);

    return () => {
      document.removeEventListener(
        "keydown",
        handleKeyDown
      );
    };
  }, [isOpen, onClose]);

  if (!isOpen) {
    return null;
  }

  const handleOverlayClick = (event) => {
    if (event.target === event.currentTarget) {
      onClose();
    }
  };

  return (
    <div
      className="modal-overlay"
      onClick={handleOverlayClick}
    >
      <div className="modal">
        <div className="modal-header">
          <h2>{title}</h2>

          <button onClick={onClose}>
            ×
          </button>
        </div>

        <div className="modal-body">
          {children}
        </div>

        <div className="modal-footer">
          <button onClick={onClose}>
            Close
          </button>
        </div>
      </div>
    </div>
  );
}

function App() {
  const [isOpen, setIsOpen] = useState(false);

  return (
    <div>
      <button onClick={() => setIsOpen(true)}>
        Open Modal
      </button>

      <Modal
        isOpen={isOpen}
        onClose={() => setIsOpen(false)}
        title="Hello"
      >
        <p>
          This content is passed into the reusable Modal.
        </p>
      </Modal>
    </div>
  );
}

export default App;
Important logic to explain

}

// Escape

}
Important: The Escape listener is attached only while the modal is open and is removed during cleanup. This prevents unnecessary global event listeners from remaining active.
8. How to Explain Modal in 1 Minute

Interview-ready answer:

"I implemented a reusable Modal component in React. I use a boolean state called isOpen to control whether the modal is visible. When the user clicks Open Modal, I set isOpen to true, and the modal is conditionally rendered. The Modal receives an onClose callback, so the close button, overlay click, and Escape key can all use the same closing logic. I used event.target and event.currentTarget to make sure an outside click closes the modal without accidentally closing it when the user clicks inside the modal content. I also clean up the keydown event listener when the modal closes. The content is passed through children, which makes the component reusable."

9. How to Explain Modal in 5 Minutes
Minute 1 — Clarify requirements

I first confirm how the modal should open and close, whether outside click and Escape should close it, and whether the component needs to be reusable.

Minute 2 — Design the state

I use a single boolean isOpen state because visibility has only two states: open and closed.

Minute 3 — Implement the Modal

I conditionally render the overlay and modal when isOpen is true. I pass content through children and an onClose callback from the parent.

Minute 4 — Handle closing behavior

The close button calls onClose. For outside click, I compare event.target and event.currentTarget so only the overlay click closes the modal. I also listen for Escape while the modal is open.

Minute 5 — Discuss production improvements
  • Focus management.
  • Focus trap inside the modal.
  • Restore focus to the trigger after closing.
  • Prevent background scrolling.
  • ARIA dialog semantics.
  • Portal rendering when required.
  • Animation and different modal sizes.
Strong closing line: "The basic implementation focuses on correct state and event handling. For production, I would additionally handle focus, accessibility, body scrolling, and keyboard behavior."
10. Common Developer Mistakes
Mistake 1 — Rendering the modal all the time 
// Better
{isOpen && <Modal />}

Use the visibility state to control whether the modal is rendered.

Mistake 2 — Closing when clicking inside the modal 
const handleOverlayClick = (event) => {
  if (event.target === event.currentTarget) {
    onClose();
  }
};

The comparison ensures that only the overlay itself triggers outside-click closing.

Mistake 3 — Forgetting to clean up the Escape listener

If an event listener is added inside useEffect, remove it in the cleanup function to avoid accumulating listeners.

Mistake 4 — Using multiple visibility states

For one modal, a single isOpen state is enough. Avoid unnecessary state such as showOverlay and showModal unless the requirements actually need them.

Mistake 5 — Hardcoding Modal content

Use props and children so the Modal can display different content in different situations.

Mistake 6 — Ignoring Escape and accessibility

A production-quality modal should support appropriate keyboard behavior, focus handling, and accessible dialog semantics.

Mistake 7 — Allowing background scroll unexpectedly

If required, lock body scrolling while the modal is open and restore it when the modal closes.

Mistake 8 — Overengineering before the basic behavior works

First implement open, close, overlay, and content correctly. Then discuss focus trap, portals, animation, and advanced accessibility.

11. Interview Questions You May Be Asked

A basic modal has two visibility states: open and closed. A boolean represents those states clearly and simply.

I attach the click handler to the overlay and check whether event.target equals event.currentTarget. If they are equal, the user clicked the overlay itself rather than a child inside the modal.

children allows the parent to pass arbitrary JSX into the reusable Modal instead of hardcoding one specific content type.

The listener interacts with the document outside the component's normal JSX event flow. useEffect lets me attach it when the modal is open and clean it up when it closes.

While the modal is open, I can temporarily set document.body.style.overflow to "hidden", then restore the previous value during cleanup.

A React portal lets a component render its DOM outside its normal parent hierarchy. Modals often use portals to avoid stacking-context or overflow issues caused by parent elements.

Use appropriate dialog semantics, label the dialog, support Escape, manage focus, trap focus when appropriate, and return focus to the trigger when the modal closes.

Keep the Modal responsible for presentation and close behavior, then accept props such as isOpen, onClose, title, size, and children. The parent controls when it should open.
