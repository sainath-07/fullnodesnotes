1. What is a Checkbox Tree?

A Checkbox Tree is a hierarchical UI where items are displayed as a tree and every node can be selected using a checkbox. A parent can contain children, and selecting or unselecting a parent can affect its descendants.

Interview definition: “A Checkbox Tree is a recursive hierarchical component where parent and child checkbox states are related. Selecting a parent can select descendants, while child changes can update the parent's checked or indeterminate state.”
2. What Problem Does It Solve?

Checkbox Trees are useful when information has a hierarchy and users need bulk selection.

  • File and folder permissions
  • Role and permission management
  • Category selection
  • Product category filters
  • Organization/team selection
  • Nested menus and feature access
Machine coding insight: This task tests recursion, tree traversal, controlled inputs, immutable updates, parent-child relationships, and derived state.
3. Requirements
  1. Render nested nodes recursively.
  2. Each node has a checkbox.
  3. Selecting a parent selects all descendants.
  4. Unselecting a parent unselects all descendants.
  5. Selecting all children makes the parent checked.
  6. Selecting some children makes the parent indeterminate.
  7. Unselecting all children makes the parent unchecked.
  8. Support arbitrary nesting depth.
  9. Keep React state immutable.
Build order: First render the tree. Then implement child selection. Then parent propagation. Finally add indeterminate state and edge cases.

Each node has:

  • id — unique identifier
  • label — displayed name
  • children — nested nodes
Why recursion? A tree can have any nesting depth. A recursive component can render a node and then render the same component for its children.
5. State Design

For a scalable implementation, keep selected node IDs in a Set.

const [checkedIds, setCheckedIds] = useState(new Set());

Example:

checkedIds = new Set([3, 4, 5]);

This means nodes 3, 4 and 5 are selected.

Why IDs? The tree data describes what exists. The selection state describes what the user selected. Keeping these separate makes the component easier to reason about.
6. How Does It Work?
Step 1 — Render recursively
function TreeNode({ node }) {
  return (
    <div>
      <input type="checkbox" />
      {node.label}

      {node.children?.map(child => (
        <TreeNode key={child.id} node={child} />
      ))}
    </div>
  );
}
Step 2 — User checks a node

Find all descendants of that node and add their IDs to the checked set.

Step 3 — User unchecks a node

Find all descendants and remove their IDs.

Step 4 — Child changes

Parent status is derived from its children:

all children checked  → checked
some children checked → indeterminate
no children checked   → unchecked
Step 5 — React re-renders

Updating the selection state causes the tree to recalculate every node's visual state.

8. Indeterminate State — Important Interview Topic

A checkbox is indeterminate when some, but not all, descendants are selected.

HTML does not expose indeterminate as a normal JSX attribute. We set it through a DOM ref.

const checkboxRef = useRef(null);

useEffect(() => {
  if (checkboxRef.current) {
    checkboxRef.current.indeterminate = isIndeterminate;
  }
}, [isIndeterminate]);

So the three states are:

ChildrenParent
0 selectedUnchecked
Some selectedIndeterminate
All selectedChecked
Interview point: indeterminate is a DOM property, not a normal boolean HTML attribute, so a ref is commonly used to set it.

11. Full React Code

CheckboxTree.jsx

import { useEffect, useRef, useState } from "react";
import "./CheckboxTree.css";

const treeData = [
  {
    id: 1,
    label: "Frontend",
    children: [
      {
        id: 2,
        label: "React",
        children: [
          { id: 3, label: "Hooks", children: [] },
          { id: 4, label: "Router", children: [] }
        ]
      },
      {
        id: 5,
        label: "Vue",
        children: []
      }
    ]
  },
  {
    id: 6,
    label: "Backend",
    children: [
      { id: 7, label: "Node.js", children: [] },
      { id: 8, label: "Java", children: [] }
    ]
  }
];

function getDescendantIds(node) {
  const ids = [node.id];

  for (const child of node.children || []) {
    ids.push(...getDescendantIds(child));
  }

  return ids;
}

function TreeNode({ node, checkedIds, onToggle }) {
  const checkboxRef = useRef(null);

  const children = node.children || [];

  const childCheckedCount = children.filter(
    child => checkedIds.has(child.id)
  ).length;

  const isChecked = checkedIds.has(node.id);

  const isIndeterminate =
    children.length > 0 &&
    childCheckedCount > 0 &&
    childCheckedCount < children.length;

  useEffect(() => {
    if (checkboxRef.current) {
      checkboxRef.current.indeterminate = isIndeterminate;
    }
  }, [isIndeterminate]);

  return (
    <div className="tree-node">
      <label className="tree-label">
        <input
          ref={checkboxRef}
          type="checkbox"
          checked={isChecked}
          onChange={() => onToggle(node)}
        />

        {node.label}
      </label>

      {children.length > 0 && (
        <div className="children">
          {children.map(child => (
            <TreeNode
              key={child.id}
              node={child}
              checkedIds={checkedIds}
              onToggle={onToggle}
            />
          ))}
        </div>
      )}
    </div>
  );
}

function CheckboxTree() {
  const [checkedIds, setCheckedIds] = useState(new Set());

  function handleToggle(node) {
    setCheckedIds(prev => {
      const next = new Set(prev);
      const ids = getDescendantIds(node);

      const shouldCheck = !prev.has(node.id);

      ids.forEach(id => {
        if (shouldCheck) {
          next.add(id);
        } else {
          next.delete(id);
        }
      });

      return next;
    });
  }

  return (
    <div className="checkbox-tree">
      <h2>Checkbox Tree</h2>

      {treeData.map(node => (
        <TreeNode
          key={node.id}
          node={node}
          checkedIds={checkedIds}
          onToggle={handleToggle}
        />
      ))}
    </div>
  );
}

export default CheckboxTree;

12. How to Explain in 1 Minute
“I implemented a recursive Checkbox Tree in React. The tree itself is represented as nested data where every node has an id, label and optional children. I keep the selected node IDs in a Set.

I created a recursive TreeNode component. Each node renders its checkbox and recursively renders its children. When a node is selected, I collect that node and all descendants and add their IDs to the Set. When it is unchecked, I remove them.

For parent state, I derive whether all children are selected, none are selected, or only some are selected. When only some are selected, I set the checkbox's native indeterminate DOM property using a ref and useEffect. This keeps parent and child selections synchronized without duplicating state.”

14. Common Developer Mistakes
1. Mutating the Set directly
checkedIds.add(id); // ❌
setCheckedIds(checkedIds);

Use a copy:

const next = new Set(checkedIds);
next.add(id);
setCheckedIds(next); // ✅
2. Not using recursion

Hard-coding levels such as parent → child → grandchild breaks when the tree becomes deeper.

3. Selecting only the parent

If the requirement says parent selection controls descendants, update all descendant IDs.

4. Forgetting to unselect descendants

Unchecking a parent should remove the entire subtree when that behavior is required.

5. Keeping separate state for every parent

This can easily become inconsistent. Derive parent state from child selection.

6. Treating indeterminate as checked

Indeterminate is a third visual state and should not be confused with checked.

7. Trying checked={true} for indeterminate

The native checkbox indeterminate state is a DOM property, normally set through a ref.

8. Missing stable keys

Use unique node IDs as React keys rather than array indexes when possible.

9. Incorrect descendant traversal

Make sure recursive traversal reaches every depth.

10. Only checking immediate children for deep trees

For a deeply nested tree, parent state should ultimately reflect the complete descendant subtree, not just one level.

17. Interviewer Follow-up Questions
Q1. Why recursion?

A tree has an arbitrary number of levels. Recursion lets the same component render every depth without hard-coding levels.

Q2. Why use a Set?

It represents membership naturally and gives efficient add/delete/has operations.

Q3. Why not store checked=true inside every tree node?

Separating immutable source data from UI selection state makes updates and reasoning simpler.

Q4. What is indeterminate?

It means some descendants are selected but not all. It is a third visual state between unchecked and checked.

Q5. Why useRef for indeterminate?

Indeterminate is a native DOM property rather than a normal checkbox attribute.

Q6. How would you handle very large trees?

Normalize the data, index parent/child relationships, memoize nodes, and consider virtualization if the rendered tree is very large.

Q7. How would you support expand/collapse?

Add a separate Set of expanded IDs. Selection and expansion should remain independent states.

Q8. How would you implement “select only leaf nodes”?

Change toggle behavior so parent clicks either do nothing or only affect leaf descendants based on the product requirement.

Q9. How would you persist selections?

Serialize the selected IDs and store them in localStorage or send them to a backend.

Q10. What is the complexity?

Toggling a node can be O(k), where k is the number of nodes in that subtree, because descendants must be visited.
