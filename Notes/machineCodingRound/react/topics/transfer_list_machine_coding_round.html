Questions / Topics
WHAT

What is a Transfer List?

A Transfer List is a UI component that displays two lists of items and allows the user to move selected items from one list to another. A common version has an Available list on the left and a Selected list on the right, with controls such as →, ←, Transfer All and Clear.

Simple interview definition: “Transfer List is a dual-list selection component where users select one or more items from an available collection and transfer them to a selected collection.”

WHY

What problem does a Transfer List solve?

A normal multi-select can become difficult to understand when users need to see both available choices and already selected choices at the same time. A Transfer List makes that relationship explicit.

Problems it solves

  • Clear selection state: Users can see available and selected items separately.
  • Bulk selection: Multiple items can be moved in one action.
  • Easy reversal: Users can move items back without reopening another dialog.
  • Large collections: Search/filter can be added independently to each side.
  • Structured state: The application can maintain selected IDs rather than parsing UI text.
  • Assignment workflows: Useful for users, permissions, products, categories and teams.
Key interview point: The core problem is maintaining a consistent relationship between the source collection and the selected collection while allowing bulk, reversible movement.
HOW

How to implement a Transfer List

  1. Define the complete collection of items using stable IDs.
  2. Maintain which items are currently selected in each side, or maintain a selected-ID set and derive both lists.
  3. Track temporary UI selection separately from the final transferred state.
  4. When the user clicks Move Right, identify selected items from the left.
  5. Move those items to the right while removing them from the left.
  6. Clear the temporary selection after a transfer.
  7. Implement the reverse operation for Move Left.
  8. Add Move All / Clear All if required.
  9. Keep item IDs unique so an item never appears in both lists.
  10. Add search, sorting, disabled items and keyboard support as requirements demand.

Recommended state model

items = [
  { id: 1, name: "React" },
  { id: 2, name: "Vue" },
  { id: 3, name: "Angular" }
]

leftItems  = [React, Vue]
rightItems = [Angular]

selectedIds = new Set([1, 3])
Design choice: For a machine coding round, two arrays for left/right items are easy to explain. For a production component, keeping one source of truth plus a selected-ID set can reduce synchronization bugs.

1 MINUTE

How to explain Transfer List to the interviewer in 1 minute

“I implemented the Transfer List as a dual-list component. I have a source list and a selected list, and I keep item identity using stable IDs. The user can select one or multiple items on either side. When they click the transfer button, I collect the selected IDs, remove those items from the source list, add them to the destination list, and clear the temporary selection. I also make sure an item cannot exist in both lists at the same time. The same logic works in reverse for moving items back. I can extend this with Move All, search, disabled items, sorting and keyboard accessibility.”

What the interviewer should hear

  • Two-list / dual-list model
  • Stable item IDs
  • Multi-selection
  • Immutable state updates
  • Source-to-destination transfer
  • No duplicate items across lists
  • Temporary selection vs committed placement
  • Accessibility and extensibility
5 MINUTES

How to explain Transfer List in 5 minutes

1. Clarify the requirement

“The component should display available and selected items. Users should be able to select one or many items and transfer them in either direction. I would also clarify whether we need search, sorting, disabled items, Move All, drag-and-drop and a maximum selection.”

2. Explain the data model

“I give every item a stable unique ID. The UI selection is separate from the item's actual location. That makes it easier to move items without depending on their display text.”

3. Explain selection

“I maintain a temporary selection for each side. Clicking an item toggles its selected state. This allows bulk transfer.”

4. Explain transfer

“For Move Right, I find the selected items in the left list, append them to the right list and remove them from the left. Then I clear the selection. Move Left uses the same operation in reverse.”

5. Explain consistency

“The main invariant is that an item belongs to exactly one side. The transfer function is the only place that changes item ownership, which helps prevent duplicates.”

6. Explain edge cases

  • No items selected → disable transfer button or do nothing.
  • Duplicate IDs → reject or normalize the input data.
  • Disabled items → do not allow them to be selected or transferred.
  • Maximum selected count → enforce before moving.
  • Search active → transfer selected items from the filtered view, not only visible text.
  • Large lists → consider virtualization and efficient lookup by ID.
Strong closing line: “I separated item ownership, temporary selection and rendering concerns so that features like search, disabled items and bulk transfer can be added without changing the core transfer algorithm.”
MY IMPLEMENTATION

How I implemented it — explanation to interviewer

Explain your implementation in this order:

1. Data

“I started with an array of objects containing stable IDs and labels. IDs are used for logic; labels are only for display.”

2. Two lists

“I maintain which items are on the left and right. The key invariant is that the same ID should never exist in both.”

3. Selection

“I maintain selected IDs separately. Clicking a checkbox toggles an ID without changing its location.”

4. Transfer handler

“The handler gets selected IDs, filters them out of the source and adds them to the destination.”

5. Clear selection

“After transfer, I clear the moved IDs so stale selections cannot affect the next operation.”

6. Extensions

“Once the core works, I can add Move All, search, sorting, disabled items, keyboard support and drag-and-drop.”

Interview-friendly statement: “I first implemented select + move in both directions. After the core invariant was correct, I added bulk actions, disabled states and accessibility rather than overengineering the first version.”
FULL CODE

Standalone HTML + CSS + JavaScript

This implementation supports multi-select, move left/right and move all.

Complete implementation
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>Transfer List</title>
</head>
<body>

  <div class="transfer-list">
    <div>
      <h3>Available</h3>
      <div id="leftList"></div>
    </div>

    <div class="actions">
      <button id="moveRight">→</button>
      <button id="moveLeft">←</button>
      <button id="moveAllRight">→→</button>
      <button id="moveAllLeft">←←</button>
    </div>

    <div>
      <h3>Selected</h3>
      <div id="rightList"></div>
    </div>
  </div>

  <script>
    const items = [
      { id: 1, name: "React" },
      { id: 2, name: "Vue" },
      { id: 3, name: "Angular" },
      { id: 4, name: "Svelte" },
      { id: 5, name: "Solid" }
    ];

    let leftItems = [...items];
    let rightItems = [];
    let selectedLeft = new Set();
    let selectedRight = new Set();

    function toggleSelection(side, id) {
      const selected =
        side === "left" ? selectedLeft : selectedRight;

      if (selected.has(id)) {
        selected.delete(id);
      } else {
        selected.add(id);
      }

      render();
    }

    function moveRight() {
      const moving = leftItems.filter(item =>
        selectedLeft.has(item.id)
      );

      leftItems = leftItems.filter(item =>
        !selectedLeft.has(item.id)
      );

      rightItems = [...rightItems, ...moving];

      selectedLeft.clear();
      render();
    }

    function moveLeft() {
      const moving = rightItems.filter(item =>
        selectedRight.has(item.id)
      );

      rightItems = rightItems.filter(item =>
        !selectedRight.has(item.id)
      );

      leftItems = [...leftItems, ...moving];

      selectedRight.clear();
      render();
    }

    function moveAllRight() {
      rightItems = [...rightItems, ...leftItems];
      leftItems = [];
      selectedLeft.clear();
      render();
    }

    function moveAllLeft() {
      leftItems = [...leftItems, ...rightItems];
      rightItems = [];
      selectedRight.clear();
      render();
    }

    function renderList(containerId, list, selected, side) {
      const container = document.getElementById(containerId);
      container.innerHTML = "";

      list.forEach(item => {
        const label = document.createElement("label");

        const checkbox = document.createElement("input");
        checkbox.type = "checkbox";
        checkbox.checked = selected.has(item.id);

        checkbox.addEventListener("change", () => {
          toggleSelection(side, item.id);
        });

        label.append(
          checkbox,
          document.createTextNode(" " + item.name)
        );

        container.appendChild(label);
        container.appendChild(document.createElement("br"));
      });
    }

    function render() {
      renderList(
        "leftList",
        leftItems,
        selectedLeft,
        "left"
      );

      renderList(
        "rightList",
        rightItems,
        selectedRight,
        "right"
      );
    }

    document
      .getElementById("moveRight")
      .addEventListener("click", moveRight);

    document
      .getElementById("moveLeft")
      .addEventListener("click", moveLeft);

    document
      .getElementById("moveAllRight")
      .addEventListener("click", moveAllRight);

    document
      .getElementById("moveAllLeft")
      .addEventListener("click", moveAllLeft);

    render();
  </script>

</body>
</html>
React core implementation
import { useState } from "react";

const initialItems = [
  { id: 1, name: "React" },
  { id: 2, name: "Vue" },
  { id: 3, name: "Angular" },
  { id: 4, name: "Svelte" }
];

function TransferList() {
  const [leftItems, setLeftItems] = useState(initialItems);
  const [rightItems, setRightItems] = useState([]);
  const [selectedLeft, setSelectedLeft] = useState(new Set());
  const [selectedRight, setSelectedRight] = useState(new Set());

  const toggle = (side, id) => {
    const setter =
      side === "left" ? setSelectedLeft : setSelectedRight;

    setter(prev => {
      const next = new Set(prev);

      if (next.has(id)) {
        next.delete(id);
      } else {
        next.add(id);
      }

      return next;
    });
  };

  const moveRight = () => {
    const moving = leftItems.filter(item =>
      selectedLeft.has(item.id)
    );

    setLeftItems(prev =>
      prev.filter(item => !selectedLeft.has(item.id))
    );

    setRightItems(prev => [...prev, ...moving]);
    setSelectedLeft(new Set());
  };

  const moveLeft = () => {
    const moving = rightItems.filter(item =>
      selectedRight.has(item.id)
    );

    setRightItems(prev =>
      prev.filter(item => !selectedRight.has(item.id))
    );

    setLeftItems(prev => [...prev, ...moving]);
    setSelectedRight(new Set());
  };

  const renderList = (items, selected, side) => (
    <div>
      {items.map(item => (
        <label key={item.id}>
          <input
            type="checkbox"
            checked={selected.has(item.id)}
            onChange={() => toggle(side, item.id)}
          />
          {item.name}
        </label>
      ))}
    </div>
  );

  return (
    <div className="transfer-list">
      <div>
        <h3>Available</h3>
        {renderList(leftItems, selectedLeft, "left")}
      </div>

      <div className="actions">
        <button
          onClick={moveRight}
          disabled={selectedLeft.size === 0}
        >
          →
        </button>

        <button
          onClick={moveLeft}
          disabled={selectedRight.size === 0}
        >
          ←
        </button>
      </div>

      <div>
        <h3>Selected</h3>
        {renderList(rightItems, selectedRight, "right")}
      </div>
    </div>
  );
}

export default TransferList;
Production improvement: If the items have stable IDs, use IDs as the source of truth. Avoid relying on labels because two items may have the same display name.
COMMON MISTAKES

Common developer mistakes

1. Duplicating an item across both lists

After moving an item, forgetting to remove it from the source creates inconsistent state.

Better: Make transfer atomic: remove from source and add to destination.

2. Using labels instead of stable IDs

Two items may have the same name, so label-based transfer can move the wrong item.

Better: Identify items by stable unique IDs.

3. Mutating arrays directly

Methods like splice() can mutate state and make React updates harder to reason about.

Better: Use immutable filter(), spread and functional state updates.

4. Mixing selection with item location

A checkbox selection should not itself move the item.

Better: Keep temporary selection state separate from transfer state.

5. Not clearing selection after transfer

Stale selected IDs can cause the next transfer to move unexpected items.

Better: Clear the moved side's selection immediately after transfer.

6. Search only filters UI but breaks transfer logic

When a filtered list is shown, developers sometimes transfer only visible indexes.

Better: Transfer by stable IDs, not by filtered array indexes.

7. No disabled/empty-state handling

Users may see buttons that do nothing when no items are selected.

Better: Disable unavailable actions and show useful empty states.

8. Poor keyboard accessibility

A component that only works with mouse clicks is incomplete.

Better: Use native checkboxes/buttons, visible focus and logical keyboard order.

9. Overusing index as React key

Moving items between lists can make index-based keys unstable.

Better: Use the item's stable ID as the key.

10. Overengineering too early

Adding drag-and-drop, virtualization and async search before the core transfer works wastes time.

Better: Implement selection and two-way transfer first, then add requirements.

Machine coding round tip: State the invariant clearly: “Every item belongs to exactly one list.” Then make every transfer operation preserve that invariant.
FOLLOW-UPS

Likely interviewer follow-up questions

How would you implement Move All?

Move the entire source collection into the destination and clear the source in one state transition.

How would you add search?

Keep the complete list unchanged and derive a filtered display list. Transfer using stable IDs so filtering does not affect correctness.

How would you handle disabled items?

Store a disabled flag and prevent both selection and transfer for those items.

How would you support drag and drop?

Reuse the same transfer function. Drag-and-drop should only determine which IDs are being moved; the state transition remains the same.

How would you handle 10,000 items?

Use efficient ID lookup, memoized derived lists and possibly virtualization so only visible rows are rendered.

How would you maintain one source of truth?

Keep all items in one array and store selected IDs, or keep an item-to-side mapping. Derive left/right views from that source.

How would you preserve sorting?

Define a deterministic ordering rule and apply it after transfer, rather than depending on incidental array mutation.

How would you test it?

Test single and multi-select, both directions, Move All, empty selections, duplicate IDs, disabled items, filtering and keyboard behavior.
