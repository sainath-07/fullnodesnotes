1. What is File Upload in React?

Definition: File upload is the process of selecting a file from the user's device and sending that file from the React application to a backend server or storage service.

Layman example: Think about uploading a resume to a job website. You click Choose File, select your resume, and click Upload. React handles the browser-side interaction and sends the selected file to the backend.

React itself does not permanently store the uploaded file. React normally collects the file and sends it to an API. The backend or cloud storage is responsible for storing it.

3. Why Do We Need File Upload?
  • To allow users to upload images, PDFs, videos or documents.
  • To collect files as part of forms and workflows.
  • To send files to a backend API.
  • To validate file type and file size before upload.
  • To show selected-file information and upload status.
Machine-coding expectation: Do not stop at a file input. Show that you understand file selection, state management, validation, FormData, API submission, loading state and error handling.
4. How Does File Upload Work?
  1. User selects a file using <input type="file">.
  2. Browser gives React a File object through the input's change event.
  3. React stores the selected file in state.
  4. Application validates file type and size.
  5. On submit, the file is added to a FormData object.
  6. The frontend sends FormData to the backend using fetch or Axios.
  7. Backend receives the multipart request and stores/processes the file.
Important: For a normal multipart upload, do not manually set Content-Type: multipart/form-data when using browser fetch with FormData. The browser adds the required boundary automatically.

7. Full React Code

This example uses a functional component and fetch. Assume the backend exposes POST /api/upload.

FileUpload.jsx
import { useRef, useState } from "react";

function FileUpload() {
  const [file, setFile] = useState(null);
  const [error, setError] = useState("");
  const [message, setMessage] = useState("");
  const [loading, setLoading] = useState(false);

  const fileInputRef = useRef(null);

  const MAX_SIZE = 5 * 1024 * 1024; // 5 MB
  const ALLOWED_TYPES = [
    "image/jpeg",
    "image/png",
    "application/pdf"
  ];

  const handleFileChange = (event) => {
    const selectedFile = event.target.files[0];

    setError("");
    setMessage("");

    if (!selectedFile) {
      return;
    }

    // File type validation
    if (!ALLOWED_TYPES.includes(selectedFile.type)) {
      setError("Only JPG, PNG and PDF files are allowed.");
      event.target.value = "";
      setFile(null);
      return;
    }

    // File size validation
    if (selectedFile.size > MAX_SIZE) {
      setError("File size must be less than 5 MB.");
      event.target.value = "";
      setFile(null);
      return;
    }

    setFile(selectedFile);
  };

  const handleUpload = async () => {
    if (!file) {
      setError("Please select a file first.");
      return;
    }

    setLoading(true);
    setError("");
    setMessage("");

    const formData = new FormData();
    formData.append("file", file);

    try {
      const response = await fetch("/api/upload", {
        method: "POST",
        body: formData
      });

      if (!response.ok) {
        throw new Error("Upload failed");
      }

      const data = await response.json();

      setMessage(data.message || "File uploaded successfully.");
      setFile(null);

      if (fileInputRef.current) {
        fileInputRef.current.value = "";
      }
    } catch (err) {
      setError(err.message || "Something went wrong.");
    } finally {
      setLoading(false);
    }
  };

  return (
    <div>
      <h2>Upload File</h2>

      <input
        ref={fileInputRef}
        type="file"
        accept=".jpg,.jpeg,.png,.pdf"
        onChange={handleFileChange}
      />

      {file && (
        <p>
          Selected: <strong>{file.name}</strong>
        </p>
      )}

      {error && (
        <p style={{ color: "red" }}>{error}</p>
      )}

      {message && (
        <p style={{ color: "green" }}>{message}</p>
      )}

      <button
        onClick={handleUpload}
        disabled={!file || loading}
      >
        {loading ? "Uploading..." : "Upload"}
      </button>
    </div>
  );
}

export default FileUpload;

8. File Validation

Validation should happen on the frontend for a better user experience, but it should also happen on the backend. Client-side validation can be bypassed.

Type

Allow only expected types such as JPEG, PNG and PDF.

Size

Reject files larger than the application's limit.

Security point: Do not trust only the file extension or browser MIME type. The backend should independently validate file type, size, filename handling and storage permissions.
9. Common Developer Mistakes
1. Sending the File object as normal JSON
A file upload normally uses FormData with a multipart request rather than JSON.stringify(file).
2. Manually setting multipart Content-Type
With browser fetch and FormData, let the browser generate the multipart boundary.
3. No file validation
Always consider file type and size before upload, and validate again on the backend.
4. No loading state
The user should know that an upload is in progress and the button should normally be disabled during the request.
5. No error handling
Network errors and server errors should be handled and shown clearly.
6. Assuming React stores the file permanently
React only handles the browser-side file object. Permanent storage belongs to the backend or storage service.
7. Forgetting to reset the input
If the same file needs to be selected again, resetting the input value can be useful.
10. How I Would Explain My Implementation to the Interviewer
Interview explanation:

“I implemented the file upload as a controlled workflow around the browser File API. First, I use an input of type file to let the user select a file. In the change handler, I get the File object and validate its type and size. I store the valid file in React state. When the user clicks Upload, I create a FormData object and append the file under the key ‘file’. I send that FormData to the backend using a POST request. I also added loading, success and error states so the UI clearly communicates the upload status. For security, I would repeat validation on the backend because client-side validation cannot be trusted.”

Explain the code in this order
  1. Input: “This is where the user selects a file.”
  2. State: “I store the selected file and UI states in React.”
  3. Validation: “I check type and maximum size.”
  4. FormData: “I package the file for a multipart request.”
  5. API: “I send it to the backend with POST.”
  6. UX: “I show Uploading, success and error states.”
  7. Security: “Backend validation is still required.”
Strong interview line: “The important part is not just selecting a file; it is handling the complete upload lifecycle: selection, validation, request creation, API submission, loading state, error handling and successful completion.”
