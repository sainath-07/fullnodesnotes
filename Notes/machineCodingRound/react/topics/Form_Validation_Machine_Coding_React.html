What?

What is Form Validation?

Form validation is the process of checking whether the data entered by a user is correct, complete, and in the expected format before accepting or submitting the form.

Simple example: If the Email field is empty or does not look like an email address, show an error instead of submitting invalid data.
Typical fields
  • Name — required and minimum length.
  • Email — required and valid email format.
  • Password — required and minimum length.
  • Confirm Password — must match password.
Why?

What problem does it solve?

1. Prevents bad input
Stops incomplete or incorrectly formatted data from being submitted.
2. Better user experience
Tells users exactly what needs to be corrected.
3. Reduces server errors
Basic client-side validation catches obvious mistakes early.
Important
Client-side validation is not a security boundary. The backend must validate again.
Machine Coding Requirement

What should I build?

A practical React form can include:

  1. Controlled inputs using useState.
  2. Validation rules for each field.
  3. Error messages near the relevant fields.
  4. Submit handling that runs validation first.
  5. Success message after valid submission.
  6. Basic accessible labels and aria-invalid.
How?

How does Form Validation work?

The core idea is simple:

User enters data
      ↓
React stores input in state
      ↓
User clicks Submit
      ↓
Run validation rules
      ↓
Are there errors?
   ↙           ↘
 YES            NO
 ↓               ↓
Show errors    Submit / process data
Interview sentence: “I keep the form values in controlled state, validate those values on submit, store field-level errors, and only proceed when the error object is empty.”
Execution Flow

Visual explanation

Step 1 — User types: Each input updates the formData state.
↓
Step 2 — User submits: handleSubmit prevents the browser's default submit.
↓
Step 3 — Validate: Check required fields, email format, password length, and password confirmation.
↓
Step 4 — Store errors: Put messages into an errors object using field names as keys.
↓
Step 5 — Decision: If errors exist, render them. Otherwise process the valid form.
↓
Step 6 — Success: Show a success message and optionally reset the form.
Implementation

How I have implemented it — interviewer explanation

1. State: “I use one formData object for all input values and one errors object for validation messages.”

2. Controlled inputs: “Each input gets its value from state and updates state through a common change handler.”

3. Validation: “I created a validation function that returns field-level errors instead of mixing validation logic into the JSX.”

4. Submit: “On submit, I prevent the default browser action, validate the form, and stop if errors exist.”

5. Success: “If validation passes, I process the data and show a success message.”

Full Code

React Form Validation

This version demonstrates controlled inputs, reusable validation, field errors, submit handling, and password confirmation.

import { useState } from "react";

function FormValidation() {
  const [formData, setFormData] = useState({
    name: "",
    email: "",
    password: "",
    confirmPassword: ""
  });

  const [errors, setErrors] = useState({});
  const [submitted, setSubmitted] = useState(false);

  const handleChange = (e) => {
    const { name, value } = e.target;

    setFormData((prev) => ({
      ...prev,
      [name]: value
    }));

    // Clear the old error while the user corrects the field.
    setErrors((prev) => ({
      ...prev,
      [name]: ""
    }));

    setSubmitted(false);
  };

  const validate = () => {
    const newErrors = {};

    if (!formData.name.trim()) {
      newErrors.name = "Name is required";
    } else if (formData.name.trim().length < 3) {
      newErrors.name = "Name must be at least 3 characters";
    }

    if (!formData.email.trim()) {
      newErrors.email = "Email is required";
    } else if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(formData.email)) {
      newErrors.email = "Enter a valid email";
    }

    if (!formData.password) {
      newErrors.password = "Password is required";
    } else if (formData.password.length < 6) {
      newErrors.password = "Password must be at least 6 characters";
    }

    if (!formData.confirmPassword) {
      newErrors.confirmPassword = "Please confirm your password";
    } else if (formData.password !== formData.confirmPassword) {
      newErrors.confirmPassword = "Passwords do not match";
    }

    return newErrors;
  };

  const handleSubmit = (e) => {
    e.preventDefault();

    const validationErrors = validate();
    setErrors(validationErrors);

    if (Object.keys(validationErrors).length > 0) {
      setSubmitted(false);
      return;
    }

    console.log("Valid form data:", formData);
    setSubmitted(true);
  };

  return (
    <div>
      <h2>Registration Form</h2>

      <form onSubmit={handleSubmit} noValidate>

        <div>
          <label htmlFor="name">Name</label>
          <input
            id="name"
            name="name"
            value={formData.name}
            onChange={handleChange}
            aria-invalid={!!errors.name}
          />
          {errors.name && <p>{errors.name}</p>}
        </div>

        <div>
          <label htmlFor="email">Email</label>
          <input
            id="email"
            name="email"
            type="email"
            value={formData.email}
            onChange={handleChange}
            aria-invalid={!!errors.email}
          />
          {errors.email && <p>{errors.email}</p>}
        </div>

        <div>
          <label htmlFor="password">Password</label>
          <input
            id="password"
            name="password"
            type="password"
            value={formData.password}
            onChange={handleChange}
            aria-invalid={!!errors.password}
          />
          {errors.password && <p>{errors.password}</p>}
        </div>

        <div>
          <label htmlFor="confirmPassword">
            Confirm Password
          </label>
          <input
            id="confirmPassword"
            name="confirmPassword"
            type="password"
            value={formData.confirmPassword}
            onChange={handleChange}
            aria-invalid={!!errors.confirmPassword}
          />
          {errors.confirmPassword && (
            <p>{errors.confirmPassword}</p>
          )}
        </div>

        <button type="submit">Submit</button>

        {submitted && (
          <p>Form submitted successfully!</p>
        )}
      </form>
    </div>
  );
}

export default FormValidation;
Core logic to remember: input → state → validate() → errors → submit only if valid
Common Developer Mistakes

Mistakes to avoid in a machine coding round

1. Only validating on the frontend
Frontend validation improves UX, but backend validation is still required.
2. Mutating state directly
Wrong: formData.name = value. Use the state setter and create a new object.
3. Mixing all validation logic inside JSX
Keep validation in a separate function so the component remains readable.
4. Forgetting preventDefault()
The browser may perform its normal form submission and reload the page.
5. Showing one generic error
“Invalid form” is less useful than “Email is required” or “Passwords do not match.”
6. Incorrect empty-string checks
For text fields, trim() helps catch values containing only spaces.
7. Forgetting password confirmation
If the form contains confirm password, compare it with the actual password.
8. No loading/submission strategy for API calls
In a real application, disable submit while an API request is in progress.
Interview

How to explain in 1 minute

“I implemented form validation using controlled React inputs. I maintain the input values in a formData state object and keep validation messages in an errors object. When the user submits the form, I prevent the default submission and run a separate validation function. That function checks required fields, name length, email format, password length, and password confirmation. If validation errors exist, I display field-level messages and stop submission. If there are no errors, I process the form data and show a success message. I also clear a field's previous error when the user starts correcting it. In a production application, I would perform the same important validation on the backend because frontend validation alone is not a security mechanism.”

Interview

How to explain in 5 minutes

  1. Requirement: “The goal is to prevent invalid form data and give useful feedback.”
  2. State design: “I use formData for values and errors for field-level validation messages.”
  3. Controlled inputs: “The input value comes from React state, and onChange updates that state.”
  4. Validation: “I keep validation rules inside a dedicated validate() function.”
  5. Submit flow: “I call preventDefault(), run validation, and return early when errors exist.”
  6. Success flow: “When the returned error object is empty, the data is considered valid and can be sent to an API.”
  7. UX: “I show errors next to their fields and clear them when the user edits the field.”
  8. Production consideration: “The backend must validate again because users can bypass client-side JavaScript.”
Strong closing line: “My implementation separates state management, validation, presentation, and submission logic, which makes the form easier to maintain and extend.”
Edge Cases

What can the interviewer test?

  • Submit the completely empty form.
  • Enter only spaces in the name field.
  • Enter an invalid email such as abc@.
  • Enter a password shorter than the required length.
  • Enter different password and confirm-password values.
  • Correct an invalid field and submit again.
  • Double-click the submit button during an API request.
  • Receive a server-side validation error after client validation succeeds.
Advanced Follow-up

How can you improve it?

  • Validate on blur for better immediate feedback.
  • Use a reusable validation schema/function for larger forms.
  • Disable submit while an API request is running.
  • Focus the first invalid field after submission.
  • Add accessible error descriptions with aria-describedby.
  • Handle server-side validation errors separately from client-side errors.
  • For large forms, consider libraries such as React Hook Form with a schema validator.
