React Stopwatch

A common React machine-coding task for measuring elapsed time with Start, Stop, and Reset controls.

Goal: build a reliable timer without creating multiple intervals or leaking timers.

Left Side — Questions
1. What is a Stopwatch?

Technical definition: A Stopwatch is a timer that measures the amount of time elapsed from a starting point. It normally provides controls such as Start, Stop/Pause, and Reset.

Layman example: Imagine starting a stopwatch before running 100 meters. The timer keeps increasing while you run. When you finish, you stop it and see how much time you took.

2. What Problem Does a Stopwatch Solve?

It gives the user a way to measure elapsed time interactively without refreshing the page.

  • Measure task duration.
  • Measure workout or exercise time.
  • Track coding/practice sessions.
  • Build productivity timers.
  • Measure how long a process takes.
  • Practice timer and asynchronous logic in React.
Machine-coding point: The interviewer is usually checking whether you understand state, useEffect, intervals, cleanup, event handling, formatting, and avoiding duplicate timers.
3. Requirements + Clarification Questions
Basic requirements
  1. Display elapsed time.
  2. Start the stopwatch.
  3. Stop/Pause the stopwatch.
  4. Resume after stopping.
  5. Reset the stopwatch to zero.
  6. Prevent multiple intervals from running simultaneously.
  7. Clean up the interval when the component unmounts.
Good clarification questions

  • Should the timer show milliseconds or only seconds?
  • What precision is expected: 1 second, 10 milliseconds, or 100 milliseconds?
  • Should Reset work while the stopwatch is running?
  • Should the timer continue accurately if the browser tab is inactive?
Interview tip: State the assumptions before coding. For example: "I'll support Start, Stop/Resume, Reset, and display minutes, seconds, and milliseconds."
4. What State Do I Need?

A simple Stopwatch can be designed with two pieces of state:

const [time, setTime] = useState(0);
const [isRunning, setIsRunning] = useState(false);
  • time stores elapsed time in milliseconds.
  • isRunning tells us whether the stopwatch should currently be running.
State model:
isRunning = false → timer is stopped
isRunning = true → timer is running

time = 0 → reset state
time > 0 → elapsed time

Why store milliseconds? It gives us enough precision to display seconds and milliseconds later. The UI can convert the stored value into mm:ss:ms.

5. How Does the Timer Logic Work?

The basic approach uses setInterval inside useEffect.

useEffect(() => {
  if (!isRunning) return;

  const intervalId = setInterval(() => {
    setTime(prevTime => prevTime + 10);
  }, 10);

  return () => clearInterval(intervalId);
}, [isRunning]);
What happens here?
  1. When isRunning becomes true, the effect runs.
  2. An interval starts.
  3. Every 10 milliseconds, the previous time is increased by 10.
  4. React updates the state and re-renders the display.
  5. When isRunning becomes false, the effect cleanup clears the interval.
Important: Never start a new interval on every render. That can create multiple intervals and make the stopwatch run too fast.
Production note: For a highly accurate stopwatch, relying on interval ticks as the source of truth can drift because JavaScript timers are not guaranteed to execute exactly on schedule. A stronger design stores a start timestamp and calculates elapsed time from Date.now() or performance.now().

8. Full React Code — Stopwatch
import { useEffect, useState } from "react";

function Stopwatch() {
  const [time, setTime] = useState(0);
  const [isRunning, setIsRunning] = useState(false);

  useEffect(() => {
    if (!isRunning) return;

    const intervalId = setInterval(() => {
      setTime((prevTime) => prevTime + 10);
    }, 10);

    return () => {
      clearInterval(intervalId);
    };
  }, [isRunning]);

  const formatTime = (time) => {
    const milliseconds = Math.floor((time % 1000) / 10);
    const seconds = Math.floor(time / 1000) % 60;
    const minutes = Math.floor(time / 60000);

    return (
      String(minutes).padStart(2, "0") +
      ":" +
      String(seconds).padStart(2, "0") +
      ":" +
      String(milliseconds).padStart(2, "0")
    );
  };

  const handleStartStop = () => {
    setIsRunning((prev) => !prev);
  };

  const handleReset = () => {
    setIsRunning(false);
    setTime(0);
  };

  return (
    <div className="stopwatch">
      <h1>{formatTime(time)}</h1>

      <button onClick={handleStartStop}>
        {isRunning ? "Stop" : "Start"}
      </button>

      <button onClick={handleReset}>
        Reset
      </button>
    </div>
  );
}

export default Stopwatch;
Important pieces to explain
// Start / Stop
setIsRunning((prev) => !prev);

// Start interval only when running
if (!isRunning) return;

// Update from previous state
setTime((prevTime) => prevTime + 10);

// Cleanup
return () => clearInterval(intervalId);

// Reset
setIsRunning(false);
setTime(0);
Interview note: This is a good machine-coding implementation for demonstrating React timer lifecycle. If the interviewer asks about high accuracy, explain that a timestamp-based implementation is more reliable than treating interval ticks as exact elapsed time.

11. Common Developer Mistakes
Mistake 1 — Starting setInterval directly during render 
// ❌ Wrong
setInterval(() => {
  setTime(time + 10);
}, 10);

Rendering should remain free of side effects. Use useEffect for the interval lifecycle.

Mistake 2 — Forgetting clearInterval

Without cleanup, old intervals can continue running after Stop or component unmount. This can cause memory leaks and incorrect timing.

Mistake 3 — Creating multiple intervals

If Start is clicked repeatedly without protection, multiple intervals can update the same state. Use running state and effect lifecycle correctly.

Mistake 4 — Using stale state inside the interval 
// ❌ Risky
setTime(time + 10);

// ✅ Better
setTime(prevTime => prevTime + 10);

The functional updater works with the latest state value.

Mistake 5 — Treating setInterval as perfectly accurate

JavaScript timers can be delayed by browser scheduling and the event loop. For accurate elapsed time, calculate from timestamps instead of assuming every callback happens exactly on schedule.

Mistake 6 — Keeping unnecessary state

Do not separately store minutes, seconds, and milliseconds unless necessary. Store elapsed time once and derive the display.

Mistake 7 — Resetting only the display

Reset should also stop the timer. Otherwise the display can immediately start increasing again.

Mistake 8 — Ignoring unmount behavior

Always clean up the timer when the component unmounts. This is an important React lifecycle concept.
