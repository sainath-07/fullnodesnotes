React Machine Coding Round — Debounce
Topics

Machine Coding Question

Question

Implement a debounce search in React. Make an API call only after the user stops typing for a specific amount of time, such as 500ms.

Requirements
  • Create a search input.
  • Do not call the API for every key press.
  • Wait 500ms after the user's last event before calling the API.
  • Handle previous API requests correctly.
  • Show the latest search result.
Interview goal: Explain debounce clearly and show how you handle stale/previous API requests.

Answer

Core Idea

Debounce means: wait until the user stops triggering an event for a fixed amount of time, then perform the action.

User types → reset timer → user types again → reset timer → user stops → 500ms completes → API call

The boolean flag does not cancel the network request. It marks the old effect as invalid, so when its response arrives, we ignore it. 

useEffect(() => {
  let cancelled = false;

  const timer = setTimeout(async () => {
    try {
      const response = await fetch(`/api/search?q=${search}`);
      const data = await response.json();

      if (!cancelled) {
        setResults(data);
      }
    } catch (error) {
      if (!cancelled) {
        setError("Request failed");
      }
    }
  }, 500);

  return () => {
    clearTimeout(timer);
    cancelled = true;
  };
}, [search]);
Important: The request still goes to the server. We only prevent the old response from updating the UI.
Common Developer Mistakes
  • Thinking cancelled = true actually cancels the API/network request.
  • Forgetting clearTimeout(), so old debounce timers can still run.
  • Declaring the cancelled flag outside useEffect, causing different effects to share the same flag.
  • Forgetting to check if (!cancelled) before updating state.
  • Forgetting cleanup when the component unmounts or the search value changes.
  • Not handling API errors separately from cancelled/stale work.

Here, AbortController is used to cancel the previous fetch request when the search value changes. 

useEffect(() => {
  const controller = new AbortController();

  const timer = setTimeout(async () => {
    try {
      const response = await fetch(
        `/api/search?q=${search}`,
        { signal: controller.signal }
      );

      const data = await response.json();
      setResults(data);
    } catch (error) {
      if (error.name !== "AbortError") {
        setError("Request failed");
      }
    }
  }, 500);

  return () => {
    clearTimeout(timer);
    controller.abort();
  };
}, [search]);
Important: AbortController tells fetch to abort the request. The AbortError is intentionally ignored.
Common Developer Mistakes
  • Creating one AbortController outside useEffect and reusing it for every request.
  • Creating the controller but forgetting to pass signal to fetch().
  • Calling abort() but treating AbortError as a real API failure.
  • Forgetting clearTimeout() during cleanup.
  • Assuming abort() guarantees that the server never received or processed the request.
  • Incorrectly changing loading/error state after an old request is aborted.

This combines both techniques. AbortController cancels the fetch, while the cancelled flag makes the old effect invalid so stale work cannot update the UI. 

useEffect(() => {
  let cancelled = false;
  const controller = new AbortController();

  const timer = setTimeout(async () => {
    try {
      setLoading(true);
      setError("");

      const response = await fetch(
        `/api/search?q=${encodeURIComponent(search)}`,
        { signal: controller.signal }
      );

      if (!response.ok) {
        throw new Error("Request failed");
      }

      const data = await response.json();

      if (!cancelled) {
        setResults(data);
      }
    } catch (error) {
      if (!cancelled && error.name !== "AbortError") {
        setError("Something went wrong");
      }
    } finally {
      if (!cancelled) {
        setLoading(false);
      }
    }
  }, 500);

  return () => {
    cancelled = true;
    clearTimeout(timer);
    controller.abort();
  };
}, [search]);
Best interview explanation: Debounce reduces unnecessary API calls. AbortController cancels the previous fetch. The cancelled flag prevents invalid/stale work from updating React state.
Common Developer Mistakes
  • Using both mechanisms without understanding that they solve different problems.
  • Declaring cancelled or the controller outside useEffect.
  • Forgetting either clearTimeout() or controller.abort() in cleanup.
  • Setting cancelled = true too late instead of doing it during cleanup.
  • Treating AbortError as a normal API error.
  • Allowing an old request's finally block to incorrectly change the current loading state.
  • Thinking debounce alone solves the race condition.
Difference Between Cancel and Abort
Technique What it does
cancelled = true Invalidates old work and prevents stale UI updates.
controller.abort() Aborts an in-flight fetch request.
Debounce Waits before starting the API call.

How I Explain This to the Interviewer

"First, I keep the search value in React state. Whenever the user types, the effect runs. I start a 500ms timer. If the user types again before 500ms, the cleanup clears the previous timer. Therefore, the API is called only after the user stops typing."

"After the debounce delay, I make the API request. Because another search can happen while the previous request is running, I need to handle the previous request as well."

"I can handle this with a cancelled flag. The flag does not cancel the actual network request; it only makes the previous effect invalid, so an old response cannot update the UI."

"Alternatively, I can use AbortController. When the search changes, the cleanup calls abort(), which cancels the previous fetch request."

"For a stronger implementation, I can use both. AbortController handles the fetch cancellation, and the cancelled flag protects against stale state updates. The cleanup clears the debounce timer, marks the old effect as cancelled, and aborts the previous request."

Short interview answer:
"Debounce controls when the API call starts. AbortController cancels an old fetch, while a cancelled flag prevents an old effect from updating the UI."
Edge Cases I Handled
1. Empty search
Do not make an API call for an empty value.
2. Fast typing
Clear the previous debounce timer.
3. Previous request
Abort the previous fetch when appropriate.
4. Stale response
Use the cancelled flag to prevent stale state updates.
5. API error
Handle normal errors separately from AbortError.
6. Component cleanup
Clear the timer and clean up the request on effect cleanup.
