What is a Countdown Timer?

A Countdown Timer is a UI component that continuously decreases a remaining time value until it reaches zero.

Simple example: Start with 00:10 → after one second 00:09 → then 00:08 → continue until 00:00.

Core idea: Store the remaining time, decrease it at a fixed interval, update the UI, and stop the interval when the timer reaches zero.

What problem does a Countdown Timer solve?

  • Shows users how much time remains before an event or action.
  • Useful for OTP expiration, quizzes, offers, auctions, contests, launches, and session expiry.
  • Provides visual feedback that an event is approaching.
  • Demonstrates real-time state updates and timer management in React.
Interview point: The important React concepts are useState, useEffect, setInterval, cleanup with clearInterval, and conditional rendering.

Expected Machine Coding Requirements

1. Initial Time
Allow a starting duration such as 60 seconds.
2. Start
Begin decreasing the remaining time every second.
3. Pause
Stop decrementing without resetting the remaining time.
4. Reset
Restore the timer to its initial duration.
5. Display
Show the remaining time as MM:SS.
6. Completion
Stop at zero and show a completion message.

How is Countdown Time Calculated?

If the remaining time is stored as total seconds:

Minutes 
minutes = Math.floor(timeLeft / 60)
Seconds 
seconds = timeLeft % 60
Example: If timeLeft = 125, then minutes = 2 and seconds = 5, so display 02:05.
Why store seconds instead of "02:05"?
Because arithmetic is much easier with a numeric value. The display format can be calculated whenever the component renders.

How I Have Implemented It — Interview Explanation

  1. I store the remaining time in seconds using timeLeft.
  2. I store whether the timer is active using isRunning.
  3. When the user clicks Start, I set isRunning to true.
  4. A useEffect watches the running state and creates a setInterval when the timer starts.
  5. Every one second, I decrease timeLeft by one.
  6. I use a functional state update so the timer works with the latest state value.
  7. When the value reaches zero, I stop the timer.
  8. When the component unmounts or the running state changes, I clean up the interval using clearInterval.
  9. For display, I convert total seconds into minutes and seconds and format them with leading zeros.
Good interview sentence:
"I keep the countdown value as total seconds because it makes the calculation simple. I use useEffect to create and clean up the interval based on the running state. Every second I decrement the value using a functional state update. Once it reaches zero, I stop the interval. The displayed MM:SS value is derived from the seconds."

Full React Code

This version includes Start, Pause, Reset, MM:SS display, completion handling, and interval cleanup.

import { useEffect, useState } from "react";

function CountdownTimer() {
  const initialTime = 60;

  const [timeLeft, setTimeLeft] = useState(initialTime);
  const [isRunning, setIsRunning] = useState(false);

  useEffect(() => {
    if (!isRunning || timeLeft <= 0) {
      return;
    }

    const intervalId = setInterval(() => {
      setTimeLeft((prevTime) => {
        if (prevTime <= 1) {
          clearInterval(intervalId);
          return 0;
        }

        return prevTime - 1;
      });
    }, 1000);

    return () => {
      clearInterval(intervalId);
    };
  }, [isRunning, timeLeft]);

  const handleStart = () => {
    if (timeLeft > 0) {
      setIsRunning(true);
    }
  };

  const handlePause = () => {
    setIsRunning(false);
  };

  const handleReset = () => {
    setIsRunning(false);
    setTimeLeft(initialTime);
  };

  const minutes = Math.floor(timeLeft / 60);
  const seconds = timeLeft % 60;

  const formattedMinutes = String(minutes).padStart(2, "0");
  const formattedSeconds = String(seconds).padStart(2, "0");

  return (
    <div className="timer">

      <h1>
        {formattedMinutes}:{formattedSeconds}
      </h1>

      {timeLeft === 0 && (
        <p>Time's up!</p>
      )}

      <button
        onClick={handleStart}
        disabled={isRunning || timeLeft === 0}
      >
        Start
      </button>

      <button
        onClick={handlePause}
        disabled={!isRunning}
      >
        Pause
      </button>

      <button onClick={handleReset}>
        Reset
      </button>

    </div>
  );
}

export default CountdownTimer;

How to Explain in 1 Minute

"I implemented a countdown timer using React state and an interval. I store the remaining duration as total seconds in timeLeft and use isRunning to control whether the timer is active. When Start is clicked, an effect creates a one-second interval and decreases the remaining time using a functional state update. When the timer reaches zero, I stop it. I also clean up the interval with clearInterval to avoid multiple timers or memory leaks. For the UI, I convert the total seconds into minutes and seconds and format them as MM:SS. I also added Pause and Reset."

How to Explain in 5 Minutes

1. Requirement

The user should see a countdown, start it, pause it, reset it, and receive a completion state when it reaches zero.

2. Data Representation

I store time as a single number representing total seconds. This makes decrementing and reset logic straightforward.

3. Running State

isRunning determines whether an interval should be active. This avoids starting an interval when the timer is paused.

4. Timer Mechanism

I use setInterval(..., 1000) to run the countdown logic once per second.

5. State Update

I use setTimeLeft(prev => prev - 1) because the new value depends on the previous value.

6. Stop Condition

When the timer reaches zero, I make sure it does not become negative and stop the countdown.

7. Cleanup

The interval is cleared inside the effect cleanup function. This is important because timers are external side effects and should not continue unnecessarily.

8. Display

I calculate minutes with Math.floor(timeLeft / 60) and seconds with timeLeft % 60. Then I use padStart(2, "0") for a consistent MM:SS format.

9. Production Improvements

For a production timer where timing accuracy is important, I would consider using an absolute end timestamp such as Date.now() rather than trusting interval callbacks to execute exactly every 1000ms.

Interview mindset: First implement the correct basic timer. Then demonstrate that you understand interval cleanup, stale state, timing drift, and production-level accuracy.

Common Developer Mistakes

1. Creating an interval on every render
Calling setInterval directly in the component body can create multiple intervals. Timer side effects belong inside useEffect.
2. Forgetting clearInterval()
Without cleanup, intervals may continue running and multiple timers can accumulate.
3. Using stale state
Prefer setTimeLeft(prev => prev - 1) when the next value depends on the previous value.
4. Allowing the timer to become negative
Always stop at zero. The UI should never display values such as -1 seconds.
5. Starting multiple intervals
Disable the Start button while running or guard the effect so only one active interval exists.
6. Incorrect dependency handling
A useEffect that manages the timer must have dependencies that correctly represent when the timer should be created or cleaned up.
7. Storing "MM:SS" as the main state
Keeping a formatted string makes arithmetic harder. Store total seconds and derive the display.
8. Assuming setInterval is perfectly accurate
JavaScript timers can be delayed by the event loop. For highly accurate countdowns, calculate remaining time from an end timestamp.
9. Resetting without stopping the timer
Reset should normally clear the running state before restoring the initial duration.

Important Edge Cases

  • Initial duration is zero.
  • User clicks Start multiple times.
  • User clicks Pause immediately after Start.
  • User clicks Reset while the timer is running.
  • Timer reaches exactly zero.
  • Timer should never become negative.
  • Component unmounts while the timer is running.
  • User refreshes or leaves the page during an important countdown.
  • Very long durations such as several hours.
  • Timer needs to remain accurate even when the browser tab is inactive.

Production-Level Improvements

Use an end timestamp
Instead of assuming each interval is exactly one second, calculate remaining time from endTime - Date.now().
Handle browser throttling
Background tabs may delay timer callbacks. Timestamp-based calculations are more reliable.
Persist timer state
Use storage or a backend when the countdown needs to survive refreshes.
Accessibility
Make important countdown changes understandable to screen-reader users without creating excessive announcements.
Reusable props
Accept initial duration, auto-start, callback on completion, and formatting options as props.
Completion callback
Trigger an action such as showing a message, calling an API, or moving to the next question when time expires.
