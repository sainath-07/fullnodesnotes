What?

What is an Image Carousel?

An Image Carousel is a UI component that displays a collection of images one at a time and allows the user to move between them.

For example, an e-commerce website may show multiple product images inside one area instead of displaying every image separately.

Slide 1
One image is visible at a time.
Interview definition: “An image carousel is a reusable component that manages the currently visible slide and provides navigation through previous, next, indicators, and optionally autoplay.”
Why?

What problem does it solve?

Save screen space

Multiple images can be presented inside a single compact UI area.

Better product browsing

Users can quickly move through product, banner, gallery, or promotional images.

Controlled navigation

Previous, next, dots, and keyboard controls provide predictable navigation.

Reusable component

The same component can accept different image arrays and configuration options.

Requirements

What should I implement?

  1. Receive an array of image objects through props.
  2. Display the current image.
  3. Implement Previous and Next buttons.
  4. Loop from the last image back to the first.
  5. Loop from the first image back to the last.
  6. Display clickable dot indicators.
  7. Add optional autoplay.
  8. Pause autoplay when the user hovers over the carousel.
  9. Support keyboard ArrowLeft and ArrowRight navigation.
  10. Clean up timers and event listeners when the component unmounts.
Machine coding strategy: First implement current index + previous/next. Then add indicators. After the core behavior works, add autoplay, pause-on-hover, keyboard support, and polish.
How?

How does it work?

The carousel does not need to store every image in state. The image list comes from props; state only needs to track which image is currently visible.

const [currentIndex, setCurrentIndex] = useState(0);

images[currentIndex]

For the Next button:

setCurrentIndex((prev) =>
  (prev + 1) % images.length
);

For the Previous button:

setCurrentIndex((prev) =>
  (prev - 1 + images.length) % images.length
);
Key idea: The modulo operator % makes the carousel loop safely between 0 and images.length - 1.

React Image Carousel — Interview Version

This version includes navigation, indicators, autoplay, pause-on-hover, keyboard navigation, and timer cleanup.

import { useEffect, useRef, useState } from "react";

const images = [
  {
    id: 1,
    url: "https://picsum.photos/id/1018/1000/600",
    title: "Mountain"
  },
  {
    id: 2,
    url: "https://picsum.photos/id/1015/1000/600",
    title: "River"
  },
  {
    id: 3,
    url: "https://picsum.photos/id/1019/1000/600",
    title: "Nature"
  },
  {
    id: 4,
    url: "https://picsum.photos/id/1025/1000/600",
    title: "Dog"
  }
];

function ImageCarousel({
  images,
  autoPlay = true,
  interval = 3000
}) {
  const [currentIndex, setCurrentIndex] = useState(0);
  const [isPaused, setIsPaused] = useState(false);
  const carouselRef = useRef(null);

  const nextSlide = () => {
    setCurrentIndex((prev) =>
      (prev + 1) % images.length
    );
  };

  const previousSlide = () => {
    setCurrentIndex((prev) =>
      (prev - 1 + images.length) % images.length
    );
  };

  const goToSlide = (index) => {
    setCurrentIndex(index);
  };

  // Autoplay
  useEffect(() => {
    if (!autoPlay || isPaused || images.length <= 1) {
      return;
    }

    const timerId = setInterval(() => {
      nextSlide();
    }, interval);

    return () => {
      clearInterval(timerId);
    };
  }, [autoPlay, interval, isPaused, images.length]);

  // Keyboard navigation
  useEffect(() => {
    const handleKeyDown = (event) => {
      if (event.key === "ArrowRight") {
        nextSlide();
      }

      if (event.key === "ArrowLeft") {
        previousSlide();
      }
    };

    window.addEventListener("keydown", handleKeyDown);

    return () => {
      window.removeEventListener("keydown", handleKeyDown);
    };
  }, []);

  if (!images.length) {
    return <p>No images available.</p>;
  }

  const currentImage = images[currentIndex];

  return (
    <div
      ref={carouselRef}
      className="carousel"
      onMouseEnter={() => setIsPaused(true)}
      onMouseLeave={() => setIsPaused(false)}
      tabIndex={0}
    >

      <div className="image-wrapper">
        <img
          src={currentImage.url}
          alt={currentImage.title}
        />

        <button
          onClick={previousSlide}
          aria-label="Previous image"
          className="previous"
        >
          ←
        </button>

        <button
          onClick={nextSlide}
          aria-label="Next image"
          className="next"
        >
          →
        </button>

        <div className="caption">
          {currentImage.title}
        </div>
      </div>

      <div className="indicators">
        {images.map((image, index) => (
          <button
            key={image.id}
            onClick={() => goToSlide(index)}
            aria-label={`Go to slide ${index + 1}`}
            className={
              index === currentIndex ? "active" : ""
            }
          >
            ●
          </button>
        ))}
      </div>

      <p>
        Slide {currentIndex + 1} of {images.length}
      </p>
    </div>
  );
}

export default function App() {
  return (
    <ImageCarousel
      images={images}
      autoPlay={true}
      interval={3000}
    />
  );
}

Interview Answer

How to explain in 1 minute

“I implemented the image carousel as a reusable React component. The image list is passed through props, and I keep only the current slide index in state. The Previous and Next buttons update that index using the modulo operator so the carousel loops from the last image to the first and vice versa. I also added dot indicators so the user can directly select a slide. For autoplay, I use useEffect with setInterval, and I clear the interval during cleanup to prevent memory leaks. I pause autoplay while the user hovers over the carousel and added keyboard navigation for the left and right arrow keys.”
Interview Answer

How to explain in 5 minutes

  1. Start with the requirement: “The component needs to display one image and allow navigation through a collection.”
  2. Data: “I keep the image data outside the component and pass it through props, making the component reusable.”
  3. State: “The only main state is currentIndex, because the images themselves do not need to be duplicated into state.”
  4. Next: “For Next, I increment the index. The modulo operator wraps the value back to zero after the last slide.”
  5. Previous: “For Previous, I subtract one and add the array length before applying modulo, which avoids a negative index.”
  6. Indicators: “Each indicator calls a function with its index, allowing direct navigation.”
  7. Autoplay: “I use useEffect and setInterval to automatically advance the slide.”
  8. Cleanup: “The effect returns clearInterval so the timer does not continue after unmount or effect changes.”
  9. Pause on hover: “I track hover state and stop autoplay while the user interacts with the carousel.”
  10. Keyboard: “I listen for ArrowLeft and ArrowRight and remove the event listener during cleanup.”
  11. Accessibility: “I provide meaningful alt text and aria-labels for navigation controls.”
Strong closing line: “The main design principle is to keep the data immutable, store only the current index as state, and isolate side effects like timers and event listeners inside useEffect with proper cleanup.”
Debugging

Common Developer Mistakes

Mistake Why it is a problem Better approach
Mutating the image array Can create unexpected state/data behavior. Keep the input data immutable.
Storing all images in state unnecessarily Creates duplicated state. Receive images through props and store only the current index.
Using currentIndex + 1 without wrapping Eventually produces an out-of-range index. Use (index + 1) % images.length.
Previous creates -1 Negative array index does not select the last item. Use (index - 1 + length) % length.
Creating interval outside useEffect A new timer can be created on every render. Create and clean up timers inside useEffect.
Forgetting clearInterval Can leave timers running after unmount. Return cleanup function from the effect.
Forgetting removeEventListener Repeated listeners can accumulate. Remove the listener in effect cleanup.
Autoplay continues while user interacts The slide may change while the user is reading/clicking. Pause autoplay on hover/focus.
Missing alt text Bad accessibility and poor image context. Use meaningful alt text.
Using array index as key when data has stable IDs Can make reconciliation less reliable when lists change. Use a stable image ID as the key.
No empty-array handling images[0] may be undefined. Render a fallback when there are no images.
Not considering rapid button clicks Stale state can cause incorrect navigation in some implementations. Use functional state updates: setCurrentIndex(prev => ...).
Most important mistake: Creating setInterval on every render without cleanup. This can result in multiple timers changing the slide at the same time.

Implementation Explanation

How I implemented it — interviewer flow

1. I started with data

“I created an array of image objects containing an ID, URL, and title.”

2. I created currentIndex

“I used state to track which image is currently visible.”

3. I implemented Next/Previous

“I used modulo arithmetic so navigation wraps around the image array.”

4. I added indicators

“Each indicator maps to an image index and allows direct navigation.”

5. I added autoplay

“I used useEffect with setInterval and returned clearInterval for cleanup.”

6. I added interaction

“I pause autoplay on hover and support keyboard navigation with arrow keys.”

If the interviewer asks: “Why use modulo?”
“Modulo keeps the index within the valid range. If there are four images, (3 + 1) % 4 becomes 0, so the carousel automatically returns to the first image.”
If the interviewer asks: “Why use useEffect?”
“Autoplay and keyboard listeners are side effects. useEffect lets me create them after render and clean them up when dependencies change or the component unmounts.”
If the interviewer asks: “Why not store the current image itself?”
“The index is enough to derive the current image from the source array. Storing both would duplicate information and could create synchronization problems.”
