Frontend Pagination — Machine Coding Round

Build pagination completely on the frontend when the complete data set is already available in the browser.

1. What is Frontend Pagination?
Question

What is frontend-side pagination?

Answer

Frontend pagination means the browser already has the full list of data, but we display only a small number of records at a time.

Simple idea: Keep all data in memory → choose the current page → show only that page's items.

Example: 100 products, 10 products per page = 10 pages.

2. Why Do We Need It?
Question

Why use pagination if the data is already available?

Answer
  • Users can scan a smaller list easily.
  • The page becomes less visually crowded.
  • We avoid rendering hundreds or thousands of rows at once.
  • Navigation becomes predictable: Previous → pages → Next.
Important: Frontend pagination does not reduce network data. If all 10,000 records are downloaded, the browser still receives all 10,000 records.
3. How Does It Work?
Question

How do we calculate which items belong to the current page?

Core formulas

startIndex = (currentPage - 1) × pageSize

endIndex = startIndex + pageSize

currentItems = data.slice(startIndex, endIndex)

Example: Page 3, pageSize 10 → startIndex = (3 - 1) × 10 = 20. So we display indexes 20–29.
4. Important State and Calculations
  • data: complete array received by the frontend.
  • currentPage: currently selected page.
  • pageSize: number of records shown per page.
  • totalPages: number of pages.

totalPages = Math.ceil(data.length / pageSize)

When pageSize changes, reset currentPage to 1 to avoid landing on an invalid page.
5. Full React Code — Machine Coding Answer
import React, { useMemo, useState } from "react";

const data = Array.from({ length: 100 }, (_, index) => ({
  id: index + 1,
  name: `Product ${index + 1}`
}));

function Pagination() {
  const [currentPage, setCurrentPage] = useState(1);
  const [pageSize, setPageSize] = useState(10);

  const totalPages = Math.ceil(data.length / pageSize);

  const currentItems = useMemo(() => {
    const startIndex = (currentPage - 1) * pageSize;
    const endIndex = startIndex + pageSize;

    return data.slice(startIndex, endIndex);
  }, [currentPage, pageSize]);

  const goToPage = (page) => {
    if (page < 1 || page > totalPages) return;
    setCurrentPage(page);
  };

  const handlePageSizeChange = (event) => {
    setPageSize(Number(event.target.value));
    setCurrentPage(1);
  };

  return (
    <div>
      <h2>Products</h2>

      <div>
        <label>Items per page: </label>
        <select
          value={pageSize}
          onChange={handlePageSizeChange}
        >
          <option value={5}>5</option>
          <option value={10}>10</option>
          <option value={20}>20</option>
        </select>
      </div>

      <ul>
        {currentItems.map((item) => (
          <li key={item.id}>
            {item.name}
          </li>
        ))}
      </ul>

      <button
        disabled={currentPage === 1}
        onClick={() => goToPage(currentPage - 1)}
      >
        Previous
      </button>

      {Array.from({ length: totalPages }, (_, index) => {
        const page = index + 1;

        return (
          <button
            key={page}
            onClick={() => goToPage(page)}
            aria-current={currentPage === page ? "page" : undefined}
          >
            {page}
          </button>
        );
      })}

      <button
        disabled={currentPage === totalPages}
        onClick={() => goToPage(currentPage + 1)}
      >
        Next
      </button>
    </div>
  );
}

export default Pagination;
Machine-coding flow: store page state → calculate total pages → calculate start/end → slice data → render current items → handle Previous/Next/page buttons.
6. Common Developer Mistakes
1. Wrong start index: Using currentPage × pageSize skips the first page. Use (currentPage - 1) × pageSize.
2. Wrong page count: Use Math.ceil(), not Math.floor(), otherwise the last partial page disappears.
3. Not disabling Previous/Next: Users can move outside the valid page range.
4. Not resetting page: If page size changes from 10 to 20 while on page 10, page 10 may no longer exist. Reset to page 1.
5. Using array index as data key: Prefer a stable unique ID such as item.id.
6. Confusing frontend pagination with API pagination: Frontend pagination slices already-loaded data. API pagination asks the server for only one page.
7. Rendering thousands of page buttons: For very large datasets, show a compact range such as 1, 2, 3, ..., 50 instead of every page button.
8. Mutating the original array: Use slice() for selecting records; do not modify the source data just to paginate it.

How I Would Explain My Implementation to the Interviewer

Interviewer-ready explanation:

“I am implementing client-side pagination because the complete dataset is already available on the frontend. I keep the data unchanged and maintain two pieces of UI state: the current page and the page size. From these values, I calculate the total number of pages. For the selected page, I calculate the starting index using (currentPage - 1) * pageSize, then use slice() to select only the records that should be displayed. Previous and Next buttons update the page while boundary checks prevent invalid pages. If the page size changes, I reset the current page to 1. For list rendering, I use a stable unique ID as the React key.”

Edge Cases Interviewers May Test
  • Empty data array.
  • Only one page.
  • Total records not divisible by page size.
  • User clicks Previous on page 1.
  • User clicks Next on the last page.
  • Changing page size while on a later page.
  • Very large number of pages.
  • Search/filter changes the total number of records.

Remember: Pagination controls how much data is displayed per page. Virtualization controls how many DOM elements are mounted at once. They solve different problems and can be combined.
