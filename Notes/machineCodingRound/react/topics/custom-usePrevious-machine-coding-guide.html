Custom usePrevious Hook

Build a reusable React hook that gives you the value from the previous render.

What is Custom usePrevious?
Definition

usePrevious is a custom React hook used to remember the value from the previous render.

Layman example: Imagine a scoreboard. The current score is 20, but you also want to know what the score was before the latest update. usePrevious keeps that previous value available.

Example:

const [count, setCount] = useState(0);

const previousCount = usePrevious(count);

Why Do We Need usePrevious?

React gives us the current state or prop value, but sometimes we need to compare the current value with the value from the previous render.

  • Compare current and previous state.
  • Detect whether a value changed.
  • Show "increased/decreased" behavior.
  • Compare previous and current props.
  • Track previous search/filter values.
  • Build reusable logic instead of repeating previous-value code.
Simple idea: useState gives you the current value. usePrevious helps you remember the value from the previous render.
What Problem Does It Solve?

Suppose a counter changes:

Previous: 10
→
Current: 15

The component may want to know:

  • Did the value increase?
  • Did it decrease?
  • What was the old value?
  • Should I show a transition or message?
if (count > previousCount) {
  // count increased
}
Important: The hook is about remembering the value from the previous render, not about creating a second piece of React state.

Full Code
usePrevious.js
import { useEffect, useRef } from "react";

function usePrevious(value) {
  const ref = useRef();

  useEffect(() => {
    ref.current = value;
  }, [value]);

  return ref.current;
}

export default usePrevious;
App.jsx — Example Usage
import { useState } from "react";
import usePrevious from "./usePrevious";

function App() {
  const [count, setCount] = useState(0);

  const previousCount = usePrevious(count);

  return (
    <div>
      <h2>Current: {count}</h2>
      <h3>
        Previous: {previousCount ?? "No previous value"}
      </h3>

      <button onClick={() => setCount(count + 1)}>
        Increase
      </button>

      <button onClick={() => setCount(count - 1)}>
        Decrease
      </button>
    </div>
  );
}

export default App;
Result: First render → previous is undefined. After clicking Increase → current becomes 1, previous is 0. Next click → current 2, previous 1.
Step-by-Step Code Walkthrough
1. Create the custom hook
function usePrevious(value) {

The hook accepts the value whose previous version we want to remember.

2. Create persistent storage
const ref = useRef();

The ref survives React renders. Initially, ref.current is undefined.

3. Save the current value after render
useEffect(() => {
  ref.current = value;
}, [value]);

The effect runs after the render commits. It stores the current value for the next render.

4. Return the previous value
return ref.current;

Because the assignment happens in the effect after render, the returned value during the current render is the value saved from the previous render.

Practical Example — Detect Increase or Decrease
const [price, setPrice] = useState(100);
const previousPrice = usePrevious(price);

let message = "No previous value";

if (previousPrice !== undefined) {
  if (price > previousPrice) {
    message = "Price increased";
  } else if (price < previousPrice) {
    message = "Price decreased";
  } else {
    message = "Price did not change";
  }
}

Common Developer Mistakes
1. Using useState for the previous value unnecessarily
This can introduce extra state updates and re-renders. A ref is usually a better fit for simply remembering a value.
2. Updating ref.current during render
Do not write ref.current = value before returning the previous value. That would overwrite the old value too early.
3. Forgetting useEffect
The common pattern relies on storing the current value after render. Without the effect, the previous-value timing is incorrect.
4. Wrong dependency array
Use [value] so the stored value is updated when the tracked value changes.
5. Expecting a previous value on the first render
There is no earlier render value, so the initial result is normally undefined.
6. Assuming useRef causes re-render
Changing ref.current does not trigger a render. React will update the UI only when some render-triggering event occurs.
7. Confusing previous render with previous event
The hook tracks the value from the previous committed render, not necessarily the previous button click or API response.
8. Ignoring object identity
If the tracked value is an object, the effect dependency checks its reference identity. A newly created equivalent object can still count as a changed dependency.
How I Would Explain It to the Interviewer

"I will build a reusable usePrevious hook that accepts a value and returns that value from the previous render. I'll use useRef because the ref persists across renders without causing a re-render when its current property changes. During render, I first return the existing ref.current. Then, inside useEffect, I store the current value into ref.current. Because the effect runs after the render, the next render can read the value that was current during the previous render. On the first render there is no previous value, so it returns undefined."

Edge Cases & Testing
  • First render: previous value should be undefined.
  • Number: verify 10 → 20 → 30 returns undefined → 10 → 20.
  • String: verify previous text is returned correctly.
  • Boolean: verify false → true.
  • Object: understand reference identity when object references change.
  • Rapid updates: verify the displayed previous value follows committed renders.
  • Same value: understand that no meaningful dependency change occurs when the primitive value remains the same.
Machine-round tip: Test the sequence 0 → 1 → 2 → 3 and explain exactly what the hook returns on each render. This demonstrates that you understand the timing rather than just memorizing the code.
