Custom useLocalStorage Hook

Build a reusable React hook that keeps state synchronized with browser localStorage.

What is a Custom useLocalStorage Hook?
Definition

A custom useLocalStorage hook is a reusable React hook that behaves like useState, but also saves the value in the browser's localStorage.

Layman example: useState is like writing a note on a temporary whiteboard. localStorage is like writing the same note in a notebook that remains after you leave the room.

When the page is refreshed, the hook reads the previously stored value and restores it.

Why create a custom hook?

Without a custom hook, every component would repeat the same logic:

  • Read from localStorage.
  • Parse the stored JSON.
  • Keep React state.
  • Write updated state back to storage.
  • Handle invalid or missing data.
Goal: Put this repeated logic in one reusable hook and use it anywhere with const [value, setValue] = useLocalStorage(key, initialValue).

What problem does it solve?

React state normally disappears when the page is refreshed. localStorage lets us persist small pieces of client-side data.

Full Code
useLocalStorage.js
import { useEffect, useState } from "react";

function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    try {
      const storedValue = localStorage.getItem(key);

      if (storedValue !== null) {
        return JSON.parse(storedValue);
      }

      return initialValue;
    } catch (error) {
      console.error("Failed to read localStorage:", error);
      return initialValue;
    }
  });

  useEffect(() => {
    try {
      localStorage.setItem(key, JSON.stringify(value));
    } catch (error) {
      console.error("Failed to write localStorage:", error);
    }
  }, [key, value]);

  return [value, setValue];
}

export default useLocalStorage;
App.jsx — Example Usage
import useLocalStorage from "./useLocalStorage";

function App() {
  const [name, setName] = useLocalStorage("userName", "");

  return (
    <div>
      <h2>Hello, {name || "Guest"}</h2>

      <input
        value={name}
        onChange={(e) => setName(e.target.value)}
        placeholder="Enter your name"
      />
    </div>
  );
}

export default App;
Result: Type a name → state updates → effect stores it → refresh the page → the name is restored.
Step-by-Step Code Walkthrough
1. Function accepts a key and initial value
function useLocalStorage(key, initialValue) {

key identifies the storage item. initialValue is used when nothing exists yet.

2. Lazy state initialization
useState(() => {
  const storedValue = localStorage.getItem(key);
  ...
});

The function reads storage when React initializes the state. Lazy initialization avoids putting the read expression directly into every render.

3. Convert JSON back to JavaScript
return JSON.parse(storedValue);

localStorage stores strings. JSON lets us persist objects, arrays, numbers, booleans, and strings in a consistent way.

4. Save when state changes
useEffect(() => {
  localStorage.setItem(key, JSON.stringify(value));
}, [key, value]);

The effect runs after React commits a render where key or value changed.

5. Return the same API as useState
return [value, setValue];

This makes the custom hook easy to adopt because components use it almost exactly like useState.

Common Developer Mistakes
1. Forgetting JSON.stringify()
localStorage.setItem(key, value) converts data to a string. For objects/arrays, explicitly use JSON.stringify(value).
2. Forgetting JSON.parse()
If you store an object as JSON and retrieve it without parsing, you get a string instead of the original object.
3. Reading storage on every render
Do not blindly call localStorage.getItem() as the direct state value on every render. Use lazy initialization.
4. Missing effect dependencies
If the key/value are omitted from the dependency array, updates can become stale or fail to persist as expected.
5. No error handling
JSON.parse() can fail if stored data is malformed. Storage can also fail due to browser restrictions or quota limits.
6. Using it for sensitive data
localStorage is accessible to JavaScript running on the page. Treat it as client-side storage, not a secure vault.
7. Ignoring SSR environments
In environments such as Next.js server rendering, localStorage is not available on the server. Browser-only access must be handled appropriately.
8. Forgetting the initial-value behavior
When no saved value exists, return the provided initialValue.
How I Would Explain It to the Interviewer

"I would create a reusable custom hook called useLocalStorage. The hook accepts a storage key and an initial value. During state initialization, I first check whether that key already exists in localStorage. If it exists, I parse the stored JSON and use it as the initial state; otherwise, I use the provided initial value. Then I use useEffect to synchronize the latest React state back to localStorage whenever the key or value changes. Finally, I return [value, setValue], so the component can use it almost like the normal useState hook. I also add error handling for malformed JSON and storage failures."

  2. "I'll use lazy initialization so I can read the saved value while initializing state."
  3. "Because localStorage stores strings, I'll use JSON.parse and JSON.stringify."
  4. "I'll synchronize changes with useEffect."
  5. "I'll return the state and setter so the API looks like useState."
  6. "Finally, I'll test refresh behavior and invalid storage data."
Edge Cases to Test
  • No existing storage key → use initialValue.
  • Stored string value → restore correctly.
  • Stored object/array → parse correctly.
  • Malformed JSON → catch error and use fallback.
  • State changes multiple times → storage stays synchronized.
  • Page refresh → persisted value should be restored.
  • Storage key changes → new key should be used.
Machine-round tip: After coding, demonstrate at least one refresh test. It proves the persistence requirement rather than only showing code.
