1. What is a Custom useFetch Hook?

Definition: A custom useFetch hook is a reusable React function that contains common API-fetching logic such as making a request, storing the response, tracking loading state and handling errors.

Layman example: Imagine you order food from a restaurant. Instead of every customer learning how to call the restaurant, wait for the food and handle “restaurant closed” errors, one helper can manage the whole process. Different pages can use the same helper.
Request
Call API using a URL.
Response
Store returned data.
Status
Track loading and error.

The hook hides repetitive fetching logic from UI components and exposes a simple interface such as { data, loading, error }.

2. What Problem Does It Resolve?

Without a custom hook, multiple components may repeat the same useEffect, fetch(), loading state and error handling code.

Without useFetch
Users, Products, Orders and Posts components can each contain duplicated API logic.
With useFetch
One reusable hook handles the common request lifecycle.
Problem solved: It reduces duplicate code and gives different components a consistent way to handle API requests.

♻️ Reuse

4. How Does useFetch Work?
  1. Component calls useFetch(url).
  2. The hook initializes data, loading and error.
  3. useEffect starts the request when the URL changes.
  4. Set loading to true.
  5. Call fetch(url).
  6. Check whether the HTTP response is successful.
  7. Convert the response to JSON.
  8. Store the data.
  9. If something fails, store an error.
  10. Set loading back to false.
  11. Return the state to the component.
Core idea: useFetch is a reusable stateful function. It manages the API request lifecycle, while the component decides how to display the result.

7. Full React Code
useFetch.js
import { useEffect, useState } from "react";

function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controller = new AbortController();

    const fetchData = async () => {
      try {
        setLoading(true);
        setError(null);

        const response = await fetch(url, {
          signal: controller.signal
        });

        if (!response.ok) {
          throw new Error(
            `Request failed: ${response.status}`
          );
        }

        const result = await response.json();

        setData(result);
      } catch (err) {
        if (err.name !== "AbortError") {
          setError(err.message);
        }
      } finally {
        setLoading(false);
      }
    };

    fetchData();

    return () => {
      controller.abort();
    };
  }, [url]);

  return {
    data,
    loading,
    error
  };
}

export default useFetch;
App.jsx — Using the Hook
import useFetch from "./useFetch";

function App() {
  const {
    data,
    loading,
    error
  } = useFetch(
    "https://jsonplaceholder.typicode.com/users"
  );

  if (loading) {
    return <h2>Loading...</h2>;
  }

  if (error) {
    return <h2>Error: {error}</h2>;
  }

  return (
    <div>
      <h1>Users</h1>

      {data?.map((user) => (
        <div key={user.id}>
          {user.name}
        </div>
      ))}
    </div>
  );
}

export default App;

8. Why useEffect?

Fetching data is a side effect. React's useEffect is used to perform side effects after rendering and when dependencies change.

Dependency
[url]
Run the request when the URL changes.
Cleanup
controller.abort()
Cancel the previous request when necessary.
Important: Do not call fetch() directly during the component's render. Rendering should remain predictable; side effects belong in an effect or another appropriate event-driven mechanism.

9. Why AbortController?

Definition: AbortController lets us cancel an in-progress fetch request.

Layman example: Imagine you ask a waiter for Product A information, but before the waiter returns, you change your mind and ask for Product B. You do not want the old Product A response to unnecessarily continue.
User requests URL A
  ↓
Request A starts
  ↓
User changes URL
  ↓
Cleanup runs
  ↓
Abort request A
  ↓
Request B starts
Interview point: Aborting stale requests reduces unnecessary work and helps prevent outdated responses from affecting the UI.
10. Common Developer Mistakes
1. Forgetting the dependency array
Without correct dependencies, the request may run repeatedly or fail to run when the URL changes.
2. Fetching during render
Do not make API calls directly in the component body. Use useEffect for this side effect.
3. Not handling HTTP errors
fetch() does not automatically reject for HTTP 404 or 500. Check response.ok or the status code.
4. Forgetting loading state
Users need feedback while a request is in progress.
5. Forgetting error state
Network failures and unsuccessful HTTP responses should produce useful UI feedback.
6. Updating state after stale requests
Use AbortController or another race-condition strategy when requests can overlap.
7. Incorrect cleanup
Abort the controller in the effect cleanup and ignore the expected AbortError.
8. Making the hook too specific
Hard-coding one API or one response shape reduces reusability. Keep the basic hook generic.
9. Overusing useFetch
For complex applications, a dedicated server-state library may provide caching, retries, invalidation and deduplication that a small custom hook does not.
11. How I Would Explain My Implementation to the Interviewer
Interview explanation:

“I created a reusable custom hook called useFetch to centralize API request logic. The hook accepts a URL and internally manages data, loading and error state. I use useEffect because fetching is a side effect, and the URL is a dependency so the request runs whenever it changes. I check response.ok because fetch does not reject automatically for HTTP error statuses. I also use AbortController in the cleanup function to cancel stale requests. The component only consumes the returned data, loading and error states, so the UI code stays clean.”

  8. Output: “The hook returns an object consumed by the component.”
Strong interview line: “I am separating data-fetching concerns from presentation concerns so multiple components can reuse the same request lifecycle logic.”
12. Common Follow-Up Questions

It is a reusable JavaScript function whose name starts with use and which can call React hooks such as useState and useEffect.

The Fetch API generally resolves its promise for HTTP responses such as 404 or 500. Checking response.ok lets the hook convert unsuccessful HTTP statuses into an application error.

Keep the fetch logic inside a function and expose a state value such as reloadKey. Incrementing it can trigger the effect again, or the hook can expose a stable refetch function.

Accept a request options object containing method, headers and body, or separate read and mutation hooks depending on the application's complexity.

A basic custom hook does not need to implement caching. For production applications with complex server state, libraries such as TanStack Query can provide caching, retries, invalidation and request deduplication.

It can happen when multiple requests overlap and an older request finishes after a newer request, potentially replacing fresh data with stale data. Cancellation or request identity checks can help.
