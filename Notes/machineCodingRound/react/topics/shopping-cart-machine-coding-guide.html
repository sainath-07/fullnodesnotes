Shopping Cart in React

Build a reusable shopping cart with add, remove, quantity update, subtotal, and total calculation.

What is a Shopping Cart?
Definition

A shopping cart is a UI feature that lets users collect products they want to buy, change quantities, remove products, and see the calculated amount before checkout.

Layman example: Think about a physical supermarket basket. You put products into the basket, increase or decrease how many you want, remove products you changed your mind about, and finally check the total bill.
Typical cart data
[
  {
    id: 1,
    title: "Wireless Headphones",
    price: 2000,

  {

Why is a Shopping Cart Needed?
  • Users can select multiple products before checkout.
  • Users can change product quantity.
  • Users can remove unwanted products.
  • The UI can calculate subtotal and total dynamically.
  • Cart state can be shared across product and cart screens.
Machine-round goal: Show that you can manage state, update arrays immutably, render lists, handle user actions, and derive calculated values from state.
Requirements to Clarify Before Coding

How Should I Manage Cart State?

For a small machine coding problem, local component state is enough. If multiple distant components need the cart, Context API or a state library can be introduced.

Full Code — React Shopping Cart
App.jsx
import { useMemo, useState } from "react";

const products = [
  { id: 1, title: "Wireless Headphones", price: 2000 },
  { id: 2, title: "Keyboard", price: 1500 },
  { id: 3, title: "Mouse", price: 800 },
  { id: 4, title: "Monitor", price: 12000 }
];

function App() {
  const [cart, setCart] = useState([]);

  const addToCart = (product) => {
    setCart((currentCart) => {
      const existingItem = currentCart.find(
        (item) => item.id === product.id
      );

      if (existingItem) {
        return currentCart.map((item) =>
          item.id === product.id
            ? { ...item, quantity: item.quantity + 1 }
            : item
        );
      }

      return [...currentCart, { ...product, quantity: 1 }];
    });
  };

  const increaseQuantity = (id) => {
    setCart((currentCart) =>
      currentCart.map((item) =>
        item.id === id
          ? { ...item, quantity: item.quantity + 1 }
          : item
      )
    );
  };

  const decreaseQuantity = (id) => {
    setCart((currentCart) =>
      currentCart
        .map((item) =>
          item.id === id
            ? { ...item, quantity: item.quantity - 1 }
            : item
        )
        .filter((item) => item.quantity > 0)
    );
  };

  const removeFromCart = (id) => {
    setCart((currentCart) =>
      currentCart.filter((item) => item.id !== id)
    );
  };

  const totalItems = useMemo(
    () => cart.reduce((sum, item) => sum + item.quantity, 0),
    [cart]
  );

  const totalAmount = useMemo(
    () =>
      cart.reduce(
        (sum, item) => sum + item.price * item.quantity,
        0
      ),
    [cart]
  );

  return (
    <div className="container py-4">
      <h1>Shopping Cart</h1>

      <h3 className="mt-4">Products</h3>

      <div>
        {products.map((product) => (
          <div key={product.id}>
            <span>{product.title} - ₹{product.price}</span>

            <button onClick={() => addToCart(product)}>
              Add to Cart
            </button>
          </div>
        ))}
      </div>

      <hr />

      <h3>Cart ({totalItems} items)</h3>

      {cart.length === 0 ? (
        <p>Your cart is empty.</p>
      ) : (
        <>
          {cart.map((item) => (
            <div key={item.id}>
              <strong>{item.title}</strong>
              <p>₹{item.price} × {item.quantity}</p>

              <button onClick={() => decreaseQuantity(item.id)}>
                -
              </button>

              <span> {item.quantity} </span>

              <button onClick={() => increaseQuantity(item.id)}>
                +
              </button>

              <button onClick={() => removeFromCart(item.id)}>
                Remove
              </button>
            </div>
          ))}

          <h3>Total: ₹{totalAmount}</h3>

          <button>Checkout</button>
        </>
      )}
    </div>
  );
}

export default App;
Core operations: find() checks whether an item exists, map() updates an item, filter() removes an item, and reduce() calculates totals.
Step-by-Step Code Walkthrough
1. Start with empty cart state
const [cart, setCart] = useState([]);

The cart is an array because it contains multiple products.

2. Add a product
const existingItem = currentCart.find(
  (item) => item.id === product.id
);

First check whether the product already exists. This prevents duplicate rows for the same product.

3. Increase duplicate quantity
return currentCart.map((item) =>
  item.id === product.id
    ? { ...item, quantity: item.quantity + 1 }
    : item
);

map() creates a new array. Only the matching product gets a new object with an increased quantity.

4. Add a new product
return [...currentCart, { ...product, quantity: 1 }];

The spread operator creates a new array and adds the product with quantity 1.

5. Remove a product
setCart((currentCart) =>
  currentCart.filter((item) => item.id !== id)
);
6. Calculate the total
cart.reduce(
  (sum, item) => sum + item.price * item.quantity,
  0
);

For every item, calculate price × quantity and add it to the running total.

7. Why functional state updates?
setCart((currentCart) => {
  // calculate the next state from currentCart
});

This is safer when the next state depends on the previous state, especially when multiple updates may be queued.

Common Developer Mistakes
1. Mutating state directly
Bad: item.quantity++ on the existing state object. Prefer creating a new object with { ...item, quantity: item.quantity + 1 }.
2. Adding duplicate product rows
Clicking Add twice should normally increase quantity rather than create two separate rows for the same product.
3. Using array index as the React key
Use a stable product ID such as key={item.id}.
4. Incorrect total calculation
Total should normally be price × quantity for each item, then summed.
5. Allowing quantity to become 0 or negative
Decide the rule clearly. This implementation removes the item when quantity falls below 1.
6. Mixing derived state with source state
Do not unnecessarily store totalAmount separately when it can be calculated from cart. This avoids stale totals.
7. Forgetting the empty state
Always handle cart.length === 0 with a useful message or empty-cart UI.
8. Over-engineering too early
For a small machine round, start with useState. Add Context, Redux, API calls, persistence, or backend synchronization only when requirements need them.
9. Trusting client-side prices for payment
The UI can calculate a display total, but a real checkout should validate prices, stock, discounts, and the final amount on the server.
How I Would Explain It to the Interviewer

"First, I'll clarify the cart requirements: add products, prevent duplicate product rows by increasing quantity, increase and decrease quantity, remove products, show an empty state, and calculate the total. I'll keep the cart array as the single source of truth. When adding a product, I'll use find() to check whether it already exists. If it exists, I'll use map() to increase its quantity; otherwise I'll append a new item with quantity 1. For removing, I'll use filter(). The total is derived using reduce() rather than stored separately. I will update state immutably and use stable product IDs as React keys. After the basic version works, I'll test duplicate adds, quantity boundaries, removal, empty state, and total calculation."

How Can I Improve It?
  1. Persistence: Sync the cart with localStorage so refresh does not lose it.
  2. Global state: Use Context API or Redux Toolkit when many components need cart state.
  3. API integration: Load products from a backend instead of a hard-coded array.
  4. Validation: Check stock and current server-side prices before checkout.
  5. Performance: Avoid unnecessary calculations and component re-renders when the cart grows.
  6. UX: Add loading states, disabled quantity controls, confirmation feedback, and an accessible checkout flow.
Interview strategy: Finish the required version first. Then explain these as possible extensions instead of trying to implement every feature before the core cart works.
