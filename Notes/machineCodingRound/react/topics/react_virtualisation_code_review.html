1. What Your Virtualisation Is Doing

Virtualisation means we do not render every item in a large list. If there are 10,000 products, the user may see only 10–20 at a time. We render the visible products plus a few extra products called overscan.

↓
Calculate visible indexes
↓
Render visible items + overscan
Key idea: The browser still gets a large inner scroll area, but React creates DOM elements only for the small portion currently needed.

3. How the Calculation Works

Step 1 — Find the first visible index
const firstVisibleIndex = Math.floor(
  scrollTop / ITEM_HEIGHT
);

If scrollTop = 200 and each row is 50px:

200 / 50 = 4
firstVisibleIndex = 4
Step 2 — Find how many rows fit
const visibleItemCount = Math.ceil(
  CONTAINER_HEIGHT / ITEM_HEIGHT
);
500 / 50 = 10 rows
Step 3 — Add overscan
const startIndex = Math.max(
  0,
  firstVisibleIndex - OVERSCAN
);

const endIndex = Math.min(
  PRODUCTS.length,
  firstVisibleIndex + visibleItemCount + OVERSCAN
);

For index 20, 10 visible rows and overscan 5:

startIndex = 15
endIndex   = 35
Why overscan? We render a few rows outside the viewport so a fast scroll does not immediately expose an empty area.
Step 4 — Create the full virtual height
const totalHeight = PRODUCTS.length * ITEM_HEIGHT;

For 100 products × 50px = 5000px. This creates the space for the full virtual list without creating 100 DOM rows.

4. Improved Version of Your Code

This version keeps your manual approach because it is useful for learning how virtualisation works internally.
import React, { useMemo, useState } from "react";

const PRODUCTS = Array.from({ length: 100 }, (_, index) => ({
  id: index + 1,
  label: `Product ${index + 1}`,
}));

// The visible scrolling area.
const CONTAINER_HEIGHT = 500;

// IMPORTANT: This algorithm assumes every item has the same height.
const ITEM_HEIGHT = 50;

// Render a few extra items above and below the viewport.
// This improves the visual experience during fast scrolling.
const OVERSCAN = 5;

const Virtualisation = () => {
  const [scrollTop, setScrollTop] = useState(0);

  // Convert the scroll position in pixels into an item index.
  // Example: 200px / 50px = index 4.
  const firstVisibleIndex = Math.floor(
    scrollTop / ITEM_HEIGHT
  );

  // How many complete rows can fit in the viewport?
  const visibleItemCount = Math.ceil(
    CONTAINER_HEIGHT / ITEM_HEIGHT
  );

  // Start before the viewport by OVERSCAN rows.
  // Math.max prevents a negative start index.
  const startIndex = Math.max(
    0,
    firstVisibleIndex - OVERSCAN
  );

  // Stop after the viewport by OVERSCAN rows.
  // Math.min prevents going beyond the array length.
  const endIndex = Math.min(
    PRODUCTS.length,
    firstVisibleIndex + visibleItemCount + OVERSCAN
  );

  // Only this small section is rendered.
  // useMemo is optional here because slice() is inexpensive,
  // but it is kept to make the virtual window explicit.
  const visibleProducts = useMemo(() => {
    return PRODUCTS.slice(startIndex, endIndex);
  }, [startIndex, endIndex]);

  // Reserve space for the complete list.
  // We reserve the space; we do NOT render every product.
  const totalHeight = PRODUCTS.length * ITEM_HEIGHT;

  return (
    <div
      style={{
        width: "min(100%, 500px)",
        height: CONTAINER_HEIGHT,
        overflowY: "auto",
        border: "1px solid #0c7ae8",
        borderRadius: "12px",
        background: "#f8fafc",
      }}
      onScroll={(event) => {
        // scrollTop tells us how far the user has scrolled.
        setScrollTop(event.currentTarget.scrollTop);
      }}
    >
      {/*
        This element creates the complete virtual scroll space.

        Example:
        100 products × 50px = 5000px.

        The browser gets a scrollbar for this full height,
        even though only a small number of rows are rendered.
      */}
      <div
        style={{
          height: totalHeight,
          position: "relative",
        }}
      >
        {visibleProducts.map((product, index) => {
          // index is the index inside the sliced array.
          // actualIndex is the index inside the original array.
          //
          // Example:
          // startIndex = 15
          // index = 0
          // actualIndex = 15
          const actualIndex = startIndex + index;

          return (
            <div
              key={product.id}
              style={{
                position: "absolute",

                // Put this row at its real position
                // inside the complete virtual list.
                top: actualIndex * ITEM_HEIGHT,

                left: 0,
                right: 0,
                height: ITEM_HEIGHT,

                boxSizing: "border-box",
                display: "flex",
                alignItems: "center",
                padding: "0 14px",

                background: "#dad6aa",
                border: "1px solid #c2a8a8",
                borderRadius: "8px",
                fontSize: "18px",
                fontWeight: "700",
              }}
            >
              {product.label}
            </div>
          );
        })}
      </div>
    </div>
  );
};

export default Virtualisation;
Why this version is better: The algorithm is still yours. The names are clearer, the key uses the stable ID, margin is removed from the virtual coordinate system, and comments explain both what each part does and why it exists.

5. Changes Made and Why

1. product.label → product.id
// Before
key={product.label}

// Better
key={product.id}

A product ID is a stable unique identifier. The label is display text and may change.

2. Better variable names
firstIndexValue  → firstVisibleIndex
visibleListCount → visibleItemCount
start            → startIndex
end              → endIndex
getProductList   → visibleProducts
ITEMS_HEIGHT     → ITEM_HEIGHT

Good names make the algorithm easier to understand without reading every line.

3. Removed the inner margin

Your original code has margin: "12px". The calculation says a row is positioned every 50px. Extra spacing can make the visual layout disagree with the mathematical position. The improved version uses a simpler coordinate system.

4. Changed <p> to <div>

The row is a visual container, so div is a clearer choice. If this represents an actual semantic list, you can also use ul and li with suitable styling.

5. Changed overflowY: "scroll" to "auto"

auto allows the browser to show the scrollbar when it is needed. This is mostly a UI improvement; your original approach also works.

6. Removed development logging

Your console.log() is useful while learning. However, scroll events can happen many times, so it should normally be removed after debugging.

One thing I did not change: I kept useMemo. It is not required for this small slice(), but keeping it is reasonable while learning. Later, learn when memoisation actually helps instead of using it automatically.

7. Interview Tips

Q: What problem does virtualisation solve?
It reduces the number of DOM elements created for a large list. This can improve rendering and scrolling performance.
Q: Why create a large inner container?
It preserves the scrollbar and total scrollable space for the complete list while only a small window is rendered.
Q: Why use absolute positioning?
Because every rendered item must appear at its correct location in the full virtual list.
Q: Why is fixed height important?
Because the simple formula index × ITEM_HEIGHT assumes every row has the same height.
Q: What is overscan?
Rendering a few items outside the viewport so scrolling feels smoother.
Q: Why use product.id as the key?
It is a stable unique identifier and is better suited for React's list reconciliation than display text.
Interview-ready explanation: “Virtualisation renders only the items needed for the current viewport, plus a small buffer, while a large inner container preserves the full scrollable height.”
