Question

Implement a Debounce Feature in React

Create a reusable custom hook called useDebounce. Use this hook in a React component so that an action, such as a search API call, happens only after the user stops typing for a specified amount of time.

Machine coding requirement: Do not write the debounce timer logic directly inside the search component. Create a separate useDebounce hook and reuse it.
Example requirement
  • User types continuously.
  • Every new keystroke should reset the waiting time.
  • When the user stops typing for 500 ms, the latest value should be returned.
  • The component can then use that value to call an API or perform another action.

Answer

Step 1 — Create useDebounce
import { useEffect, useState } from "react";

function useDebounce(value, delay = 500) {
  const [debouncedValue, setDebouncedValue] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => {
      setDebouncedValue(value);
    }, delay);

    return () => {
      clearTimeout(timer);
    };
  }, [value, delay]);

  return debouncedValue;
}

export default useDebounce;
Step 2 — Reuse the hook
import { useEffect, useState } from "react";
import useDebounce from "./useDebounce";

function Search() {
  const [search, setSearch] = useState("");

  const debouncedSearch = useDebounce(search, 500);

  useEffect(() => {
    if (!debouncedSearch.trim()) return;

    console.log("API call:", debouncedSearch);

    // fetch(
    //   `/api/search?q=${encodeURIComponent(debouncedSearch)}`
    // );
  }, [debouncedSearch]);

  return (
    <input
      value={search}
      onChange={(e) => setSearch(e.target.value)}
      placeholder="Search..."
    />
  );
}

export default Search;
Important: The hook is responsible for waiting and returning the debounced value. The component is responsible for deciding what to do with that value.

How I Have Implemented This — Explanation to Interviewer

Interview-ready answer

“I separated the debounce logic into a reusable useDebounce custom hook. The hook accepts the current value and a delay. Whenever the value changes, I create a new timer. If another value arrives before the timer finishes, the cleanup function clears the previous timer. Once the user stops changing the value for the configured delay, the timer completes and I update the debounced value. The component consumes that debounced value and uses it to trigger the required action, such as an API call.”

Why use a separate custom hook?
  • Reusable: the same debounce behavior can be used in many components.
  • Clean component: the component does not contain timer-management code.
  • Easy to configure: the delay can be passed as an argument.
  • Separation of responsibility: the hook handles debounce; the component handles business logic.
What does cleanup do?

The cleanup function runs before the effect runs again because the dependency changed. It calls clearTimeout(timer), which removes the previous pending timer. Then a fresh timer is created for the latest value.

One-line explanation: “Every new input cancels the previous waiting timer, and only the latest value is emitted after the user becomes idle for the configured delay.”

Common Developer Mistakes

1. Forgetting clearTimeout

If the old timer is not cleared, multiple timers can complete. The debounce behavior will not work correctly.

2. Putting debounce logic directly inside every component

This duplicates code. If debounce is needed in multiple places, create and reuse useDebounce.

3. Putting API logic inside the generic hook

A reusable value-based debounce hook should normally return the debounced value. Let the component decide whether to call an API or perform another action.

4. Forgetting the dependency array

Use [value, delay] so the effect responds to changes in the value or delay.

5. Not handling empty search input

For search features, check trim() and decide whether an empty search should clear results or avoid an API call.

6. Thinking debounce prevents API race conditions

Debounce controls how frequently requests start. If multiple requests can overlap, an older response can still arrive later. Use stale-response protection or AbortController when required.

7. Using an unsuitable delay

A very short delay may create too many requests. A very long delay can make the UI feel slow. For search, a value around 300–500 ms is a common starting point, then adjust based on the product requirement.

useDebounce.js
import { useEffect, useState } from "react";

function useDebounce(value, delay = 500) {
  const [debouncedValue, setDebouncedValue] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => {
      setDebouncedValue(value);
    }, delay);

    return () => {
      clearTimeout(timer);
    };
  }, [value, delay]);

  return debouncedValue;
}

export default useDebounce;
Search.jsx
import { useEffect, useState } from "react";
import useDebounce from "./useDebounce";

function Search() {
  const [search, setSearch] = useState("");

  const debouncedSearch = useDebounce(search, 500);

  useEffect(() => {
    if (!debouncedSearch.trim()) {
      return;
    }

    async function searchProducts() {
      try {
        const response = await fetch(
          `/api/search?q=${encodeURIComponent(debouncedSearch)}`
        );

        if (!response.ok) {
          throw new Error("Request failed");
        }

        const data = await response.json();
        console.log(data);
      } catch (error) {
        console.error(error);
      }
    }

    searchProducts();
  }, [debouncedSearch]);

  return (
    <div>
      <input
        value={search}
        onChange={(e) => setSearch(e.target.value)}
        placeholder="Search products..."
      />
    </div>
  );
}

export default Search;
