1. What is a Multi-Step Form?

A multi-step form divides one large form into smaller screens or steps.

Instead of showing 10–20 fields at once, we show a few related fields, let the user complete them, and then move to the next step.

Simple definition for interview: “A multi-step form breaks a large form into smaller steps and keeps the user's entered data while navigating between those steps.”
2. Why do we need a Multi-Step Form?
Problem
Large forms can look overwhelming and difficult to complete.
Better UX
Related fields can be grouped into meaningful steps.
Controlled flow
We can validate each step before allowing the user to continue.

Typical examples: signup, checkout, onboarding, job applications, profile creation and registration.

Simple execution flow
  1. Keep a step state to know which screen is visible.
  2. Keep one object such as formData for all form values.
  3. When an input changes, update only that field.
  4. When Next is clicked, validate the current step.
  5. If valid, increase step.
  6. On Back, decrease step without deleting entered data.
  7. On the final step, submit the complete formData.
4. State Design — the important React part

For a simple machine-coding solution, two main pieces of state are enough:

const [step, setStep] = useState(1);

step decides which form screen should be displayed.

const [formData, setFormData] = useState({
  name: "",
  email: "",
  city: "",
  address: ""
});

formData stores values from all steps.

Key idea: Do not create separate state for every step unless the requirement needs it. A single form object makes it easy to submit everything together.
5. Full React Code — Simple Multi-Step Form
import React, { useState } from "react";

const MultiStepForm = () => {
  const [step, setStep] = useState(1);

  const [formData, setFormData] = useState({
    name: "",
    email: "",
    city: "",
    address: ""
  });

  const [errors, setErrors] = useState({});

  const handleChange = (e) => {
    const { name, value } = e.target;

    setFormData((prev) => ({
      ...prev,
      [name]: value
    }));
  };

  const validateStep = () => {
    const newErrors = {};

    if (step === 1) {
      if (!formData.name.trim()) {
        newErrors.name = "Name is required";
      }

      if (!formData.email.trim()) {
        newErrors.email = "Email is required";
      }
    }

    if (step === 2) {
      if (!formData.city.trim()) {
        newErrors.city = "City is required";
      }

      if (!formData.address.trim()) {
        newErrors.address = "Address is required";
      }
    }

    setErrors(newErrors);

    return Object.keys(newErrors).length === 0;
  };

  const handleNext = () => {
    if (validateStep()) {
      setStep((prev) => prev + 1);
    }
  };

  const handleBack = () => {
    setErrors({});
    setStep((prev) => prev - 1);
  };

  const handleSubmit = (e) => {
    e.preventDefault();

    console.log("Final Form Data:", formData);
    alert("Form submitted successfully!");
  };

  return (
    <div className="container mt-5">
      <div className="card shadow p-4 mx-auto" style={{ maxWidth: "600px" }}>

        <h2 className="mb-4">Registration Form</h2>

        <div className="mb-4">
          Step {step} of 3
        </div>

        <form onSubmit={handleSubmit}>

          {step === 1 && (
            <div>
              <h4>Personal Details</h4>

              <input
                className="form-control mb-2"
                name="name"
                placeholder="Enter name"
                value={formData.name}
                onChange={handleChange}
              />

              {errors.name && (
                <div className="text-danger mb-3">
                  {errors.name}
                </div>
              )}

              <input
                className="form-control mb-2"
                name="email"
                placeholder="Enter email"
                value={formData.email}
                onChange={handleChange}
              />

              {errors.email && (
                <div className="text-danger mb-3">
                  {errors.email}
                </div>
              )}

              <button
                type="button"
                className="btn btn-primary"
                onClick={handleNext}
              >
                Next
              </button>
            </div>
          )}

          {step === 2 && (
            <div>
              <h4>Address Details</h4>

              <input
                className="form-control mb-2"
                name="city"
                placeholder="Enter city"
                value={formData.city}
                onChange={handleChange}
              />

              {errors.city && (
                <div className="text-danger mb-3">
                  {errors.city}
                </div>
              )}

              <textarea
                className="form-control mb-2"
                name="address"
                placeholder="Enter address"
                value={formData.address}
                onChange={handleChange}
              />

              {errors.address && (
                <div className="text-danger mb-3">
                  {errors.address}
                </div>
              )}

              <button
                type="button"
                className="btn btn-secondary me-2"
                onClick={handleBack}
              >
                Back
              </button>

              <button
                type="button"
                className="btn btn-primary"
                onClick={handleNext}
              >
                Next
              </button>
            </div>
          )}

          {step === 3 && (
            <div>
              <h4>Review Details</h4>

              <div className="border rounded p-3 mb-3">
                <p><strong>Name:</strong> {formData.name}</p>
                <p><strong>Email:</strong> {formData.email}</p>
                <p><strong>City:</strong> {formData.city}</p>
                <p><strong>Address:</strong> {formData.address}</p>
              </div>

              <button
                type="button"
                className="btn btn-secondary me-2"
                onClick={handleBack}
              >
                Back
              </button>

              <button
                type="submit"
                className="btn btn-success"
              >
                Submit
              </button>
            </div>
          )}

        </form>
      </div>
    </div>
  );
};

export default MultiStepForm;

6. Step Validation

The important rule is: do not move to the next step if the current step is invalid.

Click Next
→

→
Errors?
→
❌ Show errors

✅ setStep(step + 1)
const handleNext = () => {
  if (validateStep()) {
    setStep((prev) => prev + 1);
  }
};
Interview point: “I validate only the fields belonging to the current step. This avoids showing errors for fields the user has not reached yet.”
7. Next / Back Navigation
➡️ Next

Validate current step first.

if (validateStep()) {
  setStep(prev => prev + 1);
}
⬅️ Back

Move backward and keep form data.

const handleBack = () => {
  setErrors({});
  setStep(prev => prev - 1);
};
Why does data remain? Because formData is stored in the parent component state. Changing step changes what is rendered, but it does not erase formData.
8. Common Developer Mistakes
❌ Mistake 1: Keeping each step's data in temporary local variables
When the UI changes, the values can be lost. Keep the form values in React state.
❌ Mistake 2: Moving to the next step before validation
Always validate the current step before changing step.
❌ Mistake 3: Creating a separate submit handler for every step
Usually only the final step should submit the complete form. Intermediate buttons can use type="button".
❌ Mistake 4: Accidentally submitting the form when clicking Next
A button inside a form defaults to submit. Use type="button" for Next and Back.
❌ Mistake 5: Mutating formData directly
Do not write formData.name = value. Use the state setter and spread the previous object.
❌ Mistake 6: Losing data when going Back
Do not reset the entire form when changing steps. Keep formData independent from step.
❌ Mistake 7: Showing every validation error on every step
Validate only fields relevant to the current step unless the product requirement says otherwise.
9. How I would explain my implementation to the interviewer
🎤 Interview-ready explanation

“I will divide the form into three steps: personal details, address details, and a final review step.”

“First, I keep the current step in a step state. Then I keep all form values inside one formData object so the data is available across all steps.”

“For every input, I use one common handleChange function. It gets the input's name and value and updates only that property using the previous state.”

“When the user clicks Next, I call validateStep(). The validation function checks only the fields belonging to the current step. If there are errors, I show them and do not move forward.”

“If validation passes, I increase the step number. For Back, I decrease the step number, but I do not clear formData, so the user's previous values remain available.”

“On the final step, I display a review of the complete form data. The Submit button then submits the complete object.”

Finally, I would mention: “For a production application, I would also consider stronger validation, accessibility, API integration, loading states, server-side validation, and handling browser refresh or persistence if required.”
