Machine Coding Question

Implement Infinite Scrolling using React.

Question

Build a React page that displays a list of items. When the user reaches near the bottom of the list, automatically load and append more items.

Requirements
  • Display a list of items.
  • Load the first batch when the component starts.
  • Detect when the user reaches the bottom or near-bottom of the list.
  • Load the next batch and append it to the existing items.
  • Show a loading indicator while loading.
  • Prevent duplicate loading.
  • Handle the end of the list.
  • Handle errors and allow retry.
  • Use React frontend logic only.
Machine coding focus: The interviewer is mainly checking your React state management, scroll detection, effect cleanup, loading control, pagination logic, and ability to avoid unnecessary work.

Layman Example

Answer

Understand the approach before writing the code.

What is Infinite Scrolling?

Infinite scrolling is a UI pattern where more content is loaded automatically as the user approaches the end of the currently visible list.

Why do we use it?

  • It avoids loading a huge amount of data at one time.
  • It gives the user a smooth browsing experience.
  • It works well for feeds, product lists, search results, and social timelines.
  • It can reduce the amount of data initially rendered.

What problem does it solve?

Imagine 10,000 products. Rendering all 10,000 products immediately can be expensive. Infinite scrolling lets the UI work with smaller batches.

10,000 items available
→
Render 20
→
User reaches bottom
→
Add next 20

Common implementation approaches

Approach 1 — Scroll Event

Listen to the window/container scroll event and check whether the user is near the bottom. 

window.addEventListener("scroll", handleScroll);

const nearBottom =
  window.innerHeight + window.scrollY >=
  document.documentElement.scrollHeight - 200;

Easy to understand, but scroll events can fire very frequently, so careless implementations can do unnecessary work.

Approach 2 — IntersectionObserver ⭐

Put a small invisible/sentinel element at the bottom of the list. When that element enters the viewport, load more items. 

const observer = new IntersectionObserver(entries => {
  if (entries[0].isIntersecting) {
    loadMore();
  }
});

This is generally the preferred modern frontend approach because the browser handles visibility observation instead of us repeatedly calculating scroll position.

Approach 3 — Scroll Container + Sentinel

Instead of observing the whole page, create a fixed-height scrollable container and observe a sentinel at its bottom. This is useful when the machine-coding requirement specifically asks for a scrollable panel.

Best interview approach: Prefer IntersectionObserver when the requirement allows it. Explain that a sentinel element is placed at the end of the list and the observer triggers loading when it becomes visible. Also mention loading guards, hasMore, cleanup, and error handling.

Important React states

  • items — stores all currently loaded items.
  • page — tells us which batch/page should be loaded next.
  • loading — prevents multiple loads at the same time.
  • hasMore — tells us whether more items are available.
  • error — stores an error message if loading fails.
Interview shortcut: Remember this flow: List → Sentinel → Observer → Loading Guard → Next Page → Append → Check hasMore.

"When the sentinel becomes visible, I check two conditions: whether another load is already running and whether more items are available."

"If loading is allowed, I increase the page number and load the next batch. The new items are appended to the previous items instead of replacing them."

Core React pattern

const [items, setItems] = useState([]);
const [page, setPage] = useState(1);
const [loading, setLoading] = useState(false);
const [hasMore, setHasMore] = useState(true);
const [error, setError] = useState("");

const loadMore = async () => {
  if (loading || !hasMore) return;

  setLoading(true);
  setError("");

  try {
    // Frontend practice:
    // simulate getting the next batch
    const nextItems = createItems(page);

    setItems(prev => [...prev, ...nextItems]);

    if (page >= 5) {
      setHasMore(false);
    } else {
      setPage(prev => prev + 1);
    }
  } catch (err) {
    setError("Unable to load more items.");
  } finally {
    setLoading(false);
  }
};
Note: The sample above intentionally simulates data in the frontend. In a real application, loadMore() could call an API, but backend code is outside this practice task.

Common Developer Mistakes

Important issues interviewers may look for.

1. Loading multiple times

IntersectionObserver may trigger while the previous load is still running. Always use a loading guard.

2. Forgetting hasMore

When there are no more items, stop observing/loading. Otherwise the application may keep trying forever.

3. Replacing instead of appending

setItems(nextItems) removes previous items. Infinite scrolling normally needs setItems(prev => [...prev, ...nextItems]).

4. Creating observers repeatedly without cleanup

Always disconnect the observer in the effect cleanup. Otherwise multiple observers can remain active.

5. Using scroll events carelessly

Scroll events can fire very frequently. If using them, consider throttling, debouncing where appropriate, and passive listeners.

6. Incorrect useEffect dependencies

Incorrect dependencies can create stale values or repeatedly recreate the observer.

7. Updating state after an invalid request

If the implementation becomes asynchronous, think about cleanup, cancellation, and stale responses when the component unmounts or state changes.

8. No loading/error UI

Users need feedback while more content is being loaded and a retry path when something fails.

9. Loading too early or too late

With IntersectionObserver, you can use rootMargin to start loading before the user reaches the exact bottom.

10. Forgetting accessibility and UX

Make sure the loading indicator and end-of-list message are understandable, and do not make keyboard users depend entirely on scrolling.

Frontend-only React implementation using IntersectionObserver.

Complete React Example

import { useEffect, useRef, useState } from "react";

const createItems = (page) => {
  return Array.from({ length: 10 }, (_, index) => ({
    id: `${page}-${index}`,
    title: `Item ${(page - 1) * 10 + index + 1}`
  }));
};

export default function InfiniteScroll() {
  const [items, setItems] = useState([]);
  const [page, setPage] = useState(1);
  const [loading, setLoading] = useState(false);
  const [hasMore, setHasMore] = useState(true);
  const [error, setError] = useState("");

  const sentinelRef = useRef(null);

  const loadMore = async () => {
    if (loading || !hasMore) return;

    setLoading(true);
    setError("");

    try {
      // Simulate frontend-only async work
      await new Promise(resolve => setTimeout(resolve, 700));

      const nextItems = createItems(page);

      setItems(prev => [...prev, ...nextItems]);

      if (page >= 5) {
        setHasMore(false);
      } else {
        setPage(prev => prev + 1);
      }
    } catch (err) {
      setError("Unable to load more items.");
    } finally {
      setLoading(false);
    }
  };

  useEffect(() => {
    const sentinel = sentinelRef.current;

    if (!sentinel) return;

    const observer = new IntersectionObserver(
      entries => {
        const entry = entries[0];

        if (entry.isIntersecting && !loading && hasMore) {
          loadMore();
        }
      },
      {
        root: null,
        rootMargin: "200px",
        threshold: 0
      }
    );

    observer.observe(sentinel);

    return () => {
      observer.disconnect();
    };
  }, [loading, hasMore, page]);

  useEffect(() => {
    loadMore();
  }, []);

  return (
    <div>
      <h2>Products</h2>

      {items.map(item => (
        <div key={item.id}>
          {item.title}
        </div>
      ))}

      {error && (
        <div>
          <p>{error}</p>
          <button onClick={loadMore}>Retry</button>
        </div>
      )}

      {loading && <p>Loading more...</p>}

      {!hasMore && <p>You reached the end.</p>}

      <div ref={sentinelRef} style={{ height: 1 }} />
    </div>
  );
}
Important interview note: For a production implementation, you would usually separate the data-loading logic into a custom hook or data-fetching layer. For a machine-coding round, first make the component correct and understandable, then refactor if time allows.

Production-quality considerations

  • Use IntersectionObserver rather than manual scroll calculations when appropriate.
  • Use a sentinel element at the end of the list.
  • Use rootMargin to prefetch before the user reaches the bottom.
  • Prevent duplicate loads with a loading guard.
  • Stop when hasMore is false.
  • Handle errors and retry.
  • Clean up the observer.
  • For very large lists, consider virtualization/windowing so old DOM nodes are not all kept rendered.
  • For real async requests, consider cancellation and stale-response protection.
Final interview sentence: "I prefer IntersectionObserver for infinite scrolling because I can observe a sentinel at the bottom of the list instead of continuously calculating scroll position. I guard against duplicate loads, append new items, stop when there is no more data, clean up the observer, and handle loading and error states."
