Chat UI

Interview-ready explanation, implementation flow, complete React example, and common developer mistakes.

Questions
WHAT

What is Chat UI?

A Chat UI is the user interface used to display conversations between users, agents, or systems. It normally contains a conversation list, message history, message composer, send action, timestamps, and visual distinction between incoming and outgoing messages.

WHY

What problem does Chat UI solve?

Without a structured conversation interface, users cannot easily see message history, identify who sent each message, compose new messages, or understand the latest state of a conversation.

User Problems

  • Messages are difficult to scan.
  • Sender and receiver are unclear.
  • New messages are not reflected immediately.
  • Long conversations become hard to navigate.

UI Solution

  • Separate incoming/outgoing message bubbles.
  • Central message state.
  • Controlled input for composing messages.
  • Auto-scroll to the latest message.
HOW

How does a Chat UI work?

User types→ Input state updates→ Send / Enter→ Validate→ Add message→ Render→ Scroll to bottom

The key idea is that the UI should be a function of state. The message array is the source of truth. When a new message is added, React re-renders the message list.

1 MINUTE ANSWER

How to explain Chat UI to an interviewer in 1 minute

“I implemented the Chat UI as a state-driven React component. I keep the conversation in a messages array and keep the text box as a controlled input. When the user clicks Send or presses Enter, I validate the input, create a new message object, append it to the messages state, clear the input, and scroll the conversation to the latest message. For rendering, I map over the messages array and use the sender/type to apply different styles for incoming and outgoing messages. The main focus is predictable state updates, reusable message rendering, keyboard accessibility, and keeping the UI responsive.”

Keywords to mention

State → controlled input → event handling → immutable update → conditional rendering → auto-scroll → reusable components.

5 MINUTE ANSWER

How to explain Chat UI to an interviewer in 5 minutes

  1. Requirements: Show messages, sender identity, timestamp, composer, send button, Enter-to-send, and latest-message visibility.
  2. Data model: Each message has an id, text, sender, and timestamp.
  3. State: Use messages for conversation data and input for the draft message.
  4. Interaction: Send validates the trimmed input, creates a message, and appends it immutably.
  5. Rendering: Map messages into a reusable message bubble. Use conditional classes for sender.
  6. UX: Clear the input after sending, support Enter, and scroll to the newest message.
  7. Scalability: In a real application, replace local state updates with an API/WebSocket layer and add loading, failed-send, pagination, unread count, and optimistic update handling.

IMPLEMENTATION

How I would explain my implementation to the interviewer

“First, I identify the minimum UI and data requirements. I split the problem into a message list and message composer. I use one state variable for the messages and another for the current draft. The input is controlled, so React always owns the current value. On send, I trim and validate the text, create a message object, and update the array immutably. I render messages with a reusable component and conditionally style them based on the sender. Finally, I use a bottom ref to keep the latest message visible. If this were production code, I would separate API/WebSocket communication from the presentation layer and handle loading, errors, optimistic updates, and pagination.”

FULL CODE

React implementation

This is a compact machine-coding-round implementation. It intentionally keeps the solution easy to explain and extend.

import React, { useEffect, useRef, useState } from "react";
import "./ChatApp.css";

const initialMessages = [
  {
    id: 1,
    text: "Hi! How can I help you?",
    sender: "other",
    time: "09:30 AM",
  },
  {
    id: 2,
    text: "I want to know my order status.",
    sender: "me",
    time: "09:31 AM",
  },
];

function MessageBubble({ message }) {
  return (
    <div className={`message ${message.sender}`}>
      <div className="message-text">{message.text}</div>
      <small>{message.time}</small>
    </div>
  );
}

function MessageList({ messages, bottomRef }) {
  return (
    <div className="messages">
      {messages.map((message) => (
        <MessageBubble key={message.id} message={message} />
      ))}
      <div ref={bottomRef} />
    </div>
  );
}

function MessageComposer({ input, setInput, onSend }) {
  const handleKeyDown = (event) => {
    if (event.key === "Enter" && !event.shiftKey) {
      event.preventDefault();
      onSend();
    }
  };

  return (
    <div className="composer">
      <input
        value={input}
        onChange={(event) => setInput(event.target.value)}
        onKeyDown={handleKeyDown}
        placeholder="Type a message..."
        aria-label="Message"
      />

      <button onClick={onSend}>Send</button>
    </div>
  );
}

export default function ChatApp() {
  const [messages, setMessages] = useState(initialMessages);
  const [input, setInput] = useState("");
  const bottomRef = useRef(null);

  useEffect(() => {
    bottomRef.current?.scrollIntoView({ behavior: "smooth" });
  }, [messages]);

  const sendMessage = () => {
    const text = input.trim();

    if (!text) return;

    const newMessage = {
      id: Date.now(),
      text,
      sender: "me",
      time: new Date().toLocaleTimeString([], {
        hour: "2-digit",
        minute: "2-digit",
      }),
    };

    setMessages((previousMessages) => [
      ...previousMessages,
      newMessage,
    ]);

    setInput("");
  };

  return (
    <div className="chat-app">
      <header className="chat-header">
        <strong>Support Chat</strong>
        <span>Online</span>
      </header>

      <MessageList
        messages={messages}
        bottomRef={bottomRef}
      />

      <MessageComposer
        input={input}
        setInput={setInput}
        onSend={sendMessage}
      />
    </div>
  );
}

COMMON MISTAKES

Common developer mistakes

  • Mutating the messages array: Avoid messages.push(). Use setMessages(prev => [...prev, message]).
  • Using the input DOM value as the source of truth: Prefer a controlled React input.
  • Allowing empty messages: Always use trim() before sending.
  • Using array index as the key: Use a stable message id where possible.
  • Forgetting Enter behavior: Support keyboard submission while preserving Shift+Enter if multiline messages are required.
  • No auto-scroll: New messages may appear below the visible area.
  • Scrolling on every render: Trigger scrolling when the messages collection changes, not on unrelated renders.
  • Mixing API code with UI code: Keep network/WebSocket communication in a separate service or hook.
  • No loading/error state: Real messaging can fail; model sending, failed, and retry states.
  • Ignoring long conversations: Production apps should consider pagination or virtualization.
  • Missing accessibility: Provide labels, keyboard support, readable contrast, and appropriate live-region behavior for incoming messages.
  • Unsafe rendering: Treat user messages as text. Do not inject arbitrary HTML into the message body.
Interview tip: Don't just list mistakes. Explain the trade-off and the correction. For example: “I avoid array index keys because message insertion/deletion can cause React to associate the wrong DOM node with a message.”
