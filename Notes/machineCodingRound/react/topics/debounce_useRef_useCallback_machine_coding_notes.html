Debounce Search with useRef + useCallback

React API search example with a 500ms debounce, timer cancellation, request cancellation, cleanup, loading state, and product rendering.

1. Question
Build a search box that calls an API only after the user stops typing.

When a user types continuously, do not make an API request for every key press. Wait until the user has stopped typing for 500ms, then call the API.

  • Use useRef to store the debounce timer.
  • Use useCallback to keep the debounce function stable.
  • Use AbortController to cancel an older in-flight request.
  • Clean up the timer and request when the component unmounts.
  • Show loading state and API results.
2. Answer — What is Debouncing?
Simple definition: Debouncing means waiting for a short period after the last event before performing an expensive operation.

For search, the expensive operation is normally the API request. If the user types react, we do not want five requests for r, re, rea, reac, and react. We wait until typing pauses.

Why use useRef?

timerRef.current stores the timeout ID without causing a React re-render. It lets us cancel the previous timeout before creating a new one.

Why use useCallback?

It keeps the function reference stable between renders. Here the callback has an empty dependency array because it does not directly depend on changing state/props.

Why use AbortController?

Debouncing prevents many scheduled requests, but it does not cancel a request that has already started. AbortController handles that second problem by aborting the previous in-flight fetch.

4. Full Reference Code — Corrected & Commented

Your overall approach is correct. I made a few small improvements: handle an empty search by clearing old results, explicitly ignore an expected abort error, avoid unnecessary array copying, and ensure loading state is not incorrectly turned off by an older aborted request.

import React, { useCallback, useEffect, useRef, useState } from "react";

const Debounce_useRef_useCallback = () => {
  // Stores API results.
  const [products, setProducts] = useState([]);

  // Controls the loading UI.
  const [isLoading, setLoading] = useState(false);

  // useRef is used because changing .current does NOT cause a re-render.
  // We store the timeout ID here so we can cancel the previous timer.
  const timerRef = useRef(null);

  // Stores the AbortController for the currently running request.
  const controllerRef = useRef(null);

  // Cleanup when the component is removed from the screen.
  useEffect(() => {
    return () => {
      // Cancel the pending debounce timer.
      if (timerRef.current) {
        clearTimeout(timerRef.current);
      }

      // Cancel an API request if one is currently running.
      controllerRef.current?.abort();
    };
  }, []);

  // useCallback keeps this function reference stable between renders.
  const debounceSearchApi = useCallback((searchValue) => {
    // If the user clears the input:
    // 1. Cancel the old timer.
    // 2. Cancel the old request.
    // 3. Clear old results.
    if (!searchValue) {
      if (timerRef.current) {
        clearTimeout(timerRef.current);
      }

      controllerRef.current?.abort();
      controllerRef.current = null;

      setProducts([]);
      setLoading(false);
      return;
    }

    // A new search means the old scheduled call is no longer needed.
    if (timerRef.current) {
      clearTimeout(timerRef.current);
    }

    // If an older request is already running, cancel it.
    controllerRef.current?.abort();

    // Start a new 500ms countdown.
    timerRef.current = setTimeout(async () => {
      // Create a fresh controller for this request.
      const controller = new AbortController();
      controllerRef.current = controller;

      setLoading(true);

      try {
        const URL =
          `https://dummyjson.com/products/search?q=${encodeURIComponent(searchValue)}`;

        const response = await fetch(URL, {
          signal: controller.signal,
        });

        if (!response.ok) {
          throw new Error(`HTTP error: ${response.status}`);
        }

        const output = await response.json();

        // output.products is already an array.
        setProducts(output.products);
      } catch (error) {
        // Abort is expected when a newer search replaces this request.
        if (error.name === "AbortError") {
          return;
        }

        console.error("Search API error:", error);
      } finally {
        // Only turn loading off if this is still the current request.
        if (controllerRef.current === controller) {
          setLoading(false);
          controllerRef.current = null;
        }
      }
    }, 500);
  }, []);

    // part of the search value.
    const value = e.target.value.trim();

    debounceSearchApi(value);

5. Common Developer Mistakes
1. Calling fetch directly inside onChange.
That creates an API request for almost every keystroke. Use a debounce timer first.
2. Storing the timer in state.
Timer IDs are not UI data. useRef is a better fit because changing it does not trigger a render.
3. Forgetting clearTimeout().
Without clearing the previous timer, multiple delayed callbacks can run.
4. Thinking debounce cancels an already-started fetch.
It does not. Once fetch has started, use AbortController if you want to cancel it.
5. Forgetting unmount cleanup.
Clear the timer and abort an active request when the component unmounts.
6. Ignoring AbortError.
Aborting a request is expected behavior, not necessarily an application error. Do not show a scary error message for normal cancellation.
7. Calling setLoading(false) from an old request without checking ownership.
An older request can finish after a newer request starts. Guarding with controllerRef.current === controller prevents stale cleanup from changing the current loading state.
8. Forgetting empty input handling.
If the input becomes empty, cancel pending work and clear stale search results.
9. Missing React keys when rendering a list.
Use a stable unique key such as product.id.
6. How I Would Explain This to the Interviewer

Start with the problem:

“In a search box, the onChange event fires for every character. If I call the API directly, I can generate many unnecessary requests. I will use debouncing so that the API is called only after the user stops typing for 500 milliseconds.”

Then explain useRef:

“I use useRef to store the timer ID because the timer is not UI state and changing it should not cause a re-render. Before creating a new timer, I clear the previous timer.”

Then explain useCallback:

“I wrap the debounce function with useCallback so React keeps the same function reference across renders. The function has no changing dependencies, so the dependency array is empty.”

Then explain AbortController:

“Debouncing prevents requests that have not started yet. If an older request has already started, I use AbortController to cancel it when a newer search replaces it.”

Then explain cleanup:

“In the useEffect cleanup, I clear the pending timeout and abort the active request so the component does not leave asynchronous work behind after unmounting.”

Strong interview closing:
“Therefore, the solution controls both sides of the problem: debounce controls unnecessary scheduled API calls, and AbortController controls stale requests that are already in flight.”

Complexity

Typing: Each input event does O(1) timer/controller work.

Rendering: Depends on the number of returned products.

Network: Debouncing reduces the number of API calls, but the exact number depends on typing pauses and server behavior.

One-line memory trick
useRef = remember timer/request without rendering.
useCallback = keep function stable.
clearTimeout = cancel scheduled work.
AbortController = cancel running fetch.
