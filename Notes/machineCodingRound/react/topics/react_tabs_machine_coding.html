React Tabs

A common React machine-coding task for switching between different sections of content.

Goal: Show one content section at a time based on the tab selected by the user.

Left Side — Questions
1. What are Tabs?

Technical definition: Tabs are a UI pattern where multiple related sections of content are placed behind selectable tab buttons, and the application displays the content belonging to the currently selected tab.

Layman example: Imagine a notebook with three sections: Profile, Settings, and Security. Instead of showing everything together, you click a section name and see only that section.

Core React concepts State → Event Handling → Conditional Rendering → Dynamic Content

Simple visual:
Currently selected: Profile
2. What Problem Do Tabs Solve?

Tabs organize related content into separate sections without showing all sections at the same time.

  • Reduce visual clutter.
  • Group related information.
  • Allow users to switch sections quickly.
  • Improve navigation within a page.
  • Demonstrate state-driven UI in React.
Machine-coding point: The interviewer is checking whether you can manage the selected tab, handle clicks, and render the correct content without unnecessary complexity.
3. Requirements
Basic requirements
  1. Create multiple tabs.
  2. Show one tab as active.
  3. Clicking a tab changes the active tab.
  4. Display content corresponding to the selected tab.
  5. Clearly indicate which tab is active.
Good clarification questions
  • Which tab should be active initially?
  • Should all tab content be loaded initially or only the active content?
  • Can tabs be disabled?
  • Do we need keyboard navigation?
  • Should the tabs be reusable with dynamic data?
  • Should tab state be reflected in the URL?
4. State Design — What State Do I Need?

For a basic Tabs component, I need only one piece of state: the currently selected tab.

const [activeTab, setActiveTab] = useState("profile");

The tab data itself does not need to be state if it is static or passed through props.

const tabs = [
  {
    id: "profile",
    label: "Profile",
    content: "Profile content"
  },
  {
    id: "settings",
    label: "Settings",
    content: "Settings content"
  },
  {
    id: "security",
    label: "Security",
    content: "Security content"
  }
];
Important interview concept: Keep only data that can change through user interaction in state. The active tab changes, so it belongs in state. Static tab definitions do not need state.

6. How I Have Implemented It — Interview Explanation
Step 1 — Define tab data

I keep the tab information in an array. Each tab has an id, label, and content.

Step 2 — Track active tab

I use useState to store the id of the currently selected tab.

Step 3 — Render tab buttons

I use map() to generate the tab buttons dynamically instead of writing each button manually.

Step 4 — Handle tab click

When the user clicks a tab, I pass its id to setActiveTab.

Step 5 — Render selected content

I find the tab whose id matches activeTab and display its content.

One-line implementation summary: "I store the active tab id in state, dynamically render the tab buttons from data, update the active id on click, and render the content associated with that id."
7. Full React Code
import { useState } from "react";

function Tabs() {
  const [activeTab, setActiveTab] = useState("profile");

  const tabs = [
    {
      id: "profile",
      label: "Profile",
      content: "This is the Profile section."
    },
    {
      id: "settings",
      label: "Settings",
      content: "This is the Settings section."
    },
    {
      id: "security",
      label: "Security",
      content: "This is the Security section."
    }
  ];

  const selectedTab = tabs.find(
    tab => tab.id === activeTab
  );

  return (
    <div>
      <h2>Tabs</h2>

      <div>
        {tabs.map(tab => (
          <button
            key={tab.id}
            onClick={() => setActiveTab(tab.id)}
            className={
              activeTab === tab.id
                ? "active"
                : ""
            }
          >
            {tab.label}
          </button>
        ))}
      </div>

      <div>
        {selectedTab?.content}
      </div>
    </div>
  );
}

export default Tabs;
Important code logic
// 1. Store selected tab
const [activeTab, setActiveTab] = useState("profile");

// 2. Change selected tab
onClick={() => setActiveTab(tab.id)}

// 3. Find selected tab
const selectedTab = tabs.find(
  tab => tab.id === activeTab
);

// 4. Render selected content
{selectedTab?.content}
Why use an id? The id gives every tab a stable identity. The same id can be used for state, lookup, keys, and accessibility attributes in a more advanced implementation.
8. How to Explain Tabs in 1 Minute

Interview-ready answer:

"I implemented a reusable Tabs component in React. I store the id of the currently active tab using the useState hook. I keep the tab definitions in an array where each tab has an id, label, and content. I use map to dynamically render the tab buttons. When a user clicks a tab, I update the activeTab state with that tab's id. React then re-renders the component, and I use the active id to find and display the corresponding content. I also use the same stable id as the React key, which makes the list rendering predictable."
1-minute structure
  1. Data: array of tabs
  2. State: activeTab id
  3. Render: map()
  4. Click: setActiveTab(tab.id)
  5. Content: find selected tab
  6. UI: React re-renders
9. How to Explain Tabs in 5 Minutes
Minute 1 — Clarify requirements

I first confirm the number of tabs, initial active tab, whether tabs are static or dynamic, and whether disabled or keyboard-accessible tabs are required.

Minute 2 — Design the data

I represent tabs as data objects with a stable id, label, and content. This avoids hardcoding separate button and content blocks.

Minute 3 — Design the state

I only keep the active tab id in state because that is the value that changes due to user interaction. The tab definitions can remain outside state.

Minute 4 — Implement interaction

I map over the tabs to create buttons. On click, I set the active tab id. I then find the matching tab and render its content. I also compare the active id with each tab id to apply the active style.

Minute 5 — Discuss improvements
  • Add disabled tabs.
  • Add keyboard navigation with arrow keys.
  • Add ARIA roles and attributes for accessibility.
  • Support URL-based tabs if deep linking is required.
  • Support lazy loading if tab content is expensive.
Strong closing line: "The key idea is that the UI is driven by one source of truth—the active tab id—and the displayed content is derived from that selection."
10. Common Developer Mistakes
Mistake 1 — Creating separate state for every tab

You generally do not need isProfileActive, isSettingsActive, etc. One activeTab state is enough.

Mistake 2 — Hardcoding every button unnecessarily

For reusable tabs, keep tab information in an array and use map() to generate the UI.

Mistake 3 — Using array index as key 
// Avoid when a stable id exists
{tabs.map((tab, index) =>
  <button key={index}>...</button>
)}

// Prefer
{tabs.map(tab =>
  <button key={tab.id}>...</button>
)}
Mistake 4 — Duplicating tab state and data

Do not keep separate state for the selected tab object when it can be derived from activeTab and the tabs array.

Mistake 5 — Forgetting the active visual state

The user should clearly know which tab is selected. Apply an active class, style, or appropriate accessibility state.

Mistake 6 — Rendering all content when only one section is required

For a simple requirement where only active content should be displayed, render the selected content rather than unnecessarily displaying every section.

Mistake 7 — Ignoring accessibility in production-quality Tabs

A more complete Tabs component should consider keyboard navigation, focus management, and ARIA semantics. Mention these if the interviewer asks about production readiness.
