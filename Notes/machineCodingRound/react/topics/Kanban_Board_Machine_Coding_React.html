What?

What is a Kanban Board?

A Kanban Board is a visual task-management system where work items are represented as cards and organized into columns based on their current status.

Interview definition: “A Kanban Board is a visual workflow component where tasks are represented as cards and grouped by status. In React, I model the board as state and update that state when tasks are added, deleted, edited, or moved between columns.”
Why?

What problem does it solve?

Visual workflow

Users can immediately see what is pending, in progress, or completed.

Task organization

Tasks are grouped into meaningful workflow stages instead of one long list.

Easy status changes

Drag-and-drop lets users move work from one stage to another quickly.

Team collaboration

Kanban is commonly used to visualize development and operational workflows.

Requirements

What should I implement?

  1. Create columns such as To Do, In Progress, and Done.
  2. Render task cards inside each column.
  3. Add a new task.
  4. Delete a task.
  5. Drag a task from one column to another.
  6. Update the task's status after dropping.
  7. Keep the state immutable.
  8. Handle empty columns.
  9. Give every task a stable unique ID.
  10. Keep the board reusable and easy to extend.
Machine coding strategy: Start with static columns → add task state → render cards → add/delete → implement drag-and-drop → update the task's column → handle edge cases and UX.
How?

How does it work?

A simple and interview-friendly model is to keep a flat array of tasks. Each task contains a column/status field.

const [tasks, setTasks] = useState([
  {
    id: 1,
    title: "Build Login Page",
    status: "todo"
  },
  {
    id: 2,
    title: "Create Dashboard",
    status: "progress"
  },
  {
    id: 3,
    title: "Setup Navbar",
    status: "done"
  }
]);

Then filter tasks while rendering each column:

tasks.filter(
  task => task.status === column.id
)
Key idea: The task's status determines which column displays it. Moving a card is therefore mainly a state update: change its status from one column ID to another.

Drag & Drop

Drag-and-Drop Logic

The native HTML5 Drag and Drop API is enough for a basic machine coding round.

// Task card
onDragStart={() => {
  setDraggedTaskId(task.id);
}}


// Column
onDragOver={(event) => {
  event.preventDefault();
}}


// Column
onDrop={() => {
  moveTask(draggedTaskId, column.id);
}}

The actual state update:

const moveTask = (taskId, newStatus) => {
  setTasks(prevTasks =>
    prevTasks.map(task =>
      task.id === taskId
        ? { ...task, status: newStatus }
        : task
    )
  );
};
Why event.preventDefault()? The browser's default drag-over behavior can prevent the drop event from working. Calling preventDefault() on onDragOver allows the target column to accept the drop.
Full Code

React Kanban Board — Interview Version

This implementation covers columns, add task, delete task, drag-and-drop, status changes, and empty-column handling.

import { useState } from "react";

const initialColumns = [
  { id: "todo", title: "To Do" },
  { id: "progress", title: "In Progress" },
  { id: "done", title: "Done" }
];

const initialTasks = [
  {
    id: 1,
    title: "Build Login Page",
    status: "todo"
  },
  {
    id: 2,
    title: "Create Dashboard",
    status: "progress"
  },
  {
    id: 3,
    title: "Setup Navbar",
    status: "done"
  }
];

function KanbanBoard() {
  const [columns] = useState(initialColumns);
  const [tasks, setTasks] = useState(initialTasks);
  const [newTask, setNewTask] = useState("");
  const [draggedTaskId, setDraggedTaskId] = useState(null);

  const addTask = () => {
    const title = newTask.trim();

    if (!title) return;

    const task = {
      id: Date.now(),
      title,
      status: "todo"
    };

    setTasks(prevTasks => [
      ...prevTasks,
      task
    ]);

    setNewTask("");
  };

  const deleteTask = (taskId) => {
    setTasks(prevTasks =>
      prevTasks.filter(
        task => task.id !== taskId
      )
    );
  };

  const moveTask = (taskId, newStatus) => {
    setTasks(prevTasks =>
      prevTasks.map(task =>
        task.id === taskId
          ? {
              ...task,
              status: newStatus
            }
          : task
      )
    );

    setDraggedTaskId(null);
  };

  const handleDragStart = (
    event,
    taskId
  ) => {
    setDraggedTaskId(taskId);

    // Optional: useful for native drag APIs.
    event.dataTransfer.effectAllowed = "move";
    event.dataTransfer.setData(
      "text/plain",
      String(taskId)
    );
  };

  const handleDrop = (
    event,
    columnId
  ) => {
    event.preventDefault();

    const taskId =
      draggedTaskId ??
      Number(
        event.dataTransfer.getData("text/plain")
      );

    if (!taskId) return;

    moveTask(taskId, columnId);
  };

  return (
    <div className="kanban">

      <div className="add-task">
        <input
          value={newTask}
          placeholder="Enter task"
          onChange={event =>
            setNewTask(event.target.value)
          }
          onKeyDown={event => {
            if (event.key === "Enter") {
              addTask();
            }
          }}
        />

        <button onClick={addTask}>
          Add Task
        </button>
      </div>

      <div className="board">
        {columns.map(column => {
          const columnTasks = tasks.filter(
            task => task.status === column.id
          );

          return (
            <section
              key={column.id}
              className="column"
              onDragOver={event =>
                event.preventDefault()
              }
              onDrop={event =>
                handleDrop(event, column.id)
              }
            >

              <h2>
                {column.title}
                <span>
                  {columnTasks.length}
                </span>
              </h2>

              {columnTasks.length === 0 && (
                <p className="empty">
                  Drop tasks here
                </p>
              )}

              {columnTasks.map(task => (
                <article
                  key={task.id}
                  draggable
                  className="task-card"
                  onDragStart={event =>
                    handleDragStart(
                      event,
                      task.id
                    )
                  }
                >
                  <div>
                    <strong>
                      {task.title}
                    </strong>
                  </div>

                  <button
                    onClick={() =>
                      deleteTask(task.id)
                    }
                    aria-label={`Delete ${task.title}`}
                  >
                    Delete
                  </button>
                </article>
              ))}
            </section>
          );
        })}
      </div>
    </div>
  );
}

export default KanbanBoard;

Interview Answer

How to explain in 1 minute

“I implemented the Kanban Board using React state. I keep the tasks in a flat array, and each task has an ID, title, and status. The status determines which column displays that task. I render the columns dynamically and filter the task array by the column ID. For drag-and-drop, I store the dragged task ID when dragging starts, allow the column to receive the drop using preventDefault, and then update that task's status immutably when it is dropped. I also added task creation and deletion. This approach keeps the state simple because moving a task only requires changing one property.”
Interview Answer

How to explain in 5 minutes

  1. Requirement: “The board has multiple workflow columns and draggable task cards.”
  2. Data model: “Each task has a stable ID, title, and status. Status points to a column ID.”
  3. Rendering: “I map through the columns and filter tasks whose status matches that column.”
  4. Add: “I validate the title, create a task with a unique ID and default status of To Do, then append it to state.”
  5. Delete: “I use filter to create a new array without the selected task.”
  6. Drag: “When dragging starts, I store the task ID and mark the drag operation as move.”
  7. Drop: “The target column calls preventDefault during drag-over and then receives the task on drop.”
  8. Move: “I use map to create a new task object with the updated status while leaving all other tasks unchanged.”
  9. Immutability: “I never mutate the existing task array directly because React state updates should produce new references.”
  10. Empty state: “If a column has no tasks, I show a drop area message so the user knows where a task can be moved.”
  11. Scalability: “For a larger application, I could persist the board through an API, add optimistic updates, permissions, ordering, and a drag-and-drop library if the interaction becomes more advanced.”
Strong closing line: “The main design decision is representing the task's workflow position as data. The UI is derived from that status, so moving a card becomes a predictable state transformation instead of manually moving DOM elements.”
Debugging

Common Developer Mistakes

Mistake Why it is a problem Better approach
Mutating the task array directly Can prevent predictable React updates. Use map, filter, and spread to create new references.
Using array index as task key Can cause incorrect DOM reconciliation when tasks move/delete. Use a stable task ID.
Storing duplicate task state per column Moving tasks requires updating multiple arrays and can cause synchronization bugs. Use one task list with a status/column ID.
Forgetting preventDefault() on dragover The drop event may not fire correctly. Call event.preventDefault() in the drop target's dragover handler.
Not tracking the dragged task ID The drop target does not know which task to move. Store the dragged task ID in state or use dataTransfer.
Updating the DOM manually Creates UI/state synchronization problems in React. Update state and let React render the board.
No empty-column state Users may not understand where to drop a task. Render a visible drop area or empty message.
Generating unstable IDs React keys can change unexpectedly. Use a stable backend ID or a proper ID generator in production.
Ignoring mobile interaction Native HTML5 drag-and-drop support is not equally convenient across touch devices. Use a touch-friendly interaction or a suitable drag-and-drop library when required.
Implementing drag-and-drop before basic CRUD Increases debugging complexity during the round. Build the smallest working board first, then add drag-and-drop.
Not considering task order Moving between columns works, but reordering within a column may not. Store an order/index or use a drag-and-drop library for advanced ordering.
Mixing API calls into every card Creates tightly coupled components. Keep board state logic separate from persistence logic.
Most common interview bug: Trying to “move the DOM element” instead of updating React state. In React, the data/state should change first; the UI should be derived from that state.
Testing

Edge Cases & Test Cases

  • Add a task with an empty title.
  • Add multiple tasks quickly.
  • Delete the first, middle, and last task.
  • Drag a task from To Do to In Progress.
  • Drag a task from In Progress to Done.
  • Drag a task back to an earlier column.
  • Drop a task into an empty column.
  • Drop the task into the same column.
  • Move several tasks quickly.
  • Verify the task ID remains unchanged after moving.
  • Verify other tasks are not modified when one task moves.
  • Check responsive behavior on small screens.
  • Test keyboard accessibility for non-drag actions such as delete/add.
  • Consider touch-device behavior if drag-and-drop is required on mobile.
Implementation Explanation

How I implemented it — interviewer flow

1. I defined columns

“I created column objects with stable IDs such as todo, progress, and done.”

2. I defined task state

“Every task has an ID, title, and status. Status maps directly to a column.”

3. I rendered dynamically

“I map columns and filter tasks by status, so I don't duplicate rendering logic.”

4. I added CRUD

“I added a task with an immutable array update and delete using filter.”

5. I added drag-and-drop

“I capture the dragged task ID and update its status when it is dropped on a column.”

6. I handled edge cases

“I handle empty tasks, empty columns, invalid task titles, and responsive layout.”

If the interviewer asks: “Why keep a flat task array?”
“Because the workflow position is just a property of the task. A single source of truth makes moving, deleting, filtering, and updating tasks simpler and avoids synchronizing multiple column arrays.”
If the interviewer asks: “Why use map for moving a task?”
“Map lets me create a new array while changing only the matching task. The other task objects are preserved, which keeps the state update immutable and predictable.”
If the interviewer asks: “How would you persist it?”
“After changing the task status, I would send the task ID and new status to the backend. For a better UX, I could update the UI optimistically and roll back if the API request fails.”
If the interviewer asks: “How would you support reordering?”
“I would add an order property or use the source and destination indexes from a drag-and-drop library, then update the task order immutably.”
Interview Follow-ups

Possible interviewer questions

For a simple machine-coding task, native HTML5 drag-and-drop can be enough. For production-level touch support, keyboard interactions, reordering, collision detection, and better UX, a dedicated drag-and-drop library can be preferable.

Store the editing task ID and draft title, then use map to replace only the matching task after Save.

Add a priority field such as low, medium, or high. Then use conditional styling or filtering to display it.

For a small local demo, use localStorage. In a real application, persist tasks through a backend API/database and fetch them when the board loads.
