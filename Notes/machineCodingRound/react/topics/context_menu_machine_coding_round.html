Questions / Topics

WHATINTERACTION

What is a Context Menu?

A context menu is a small menu that appears near the user's pointer after a context-specific action, most commonly a right-click. It contains actions relevant to the selected element or location, such as Copy, Rename, Delete, Open, Download or Inspect.

Try right-clicking anywhere inside the demo area.

Common use cases

  • File managers: Open, Rename, Delete, Download
  • Text editors: Copy, Paste, Select All
  • Tables: Row-specific actions
  • Design tools: Duplicate, Group, Bring Forward
  • Maps and canvases: Context-specific actions
WHY

What problem does it solve?

A context menu reduces UI clutter by showing actions when and where they are relevant.

Without a context menu
Every possible action may need a permanently visible button or toolbar, making the interface crowded.
With a context menu
Secondary or contextual actions stay hidden until the user asks for them.

Interview answer

“The context menu provides contextual actions without permanently occupying screen space. The important part is that the menu depends on the target and appears at the correct pointer position, while closing when the user clicks outside, presses Escape, or selects an action.”
HOW

How to implement a Context Menu

  1. Listen for the contextmenu event on the target area.
  2. Call preventDefault() if the custom menu should replace the browser's native menu.
  3. Store the pointer coordinates and the target/context data.
  4. Set the menu position and make it visible.
  5. Keep the menu inside the viewport by adjusting its position when necessary.
  6. Close it on outside click, Escape, scroll, or after an action.
  7. For keyboard users, provide an accessible alternative rather than relying only on right-click.
target.addEventListener("contextmenu", (event) => {
  event.preventDefault();

  menu.style.left = `${event.clientX}px`;
  menu.style.top = `${event.clientY}px`;
  menu.hidden = false;
});

document.addEventListener("click", closeMenu);

1 MINUTE

How to explain it to the interviewer in 1 minute

“I implemented a custom context menu that opens on the contextmenu event. I prevent the browser's default menu, capture the pointer coordinates and the target item, then position the custom menu near the cursor. I also handle important dismissal cases like clicking outside and pressing Escape. For production, I would keep the menu inside the viewport and make its actions keyboard accessible. If the menu is attached to a list or table, the selected target can be stored so each action operates on the correct item.”

1-minute structure

  1. What: Context-specific action menu.
  2. Trigger: contextmenu event.
  3. State: open/closed + position + target.
  4. Interaction: select action or dismiss.
  5. Production: viewport boundaries + accessibility.
5 MINUTES

How to explain it to the interviewer in 5 minutes

Opening: “I’ll explain the event flow, state model, positioning, dismissal behavior, accessibility and edge cases.”

1. Requirement

Show a custom action menu when the user invokes a context action, position it close to the pointer, and provide relevant actions for the target.

2. State model

I need three main pieces of state: whether the menu is open, its position, and the target/context for which the menu was opened.

3. Event handling

The contextmenu event gives me the pointer coordinates and target element. I call preventDefault() only when I intentionally replace the browser menu.

4. Positioning

The menu is positioned using pointer coordinates. Before showing it, I can compare its dimensions with viewport boundaries and shift it left/up when it would overflow.

5. Closing behavior

  • Click outside the menu.
  • Press Escape.
  • Scroll or resize when appropriate.
  • Select a menu action.
  • Open another context menu and replace the previous one.

6. Accessibility

Use semantic menu/menuitem roles where appropriate, support keyboard navigation, provide a non-pointer way to reach actions, and manage focus if the component behaves like a full menu.

7. Edge cases

  • Menu near the bottom/right edge of the viewport.
  • Rapidly opening multiple menus.
  • Target removed while the menu is open.
  • Nested elements with different context actions.
  • Touch devices where long-press behavior may be needed instead of right-click.
MY IMPLEMENTATION

How I would explain my implementation

“I started with a closed menu as the default state. On a right-click, I prevent the native context menu, store the cursor position and the target element, then make the custom menu visible. I keep the positioning logic separate so I can later add viewport-boundary handling. I attach global dismissal behavior for outside clicks and Escape. If this were a file list, the target reference or item ID would be stored in state so actions such as Rename or Delete know exactly which item the user selected.”

Standalone implementation

Framework-free implementation showing the core machine-coding logic.

<div id="target" class="target">
  Right-click here
</div>

<div id="menu" class="context-menu" role="menu" hidden>
  <button role="menuitem" data-action="copy">Copy</button>
  <button role="menuitem" data-action="rename">Rename</button>
  <button role="menuitem" data-action="delete">Delete</button>
</div>

<script>
const target = document.querySelector("#target");
const menu = document.querySelector("#menu");

let contextTarget = null;

target.addEventListener("contextmenu", (event) => {
  event.preventDefault();

  contextTarget = event.target;

  const menuWidth = 190;
  const menuHeight = 150;

  const left = Math.min(
    event.clientX,
    window.innerWidth - menuWidth - 8
  );

  const top = Math.min(
    event.clientY,
    window.innerHeight - menuHeight - 8
  );

  menu.style.left = `${Math.max(8, left)}px`;
  menu.style.top = `${Math.max(8, top)}px`;
  menu.hidden = false;
});

document.addEventListener("click", (event) => {
  if (!menu.contains(event.target)) {
    closeMenu();
  }
});

document.addEventListener("keydown", (event) => {
  if (event.key === "Escape") {
    closeMenu();
  }
});

menu.addEventListener("click", (event) => {
  const action = event.target.dataset.action;

  if (!action || !contextTarget) return;

  console.log("Action:", action, "Target:", contextTarget);
  closeMenu();
});

function closeMenu() {
  menu.hidden = true;
  contextTarget = null;
}
</script>

React version — core idea

function ContextMenu({ children }) {
  const [menu, setMenu] = useState(null);

  const handleContextMenu = (event) => {
    event.preventDefault();

    setMenu({
      x: event.clientX,
      y: event.clientY,
      target: event.currentTarget
    });
  };

  return (
    <div onContextMenu={handleContextMenu}>
      {children}

      {menu && (
        <div
          role="menu"
          style={{
            position: "fixed",
            left: menu.x,
            top: menu.y
          }}
        >
          <button role="menuitem">Copy</button>
          <button role="menuitem">Rename</button>
          <button role="menuitem">Delete</button>
        </div>
      )}
    </div>
  );
}
COMMON MISTAKES

Common developer mistakes

1. Forgetting preventDefault()
The browser's native context menu appears together with the custom menu.
2. Not closing on outside click
The menu can remain stuck on screen after the user moves elsewhere.
3. Ignoring Escape
Keyboard users need a predictable way to dismiss the menu.
4. Positioning without viewport checks
A menu near the right or bottom edge can render partially outside the screen.
5. Losing the target item
In a list/table, actions can affect the wrong row if the selected target is not stored correctly.
6. Using only right-click
Touch devices and keyboard users may not have the same interaction. Provide accessible alternatives.
7. Putting all logic in one handler
Separate opening, positioning, action execution and closing so the component is easier to test.
8. Overengineering keyboard behavior
For a basic round, start with accessible semantics and Escape/outside-click handling, then add arrow-key navigation if the requirements call for a full menu pattern.
FOLLOW-UP QUESTIONS

Likely interviewer follow-ups

How do you prevent the menu from going outside the viewport?

Measure the menu and compare its dimensions with window.innerWidth/innerHeight. Shift the menu left/up when necessary and keep a small viewport margin.

How would you make it work for a table?

Attach the handler to rows or the table container, identify the row from the event target, and store the row ID as the context target. Menu actions then operate on that ID.

How would you support touch devices?

Provide an explicit action button or support a long-press gesture if the product genuinely needs context-menu behavior on touch.

How would you make it accessible?

Use semantic controls, keyboard access, visible focus, Escape to close, and an accessible trigger/alternative action path. A context menu should not depend solely on a mouse.

How would you test it?

  • Right-click opens at the pointer location.
  • Browser native menu does not appear when custom behavior is enabled.
  • Click outside closes it.
  • Escape closes it.
  • Bottom/right-edge positioning stays visible.
  • Correct target is used for actions.
  • Keyboard and touch alternatives work.
