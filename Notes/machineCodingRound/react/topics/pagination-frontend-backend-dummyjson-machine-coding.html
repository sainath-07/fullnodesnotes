Pagination — Frontend + Backend

Machine Coding Round • React + DummyJSON server-side pagination

1. What is Pagination?
Question

What is pagination?

Answer

Pagination means dividing a large collection of records into smaller pages. Instead of showing every record at once, we show one page at a time.

Two common approaches:
Frontend pagination: the browser already has all records and uses slice() to display one page.
Backend pagination: the browser asks the server for only the records needed for the selected page.

For this machine-coding example, we will use DummyJSON so the server performs the pagination.

2. Why Backend Pagination?
Question

Why should pagination happen on the server?

  • We do not download the complete dataset.
  • Less data travels over the network.
  • The browser stores fewer records.
  • Large database tables are easier to work with.
  • The API can return exactly the requested page.
Key difference: With frontend pagination, all data may already be downloaded. With backend pagination, the server sends only the requested portion.
3. How Does Server-Side Pagination Work?
Question

How does the frontend request a specific page?

The frontend sends pagination information to the API, commonly using limit and skip.

skip = (page - 1) × limit

Example: page 3 with 10 items per page:

skip = (3 - 1) × 10 = 20

The server returns records starting from item 21, with at most 10 records.
4. DummyJSON API
Question

What API are we using?

We use the DummyJSON products endpoint:

https://dummyjson.com/products?limit=10&skip=0

For page 2 with 10 items:

https://dummyjson.com/products?limit=10&skip=10

Important response fields:

  • products — records for the current page
  • total — total number of records
  • skip — number of records skipped
  • limit — number of records requested
Why total matters: The frontend uses total to calculate how many page buttons are required.
5. Full React Code — Machine Coding Answer
import React, { useEffect, useState } from "react";

const API_URL = "https://dummyjson.com/products";

function ProductPagination() {
  const [products, setProducts] = useState([]);
  const [currentPage, setCurrentPage] = useState(1);
  const [limit, setLimit] = useState(10);
  const [total, setTotal] = useState(0);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState("");

  const totalPages = Math.ceil(total / limit);

  useEffect(() => {
    const controller = new AbortController();

    async function fetchProducts() {
      try {
        setLoading(true);
        setError("");

        const skip = (currentPage - 1) * limit;

        const response = await fetch(
          `${API_URL}?limit=${limit}&skip=${skip}`,
          { signal: controller.signal }
        );

        if (!response.ok) {
          throw new Error("Failed to fetch products");
        }

        const result = await response.json();

        setProducts(result.products);
        setTotal(result.total);
      } catch (err) {
        if (err.name !== "AbortError") {
          setError(err.message);
        }
      } finally {
        if (!controller.signal.aborted) {
          setLoading(false);
        }
      }
    }

    fetchProducts();

    return () => controller.abort();
  }, [currentPage, limit]);

  const goToPage = (page) => {
    if (page < 1 || page > totalPages) return;
    setCurrentPage(page);
  };

  const handleLimitChange = (event) => {
    setLimit(Number(event.target.value));
    setCurrentPage(1);
  };

  return (
    <div>
      <h2>Products</h2>

      <label>Items per page: </label>

      <select
        value={limit}
        onChange={handleLimitChange}
      >
        <option value={5}>5</option>
        <option value={10}>10</option>
        <option value={20}>20</option>
      </select>

      {loading && <p>Loading...</p>}
      {error && <p>{error}</p>}

      <ul>
        {products.map((product) => (
          <li key={product.id}>
            {product.title}
          </li>
        ))}
      </ul>

      <button
        disabled={currentPage === 1 || loading}
        onClick={() => goToPage(currentPage - 1)}
      >
        Previous
      </button>

      {Array.from(
        { length: totalPages },
        (_, index) => index + 1
      ).map((page) => (
        <button
          key={page}
          disabled={loading}
          onClick={() => goToPage(page)}
          aria-current={
            currentPage === page ? "page" : undefined
          }
        >
          {page}
        </button>
      ))}

      <button
        disabled={currentPage === totalPages || loading}
        onClick={() => goToPage(currentPage + 1)}
      >
        Next
      </button>
    </div>
  );
}

export default ProductPagination;
Core logic: page changes → useEffect runs → calculate skip → call API → receive current page → update products and total → render.
6. Common Developer Mistakes
1. Wrong skip calculation: Use (currentPage - 1) * limit. Do not use currentPage * limit.
2. Forgetting total: The API's total is needed to calculate totalPages.
3. Fetching only once: The API request must depend on currentPage and limit.
4. Not resetting page-size: When limit changes, reset to page 1.
5. Not handling loading: Rapid clicks can create multiple requests and poor UI feedback.
6. Ignoring race conditions: A slower old response can overwrite a newer response. Abort the previous request or otherwise guard against stale responses.
7. No error handling: Network/API failures should show a useful message.
8. Rendering every page button: Thousands of pages can create a huge pagination control. Use condensed pagination for large page counts.
9. Unstable React keys: Use a unique product ID such as product.id.
10. Mixing frontend and backend pagination: Do not download all records and call it server-side pagination. The API request itself should contain the page range.

Page Calculation Example

Assume:

  • Total products = 194
  • Items per page = 10
  • Current page = 4

totalPages = Math.ceil(194 / 10) = 20

skip = (4 - 1) × 10 = 30

So the request becomes:

GET /products?limit=10&skip=30
The server returns up to 10 products starting after the first 30 products.

Loading and Race-Condition Explanation

Suppose the user quickly clicks page 2 and page 3.

Request A
Page 2
→
Request B
Page 3
→
B finishes first
→
A finishes later

If we do not protect against stale responses, page 2 data could overwrite page 3 data.

Solution used in our code: AbortController cancels the previous fetch when the effect is cleaned up.
How I Would Explain My Implementation to the Interviewer

Interviewer-ready answer:

“I am implementing server-side pagination because the dataset can be large, so I do not want to download all records to the browser. I maintain the current page and page size in React state. Whenever either value changes, I calculate the skip value using (currentPage - 1) * limit. I then call the DummyJSON products API with limit and skip. The API returns the current page of products along with the total number of products. I store the products and total in state. The total lets me calculate the number of pages using Math.ceil(total / limit). I also handle loading and errors, disable navigation while loading, reset to page 1 when the page size changes, use stable product IDs as React keys, and abort stale requests to avoid race conditions.”

Then explain the implementation in this order:
  1. State: products, currentPage, limit, total, loading, error.
  2. Derived value: totalPages.
  3. Request: calculate skip and call API.
  4. Response: update products and total.
  5. Navigation: change currentPage.
  6. Edge cases: loading, errors, invalid pages, page-size changes, stale requests.
Interview tip: First explain the API contract and data flow. Then write the smallest working pagination. Finally add production concerns such as cancellation, error handling and large page-button handling.
