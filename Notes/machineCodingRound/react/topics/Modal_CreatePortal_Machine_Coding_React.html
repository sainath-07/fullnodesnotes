What?

What is a Modal?

A modal is a temporary UI layer that appears above the current page and asks the user to focus on a specific action or piece of information.

Examples include:

  • Delete confirmation
  • Login/signup form
  • Product details
  • Image preview
  • Payment confirmation

React Portal

What is createPortal?

createPortal allows React to render a component's DOM into a different DOM node while the component remains part of the same React tree.

import { createPortal } from "react-dom";

return createPortal(
  <div>Modal content</div>,
  document.getElementById("modal-root")
);
#root
App content
→
#modal-root
Modal DOM
Simple interview answer: “I use a React Portal so the modal is rendered outside the normal application DOM container, which helps avoid layout and stacking issues such as parent overflow or z-index problems.”
Why?

Why use a Portal for a Modal?

1. Avoid overflow issues
A modal should not be clipped by a parent container with overflow: hidden.
2. Easier stacking
Rendering near the document body makes full-screen overlays and z-index management easier.
3. Cleaner DOM structure
The modal is separated from page layout while remaining controlled by React.
4. Reusable UI
The same Modal component can be used for delete dialogs, forms, previews, and confirmations.
Machine Coding Requirement

What should I build?

  1. Parent component controls whether the modal is open.
  2. Modal renders using createPortal.
  3. Clicking the close button closes the modal.
  4. Pressing Escape closes the modal.
  5. Clicking the backdrop closes the modal.
  6. Clicking the actual modal content does not close it.
  7. Event listener must be cleaned up when the modal closes/unmounts.
Keyboard Interaction

Close Modal with Escape using useEffect

When the modal is open, attach a keydown event listener to the document. If the pressed key is Escape, call onClose().

useEffect(() => {
  if (!isOpen) return;

  const handleKeyDown = (e) => {
    if (e.key === "Escape") {
      onClose();
    }
  };

  document.addEventListener("keydown", handleKeyDown);

  return () => {
    document.removeEventListener("keydown", handleKeyDown);
  };
}, [isOpen, onClose]);
Why cleanup? Without removeEventListener, old listeners can remain attached and cause duplicate handlers, memory leaks, or unexpected behavior.
Interview sentence: “I only attach the keyboard listener when the modal is open and clean it up in the effect cleanup function.”
Backdrop Interaction

Why e.target === e.currentTarget?

This is one of the most important Modal interview patterns.

const handleBackdropClick = (e) => {
  if (e.target === e.currentTarget) {
    onClose();
  }
};
What is the difference?
  • e.target = the actual element that was clicked.
  • e.currentTarget = the element whose handler is currently running.
Modal content

Click here → target is the modal content.

Click backdrop: target === currentTarget → close modal ✅
Click modal content: target !== currentTarget → keep modal open ✅
Simple memory trick:
target = “What did I actually click?”
currentTarget = “Which element owns this handler?”

React Modal using createPortal

index.html: Add a dedicated DOM node for the portal.

<body>
  <div id="root"></div>
  <div id="modal-root"></div>

  <script type="module" src="/src/main.jsx"></script>
</body>

Modal.jsx:

import { useEffect } from "react";
import { createPortal } from "react-dom";

function Modal({ isOpen, onClose, children }) {

  useEffect(() => {
    if (!isOpen) return;

    const handleKeyDown = (e) => {
      if (e.key === "Escape") {
        onClose();
      }
    };

    document.addEventListener("keydown", handleKeyDown);

    return () => {
      document.removeEventListener("keydown", handleKeyDown);
    };
  }, [isOpen, onClose]);

  if (!isOpen) {
    return null;
  }

  const handleBackdropClick = (e) => {
    if (e.target === e.currentTarget) {
      onClose();
    }
  };

  return createPortal(
    <div
      className="modal-backdrop"
      onClick={handleBackdropClick}
      role="presentation"
    >
      <div
        className="modal-content"
        role="dialog"
        aria-modal="true"
        aria-labelledby="modal-title"
      >
        {children}

        <button
          type="button"
          onClick={onClose}
          aria-label="Close modal"
        >
          ×
        </button>
      </div>
    </div>,
    document.getElementById("modal-root")
  );
}

export default Modal;

App.jsx:

import { useState } from "react";
import Modal from "./Modal";

function App() {
  const [isOpen, setIsOpen] = useState(false);

  return (
    <div>
      <button onClick={() => setIsOpen(true)}>
        Open Modal
      </button>

      <Modal
        isOpen={isOpen}
        onClose={() => setIsOpen(false)}
      >
        <h2 id="modal-title">Delete Item</h2>
        <p>Are you sure you want to delete this item?</p>

        <button onClick={() => setIsOpen(false)}>
          Cancel
        </button>

        <button
          onClick={() => {
            console.log("Delete confirmed");
            setIsOpen(false);
          }}
        >
          Delete
        </button>
      </Modal>
    </div>
  );
}

export default App;
Core logic to remember: isOpen → createPortal → Escape / backdrop / close button → onClose → isOpen=false
Common Developer Mistakes

Mistakes to avoid

1. Forgetting the Portal target
document.getElementById("modal-root") must exist in the HTML.
2. Closing when clicking inside the modal
Do not simply use onClick={onClose} on the entire backdrop. Use e.target === e.currentTarget.
3. Forgetting Escape listener cleanup
Always remove the exact same handler in the useEffect cleanup.
4. Adding the listener even when the modal is closed
Return early when isOpen is false.
5. Wrong dependency array
If onClose is used inside the effect, account for it in the dependency array or stabilize the callback appropriately.
6. Using array indexes for unrelated modal identity
For dynamic lists, use stable IDs for modal content and selected items.
7. Ignoring accessibility
Use role="dialog", aria-modal="true", an accessible label, and a real close button.
8. Not handling body scroll
A production modal may need to prevent background scrolling while open.
Interview

How to explain in 1 minute

“I built a reusable Modal component controlled by an isOpen state in the parent. I use React's createPortal to render the modal into a dedicated modal-root outside the main application DOM container. This helps avoid layout, overflow, and stacking issues. For closing behavior, I support three methods: a close button, the Escape key, and clicking the backdrop. I use useEffect to add a document-level keydown listener only while the modal is open, and I remove it in the cleanup function. For backdrop clicks, I check e.target === e.currentTarget, which means the modal closes only when the backdrop itself was clicked, not when the user clicks inside the modal content.”

Edge Cases

What can the interviewer test?

  • Open and close the modal repeatedly.
  • Press Escape while the modal is open.
  • Press Escape when the modal is closed.
  • Click the backdrop.
  • Click inside modal content and verify it stays open.
  • Render long content and verify scrolling works.
  • Open a form inside the modal.
  • Open multiple modal-like flows without leaving stale event listeners.
  • Test keyboard accessibility.
Advanced Follow-up

How can you improve it?

  • Trap keyboard focus inside the modal while it is open.
  • Return focus to the element that opened the modal.
  • Prevent background page scrolling.
  • Add enter/exit animations.
  • Support a configurable closeOnBackdropClick prop.
  • Support a configurable closeOnEscape prop.
  • Add nested-modal or stacking management only if the product actually requires it.
  • Create a reusable modal API using children and composable actions.
