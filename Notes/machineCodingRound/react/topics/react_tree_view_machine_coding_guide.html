1. What is a Tree View?

Definition: A Tree View is a UI component that displays hierarchical data using parent-child relationships. A parent node can contain one or more child nodes.

Layman example: Think about folders on your computer. A main folder can contain subfolders, and those subfolders can contain more folders and files. The UI displays this relationship like a tree.
📁 src
├── 📁 components
│   ├── 📄 Header.jsx
│   └── 📄 Button.jsx
├── 📁 pages
│   └── 📄 Home.jsx
└── 📄 App.jsx

The important idea is that the data is hierarchical and the UI should represent the same hierarchy.

2. What Problem Does Tree View Resolve?

A normal list is useful when every item has the same level. But it becomes difficult to understand relationships when data has multiple levels.

Flat List
Folder and files appear at the same level. Parent-child relationships are difficult to see.
Tree View
Children are displayed under their parent and can be expanded or collapsed.
Problem solved: Tree View makes hierarchical data easier to understand, navigate and manage.

4. How Does Tree View Work?
  1. Receive hierarchical data from state or an API.
  2. Render the root nodes.
  3. Check whether each node has children.
  4. Display an expand/collapse button when children exist.
  5. When expanded, recursively render the children.
  6. When collapsed, hide the children.
  7. Maintain expanded node IDs in React state.
Core idea: The component renders one node. If that node has children and is expanded, the same component renders its children.

import { useState } from "react";
import TreeNode from "./TreeNode";

const treeData = [
  {
    id: 1,
    name: "src",
    type: "folder",
    children: [
      {
        id: 2,
        name: "components",
        type: "folder",
        children: [
          {
            id: 3,
            name: "Header.jsx",
            type: "file",
            children: []
          },
          {
            id: 4,
            name: "Button.jsx",
            type: "file",
            children: []
          }
        ]
      },
      {
        id: 5,
        name: "pages",
        type: "folder",
        children: [
          {
            id: 6,
            name: "Home.jsx",
            type: "file",
            children: []
          }
        ]
      },
      {
        id: 7,
        name: "App.jsx",
        type: "file",
        children: []
      }
    ]
  }
];

function App() {
  const [expandedIds, setExpandedIds] = useState(new Set());

  const toggleNode = (id) => {
    setExpandedIds((previous) => {
      const next = new Set(previous);

      if (next.has(id)) {
        next.delete(id);
      } else {
        next.add(id);
      }

      return next;
    });
  };

  return (
    <div>
      <h1>React Tree View</h1>

      {treeData.map((node) => (
        <TreeNode
          key={node.id}
          node={node}
          expandedIds={expandedIds}
          onToggle={toggleNode}
        />
      ))}
    </div>
  );
}

export default App;
TreeNode.jsx
function TreeNode({ node, expandedIds, onToggle }) {
  const hasChildren = node.children?.length > 0;
  const isExpanded = expandedIds.has(node.id);

  const handleToggle = () => {
    if (hasChildren) {
      onToggle(node.id);
    }
  };

  return (
    <div style={{ marginLeft: "20px" }}>

      <div
        style={{
          display: "flex",
          alignItems: "center",
          gap: "8px",
          padding: "8px"
        }}
      >

        {hasChildren ? (
          <button onClick={handleToggle}>
            {isExpanded ? "▼" : "▶"}
          </button>
        ) : (
          <span style={{ width: "32px" }} />
        )}

        <span>
          {node.type === "folder" ? "📁" : "📄"}
        </span>

        <span>{node.name}</span>
      </div>

      {hasChildren && isExpanded && (
        <div>
          {node.children.map((child) => (
            <TreeNode
              key={child.id}
              node={child}
              expandedIds={expandedIds}
              onToggle={onToggle}
            />
          ))}
        </div>
      )}

    </div>
  );
}

export default TreeNode;
Key implementation concepts: recursive component tree traversal Set for expanded IDs immutable state stable keys
Why use a Set for expandedIds?

A Set makes it simple to check whether a node is currently expanded.

expandedIds.has(node.id)   // check
expandedIds.add(node.id)   // expand
expandedIds.delete(node.id) // collapse
9. Why Recursion?

Tree data can have any number of levels. Recursion lets the same TreeNode component render every level.

Without Recursion

You may write separate logic for Level 1, Level 2, Level 3, etc.

This becomes repetitive and does not handle unknown depth well.

With Recursion

The component renders itself for each child.

The same code works for any supported tree depth.

Recursive flow
TreeNode
   ↓
Render current node
   ↓
Has children?
   ↓ yes
Is expanded?
   ↓ yes
children.map(...)
   ↓
TreeNode(child)
   ↓
Repeat
Interview line: “I use recursion because the UI structure mirrors the recursive nature of the tree data.”
10. State Management

The tree data and UI state are two different things.

Tree Data

Represents what nodes exist.

treeData
UI State

Represents which nodes are currently expanded.

expandedIds
Good design: Keep the main tree state in the parent component and pass only the data and actions required by the recursive child component.
Expand / Collapse logic
if (expandedIds.has(id)) {
    // node is open → close it
    next.delete(id);
} else {
    // node is closed → open it
    next.add(id);
}
11. Common Developer Mistakes
1. Using array index as the key
Use a stable unique ID such as node.id. Index keys can cause incorrect rendering when tree items change.
2. Hard-coding nesting levels
Do not create separate components for Level 1, Level 2 and Level 3. Use recursion.
3. Mutating the Set directly
Avoid changing the existing state object and returning it. Create a new Set so React receives a new reference.
4. Mutating tree data directly
Avoid direct operations such as node.children.push() when tree data is React state. Use immutable updates.
5. Forgetting the leaf-node case
Files or nodes without children should not display an expand/collapse button.
6. Expanding every node unintentionally
Decide whether the initial UI should be collapsed, partially expanded or fully expanded.
7. Rendering huge trees without optimization
Thousands of nodes can make rendering expensive. Consider lazy loading, virtualization or pagination depending on the use case.
8. Mixing data logic and UI logic everywhere
Keep tree operations and rendering responsibilities organized so the component remains maintainable.
12. How I Would Explain My Implementation to the Interviewer
Interview explanation:

“I implemented the Tree View using a hierarchical tree data structure. Each node contains an ID, name, type and a children array. I created a reusable TreeNode component that renders one node. If the node has children and it is expanded, TreeNode recursively renders each child. I maintain a Set of expanded node IDs in the parent component, which allows me to control the expand and collapse state without changing the actual tree data.”

Explain it in this order
  1. Data structure: “The data follows a parent-child tree structure.”
  2. Component: “TreeNode handles one node.”
  3. Recursion: “TreeNode renders itself for child nodes.”
  4. Expand state: “I keep expanded IDs in a Set.”
  5. Toggle: “Clicking a folder adds or removes its ID from the Set.”
  6. Conditional rendering: “Children are rendered only when the node is expanded.”
  7. Leaf handling: “Nodes without children do not show an expand button.”
  8. Scalability: “For large trees, I would consider lazy loading or virtualization.”
Strong interview line: “The key challenge is making the component work for an unknown number of nesting levels while keeping expansion state separate from the tree data.”
13. Common Follow-Up Questions

A tree contains nodes that can contain more nodes of the same structure. Recursion lets the same component render every level.

A Set is convenient for membership checks and add/delete operations. It also clearly represents a collection of unique expanded node IDs.

Find the target parent node recursively, create a new node with a unique ID, and immutably add it to that parent's children array.

Recursively traverse the tree and filter the target node from each children array. If deleting a folder, decide whether its descendants should also be removed.

Traverse the tree, collect the IDs of nodes that have children, and put those IDs into the expanded Set.

Load children on demand, avoid rendering collapsed descendants, consider virtualization for large visible lists, and fetch data incrementally when appropriate.
