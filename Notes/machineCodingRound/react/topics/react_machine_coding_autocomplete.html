Answer

Different ways to build autocomplete.

What is Autocomplete?

Autocomplete is a UI feature that gives the user suggestions while they type. Instead of making the user type the complete value, the application predicts or filters possible values and lets the user choose one.

Why do we use it?

  • It makes searching faster.
  • It reduces typing effort.
  • It helps users find valid values.
  • It improves the user experience.
  • It reduces spelling mistakes when selecting from known options.

What problem does it solve?

Without autocomplete, the user may need to remember and type the complete value. With autocomplete, the UI narrows a large list into a small set of useful choices.

Industry interview recommendation: For a frontend React machine-coding round, a good solution is a reusable component using controlled input + filtered suggestions + debounce when the search operation is expensive or represents an API-like operation. If asynchronous requests are involved, also think about stale responses/race conditions.

Common ways to implement it

Approach 1 — Filter a local array

Keep suggestions in memory and use filter() whenever the input changes. This is the simplest approach for small/static data. 

const filtered = options.filter(item =>
  item.toLowerCase().includes(value.toLowerCase())
);
Approach 2 — Debounced autocomplete

Wait for the user to stop typing for a short time before calculating suggestions or starting an API-like operation. This avoids doing expensive work on every keystroke. 

const debouncedValue = useDebounce(value, 300);

useEffect(() => {
  // calculate or load suggestions
}, [debouncedValue]);
Approach 3 — Debounce + request cancellation/stale-response protection

This is useful when suggestions are asynchronous. Debounce reduces how many requests start, while cancellation or stale-response protection prevents an older result from incorrectly replacing a newer result.

Best interview answer: Start simple. If the interviewer gives a local/static dataset, use filtering. If they expect realistic search behavior, use a reusable useDebounce hook. If asynchronous requests are part of the requirement, add AbortController or another stale-response strategy.

Reusable useDebounce Hook

import { useEffect, useState } from "react";

function useDebounce(value, delay = 300) {
  const [debouncedValue, setDebouncedValue] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => {
      setDebouncedValue(value);
    }, delay);

    return () => {
      clearTimeout(timer);
    };
  }, [value, delay]);

  return debouncedValue;
}

export default useDebounce;

Example Component

import { useMemo, useState } from "react";
import useDebounce from "./useDebounce";

const options = [
  "React",
  "React Native",
  "Redux",
  "JavaScript",
  "TypeScript",
  "Next.js"
];

function Autocomplete() {
  const [search, setSearch] = useState("");
  const [selected, setSelected] = useState("");

  const debouncedSearch = useDebounce(search, 300);

  const suggestions = useMemo(() => {
    if (!debouncedSearch.trim()) return [];

    return options.filter(item =>
      item.toLowerCase().includes(debouncedSearch.toLowerCase())
    );
  }, [debouncedSearch]);

  function handleSelect(item) {
    setSearch(item);
    setSelected(item);
  }

  return (
    <div>
      <input
        value={search}
        onChange={(e) => setSearch(e.target.value)}
        placeholder="Search technology..."
      />

      {debouncedSearch && (
        <ul>
          {suggestions.length === 0 ? (
            <li>No results found</li>
          ) : (
            suggestions.map(item => (
              <li
                key={item}
                onClick={() => handleSelect(item)}
              >
                {item}
              </li>
            ))
          )}
        </ul>
      )}

      {selected && <p>Selected: {selected}</p>}
    </div>
  );
}

export default Autocomplete;

Common Developer Mistakes

Things interviewers commonly notice.

1. Filtering on every expensive operation

For a tiny local array this may be fine. For expensive computation or API search, consider debounce.

2. Putting debounce logic directly everywhere

If the same debounce behavior is needed in multiple components, create a reusable useDebounce hook.

3. Forgetting clearTimeout

Every new value should clear the previous timer. Otherwise multiple delayed callbacks can run.

4. Showing stale asynchronous results

Debounce does not automatically solve race conditions. If requests can overlap, protect the UI from older responses.

5. Forgetting the empty-input case

When the input is empty, do not show a meaningless suggestion dropdown.

6. Missing stable keys

When rendering suggestions with map(), provide a stable React key.

7. Not handling "No results"

A good autocomplete should clearly tell the user when there are no matching options.

8. Making the hook responsible for UI

A generic useDebounce hook should handle debounce behavior, not dropdown rendering, selection, or API-specific UI.

9. Ignoring keyboard accessibility

In a production-quality autocomplete, consider Arrow Up/Down, Enter, Escape, focus management, and appropriate ARIA attributes.

2. Autocomplete.jsx

import { useMemo, useState } from "react";
import useDebounce from "./useDebounce";

const options = [
  "React",
  "React Native",
  "Redux",
  "JavaScript",
  "TypeScript",
  "Next.js",
  "Node.js",
  "Django"
];

export default function Autocomplete() {
  const [search, setSearch] = useState("");
  const [selected, setSelected] = useState("");

  const debouncedSearch = useDebounce(search, 300);

  const suggestions = useMemo(() => {
    const value = debouncedSearch.trim().toLowerCase();

    if (!value) return [];

    return options.filter(item =>
      item.toLowerCase().includes(value)
    );
  }, [debouncedSearch]);

  const handleSelect = (item) => {
    setSearch(item);
    setSelected(item);
  };

  return (
    <div className="autocomplete">
      <input
        value={search}
        onChange={(e) => {
          setSearch(e.target.value);
          setSelected("");
        }}
        placeholder="Search technology..."
      />

      {debouncedSearch.trim() && (
        <div className="suggestions">
          {suggestions.length === 0 ? (
            <div>No results found</div>
          ) : (
            suggestions.map(item => (
              <button
                key={item}
                type="button"
                onClick={() => handleSelect(item)}
              >
                {item}
              </button>
            ))
          )}
        </div>
      )}

      {selected && (
        <p>Selected: {selected}</p>
      )}
    </div>
  );
}

Production-level improvements

  • Keyboard navigation: Arrow Up / Arrow Down.
  • Enter to select the highlighted suggestion.
  • Escape to close the dropdown.
  • Click-outside handling.
  • ARIA roles and accessibility.
  • Loading and error states for async suggestions.
  • AbortController or stale-response protection for overlapping requests.
  • Virtualization if the suggestion list becomes very large.
Interview tip: Do not over-engineer the first version. Build the basic autocomplete first, explain your state and data flow, then add debounce, async handling, keyboard support, and accessibility if the interviewer asks for them.
