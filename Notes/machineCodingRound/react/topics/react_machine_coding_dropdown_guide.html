What is a Dropdown?

A Dropdown is a UI component that displays a list of options when the user clicks or interacts with a trigger such as a button.

Simple example: Click "Select Country" → a list of countries appears → select one country → the selected value is displayed.

Core idea: We control whether the options are visible using React state, and we update the selected option when the user clicks an item.

What problem does it solve?

  • Saves screen space by hiding options until they are needed.
  • Allows users to choose one option from a predefined list.
  • Provides a reusable UI pattern for menus, filters, categories, countries, sorting, etc.
  • Prevents a large list of options from occupying the entire page.
Interview point: A dropdown separates the trigger, open/close state, and option selection.

Expected Features for Machine Coding

1. Open / Close
Click the button to show or hide options.
2. Select Option
Click an option and update the selected value.
3. Close After Selection
Hide the menu after selecting an option.
4. Reusable Data
Render options using an array and map().
5. Outside Click
Close the dropdown when clicking outside it.
6. Accessibility
Use semantic buttons and keyboard-friendly behavior in a production version.

How I Have Implemented It — Interview Explanation

  1. I first created an array containing the dropdown options.
  2. I used useState to maintain whether the dropdown is open.
  3. I used another state variable to store the selected option.
  4. On button click, I toggle isOpen.
  5. If isOpen is true, I render the options using map().
  6. When an option is clicked, I update selected and close the dropdown.
  7. For a production-ready version, I would add outside-click handling, keyboard navigation, ARIA attributes, and focus management.
Good interview sentence:
"I kept the dropdown state-driven: one state controls visibility and another stores the selected option. The UI is derived from that state, so every user interaction causes a predictable React re-render."

Full React Code

This is a clean interview version. It focuses on the core dropdown behavior without adding unnecessary complexity.

import { useState } from "react";

const options = ["India", "USA", "UK", "Canada"];

function Dropdown() {
  const [isOpen, setIsOpen] = useState(false);
  const [selected, setSelected] = useState("Select Country");

  const handleSelect = (option) => {
    setSelected(option);
    setIsOpen(false);
  };

  return (
    <div className="dropdown">

      <button
        onClick={() => setIsOpen((prev) => !prev)}
        className="dropdown-button"
      >
        {selected}
        <span>⌄</span>
      </button>

      {isOpen && (
        <ul className="dropdown-menu">
          {options.map((option) => (
            <li
              key={option}
              onClick={() => handleSelect(option)}
              className="dropdown-item"
            >
              {option}
            </li>
          ))}
        </ul>
      )}

    </div>
  );
}

export default Dropdown;

Why use functional state update?
setIsOpen((prev) => !prev) uses the latest state value and is the safe pattern when the next state depends on the previous state.

How to Explain in 1 Minute

"I implemented the dropdown using React state. I maintain an isOpen boolean to control whether the options are visible and a selected state to store the user's selection. When the user clicks the button, I toggle isOpen. If it is true, I render the options using map(). When the user selects an option, I update the selected value and close the dropdown. I also use stable keys for the list items. In a production version, I would additionally handle outside clicks, keyboard navigation, focus management, and accessibility attributes."

How to Explain in 5 Minutes

1. Requirement

The user should be able to open a list, choose an option, see the selected value, and close the list.

2. Data

I keep the options in an array. This makes the component data-driven instead of hardcoding every option.

3. State

isOpen controls visibility. selected stores the current selection.

4. Rendering

I conditionally render the menu with {isOpen && (...)} and generate each option using map().

5. User interaction

Button click toggles the menu. Option click updates the selected value and closes the menu.

6. Improvements

For a real-world component, I would add outside-click detection, Escape-to-close, arrow-key navigation, focus handling, ARIA roles/attributes, disabled options, loading states, and reusable props.

Interview mindset: First build the core working version. Then explain how you would make it production-ready.

Common Developer Mistakes

1. Directly changing state
Wrong: isOpen = !isOpen
Correct: setIsOpen(prev => !prev)
2. Forgetting to close after selection
After selecting an item, update the selected value and close the menu.
3. Missing keys in mapped options
Use a stable unique key such as key={option.id}. Avoid array index when the list can change.
4. Mixing state responsibilities
Do not use one confusing state variable for both visibility and selected value. Keep responsibilities clear.
5. Hardcoding every option
Prefer an array and map() so the component is easier to maintain and reuse.
6. Forgetting outside-click behavior
A production dropdown should generally close when the user clicks outside the component.
7. Ignoring keyboard accessibility
A visually working dropdown is not automatically an accessible dropdown. Consider Tab, Enter, Escape, and Arrow keys.
8. Overengineering too early
In a timed machine-coding round, implement the required behavior first. Add enhancements only after the core version works.

Important Edge Cases

  • Options array is empty.
  • Two options have the same visible label.
  • User clicks the trigger repeatedly.
  • User clicks outside the dropdown.
  • User presses Escape while the menu is open.
  • Very long option names.
  • Large number of options.
  • Dropdown is close to the edge of the viewport.
  • Disabled option should not be selectable.
