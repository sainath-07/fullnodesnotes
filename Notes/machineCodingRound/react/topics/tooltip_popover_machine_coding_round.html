WHATUI COMPONENT

What is Tooltip / Popover?

A tooltip is a small, usually non-interactive message that gives brief information about a UI element, typically on hover or focus. A popover is a richer floating panel that can contain interactive content such as buttons, links, forms or additional details and is usually opened by a click/tap.

Tooltip

  • Short contextual information
  • Usually hover/focus triggered
  • Usually non-interactive
  • Examples: “Delete”, “Settings”, keyboard shortcut

Popover

  • More detailed contextual content
  • Usually click/tap triggered
  • Can contain interactive controls
  • Examples: filters, account menu, date details

WHY

What problem does it solve?

Tooltip and popover components provide contextual information without permanently taking up screen space.

Tooltip
Explains an unfamiliar icon, field, control or state without adding permanent labels.
Popover
Provides richer contextual content or actions without navigating away or opening a full page/modal.

Interview answer

“The problem is contextual information and actions. We don't want to clutter the main UI with every explanation or secondary action. A tooltip gives lightweight information, while a popover provides a richer interactive surface anchored to a particular element.”
HOW

How to implement Tooltip / Popover

  1. Create a trigger element and a floating content element.
  2. For a tooltip, open it on hover and focus, and close it when the trigger loses those states.
  3. For a popover, toggle it on click/tap.
  4. Position the floating element relative to the trigger.
  5. Keep it inside the viewport by calculating available space.
  6. Close a popover on outside click and Escape.
  7. Use appropriate accessibility relationships and keyboard behavior.

5 MINUTES

How to explain it to the interviewer in 5 minutes

Opening: “I’ll explain the distinction between tooltip and popover, then state, positioning, dismissal, accessibility and edge cases.”

1. Requirement

Provide contextual information near a trigger without taking the user to another screen. The behavior differs depending on whether the content is informational or interactive.

2. Tooltip vs Popover

A tooltip is lightweight and generally non-interactive. A popover is a richer floating surface and may contain buttons, links, filters or form controls.

3. State design

At minimum, I need visibility state. For a reusable component, I may also track the trigger/reference element, placement and positioning data.

4. Positioning

Measure the trigger and floating content, then choose a placement such as top, bottom, left or right. If the preferred placement overflows the viewport, fall back to another placement or shift the content.

5. Dismissal

  • Tooltip: close on pointer leave and loss of focus.
  • Popover: close on outside click and Escape.
  • Don't close a popover when the user interacts with its own content.

6. Accessibility

Tooltip content should be associated with its trigger, and a popover should have an appropriate accessible name/relationship and keyboard behavior. The trigger itself must be keyboard accessible.

7. Edge cases

  • Trigger near viewport edges.
  • Scrolling or resizing while open.
  • Nested interactive content inside a popover.
  • Rapid open/close interactions.
  • Touch devices where hover does not exist.
  • Long tooltip text or dynamic content changing the popover size.

<script>
const infoTrigger = document.querySelector("#infoTrigger");
const tooltip = document.querySelector("#tooltip");

function showTooltip() {
  tooltip.hidden = false;
  positionFloating(infoTrigger, tooltip);
}

function hideTooltip() {
  tooltip.hidden = true;
}

infoTrigger.addEventListener("mouseenter", showTooltip);
infoTrigger.addEventListener("mouseleave", hideTooltip);
infoTrigger.addEventListener("focus", showTooltip);
infoTrigger.addEventListener("blur", hideTooltip);

const popoverTrigger = document.querySelector("#popoverTrigger");
const popover = document.querySelector("#popover");

function openPopover() {
  popover.hidden = false;
  popoverTrigger.setAttribute("aria-expanded", "true");
  positionFloating(popoverTrigger, popover);
}

function closePopover() {
  popover.hidden = true;
  popoverTrigger.setAttribute("aria-expanded", "false");
}

popoverTrigger.addEventListener("click", () => {
  if (popover.hidden) openPopover();
  else closePopover();
});

document.addEventListener("click", (event) => {
  if (
    !popover.hidden &&
    !popover.contains(event.target) &&
    !popoverTrigger.contains(event.target)
  ) {
    closePopover();
  }
});

document.addEventListener("keydown", (event) => {
  if (event.key === "Escape") closePopover();
});

function positionFloating(trigger, floating) {
  const rect = trigger.getBoundingClientRect();

  floating.style.position = "fixed";
  floating.style.left = `${rect.left}px`;
  floating.style.top = `${rect.bottom + 8}px`;

  // Production version should measure the floating element
  // and flip/shift when it would overflow the viewport.
}
</script>

React version — core idea

function Popover({ children }) {
  const [open, setOpen] = useState(false);

  useEffect(() => {
    if (!open) return;

    const onKeyDown = e => {
      if (e.key === "Escape") setOpen(false);
    };

    document.addEventListener("keydown", onKeyDown);
    return () => document.removeEventListener("keydown", onKeyDown);
  }, [open]);

  return (
    <div className="popover-wrapper">
      <button
        aria-expanded={open}
        onClick={() => setOpen(v => !v)}
      >
        Options
      </button>

      {open && (
        <div role="dialog">
          {children}
        </div>
      )}
    </div>
  );
}
COMMON MISTAKES

Common developer mistakes

1. Treating tooltip and popover as the same thing
A tooltip is generally non-interactive information; a popover can contain interactive content and has different dismissal/focus behavior.
2. Tooltip works only on hover
Keyboard users may never hover. Support focus as well.
3. No viewport collision handling
A floating element can be clipped at the top, bottom or sides of the viewport.
4. Closing popover when clicking inside it
Global outside-click logic must exclude both the trigger and the popover itself.
5. Forgetting Escape
Escape provides a predictable keyboard dismissal mechanism for popovers.
6. Using hover for interactive popovers
Interactive content should not disappear simply because the pointer moves from the trigger to the popover.
7. Missing ARIA relationships
Connect the trigger and floating content appropriately and expose expanded state where applicable.
8. Ignoring touch devices
Hover is not a reliable interaction on touch. Use click/tap or another touch-friendly interaction for appropriate components.
9. Building positioning logic from scratch unnecessarily
In production, a mature positioning solution can handle collision detection, flipping and shifting more reliably. In a machine-coding round, explain the algorithm clearly before adding dependencies.
FOLLOW-UP QUESTIONS

Likely interviewer follow-ups

What is the difference between tooltip and popover?

Tooltip is brief, contextual and normally non-interactive. Popover is richer, can contain interactive content and usually has explicit open/close behavior.

How do you prevent a tooltip from going outside the viewport?

Measure the trigger and floating element, then choose or adjust placement based on available viewport space. Common strategies are flip and shift.

How would you handle a popover inside a scrollable container?

Decide whether it should be positioned relative to the container or viewport. Recalculate on scroll/resize and ensure the correct stacking context.

How would you make it accessible?

Use a keyboard-accessible trigger, correct ARIA relationships, focus management for interactive popovers, Escape dismissal and visible focus styles.

Would you build the positioning library yourself?

For a machine-coding round, implement the core positioning logic if asked. For production, use a proven positioning primitive/library when it reduces edge-case risk.

How would you test it?

  • Tooltip opens on hover and focus.
  • Tooltip closes on pointer leave/blur.
  • Popover opens and closes on click.
  • Popover closes on outside click and Escape.
  • Interactive popover content remains usable.
  • Placement stays visible near viewport edges.
  • Keyboard and touch interactions work.
