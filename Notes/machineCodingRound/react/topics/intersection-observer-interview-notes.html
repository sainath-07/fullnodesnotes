IntersectionObserver()

Simple, interview-ready notes covering the API, callbacks, options, cleanup, rootMargin, threshold and practical React usage.

LEFT — What is IntersectionObserver?

IntersectionObserver is a browser API that lets JavaScript know when an element enters, leaves, or changes its visible intersection with another element or the viewport.

In simple words:

“Tell me when this element becomes visible.”

It is especially useful for lazy loading, infinite scrolling, analytics visibility tracking, active navigation, and revealing content when it appears on screen.

LEFT — How does it work?
  1. Create an observer.
  2. Give it a callback function.
  3. Configure optional rules such as root, rootMargin, and threshold.
  4. Tell the observer which element to watch using observe().
  5. The browser watches the element for you.
  6. When the intersection crosses the configured threshold, the callback receives an entry.
Key idea: You do not continuously ask “is this element visible?” The browser reports relevant intersection changes to your callback.
LEFT — Interview Explanation
“IntersectionObserver is a browser API used to observe the visibility or intersection of an element relative to a root, usually the viewport. I create an observer with a callback and options, observe a target element, and the browser calls my callback when the target crosses the configured threshold. This avoids manually calculating scroll position on every scroll event.”

For infinite scrolling:

“I place a sentinel element at the bottom of the list. When that sentinel becomes visible, I fetch the next page and append the new records.”

LEFT — When do you need it?
  • Infinite scrolling
  • Lazy loading images
  • Lazy loading components/content
  • Track whether an ad or section is visible
  • Analytics such as “section viewed”
  • Reveal animations when elements enter the viewport
  • Highlight the current section in a documentation page
  • Load more content before the user reaches the end
LEFT — What pairs well with it?
  • useRef: access the DOM target/sentinel.
  • useEffect: create and clean up the observer.
  • useCallback: keep callback/fetch function identity stable when appropriate.
  • AbortController: cancel in-flight network requests.
  • Pagination: fetch the next chunk of data.
  • Loading state: prevent duplicate requests.
  • Virtualization: useful when the list becomes extremely large.
RIGHT — Basic Syntax
const observer = new IntersectionObserver(
  (entries, observer) => {
    const entry = entries[0];

    if (entry.isIntersecting) {
      console.log("Element is visible");
    }
  },
  {
    root: null,
    rootMargin: "0px",
    threshold: 0,
  }
);

// Start watching the target.
observer.observe(targetElement);

// Stop watching one target.
observer.unobserve(targetElement);

// Stop the observer completely.
observer.disconnect();
Remember: new IntersectionObserver() creates the observer. observe() starts watching a target.
RIGHT — Callback and IntersectionObserverEntry

The callback is called when an observed target crosses one of the configured thresholds.

const observer = new IntersectionObserver((entries, observer) => {
  entries.forEach((entry) => {
    console.log(entry.target);        // observed element
    console.log(entry.isIntersecting); // true / false
    console.log(entry.intersectionRatio); // 0 to 1
    console.log(entry.boundingClientRect);
    console.log(entry.intersectionRect);
    console.log(entry.rootBounds);
  });
});
entries

An array of IntersectionObserverEntry objects. One callback can contain entries for multiple observed targets.

observer

The observer instance. It can be used to stop observing a target or disconnect the observer.

Interview point: Do not assume entries[0] is always the only target. It is common when observing one sentinel, but entries is an array by design.

RIGHT — Rules / Best Practices
  1. Observe a real DOM element.
    Call observe(element) only after you have a valid element.
  2. Keep the target stable when possible.
    For infinite scrolling, use one sentinel at the end instead of observing every list item.
  3. Guard expensive work.
    The callback can run many times. Prevent duplicate API calls with a loading flag/ref.
  4. Use the correct root.
    If the scrollable area is a container, set that container as root instead of assuming the window is the root.
  5. Choose threshold intentionally.
    Use 0 when you care about entering the root, and higher values when a specific amount of visibility matters.
  6. Use rootMargin for preloading.
    Load content before the user reaches the exact target position.
  7. Clean up.
    Stop observing when the component/effect is no longer active.
  8. Handle errors.
    Network failures should not leave the UI permanently stuck in a loading state.
RIGHT — Cleanup in React

When an observer is created inside useEffect, return a cleanup function.

useEffect(() => {
  const observer = new IntersectionObserver(callback);

  const target = targetRef.current;

  if (target) {
    observer.observe(target);
  }

  return () => {
    if (target) {
      observer.unobserve(target);
    }

    observer.disconnect();
  };
}, []);
Why cleanup? It prevents the effect from leaving an observer active after the related React lifecycle/effect is finished. It also prevents unnecessary callbacks and retained references.
Network cleanup is separate: If the callback starts a fetch, consider AbortController when the request should be cancellable.
RIGHT — unobserve() vs disconnect()
MethodWhat it doesUse case
unobserve(target) Stops observing one specific target element. You want the observer to continue watching other targets.
disconnect() Stops the observer from watching all targets. Cleanup when the entire observer is no longer needed.
Simple memory trick: unobserve = one target • disconnect = everything for this observer
RIGHT — rootMargin

rootMargin changes the effective boundary used for intersection calculations. Think of it as adding an invisible margin around the root.

const observer = new IntersectionObserver(callback, {
  rootMargin: "400px 0px",
});
Without rootMargin
User reaches sentinel
↓
Fetch starts
With rootMargin: "400px"
Sentinel is still below viewport
↓
Fetch can start earlier
Infinite-scroll tip: A positive bottom root margin is useful when you want to fetch the next page before the user reaches the end.
RIGHT — threshold

threshold controls the visibility ratio at which the observer callback is notified.

ValueSimple meaning
0Notify when the target crosses from not intersecting to intersecting (and the reverse transition).
0.5Notify when the intersection crosses about 50% visibility.
1Notify when the target reaches full intersection with the root.
[0, 0.25, 0.5, 0.75, 1]Notify at multiple visibility-ratio thresholds.
 
const observer = new IntersectionObserver(callback, {
  threshold: 0.5,
});
Interview note: Threshold is about the intersection ratio. It is different from rootMargin, which changes the root's effective boundary.
RIGHT — Common Developer Mistakes
1. Creating observers repeatedly without cleanup
Always clean up observers created by an effect.
2. Forgetting to call observe()
Creating the observer alone does not start watching a target.
3. Using the wrong root
If a nested container scrolls, the container may need to be the root.
4. Triggering duplicate API requests
Use a loading guard, request state, or ref when the callback starts network work.
5. Assuming entries always has one item
The callback receives an array because one observer can watch multiple targets.
6. Using threshold as a preload distance
Use rootMargin when the goal is to start earlier or later spatially.
7. Observing every list item unnecessarily
For infinite scrolling, a single sentinel is usually enough.
