Infinite Scrolling with IntersectionObserver()

A practical, interview-ready implementation using useEffect, useRef, useCallback and AbortController.

LEFT SIDE — Question
Build Infinite Scrolling in React

Fetch products in small batches. When the user reaches the bottom of the list, automatically request the next batch without using a scroll event listener.

Expected: Use IntersectionObserver(), maintain pagination state, show loading state, stop when all records are loaded, and clean up the observer/request.
LEFT SIDE — Answer

Core idea: Put a tiny sentinel element after the last product.

  1. Fetch the first page.
  2. Observe the sentinel using IntersectionObserver.
  3. When the sentinel enters the viewport, fetch the next page.
  4. Append the new products to the existing array.
  5. Increase skip by LIMIT.
  6. Stop observing/fetching when skip >= total.
Important: Do not start a second request while one request is already running.
LEFT SIDE — How I would explain it to the interviewer

You can say:

“I will implement infinite scrolling using an IntersectionObserver instead of listening to the window scroll event. I render a small sentinel div after the last product and observe it. When it becomes visible, the observer callback requests the next page using the current skip value. I append the response to the existing products instead of replacing them. I also keep a loading guard so multiple observer callbacks cannot create duplicate requests. Once the API tells me that all records have been loaded, I stop triggering further requests. Finally, I clean up the observer and abort the request when the component unmounts.”
Why IntersectionObserver?
  • No manual scroll event calculation.
  • Browser efficiently detects visibility changes.
  • Cleaner React code.
  • Easy to preload using rootMargin.
Selected Related Answer
What is the sentinel?

A tiny DOM element placed after the list. We don't need to observe every product. We only observe this one element.

What is isIntersecting?

It tells us whether the observed sentinel is currently intersecting the observer's root/viewport.

Why useRef?

To keep a reference to the sentinel DOM node without causing a re-render.

Why useCallback?

To keep the fetch function's identity stable so the effect does not unnecessarily recreate the observer.

Why AbortController?

To cancel an in-flight request when the component is unmounted or when cleanup is required.

RIGHT SIDE — Corrected Full Code
I checked your implementation. The overall approach is correct, but there are a few important React issues. The version below fixes them and is safer for an interview answer. 
import React, {
  useCallback,
  useEffect,
  useRef,
  useState,
} from "react";

const LIMIT = 10;

const InfiniteScrolling = () => {
  const [products, setProducts] = useState([]);
  const [isLoading, setIsLoading] = useState(false);
  const [hasMore, setHasMore] = useState(true);
  const [totalCount, setTotalCount] = useState(0);

  // DOM reference for the small element placed after the last product.
  const sentinelRef = useRef(null);

  // Keep pagination and loading status in refs.
  // Refs give the observer callback the latest values
  // without recreating the observer on every state change.
  const skipRef = useRef(0);
  const loadingRef = useRef(false);

  const fetchProducts = useCallback(async (currentSkip, signal) => {
    // Prevent duplicate API calls.
    if (loadingRef.current) return;

    loadingRef.current = true;
    setIsLoading(true);

    try {
      const url =
        `https://dummyjson.com/products?limit=${LIMIT}&skip=${currentSkip}`;

      const response = await fetch(url, { signal });

      if (!response.ok) {
        throw new Error(`HTTP error: ${response.status}`);
      }

      const output = await response.json();

      setTotalCount(output.total);

      // Append new products to the existing list.
      setProducts((prev) => [...prev, ...output.products]);

      const nextSkip = currentSkip + output.products.length;

      // Update pagination only after the request succeeds.
      skipRef.current = nextSkip;

      // Stop after all products are loaded.
      if (nextSkip >= output.total || output.products.length === 0) {
        setHasMore(false);
      }
    } catch (error) {
      // AbortError is expected when cleanup cancels the request.
      if (error.name !== "AbortError") {
        console.error("Failed to fetch products:", error);
      }
    } finally {
      loadingRef.current = false;
      setIsLoading(false);
    }
  }, []);

  useEffect(() => {
    const controller = new AbortController();

    // Initial page.
    fetchProducts(0, controller.signal);

    return () => {
      // Cancel the initial/in-flight request on unmount.
      controller.abort();
    };
  }, [fetchProducts]);

  useEffect(() => {
    if (!hasMore) return;

    const controller = new AbortController();

    const observer = new IntersectionObserver(
      (entries) => {
        const entry = entries[0];

        if (!entry.isIntersecting) return;

        // Do not fetch while another request is running.
        if (loadingRef.current) return;

        fetchProducts(skipRef.current, controller.signal);
      },
      {
        // 1.0 means the whole sentinel should be visible.
        // For earlier loading, rootMargin can be used.
        threshold: 1.0,

        // Example:
        // rootMargin: "400px",
      }
    );

    const sentinel = sentinelRef.current;

    if (sentinel) {
      observer.observe(sentinel);
    }

    return () => {
      // Stop observing the sentinel.
      if (sentinel) {
        observer.unobserve(sentinel);
      }

      // Stop observing all targets.
      observer.disconnect();

      // Cancel the request associated with this effect.
      controller.abort();
    };
  }, [fetchProducts, hasMore]);

  return (
    <div>
      <h1>Infinite Scrolling</h1>

      {products.map((product) => (
        <div
          // product.id is better than product.title because
          // title may not be unique.
          key={product.id}
          style={{
            border: "1px solid #ccc",
            margin: "5px",
            padding: "10px",
          }}
        >
          <p>Title: {product.title}</p>
          <p>Brand: {product.brand}</p>
          <p>Category: {product.category}</p>

          <img
            src={product.thumbnail}
            alt={product.title}
            width="150"
          />
        </div>
      ))}

      {isLoading && (
        <h2 style={{ textAlign: "center" }}>
          Loading...
        </h2>
      )}

      {/* Sentinel: IntersectionObserver watches this element. */}
      {hasMore && (
        <div
          ref={sentinelRef}
          style={{ height: "20px" }}
          aria-hidden="true"
        />
      )}

      {!hasMore && (
        <p style={{ textAlign: "center" }}>
          All {totalCount} products loaded.
        </p>
      )}
    </div>
  );
};

export default InfiniteScrolling;
RIGHT SIDE — Problems in Your Original Code
1. Side effect inside setState updater

Your code does this:

setSkip((latestvalue) => {
  if (!isLoading) {
    fetchProducts(latestvalue);
  }
  return latestvalue;
});

Calling fetchProducts() inside a state updater is not a good pattern. React expects the updater to be pure, and development/Strict Mode can expose this problem. Use a ref or a separate effect instead.

2. isLoading is stale inside the observer

Your observer effect does not depend on isLoading, so the callback can keep the value captured when the effect was created. This makes the loading guard unreliable. A ref such as loadingRef.current gives the callback the latest value.

3. Initial request can race with the observer

The sentinel can be visible immediately, especially when the first page is short. That can trigger another fetch before the initial request finishes. The loading ref prevents this duplicate request.

4. AbortController was created but never aborted

You create new AbortController() inside fetchProducts, but the controller is not returned or aborted during cleanup. Therefore it does not provide the intended cancellation behavior.

5. Dependency array is incomplete

The observer effect uses hasMore, isLoading and fetchProducts. At minimum, hasMore must be represented in the effect lifecycle. In the corrected version, the loading state is deliberately moved to a ref so the observer can remain stable.

6. key={product.title} may be unsafe

A product title is not guaranteed to be unique. Prefer key={product.id}. This also connects to React's “Encountered two children with the same key” warning.

7. Unused code

Your imports contain useReducer, and index is declared in map() but not used. totalcount is also only stored, not meaningfully displayed. Remove unused pieces in an interview to keep the solution clean.

RIGHT SIDE — Common Developer Mistakes
  • Using scroll events unnecessarily: IntersectionObserver is simpler for detecting when the sentinel enters the viewport.
  • Duplicate API calls: The observer may fire more than once. Always protect the request with a loading guard.
  • Replacing instead of appending: Use setProducts(prev => [...prev, ...newProducts]).
  • Wrong pagination: Keep the next skip value consistent with the number of records actually returned.
  • Never stopping: Use the API's total or another server-provided signal to stop.
  • Observing every list item: One sentinel after the list is enough.
  • Wrong key: Avoid non-unique values such as title, name, category, or index when a stable ID exists.
  • No cleanup: Disconnect the observer and abort in-flight requests when appropriate.
  • Very strict threshold: threshold: 1.0 waits until the entire sentinel is visible. A rootMargin can start loading earlier.
  • No error handling: A production implementation should expose an error/retry UI rather than only logging to the console.
RIGHT SIDE — Important React Concepts
useRef

Stores the sentinel DOM element and mutable values such as the latest pagination/loading state without causing a re-render.

useEffect

Creates the observer and performs cleanup when the component/effect lifecycle changes.

useCallback

Keeps the fetch function stable so it can safely be used as an effect dependency.

IntersectionObserver

Lets the browser tell us when the sentinel enters the viewport instead of repeatedly calculating scroll position ourselves.

RIGHT SIDE — Interview Follow-up Questions
  1. Why not use a scroll event?
    You can, but you must calculate scroll position and potentially throttle/debounce the handler. IntersectionObserver is purpose-built for visibility detection.
  2. Why use a sentinel?
    Only one element needs to be observed, which keeps the implementation simple.
  3. Can the observer fire multiple times?
    Yes. That's why an in-flight loading guard is important.
  4. What does rootMargin do?
    It expands or shrinks the observer's effective root boundary. For example, rootMargin: "400px" can trigger loading before the user actually reaches the bottom.
  5. How would you improve this for production?
    Add retry UI, skeleton loaders, request deduplication, caching, virtualization for very large lists, and proper API pagination/error handling.
