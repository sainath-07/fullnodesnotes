1. Question

Machine Coding Task: Build an Autocomplete search component in React. As the user types, show matching suggestions and make an API call after the user stops typing for a short time.
Expected behaviour
  1. User types text into the search box.
  2. Do not call the API on every keystroke.
  3. Wait for the user to stop typing, for example 400–500 ms.
  4. Call the API with the search text.
  5. Show loading while the request is running.
  6. Display suggestions returned by the API.
  7. Allow the user to select a suggestion.
  8. Handle empty results and API errors.
  9. Prevent an older response from replacing newer results.
Interview note: Autocomplete is not just filtering an array. In a realistic machine coding round, the interviewer may expect debounce, API handling, loading/error states, cleanup, and race-condition protection.

2. Answer

What is Autocomplete?

Autocomplete is a UI feature that gives suggestions while the user is typing. Instead of making the user type the complete value, the application predicts or searches for possible values.

Layman example: Imagine you are telling a shopkeeper, “I want to buy a Sams...”. Before you finish saying “Samsung”, the shopkeeper starts showing possible Samsung products. That is the basic idea of autocomplete.
Why do we use it?
  • It makes search faster.
  • It reduces typing effort.
  • It helps users find valid values.
  • It improves user experience.
  • It can reduce mistakes caused by spelling or incomplete input.
What problem does it solve?

Without autocomplete, users may need to type the complete value and then search. With autocomplete, the application can suggest useful values before the user finishes typing.

3. How I Implemented — Explanation to Interviewer

Interview-ready explanation:

“I first keep the user's current input in React state. I don't want to make an API call for every key press because that can create unnecessary requests. So I use a reusable useDebounce hook that updates the debounced value only after the user stops typing for a short delay.

I use that debounced value as the trigger for the API call. While the request is running, I show a loading state. When the response arrives, I store the suggestions and render them below the input.

Because API requests can finish in a different order, I also protect the component from stale responses. I can use AbortController to cancel the previous fetch, and I also make sure an old response cannot update the current UI.

Finally, I handle empty input, empty results, loading, errors, selection, cleanup, and keyboard/accessibility considerations.”

Reusable useDebounce hook
import { useEffect, useState } from "react";

function useDebounce(value, delay = 500) {
  const [debouncedValue, setDebouncedValue] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => {
      setDebouncedValue(value);
    }, delay);

    return () => {
      clearTimeout(timer);
    };
  }, [value, delay]);

  return debouncedValue;
}

export default useDebounce;

4. Common Developer Mistakes

1. API call on every keystroke
Calling the API directly inside onChange can create too many requests. Use debounce for remote autocomplete.
2. Forgetting clearTimeout
If the debounce timer is not cleaned up, old timers can still execute.
3. Thinking debounce solves race conditions
Debounce reduces request frequency, but multiple requests can still overlap. Older responses may arrive later.
4. Not cancelling or ignoring stale requests
Use AbortController or a stale-response guard when appropriate.
5. No loading state
The user should know that suggestions are being fetched.
6. No empty-result handling
Show a useful “No suggestions found” state instead of an unexplained blank area.
7. API logic inside the generic debounce hook
Keep useDebounce generic. It should debounce a value, not know about search APIs.
8. Incorrect useEffect dependencies
Missing dependencies can create stale values or incorrect behaviour.
9. Unstable list keys
Prefer a stable unique identifier from the suggestion data instead of array index when possible.
10. Ignoring accessibility
A polished autocomplete should consider keyboard navigation, highlighted options, Enter/Escape behaviour, focus management, and appropriate ARIA roles.
11. No minimum search length
Depending on the product, avoid searching for empty strings or very short input such as one character.

import { useEffect, useState } from "react";

function useDebounce(value, delay = 500) {
  const [debouncedValue, setDebouncedValue] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => {
      setDebouncedValue(value);
    }, delay);

    return () => clearTimeout(timer);
  }, [value, delay]);

  return debouncedValue;
}

export default function Autocomplete() {
  const [query, setQuery] = useState("");
  const [suggestions, setSuggestions] = useState([]);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState("");

  const debouncedQuery = useDebounce(query, 500);

  useEffect(() => {
    const value = debouncedQuery.trim();

    if (!value) {
      setSuggestions([]);
      setError("");
      setLoading(false);
      return;
    }

    const controller = new AbortController();

    async function fetchSuggestions() {
      try {
        setLoading(true);
        setError("");

        const response = await fetch(
          `/api/search?q=${encodeURIComponent(value)}`,
          { signal: controller.signal }
        );

        if (!response.ok) {
          throw new Error("Request failed");
        }

        const data = await response.json();

        setSuggestions(data);
      } catch (err) {
        if (err.name !== "AbortError") {
          setError("Unable to load suggestions.");
          setSuggestions([]);
        }
      } finally {
        if (!controller.signal.aborted) {
          setLoading(false);
        }
      }
    }

    fetchSuggestions();

    return () => {
      controller.abort();
    };
  }, [debouncedQuery]);

  function handleSelect(item) {
    setQuery(item.name);
    setSuggestions([]);
  }

  return (
    <div className="autocomplete">
      <input
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        placeholder="Search..."
        aria-label="Search"
      />

      {loading && <div>Loading...</div>}

      {error && <div>{error}</div>}

      {!loading && !error && suggestions.length > 0 && (
        <ul>
          {suggestions.map((item) => (
            <li
              key={item.id}
              onClick={() => handleSelect(item)}
            >
              {item.name}
            </li>
          ))}
        </ul>
      )}

      {!loading &&
        !error &&
        query.trim() &&
        suggestions.length === 0 && (
          <div>No suggestions found</div>
        )}
    </div>
  );
}
