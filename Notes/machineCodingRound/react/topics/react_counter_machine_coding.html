React Counter

A simple but important React machine-coding task to demonstrate state, events, rendering, and component design.

Goal: Build a counter with Increment, Decrement, and Reset actions.

Left Side — Questions
1. What is a Counter?

Technical definition: A Counter is a small React application that stores a numeric value in component state and changes that value when the user interacts with buttons.

Layman example: Imagine a room light switch. Every time you press a button, something changes. Here, pressing + increases the number, - decreases it, and Reset brings it back to the starting value.

Core React concepts useState → Event Handling → State Update → Re-render → Updated UI

2. Why build a Counter?

The Counter looks simple, but it tests the fundamentals of React.

  • Can you create and manage state using useState?
  • Can you handle button click events?
  • Can you update state correctly?
  • Do you understand that changing state causes React to re-render?
  • Can you keep UI and state synchronized?
  • Can you write clean, readable component code?
Machine-coding point: The interviewer is usually checking your implementation approach, not the difficulty of the Counter itself.
3. Requirements
  1. Initial counter value should be 0.
  2. Increment button increases the value by 1.
  3. Decrement button decreases the value by 1.
  4. Reset button changes the value back to 0.
  5. The displayed number should update immediately after each action.
Optional requirements you may clarify
  • Should negative values be allowed?
  • Should there be a minimum or maximum value?
  • Should the step be configurable, such as +5 / -5?
  • Should buttons become disabled at limits?

5. How I Have Implemented It — Interview Explanation

You can explain your implementation in this order:

Step 1 — Create state

I use React's useState hook to store the current counter value. I initialize it with 0.

Step 2 — Create actions

I create separate click handlers for increment, decrement, and reset so each action has a clear responsibility.

Step 3 — Update state

Increment adds 1, decrement subtracts 1, and reset sets the value back to 0.

Step 4 — Render state

I display the state variable inside JSX. Whenever state changes, React re-renders the component and the updated value appears on screen.

One-line implementation summary: "I used useState to maintain the counter value, event handlers to modify the state, and JSX to render the latest state in the UI."
6. Full React Code
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  const handleIncrement = () => {
    setCount(prevCount => prevCount + 1);
  };

  const handleDecrement = () => {
    setCount(prevCount => prevCount - 1);
  };

  const handleReset = () => {
    setCount(0);
  };

  return (
    <div>
      <h2>Counter: {count}</h2>

      <button onClick={handleIncrement}>
        Increment
      </button>

      <button onClick={handleDecrement}>
        Decrement
      </button>

      <button onClick={handleReset}>
        Reset
      </button>
    </div>
  );
}

export default Counter;
Why use the previous-state form?

setCount(prevCount => prevCount + 1) tells React: "Take the latest previous value and increase it by 1."

This form is especially useful when the new state depends on the previous state.

  2. Actions: increment, decrement, reset
  3. Events: onClick
  4. Update: setCount(previous => previous ± 1)
  5. UI: React re-renders with the new value
8. How to Explain Counter in 5 Minutes
Minute 1 — Understand the requirement

I first clarify the expected behavior: starting value, increment/decrement behavior, reset behavior, and whether negative values are allowed.

Minute 2 — Design the state

I only need one piece of state: count. The initial value is 0. Since the UI depends directly on this value, React state is appropriate.

Minute 3 — Implement actions

I create handlers for Increment, Decrement, and Reset. For increment/decrement, I use the functional updater because the new value depends on the previous state.

Minute 4 — Connect state to UI

I render {count} in JSX and attach handlers to buttons using onClick. A state update causes React to render the updated value.

Minute 5 — Discuss edge cases and quality
  • Negative values: clarify whether they are allowed.
  • Minimum/maximum: add conditions if the requirement specifies limits.
  • Multiple rapid updates: use functional updates when depending on previous state.
  • Maintainability: keep handlers readable and responsibilities clear.
Strong closing line: "The implementation is intentionally simple because the main goal is to demonstrate correct React state management, event handling, rendering, and handling of requirements."
9. Common Developer Mistakes
Mistake 1 — Directly changing state 
// Wrong
count = count + 1;

React state should be changed through its setter, such as setCount.

Mistake 2 — Calling the function immediately 
// Wrong
<button onClick={handleIncrement()}>
  Increment
</button>

// Correct
<button onClick={handleIncrement}>
  Increment
</button>

The second version passes the function to React. The first version executes it during rendering.

Mistake 3 — Ignoring previous state 
// Less robust when new state depends on old state
setCount(count + 1);

// Preferred for previous-state updates
setCount(prevCount => prevCount + 1);
Mistake 4 — Mutating state directly

Do not treat React state like a normal variable. Use the setter provided by useState.

Mistake 5 — Forgetting requirements

For example, the interviewer may ask for a minimum value, maximum value, step size, or disabled buttons. Clarify requirements before coding.

Developer tip: Before writing code, spend a few seconds identifying state, user actions, UI output, and edge cases.
