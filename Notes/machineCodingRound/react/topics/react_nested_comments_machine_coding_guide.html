1. What are Nested Comments?

Definition: Nested comments are comments that can contain replies, and those replies can contain more replies. This creates a tree-like structure.

Layman example: Think about a conversation. Person A asks a question. Person B replies to A. Person C replies specifically to B. Person D can reply to C. Each reply stays connected to the comment it belongs to.
Comment A
├── Reply A1
│   ├── Reply A1.1
│   └── Reply A1.2
└── Reply A2
    └── Reply A2.1

The important idea is that each comment can have a replies array containing child comments.

2. What Problem Does It Resolve?

A flat list works for simple comments, but it becomes difficult to represent conversations where users reply to specific comments.

Flat Comments
All comments appear at the same level, so conversation relationships are unclear.
Nested Comments
Replies are visually grouped under their parent comment.
Problem solved: It represents threaded conversations and makes it clear which comment a user is replying to.

4. How Does Nested Comments Work?
  1. Store comments in a hierarchical structure.
  2. Each comment has its own unique id.
  3. A comment can contain a replies array.
  4. Render each comment.
  5. If the comment has replies, render those replies inside the current comment.
  6. Use a recursive component so the same rendering logic works at every depth.
  7. When the user adds a reply, find the parent comment and add the new comment to its replies.
Core idea: The UI is recursive because the data itself is recursive: comment → replies → replies → replies...

8. Full React Code
App.jsx
import { useState } from "react";
import CommentItem from "./CommentItem";

const initialComments = [
  {
    id: 1,
    author: "Rahul",
    text: "What do you think about React?",
    replies: [
      {
        id: 2,
        author: "Priya",
        text: "I really like React.",
        replies: [
          {
            id: 3,
            author: "Amit",
            text: "Same here!",
            replies: []
          }
        ]
      }
    ]
  },
  {
    id: 4,
    author: "Neha",
    text: "Which React feature do you use most?",
    replies: []
  }
];

function App() {
  const [comments, setComments] = useState(initialComments);
  const [nextId, setNextId] = useState(5);

  const addReply = (parentId, text) => {
    const newReply = {
      id: nextId,
      author: "You",
      text,
      replies: []
    };

    setComments((currentComments) =>
      addReplyToTree(currentComments, parentId, newReply)
    );

    setNextId((id) => id + 1);
  };

  return (
    <div>
      <h1>Nested Comments</h1>

      {comments.map((comment) => (
        <CommentItem
          key={comment.id}
          comment={comment}
          onReply={addReply}
        />
      ))}
    </div>
  );
}

// Recursively find the parent and add the reply.
function addReplyToTree(comments, parentId, newReply) {
  return comments.map((comment) => {
    if (comment.id === parentId) {
      return {
        ...comment,
        replies: [...comment.replies, newReply]
      };
    }

    if (comment.replies.length > 0) {
      return {
        ...comment,
        replies: addReplyToTree(
          comment.replies,
          parentId,
          newReply
        )
      };
    }

    return comment;
  });
}

export default App;
CommentItem.jsx
import { useState } from "react";

function CommentItem({ comment, onReply }) {
  const [showReplyBox, setShowReplyBox] = useState(false);
  const [replyText, setReplyText] = useState("");

  const handleSubmit = () => {
    const text = replyText.trim();

    if (!text) return;

    onReply(comment.id, text);

    setReplyText("");
    setShowReplyBox(false);
  };

  return (
    <div
      style={{
        marginLeft: "20px",
        marginTop: "16px",
        padding: "12px",
        borderLeft: "3px solid #ddd"
      }}
    >
      <strong>{comment.author}</strong>

      <p>{comment.text}</p>

      <button
        onClick={() => setShowReplyBox((value) => !value)}
      >
        {showReplyBox ? "Cancel" : "Reply"}
      </button>

      {showReplyBox && (
        <div style={{ marginTop: "10px" }}>
          <input
            value={replyText}
            onChange={(event) =>
              setReplyText(event.target.value)
            }
            placeholder="Write a reply..."
          />

          <button onClick={handleSubmit}>
            Add Reply
          </button>
        </div>
      )}

      <div>
        {comment.replies.map((reply) => (
          <CommentItem
            key={reply.id}
            comment={reply}
            onReply={onReply}
          />
        ))}
      </div>
    </div>
  );
}

export default CommentItem;
Key implementation ideas: recursive component tree traversal immutable update unique IDs parentId
Important: The code uses addReplyToTree() to recursively search the comment tree and create new objects instead of directly mutating the existing state.
9. Why Recursion?

We use recursion because every comment has the same structure: it contains comment data and potentially another array of comments.

CommentItem

Displays one comment.

If replies exist, it renders another CommentItem for each reply.

Same component at every level

Level 1, level 2 and level 3 all use the same component.

This avoids writing separate code for each nesting level.

Simple recursion idea
CommentItem
   ↓
render comment
   ↓
does it have replies?
   ↓ yes
map replies
   ↓
render CommentItem again
   ↓
repeat until replies = []
Interview line: “I use recursion because the comment data is a tree and each node has the same structure as its children.”
10. Common Developer Mistakes
1. Using array index as the key
Use a stable unique comment ID instead of key={index}, especially when comments can be inserted or deleted.
2. Mutating nested state directly
Avoid changing comment.replies.push() directly. Create new arrays and objects so React can correctly detect the update.
3. Supporting only one nesting level
Hard-coding “comment → reply” does not solve the general nested-comments problem. Use recursion.
4. Updating the wrong parent
Use a unique parentId and recursively search the tree to find the correct parent.
5. Allowing empty replies
Trim the input and validate it before adding a new comment.
6. Putting all state inside one huge component
Separate the recursive comment item from the parent state management to keep the code easier to understand.
7. Forgetting API states
For a real application, handle loading, success, failure and retry when creating replies through an API.
8. Ignoring very deep trees
Extremely deep recursive structures can become expensive. Real applications may limit nesting depth or use alternative rendering strategies.
11. How I Would Explain My Implementation to the Interviewer
Interview explanation:

“I implemented nested comments using a tree data structure. Each comment has an id, author, text and a replies array. I created a reusable CommentItem component that renders a comment and recursively renders its replies. For adding a reply, I pass the parent comment ID to the parent state handler. The handler recursively traverses the tree, finds the matching parent and immutably adds the new reply to its replies array. This approach supports any number of nesting levels instead of hard-coding a fixed number of levels.”

Explain the implementation in this order
  1. Data structure: “Comments form a tree because each comment can have children.”
  2. Component: “CommentItem is responsible for rendering one comment.”
  3. Recursion: “CommentItem renders itself for every child reply.”
  4. Add reply: “The parent ID tells me where the new reply belongs.”
  5. Tree traversal: “I recursively search until I find that parent.”
  6. Immutable update: “I create new objects and arrays instead of mutating state.”
  7. Validation: “I prevent empty replies.”
  8. Scalability: “For production, I would also handle API states, pagination or lazy loading for large comment trees.”
Strong interview line: “The key challenge is not rendering a comment; it is correctly traversing and updating a recursive tree without mutating React state.”
12. Common Follow-Up Questions

Recursion handles an arbitrary number of nesting levels. Hard-coding multiple map levels becomes repetitive and limits the depth.

Traverse the current array. If the ID matches, use that comment. Otherwise recursively search its replies.

Recursively map the tree and filter out the target ID at each level. The resulting tree is returned as a new immutable structure.

In the worst case, O(n), because we may need to visit every comment in the tree.
