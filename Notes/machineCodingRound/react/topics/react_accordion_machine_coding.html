React Accordion

A common React machine-coding task for expanding and collapsing sections of content.

Goal: Let users open and close content sections while keeping the UI state predictable.

Left Side — Questions
1. What is an Accordion?

Technical definition: An Accordion is a UI component that displays multiple headers or questions and allows users to expand or collapse the content associated with each header.

Layman example: Imagine a list of questions in a notebook. You see only the questions initially. When you click one question, its answer opens. Click it again and the answer closes.

Core React concepts State → Event Handling → Conditional Rendering → Array Methods → UI Synchronization

React is a JavaScript library for building user interfaces.
useState allows a React component to store and update state.
2. What Problem Does an Accordion Solve?

An Accordion helps organize a large amount of related content into compact expandable sections.

  • Reduces visual clutter.
  • Keeps long pages easier to scan.
  • Shows details only when the user asks for them.
  • Works well for FAQs, settings, documentation, and product details.
  • Demonstrates state-driven UI behavior in React.
Machine-coding point: The interviewer is usually testing state management, click handling, conditional rendering, list rendering, and whether you can handle the requirement of one-open-at-a-time versus multiple-open behavior.
3. Requirements
Basic requirements
  1. Display multiple accordion items.
  2. Each item has a title and content.
  3. Clicking a title opens its content.
  4. Clicking the same title again closes it.
  5. Clearly show which item is open.
Important clarification
Ask the interviewer: "Should only one accordion item be open at a time, or can multiple items be open simultaneously?"
Possible variations
  • Single-open: opening one item closes the previous item.
  • Multi-open: multiple items can remain open.
  • First item can be open by default.
  • Items can be disabled.
  • Content can be loaded lazily.
4. State Design — What State Do I Need?

For a single-open Accordion, one simple piece of state is enough: the id of the currently open item.

const [openId, setOpenId] = useState(null);

If the user opens item 2:

openId = 2

Then item 2 is rendered as open.

Toggle logic:
If clicked item is already open → close it.
Otherwise → make clicked item the new open item. 
setOpenId(prevId =>
  prevId === id ? null : id
);
For multiple-open Accordion

You can store an array or Set of open ids instead of a single id.

const [openIds, setOpenIds] = useState([]);
Interview concept: Choose the state structure based on the requirement. One-open means one id. Multi-open means multiple ids.

6. How I Have Implemented It — Interview Explanation
Step 1 — Define Accordion data

I keep each item as an object containing an id, title, and content.

Step 2 — Track the open item

For a single-open Accordion, I store the currently open item's id in openId.

Step 3 — Render items dynamically

I use map() to generate each Accordion item from the data array.

Step 4 — Handle click

When the user clicks an item, I compare its id with openId. If it is already open, I close it; otherwise I set it as the open item.

Step 5 — Conditional rendering

I display the content only when the item's id matches openId.

One-line implementation summary: "I store the open item's id in state, dynamically render the Accordion items, toggle the id on click, and conditionally render content when the item's id matches the active open id."
7. Full React Code — Single Item Open at a Time
import { useState } from "react";

function Accordion() {
  const [openId, setOpenId] = useState(null);

  const items = [
    {
      id: 1,
      title: "What is React?",
      content:
        "React is a JavaScript library for building user interfaces."
    },
    {
      id: 2,
      title: "What is useState?",
      content:
        "useState allows a component to store and update state."
    },
    {
      id: 3,
      title: "What is JSX?",
      content:
        "JSX is a syntax extension that allows UI markup inside JavaScript."
    }
  ];

  const handleToggle = (id) => {
    setOpenId(prevId =>
      prevId === id ? null : id
    );
  };

  return (
    <div>
      <h2>Accordion</h2>

      {items.map(item => (
        <div key={item.id}>

          <button
            onClick={() => handleToggle(item.id)}
          >
            {item.title}
          </button>

          {openId === item.id && (
            <div>
              {item.content}
            </div>
          )}

        </div>
      ))}
    </div>
  );
}

export default Accordion;
Important toggle logic
const handleToggle = (id) => {
  setOpenId(prevId =>
    prevId === id ? null : id
  );
};

Meaning:

  • If the clicked item is already open → set state to null → close it.
  • If another item is open → replace its id with the clicked item's id.
  • If nothing is open → store the clicked item's id.
Why this is good: One state value controls the entire Accordion, so the state is simple and there is no need for separate boolean state variables for every item.
8. How to Explain Accordion in 1 Minute

Interview-ready answer:

"I implemented an Accordion component in React where multiple sections can be expanded or collapsed. I first represent the Accordion items as an array containing an id, title, and content. For the single-open requirement, I use one piece of state called openId to store the currently expanded item's id. I dynamically render the items using map. When a user clicks a title, I compare its id with openId. If it is already open, I set openId to null to close it; otherwise, I set openId to that item's id. During rendering, I conditionally display the content only when the item's id matches openId. This keeps the state simple and gives me one source of truth."
1-minute structure
  1. Data: id + title + content
  2. State: openId
  3. Render: map()
  4. Click: toggle openId
  5. Content: conditional rendering
  6. Rule: one open item at a time
9. How to Explain Accordion in 5 Minutes
Minute 1 — Clarify the requirement

I first ask whether the Accordion should allow only one open item or multiple open items. This decision changes the state design.

Minute 2 — Design the data

I represent each item as an object with an id, title, and content. This makes the component easy to render dynamically.

Minute 3 — Design the state

For a single-open Accordion, I use one openId state. I don't create isOpen state for every item because one id can represent the entire selection.

Minute 4 — Implement interaction

I use map() to render the items and a click handler to toggle the open id. If the same item is clicked again, I close it. If another item is clicked, the new id replaces the old one.

Minute 5 — Discuss improvements
  • Support multiple open items.
  • Add keyboard accessibility.
  • Add ARIA attributes.
  • Add disabled items.
  • Add animation for opening and closing.
  • Lazy-load expensive content when required.
Strong closing line: "The main design decision is how I represent the open state. For single-open behavior, one open id is enough; for multi-open behavior, I would maintain multiple open ids."
10. Common Developer Mistakes
Mistake 1 — Creating separate state for every item 
// Avoid this pattern
const [isItem1Open, setIsItem1Open] = useState(false);
const [isItem2Open, setIsItem2Open] = useState(false);
const [isItem3Open, setIsItem3Open] = useState(false);

For a dynamic Accordion, one openId state is much easier for single-open behavior.

Mistake 2 — Not clarifying single vs multiple open

This is an important requirement because it directly affects the state structure.

Mistake 3 — Using array index as key 
// Avoid when a stable id exists
{items.map((item, index) =>
  <div key={index}>...</div>
)}

// Prefer
{items.map(item =>
  <div key={item.id}>...</div>
)}
Mistake 4 — Wrong toggle condition

Make sure clicking an already-open item closes it, while clicking another item opens the new item.

Mistake 5 — Rendering every answer all the time

If the requirement is to show only the selected content, conditionally render the content based on the open id.

Mistake 6 — Ignoring accessibility

A production Accordion should consider keyboard interaction, focus behavior, semantic buttons, and ARIA attributes where appropriate.

Mistake 7 — Overengineering animations first

First implement correct state and behavior. Add animation only after the core functionality works.

11. Interview Questions You May Be Asked

A boolean can tell me whether something is open, but it cannot identify which item is open. An id directly represents the selected item and makes single-open behavior simple.

I would store multiple open ids, for example in an array or Set, and add/remove an id when the user clicks an item.

map() allows the Accordion to be generated from data, so I don't need to manually write every item and the component can support any number of items.

Pass the Accordion items through props and keep the open-state logic inside the component. This allows different pages to provide different content.

Compare openId with the current item's id and render one icon for the open state and another for the closed state.

After the behavior works, I can use CSS transitions/animations or an animation library. I would avoid making animation logic responsible for the actual open/close state.

Use real buttons for headers, support keyboard activation, expose expanded state with appropriate ARIA attributes, connect the button to its panel, and manage focus when needed.

If there are n Accordion items, map() processes n items during rendering, so the list rendering is O(n). The state update itself is O(1) for the single open id.
