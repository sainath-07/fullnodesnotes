1. What is Throttling?

Throttling means limiting how often a function is allowed to run.

If an event fires 100 times in one second, we may not want our expensive function to run 100 times. With throttling, we can say: “Run it at most once every X milliseconds.”

⚡ Event fires repeatedly
click / scroll / mousemove
→
🛡️ Throttle
Only allow limited calls
2. Why do we need Throttling?
Problem
High-frequency events can call functions many times.
Impact
More state updates, calculations, API calls, and rendering work.
Solution
Throttle controls the execution frequency.
Simple interview line: “I use throttling when an event happens continuously but I only need to process it periodically.”
3. How Throttling works — simple steps
1️⃣ Event happens
→
2️⃣ Get current time
→
3️⃣ Compare with last run
→
4️⃣ Enough time?
→
5️⃣ Run + update last time

Core condition:

currentTime - lastTime > limit

Example: limit = 300ms.

  • 0ms → run.
  • 100ms → ignore.
  • 200ms → ignore.
  • 350ms → run.
Important: Your implementation is a simple leading-edge throttle: it runs when the time window is available and ignores calls during the window. It does not schedule a trailing call.
4. Full React Code — your implementation
import React, { useRef, useState } from "react";

const productList = Array.from({ length: 100 }, (_, i) => ({
  id: i + 1,
  label: "Product: " + (i + 1),
}));

const createThrottle = (fn, limit) => {
  let last = 0;
  return (...args) => {
    let start = Date.now();

    if (start - last > limit) {
      fn(...args);
      last = start;
    }
  };
};

8. Common Developer Mistakes
❌ Creating throttle on every render
If createThrottle() runs during every render, the private last value can reset. Use useRef to preserve the same throttled function.
❌ Using state for last
State is UI data and causes re-renders. The timing value can stay inside the closure.
❌ Forgetting the closure
last must remain accessible to the returned function so it can remember the previous execution time.
❌ Confusing throttle with debounce
Throttle runs periodically while events continue. Debounce waits until events stop for the specified period.
❌ Assuming trailing execution
This implementation does not schedule a final call. Calls ignored during the limit are dropped.
9. How I would explain this to the interviewer
🎤 My explanation

“First, I create a reusable createThrottle function. It accepts a callback and a time limit.”

“Inside it, I keep a last timestamp in a closure. Every time the returned function is called, I get the current time using Date.now().”

“Then I compare currentTime - last with the limit. If enough time has passed, I execute the callback and update last. Otherwise, I ignore the call.”

“In React, I use useRef so the throttled function instance and its closure survive re-renders. I can reuse the same utility for button click, scrolling, and mouse movement.”

“This is a leading-edge throttle. It executes when allowed and drops calls during the waiting window. If the requirement needs a trailing call, I would extend it with a timer.”
