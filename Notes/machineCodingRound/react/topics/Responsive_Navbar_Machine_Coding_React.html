1. What is a Responsive Navbar?

A Responsive Navbar is a navigation component that changes its layout based on the available screen width.

Simple definition: On a desktop screen, navigation links can be displayed horizontally. On a smaller screen, those links are usually hidden behind a menu button such as a hamburger icon.

Interview keyword: Responsive Navbar = desktop links + mobile menu + responsive CSS + menu state.

2. What problem does it solve?

A desktop navigation bar may have enough horizontal space for several links. On mobile, the same links can overflow, wrap awkwardly, or make the header unusable.

Desktop

More horizontal space → show navigation links directly.

Mobile

Limited space → collapse links behind a menu button.

User experience

Keeps navigation readable and usable on different devices.

This pattern is common in websites, dashboards, e-commerce applications, documentation sites, and portfolio applications.

3. What are the requirements?

Core requirements

  1. Display the brand/logo.
  2. Show navigation links on desktop.
  3. Show a hamburger/menu button on smaller screens.
  4. Open and close the mobile menu.
  5. Close the menu when a navigation link is selected.
  6. Keep the layout usable at different screen widths.

Good interview-level enhancements

  • Accessible button with aria-expanded.
  • aria-controls pointing to the mobile menu.
  • Keyboard support.
  • Close menu on Escape.
  • Close menu when resizing back to desktop.
  • Close mobile menu when clicking outside.
  • Sticky navbar.
  • Dropdown/submenu support.
Machine coding tip: Finish the responsive layout and open/close behavior first. Then add accessibility and advanced behavior.

4. How does responsive behavior work?

The most important idea is that CSS controls the layout while React controls interactive state such as whether the mobile menu is open.

Desktop

.desktop-links {
  display: flex;
}

.menu-button {
  display: none;
}

Mobile

@media (max-width: 768px) {
  .desktop-links {
    display: none;
  }

  .menu-button {
    display: block;
  }
}
Large screen
→
CSS shows links
→
Hide menu button
Small screen
→

→
Show menu button
Important: Do not use React state just to detect every screen-width change unless the behavior actually requires JavaScript. CSS media queries are usually the right tool for layout.

5. What state do I need?

The basic implementation needs only one piece of state: whether the mobile menu is open. 

const [isMenuOpen, setIsMenuOpen] = useState(false);

Toggle

const toggleMenu = () => {
  setIsMenuOpen(prev => !prev);
};

Close after navigation

const handleNavClick = () => {
  setIsMenuOpen(false);
};
Memory trick: false = menu closed → click hamburger → true = menu open.
Do not overcomplicate state: For a basic navbar, you normally do not need Redux, Context, or a large state object.

6. What about accessibility?

A machine-coding solution becomes stronger when the menu button communicates its state to screen readers and supports keyboard interaction. 

<button
  type="button"
  aria-label="Toggle navigation menu"
  aria-expanded={isMenuOpen}
  aria-controls="mobile-menu"
  onClick={toggleMenu}
>
  ☰
</button>

Why these attributes?

  • aria-label explains what the icon button does.
  • aria-expanded tells whether the menu is open.
  • aria-controls identifies the menu controlled by the button.
  • A real <button> naturally supports keyboard interaction.
Interview bonus: If asked about accessibility, mention semantic HTML, keyboard navigation, focus management, and ARIA state.

10. Full React code

This version includes responsive CSS, mobile menu state, close-on-link-click, Escape handling, accessible attributes, and a clean component structure. 

import React, { useEffect, useState } from "react";
import "./Navbar.css";

const navItems = [
  { label: "Home", href: "#home" },
  { label: "About", href: "#about" },
  { label: "Services", href: "#services" },
  { label: "Contact", href: "#contact" }
];

export default function Navbar() {
  const [isMenuOpen, setIsMenuOpen] = useState(false);

  const toggleMenu = () => {
    setIsMenuOpen(prev => !prev);
  };

  const closeMenu = () => {
    setIsMenuOpen(false);
  };

  useEffect(() => {
    const handleEscape = (event) => {
      if (event.key === "Escape") {
        closeMenu();
      }
    };

    document.addEventListener("keydown", handleEscape);

    return () => {
      document.removeEventListener("keydown", handleEscape);
    };
  }, []);

  useEffect(() => {
    const handleResize = () => {
      if (window.innerWidth > 768) {
        closeMenu();
      }
    };

    window.addEventListener("resize", handleResize);

    return () => {
      window.removeEventListener("resize", handleResize);
    };
  }, []);

  return (
    <header className="navbar">
      <a href="#home" className="brand" onClick={closeMenu}>
        MyApp
      </a>

      <nav className="desktop-nav" aria-label="Primary navigation">
        {navItems.map(item => (
          <a key={item.label} href={item.href}>
            {item.label}
          </a>
        ))}
      </nav>

      <button
        type="button"
        className="menu-button"
        aria-label="Toggle navigation menu"
        aria-expanded={isMenuOpen}
        aria-controls="mobile-menu"
        onClick={toggleMenu}
      >
        {isMenuOpen ? "✕" : "☰"}
      </button>

      <nav
        id="mobile-menu"
        className={`mobile-nav ${isMenuOpen ? "open" : ""}`}
        aria-label="Mobile navigation"
      >
        {navItems.map(item => (
          <a
            key={item.label}
            href={item.href}
            onClick={closeMenu}
          >
            {item.label}
          </a>
        ))}
      </nav>
    </header>
  );
}

11. How to explain it to interviewer in 1 minute

“I implemented the Responsive Navbar using CSS media queries for the layout and React state for the mobile menu interaction. On desktop, the navigation links are displayed horizontally. Below the mobile breakpoint, CSS hides those links and shows a hamburger button. I maintain an isMenuOpen boolean in state. Clicking the button toggles it, and the mobile menu is conditionally displayed based on that state. I also close the menu when a link is selected or Escape is pressed, and I reset the menu when resizing back to desktop. For accessibility, I use a real button with aria-expanded and aria-controls.”

Keywords to say: media queries, mobile breakpoint, boolean state, conditional rendering, accessibility, Escape key, resize cleanup.

14. Common developer mistakes

1. Using JavaScript to handle basic responsive layout
Checking window.innerWidth just to decide whether links should be shown is often unnecessary.
Fix: Use CSS media queries for presentation.
2. Forgetting to close the mobile menu after navigation
The user clicks a link but the menu remains open.
Fix: Call setIsMenuOpen(false) on mobile link click.
3. Using a div as the hamburger control
A clickable div is less accessible and doesn't provide normal button keyboard behavior.
Fix: Use a semantic <button>.
4. Forgetting ARIA state
Screen readers may not know whether the menu is currently expanded.
Fix: Use aria-expanded and aria-controls.
5. Adding resize listeners without cleanup
Repeated mounting can leave event listeners behind.
Fix: Remove the listener in the useEffect cleanup.
6. Missing the viewport meta tag
Mobile browsers may not render the page at the expected device width.
Fix: Include <meta name="viewport" content="width=device-width, initial-scale=1.0">.
7. Hardcoding the same links twice without a reason
Maintaining separate desktop and mobile JSX can cause the two lists to become inconsistent.
Fix: Store navigation items in an array and map them.
8. No keyboard/escape behavior
A polished mobile menu should be easy to close without a mouse.
Fix: Support Escape and proper keyboard-focus behavior.
9. Overcomplicating the first version
Starting with animations, dropdown systems, routing logic, and global state can slow down a machine-coding round.
Fix: Build the core responsive navbar first, then enhance it.

16. Interviewer follow-up questions

Q1. Why use CSS media queries instead of React state for responsiveness?

CSS is designed for presentation and viewport-based layout. Using CSS avoids unnecessary JavaScript and resize state for simple visual changes.

Q2. How would you highlight the active page?

In a React Router application, I would compare the current route with each item's path or use the router's active-link support.

Q3. How would you close the menu when clicking outside?

I would attach a document-level pointer/mouse listener and check whether the event target is outside the navbar using a ref. I would clean up that listener in useEffect.

Q4. How would you add a dropdown?

Each dropdown can have its own open state, ideally scoped to the specific menu item. On mobile, the dropdown can become an accordion-style submenu.

Q5. How would you animate the mobile menu?

I would prefer CSS transitions for simple animations. For height-based animation, I may use opacity/transform or another CSS-friendly approach instead of forcing layout calculations in React.

Q6. How would you handle focus when the menu opens?

For a production-quality navigation drawer, I would move focus into the opened menu, trap focus when appropriate, and return focus to the trigger when the menu closes.

Q7. Would you use Context or Redux?

No, not for this basic component. Local state is enough. Global state would add unnecessary complexity unless the application has a real cross-component requirement.
