What?

What is a Star Rating?

A Star Rating is a UI component that allows users to rate something, usually on a scale such as 1 to 5 stars.

It is commonly used for products, restaurants, movies, courses, applications, and reviews.

Interview definition: “A Star Rating is an interactive React component that lets a user select a rating from a fixed range. I manage the selected value with state and use a temporary hover value to provide immediate visual feedback.”
Why?

What problem does it solve?

Simple feedback

Users can communicate satisfaction quickly without typing a review.

Better UX

Stars provide an intuitive visual interaction for rating content.

Reusable UI

The same component can be reused for products, services, courses, and reviews.

Immediate feedback

Hover preview shows the user what rating will be selected before clicking.

Requirements

What should I implement?

  1. Render a configurable number of stars, such as 5.
  2. Click a star to select the rating.
  3. Highlight stars up to the selected value.
  4. Show a temporary hover preview before clicking.
  5. Reset the hover preview when the mouse leaves.
  6. Allow the user to reset the rating to 0 if required.
  7. Display the selected rating.
  8. Support keyboard interaction for accessibility.
  9. Allow the parent component to receive the selected rating.
Machine coding strategy: Start with static stars → add selected state → add click → add hover state → add reset → add accessibility and reusable props.
How?

How does it work?

The important idea is to keep selected rating and hovered rating separate.

const [rating, setRating] = useState(0);
const [hover, setHover] = useState(0);

When rendering each star:

const activeRating = hover || rating;

starIndex <= activeRating
  ? "filled"
  : "empty"
Why two values? The clicked rating is the user's actual selection. The hover value is only temporary visual feedback and should not change the saved rating until the user clicks.

React Star Rating — Interview Version

This implementation supports configurable stars, click selection, hover preview, reset-to-zero, keyboard interaction, and a parent callback.

import { useState } from "react";

function StarRating({
  maxRating = 5,
  initialRating = 0,
  onChange
}) {
  const [rating, setRating] = useState(initialRating);
  const [hover, setHover] = useState(0);

  const handleSelect = (value) => {
    // Click the selected rating again to reset.
    const newRating = rating === value ? 0 : value;

    setRating(newRating);
    onChange?.(newRating);
  };

  const handleKeyDown = (event, value) => {
    if (event.key === "Enter" || event.key === " ") {
      event.preventDefault();
      handleSelect(value);
    }
  };

  const activeRating = hover || rating;

  return (
    <div>
      <div
        role="radiogroup"
        aria-label="Star rating"
        className="star-rating"
      >
        {Array.from({ length: maxRating }, (_, index) => {
          const value = index + 1;
          const isFilled = value <= activeRating;

          return (
            <button
              key={value}
              type="button"
              role="radio"
              aria-label={`${value} star${value > 1 ? "s" : ""}`}
              aria-checked={rating === value}
              onClick={() => handleSelect(value)}
              onMouseEnter={() => setHover(value)}
              onMouseLeave={() => setHover(0)}
              onKeyDown={(event) =>
                handleKeyDown(event, value)
              }
              className={isFilled ? "star filled" : "star"}
            >
              ★
            </button>
          );
        })}
      </div>

      <p>
        Rating: {rating} / {maxRating}
      </p>

      <button
        type="button"
        onClick={() => {
          setRating(0);
          setHover(0);
          onChange?.(0);
        }}
      >
        Clear Rating
      </button>
    </div>
  );
}

export default StarRating;

Interview Answer

How to explain in 1 minute

“I built the Star Rating as a reusable React component. I render the stars dynamically using Array.from, so the number of stars can be configured. I keep the actual selected rating in one state variable and a separate hover state for temporary visual feedback. When the user hovers over a star, I highlight all stars up to that position. When the user clicks, I update the actual rating and notify the parent through an optional callback. I also allow clicking the selected star again to reset the rating to zero. For accessibility, I use buttons, keyboard handling, ARIA attributes, and visible focus styles.”
Interview Answer

How to explain in 5 minutes

  1. Requirement: “The user should be able to select a rating from 1 to 5 stars.”
  2. Dynamic rendering: “Instead of hardcoding five elements, I generate the stars based on maxRating.”
  3. Selected state: “I store the actual selected rating in rating.”
  4. Hover state: “I use hover separately because hover should only preview a value and should not change the selected rating.”
  5. Visual logic: “The effective value is hover || rating. Every star whose value is less than or equal to that value is highlighted.”
  6. Click: “On click, I update the selected rating. If the user clicks the same selected star again, I reset it to zero.”
  7. Parent communication: “I expose an optional onChange callback so the parent can save the rating or call an API.”
  8. Accessibility: “I use actual buttons so keyboard focus and activation work naturally, and I add ARIA information to communicate the rating semantics.”
  9. Styling: “The filled and empty states are represented using CSS classes rather than putting styling logic everywhere.”
Strong closing line: “The main design decision is keeping the persistent selected value separate from the temporary hover value. That makes the component predictable and gives the user immediate visual feedback without accidentally changing the saved rating.”
Debugging

Common Developer Mistakes

Mistake Why it is a problem Better approach
Using only one state for rating and hover Hovering can accidentally overwrite the user's selected value. Keep rating and hover separate.
Hardcoding five stars The component becomes less reusable. Render stars dynamically using maxRating.
Using array index incorrectly Can create off-by-one errors when comparing star values. Use const value = index + 1.
Changing rating on mouse enter The selected rating changes before the user clicks. Update hover on mouse enter; update rating on click.
Not resetting hover The hover preview remains visible after the pointer leaves. Call setHover(0) on mouse leave.
Using divs instead of buttons Keyboard and accessibility behavior becomes harder to implement. Use native button elements for interactive stars.
No keyboard support Keyboard-only users cannot easily interact with the component. Use buttons and handle Enter/Space when custom behavior is needed.
Calling an API directly inside every star Creates tightly coupled UI and API logic. Expose onChange and let the parent decide what to do.
Mutating state directly Can produce inconsistent React behavior. Always use the state setter.
No reset behavior User may not be able to remove an accidental selection. Provide Clear Rating or allow clicking the selected star again.
Poor focus styling Keyboard users cannot tell which control is focused. Use :focus-visible styling.
Not handling initial rating The component cannot easily display an existing product rating. Support an initialRating or controlled value.
Most common interview bug: Mixing hover state with selected state. Explain clearly: hover is temporary preview; rating is the user's actual selection.

Implementation Explanation

How I implemented it — interviewer flow

1. I started with dynamic stars

“I used Array.from with a configurable maximum rating instead of hardcoding the stars.”

2. I added selected state

“I used rating to store the user's actual selection.”

3. I added hover preview

“I added hover separately so the user can preview the rating before clicking.”

4. I added click behavior

“Clicking a star updates the actual rating and sends it to the parent.”

5. I added reset

“Clicking the selected star again or Clear Rating resets the component to zero.”

6. I added accessibility

“I used buttons, keyboard activation, ARIA attributes, and visible focus styles.”

If the interviewer asks: “Why separate hover and rating?”
“Because they represent two different concepts. Rating is persistent user data, while hover is temporary UI feedback. Separating them prevents accidental changes to the selected value.”
If the interviewer asks: “Why use buttons?”
“Because each star is an interactive control. A button gives me native keyboard focus and activation behavior and is more accessible than making a div clickable.”
If the interviewer asks: “How would you save it to the backend?”
“I would keep the component responsible for UI state and expose an onChange callback. The parent or a custom hook can then call the API and handle loading, success, and error states.”
Interview Follow-ups

Possible interviewer questions

Accept value and onChange from the parent instead of owning the selected rating entirely inside the component.

Use a smaller step such as 0.5, detect whether the pointer is on the left or right half of a star, and render a partial fill using CSS or layered elements.

Add a readOnly prop and skip click/hover handlers while rendering the current rating.

Call an onChange callback from the component and let the parent perform the API request. This keeps the component reusable and separates UI from server logic.
