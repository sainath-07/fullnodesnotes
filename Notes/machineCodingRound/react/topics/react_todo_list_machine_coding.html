React Todo List

A practical React machine-coding task for managing a list of tasks.

Goal: Add todos, mark them completed, delete them, and keep the UI synchronized with state.

Left Side — Questions
1. What is a Todo List?

Technical definition: A Todo List is a React application that allows users to create, display, update, and remove tasks.

Layman example: Imagine writing tasks in a notebook: "Study React", "Practice DSA", "Go to gym". You can add a new task, tick it when completed, and remove it when it is no longer needed.

Core React concepts State → Forms/Input → Events → Array operations → Conditional rendering → Re-render

2. What Problem Does a Todo List Solve?

A Todo List demonstrates how an application manages a collection of changing data.

  • Users can create new tasks.
  • Users can see all current tasks.
  • Users can mark tasks as completed.
  • Users can delete tasks.
  • The UI stays synchronized with application state.
Machine-coding point: The task is simple visually, but it tests important concepts such as array state updates, immutable updates, event handling, controlled inputs, list rendering, and keys.
3. Requirements
Minimum requirements
  1. Input field for entering a todo.
  2. Add button to create a todo.
  3. Display all todos in a list.
  4. Mark a todo as completed.
  5. Delete a todo.
  6. Do not add an empty todo.
Good clarification questions for the interviewer
  • Should duplicate todos be allowed?
  • Should completed tasks be deleted or only marked completed?
  • Do we need edit functionality?
  • Do we need localStorage persistence?
  • Do we need filters such as All / Active / Completed?
  • Do we need a character limit?
4. State Design — What State Do I Need?

For the basic version, I need two pieces of state.

1. input

Stores what the user is currently typing.

const [input, setInput] = useState("");
2. todos

Stores the list of task objects.

const [todos, setTodos] = useState([]);
Todo object structure
{
  id: 1,
  text: "Learn React",
  completed: false
}
Why an object? A todo may need more information than just text. Keeping id, text, and completed makes future features easier to add.

6. How I Have Implemented It — Interview Explanation
Step 1 — Manage the input

I use a controlled input. The input value is stored in React state and onChange updates that state whenever the user types.

Step 2 — Add a todo

When Add is clicked, I validate that the input is not empty, create a todo object with a unique id, and append it to the existing array.

Step 3 — Display todos

I use map() to render every todo. Each item receives a stable key using its id.

Step 4 — Toggle completion

I use map() to create a new array. Only the selected todo gets its completed value toggled.

Step 5 — Delete

I use filter() to create a new array without the selected todo.

One-line implementation summary: "I manage the input and todo collection using React state, use controlled input for user entry, map for rendering and updating individual todos, and filter for deletion."
7. Full React Code
import { useState } from "react";

function TodoList() {
  const [input, setInput] = useState("");
  const [todos, setTodos] = useState([]);

  const handleAddTodo = () => {
    const text = input.trim();

    if (!text) return;

    const newTodo = {
      id: Date.now(),
      text,
      completed: false
    };

    setTodos(prevTodos => [...prevTodos, newTodo]);
    setInput("");
  };

  const handleToggleTodo = (id) => {
    setTodos(prevTodos =>
      prevTodos.map(todo =>
        todo.id === id
          ? { ...todo, completed: !todo.completed }
          : todo
      )
    );
  };

  const handleDeleteTodo = (id) => {
    setTodos(prevTodos =>
      prevTodos.filter(todo => todo.id !== id)
    );
  };

  return (
    <div>
      <h2>Todo List</h2>

      <input
        type="text"
        value={input}
        onChange={(e) => setInput(e.target.value)}
        placeholder="Enter a task"
      />

      <button onClick={handleAddTodo}>
        Add
      </button>

      <ul>
        {todos.map(todo => (
          <li key={todo.id}>
            <input
              type="checkbox"
              checked={todo.completed}
              onChange={() => handleToggleTodo(todo.id)}
            />

            <span
              style={{
                textDecoration:
                  todo.completed ? "line-through" : "none"
              }}
            >
              {todo.text}
            </span>

            <button
              onClick={() => handleDeleteTodo(todo.id)}
            >
              Delete
            </button>
          </li>
        ))}
      </ul>
    </div>
  );
}

export default TodoList;
Important code patterns

// Delete

);
Interview point: Notice that I am not modifying the existing array directly. I create a new array using spread, map, or filter.
8. How to Explain Todo List in 1 Minute

Interview-ready answer:

"I implemented a Todo List in React using two pieces of state: one for the current input value and one for the list of todos. Each todo contains an id, text, and completed status. The input is controlled using React state. When the user clicks Add, I validate the input, create a new todo object, and append it to the existing array. I use map to render the todos and also to toggle the completed state of a selected todo. For deletion, I use filter to create a new array without that todo. I use functional state updates because these operations depend on the previous todo list, and I use the todo id as the React key."
1-minute structure
  1. State: input + todos
  2. Add: create object and append
  3. Render: map()
  4. Complete: map() + toggle
  5. Delete: filter()
  6. Important: immutable array updates + stable key
9. How to Explain Todo List in 5 Minutes
Minute 1 — Clarify requirements

I first identify the basic operations: add, display, complete, and delete. I also clarify edge cases such as empty input, duplicate tasks, editing, persistence, and filtering.

Minute 2 — Design the data

I keep two states: the input text and the todos array. Each todo is an object containing an id, text, and completed boolean.

Minute 3 — Implement Add

I make the input controlled. On Add, I trim the input, reject an empty value, create a new object, append it using the spread operator, and clear the input.

Minute 4 — Implement Toggle and Delete

For completion, I use map() to return a new array and toggle only the matching todo. For deletion, I use filter() to remove the matching id.

Minute 5 — Discuss React quality
  • Use stable keys for list items.
  • Do not mutate the existing array.
  • Use functional state updates when depending on previous state.
  • Validate user input.
  • Keep event handlers small and readable.
  • Discuss possible extensions if the interviewer asks for more.
Strong closing line: "The important part of this implementation is not just displaying tasks; it is correctly managing a changing collection of state while keeping the UI predictable and synchronized."
10. Common Developer Mistakes
Mistake 1 — Mutating the todos array directly 
// Wrong
todos.push(newTodo);

// Better
setTodos(prevTodos => [...prevTodos, newTodo]);

React state should be updated by creating a new array instead of directly mutating the existing one.

Mistake 2 — Using array index as key 
// Avoid when a stable id is available
{todos.map((todo, index) =>
  <li key={index}>...</li>
)}

// Prefer
{todos.map(todo =>
  <li key={todo.id}>...</li>
)}
Mistake 3 — Allowing empty todos 
const text = input.trim();

if (!text) return;

Always validate user input before adding it.

Mistake 4 — Forgetting to clear input

After adding successfully, call setInput("") so the input is ready for the next task.

Mistake 5 — Updating the wrong todo

Always compare the selected todo's unique id before changing or deleting it.

Mistake 6 — Forgetting checkbox controlled behavior

For a controlled checkbox, keep checked connected to state and update it through the event handler.

Mistake 7 — Overengineering too early

Do not start with Redux, complex architecture, or unnecessary libraries. First implement the requested requirements cleanly, then extend if asked.

Because I need to inspect every todo and return a new array. Only the todo whose id matches should receive the updated completed value.

filter returns a new array containing only the items that satisfy the condition, so I can keep every todo except the selected one.

push mutates the existing array. In React, I prefer immutable updates so I create a new array and pass it to the state setter.

The key helps React identify which list items have changed, been added, or been removed. A stable unique id is preferred.

I would keep an editing id and input value, then use map() to replace only the matching todo's text when the user saves.

For a simple client-side requirement, I can synchronize the todos state with localStorage using useEffect. For a real application, I could persist them through a backend API and database.

I would keep a filter state such as "all", "active", or "completed", then derive the displayed list using filter() rather than creating separate copies of the todo state.
