1. What is Drag & Drop?

Drag and drop lets a user pick one item, move the mouse over another position, and place the item there.

Our React example: We reorder products inside the same list.
2. Why use useRef?

We need to remember two temporary values while dragging:

  • dragItemIndexRef → index of the item being dragged.
  • dragOnHoverIndexRef → index currently being hovered.
Why not state for both? Changing state causes a React render. A ref can store a changing value without itself causing a render. We use state only for the visual hover indicator and for the final list update.
3. How does it work?
  1. DragStart: store the dragged item's index in a ref.
  2. DragOver: prevent the browser's default behavior and record the current target index.
  3. Reorder: when the hovered position changes, create a new array, remove the dragged item, insert it at the new index, and update state.
  4. DragEnd: clear both refs and the visual hover state.
Important: React state is used for the actual list because the UI must re-render when the list order changes. We never mutate the original constant directly.

5. Why DragOver for Position, Not Drop?

DragOver tells us where the dragged item currently is. It fires continously while the user moves the dragged item across possible targets.

That makes it useful for a live reorder UI: as the pointer enters another item's area, we know the current target index and can move the item there.

Drop is different: The drop event fires when the user releases the mouse button and drops the dragged element at a valid target position.

DragOver
“Where is the user dragging right now?”
Good for live positioning / preview.
Drop
“Where did the user finally release?”
Good for final commit.
onDragStart
"Which element did the user start dragging?"
onDragEnd
"The dragging operation is finished — clean up the drag state."

Interview note: There is no universal rule that says reordering must happen in dragOver. A drop-based implementation is also valid. In this implementation, dragOver is intentionally used because we want the list position to update while dragging.

6. Corrected Full Code

This version keeps your original useRef idea, but fixes the important issues: list is state, refs use .current, the original array is not mutated, and downward movement is handled correctly. 

import React, { useRef, useState } from "react";

const DRAGDROPLIST = Array.from({ length: 20 }, (_, i) => ({
  id: i + 1,
  label: "Product " + (i + 1),
}));


const styles = {
  itemStyles: {
    border: "1px solid #d2d2d2",
    background: "#f2f3f4",
    fontSize: "22px",
    padding: "6px",
    margin: "4px",
  },
};

const DragAndDrop = () => {
  // List must be state because React needs to re-render after reordering.
  const [list, setList] = useState(DRAGDROPLIST);

  // Used only for the visual hover indicator.
  const [dragOnHoverIndex, setDragOnHoverIndex] = useState(null);

  // Store temporary drag information without causing a render.
  const dragItemIndexRef = useRef(null);
  const dragOnHoverIndexRef = useRef(null);

  const handleDragStart = (index) => {
    // Remember which item the user started dragging.
    dragItemIndexRef.current = index;

    // Reset the hover target for this drag operation.
    dragOnHoverIndexRef.current = null;
  };

  const handleDragOver = (event, index) => {
    // Required so this element can act as a drop target.
    event.preventDefault();

    const draggedIndex = dragItemIndexRef.current;
    const previousHoverIndex = dragOnHoverIndexRef.current;

    // Nothing is being dragged.
    if (draggedIndex === null) {
      return;
    }

    // Do not move an item over itself.
    if (draggedIndex === index) {
      return;
    }

    // DragOver can fire many times.
    // Do not reorder again if the target has not changed.
    if (previousHoverIndex === index) {
      return;
    }

    dragOnHoverIndexRef.current = index;
    setDragOnHoverIndex(index);

    setList((previousList) => {
      const newList = [...previousList];

      // Remove the dragged item.
      const [draggedItem] = newList.splice(draggedIndex, 1);

      // Insert the dragged item at the new position.
      newList.splice(index, 0, draggedItem);

      // The array is returned to React as new state.
      return newList;
    });

    dragItemIndexRef.current = index;
  };

  const handleDragEnd = () => {
    // Clear temporary drag information.
    dragItemIndexRef.current = null;
    dragOnHoverIndexRef.current = null;

    // Remove the hover highlight.
    setDragOnHoverIndex(null);
  };

  return (
    <div>
      <h1>DragAndDrop</h1>

      <div
        style={{
          margin: "5px",
          width: "40vw",
          border: "1px solid #d2d2d2",
        }}
        onDragOver={(event) => event.preventDefault()}
      >
        {list.map((item, index) => (
          <p
            key={item.id}
            draggable
            onDragStart={() => handleDragStart(index)}
            onDragOver={(event) => handleDragOver(event, index)}
            onDragEnd={handleDragEnd}
            style={{
              ...styles.itemStyles,
              backgroundColor:
                dragOnHoverIndex === index
                  ? "red"
                  : "#f2f3f4",
            }}
          >
            {item.label}
          </p>
        ))}
      </div>
    </div>
  );
};

export default DragAndDrop;
Important correction from your code:
  • DRAGDROPLIST.splice(...) was directly mutating a constant array.
  • dragItemIndexRef must be read with dragItemIndexRef.current.
  • onDragOver can fire repeatedly, so we compare the previous hover target.
  • When moving downward, removing the dragged item changes the target index, so we calculate newIndex.
  • The parent does not need onDrop={(e) => e.preventDefault()} for this live-reorder approach.
7. Common Developer Mistakes
1. Mutating the original array
Bad: DRAGDROPLIST.splice(...). React state should be updated immutably.
2. Forgetting .current
Bad: splice(dragItemIndexRef, 1). Correct: splice(dragItemIndexRef.current, 1).
3. Using array index as the React key
Prefer the stable item ID: key={item.id}.
4. Reordering on every dragOver event
dragOver can fire many times. Track the last target and skip duplicate work.
5. Forgetting event.preventDefault()
Without it, the browser may not allow the element to behave as a drop target.
6. Not updating the dragged index
After moving the item, its index may have changed. Keep the ref synchronized.
7. Ignoring the downward-index shift
If the dragged item is before the target, removing it shifts later indexes by one.
8. Putting everything in state
Temporary drag metadata can live in refs. Use state where the UI actually needs a render.
8. How I Would Explain This to the Interviewer

Start with the requirement:

“I need to reorder items in a list using the browser's native drag-and-drop events.”

Then explain the design:

“I am using React state for the list because changing the order must update the UI. For temporary drag information, I use useRef so I don't trigger a component render every time that information changes.”

Explain the two refs:

“The first ref stores the index of the item being dragged. The second stores the current hover target.”

Explain dragOver:

“I use dragOver to know the current position while the user is dragging. I call preventDefault because the browser needs it to allow a drop target. When the target changes, I remove the item from its old position and insert it at the new position.”

Explain performance:

“Because dragOver can fire frequently, I keep the indexes in refs and skip work when the hover target has not changed. Only the visual hover state and the actual list state cause React renders.”

Finish with edge cases:

“I also handle dragging over the same item, clearing refs on dragEnd, stable React keys, immutable state updates, and the index shift that happens when moving an item downward.”

Interview shortcut: Remember “Start → Track → Reorder → Cleanup”.
Start = dragged index → Track = hover index → Reorder = remove + insert → Cleanup = reset refs.
