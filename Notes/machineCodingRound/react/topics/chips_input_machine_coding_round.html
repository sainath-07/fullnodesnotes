Questions / Topics
WHAT

What is a Chips Input?

A Chips Input is a UI control that lets the user enter multiple values and represent each committed value as a small removable chip or tag.

Simple interview definition: “It is a multi-value input where each submitted value is converted into a chip, and the user can remove individual chips or continue adding more values.”

Typical examples

Email recipients Tags Skills Search filters Categories User mentions

Interactive demo

Try: React → Enter → JavaScript → Enter. Click × to remove a chip. Backspace on an empty input removes the last chip.

WHY

What problem does Chips Input solve?

A normal text input represents one continuous string. A chips input is useful when the application needs a collection of separate values while still keeping data entry compact.

Problems it solves

  • Multiple values: Users can enter many independent items in one control.
  • Clear visual separation: Each value is immediately recognizable as a separate item.
  • Easy deletion: Individual values can be removed without editing a long string.
  • Validation: Each item can be checked independently, for example an email address.
  • Better UX: Users can see exactly what has already been added.
  • Structured state: The UI can maintain an array instead of parsing one large string later.
Key interview point: The important part is not the visual pill. The important part is converting free-form typing into a structured array of committed values.
HOW

How to implement a Chips Input

  1. Create an array/state to store committed chips.
  2. Create a separate input state for the value currently being typed.
  3. Listen for Enter to commit the current input.
  4. Trim whitespace and ignore empty values.
  5. Optionally prevent duplicate values.
  6. Add the valid value to the chips array and clear the input.
  7. Render every item from the array as a chip.
  8. Add a remove action to delete a chip by index or ID.
  9. Handle Backspace when the input is empty to remove the last chip.
  10. Add validation/accessibility depending on the product requirement.

Core state model

chips = ["React", "JavaScript"]
inputValue = "TypeScript"

The input value and chips should be treated as different pieces of state. The typed text is temporary; a chip is a committed value.

1 MINUTE

How to explain Chips Input to the interviewer in 1 minute

“I implemented the Chips Input as a controlled multi-value input. I keep two pieces of state: one for the current text and another array for committed chips. When the user presses Enter, I trim the value, validate that it is not empty and optionally check for duplicates. If valid, I append it to the chips array and clear the input. Each chip is rendered with a remove button, so removing a chip creates a new array without that item. I also handle Backspace when the input is empty so the last chip can be removed. This keeps temporary input separate from committed data and makes the component easy to validate, reuse and extend.”

<body>

  <div class="chip-input" id="chipInput">
    <input
      id="input"
      type="text"
      placeholder="Type and press Enter..."
      aria-label="Add value"
    />
  </div>

  <script>
    const chipInput = document.getElementById("chipInput");
    const input = document.getElementById("input");

    let chips = [];

    function addChip(value) {
      const trimmed = value.trim();

      if (!trimmed) return;

      const alreadyExists = chips.some(
        chip => chip.toLowerCase() === trimmed.toLowerCase()
      );

      if (alreadyExists) return;

      chips.push(trimmed);
      render();
    }

    function removeChip(index) {
      chips = chips.filter((_, i) => i !== index);
      render();
      input.focus();
    }

    function render() {
      chipInput.querySelectorAll(".chip").forEach(el => el.remove());

      chips.forEach((chip, index) => {
        const chipElement = document.createElement("span");
        chipElement.className = "chip";

        const text = document.createElement("span");
        text.textContent = chip;

        const button = document.createElement("button");
        button.type = "button";
        button.textContent = "×";
        button.setAttribute("aria-label", "Remove " + chip);

        button.addEventListener("click", () => {
          removeChip(index);
        });

        chipElement.append(text, button);
        chipInput.insertBefore(chipElement, input);
      });
    }

    input.addEventListener("keydown", event => {
      if (event.key === "Enter") {
        event.preventDefault();
        addChip(input.value);
        input.value = "";
      }

      if (
        event.key === "Backspace" &&
        input.value === "" &&
        chips.length > 0
      ) {
        removeChip(chips.length - 1);
      }
    });
  </script>

</body>
</html>
React core implementation
import { useState } from "react";

function ChipsInput() {
  const [inputValue, setInputValue] = useState("");
  const [chips, setChips] = useState([]);

  const addChip = () => {
    const value = inputValue.trim();

    if (!value) return;

    const exists = chips.some(
      chip => chip.toLowerCase() === value.toLowerCase()
    );

    if (exists) return;

    setChips(prev => [...prev, value]);
    setInputValue("");
  };

  const removeChip = (index) => {
    setChips(prev => prev.filter((_, i) => i !== index));
  };

  const handleKeyDown = (event) => {
    if (event.key === "Enter") {
      event.preventDefault();
      addChip();
    }

    if (
      event.key === "Backspace" &&
      inputValue === "" &&
      chips.length > 0
    ) {
      removeChip(chips.length - 1);
    }
  };

  return (
    <div className="chip-input">
      {chips.map((chip, index) => (
        <span className="chip" key={chip}>
          {chip}
          <button
            type="button"
            aria-label={`Remove ${chip}`}
            onClick={() => removeChip(index)}
          >
            ×
          </button>
        </span>
      ))}

      <input
        value={inputValue}
        onChange={e => setInputValue(e.target.value)}
        onKeyDown={handleKeyDown}
        placeholder="Type and press Enter..."
        aria-label="Add value"
      />
    </div>
  );
}

export default ChipsInput;
Note: For production, prefer stable IDs as React keys when chip objects have IDs. For an email chips input, validate the email format before committing.
COMMON MISTAKES

Common developer mistakes

1. Storing everything as one string

Using "React, JS, CSS" as the source of truth makes deletion and validation harder.

Better: Keep committed values in an array.

2. Forgetting trim()

Users can accidentally create values such as " React ".

Better: Normalize the value before storing it.

3. Allowing duplicates unintentionally

The same chip can be added repeatedly if duplicate rules are not defined.

Better: Decide whether duplicates are allowed and enforce the rule.

4. Mutating state directly

Using array mutation such as chips.push() with React state can cause stale or unexpected UI.

Better: Use immutable updates such as setChips(prev => [...prev, value]).

5. Not preventing Enter's default behavior

Inside a form, Enter may submit the form instead of only adding the chip.

Better: Call event.preventDefault() when committing.

6. Missing keyboard support

A chip input that works only with mouse clicks is poor for keyboard users.

Better: Support Enter, Backspace and keyboard-accessible remove buttons.

7. Using array index blindly as key

Index keys can cause rendering problems when items are reordered or deleted.

Better: Use a stable unique ID when available.

8. Ignoring accessibility

Icon-only × buttons without labels are difficult for screen-reader users.

Better: Add an accessible name such as Remove React.

9. Not defining paste behavior

Some products expect pasted comma-separated values to become multiple chips.

Better: Clarify the requirement and support it intentionally.

10. Overengineering too early

Adding autocomplete, async APIs and complex abstractions before the basic behavior works slows the round.

Better: Build add/remove first, then layer advanced requirements.

Machine coding round tip: First make the happy path work. Then proactively mention edge cases and accessibility while improving the implementation.
FOLLOW-UPS

Likely interviewer follow-up questions

How would you prevent duplicates?

Normalize with trim/lowercase and check the existing array before adding.

How would you support email chips?

Run email validation before committing and show an item-level validation error if needed.

How would you support comma-separated input?

Parse delimiters such as comma, split into values, normalize, validate and add all valid items.

What if there is a maximum of 10 chips?

Check the current length before adding and show a clear limit message.

How would you add autocomplete?

Keep input state separate, debounce the query, fetch suggestions and let the user select one to commit.

How would you make it accessible?

Use a real input, labeled remove buttons, visible focus states and sensible keyboard interactions.

How would you handle thousands of chips?

Question the UX first. If truly required, consider virtualization and avoid unnecessary re-renders.

How would you test it?

Test add, empty input, trimming, duplicate behavior, deletion, Backspace, Enter inside forms and accessibility.
